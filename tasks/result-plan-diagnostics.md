# Result plan diagnostics

## RD01. Scope

Add a read-only per-plan diagnosis to monitoring-loop result summaries, for single and scheduled plans of arbitrary supported count. Use retained, verified audit evidence and frozen reviewed versions; never re-extract, change rules, ask for confirmation, or rewrite a historical report while reading results. Separate unmet market conditions, unresolved qualitative criteria, extraction/validation problems, data absence, execution restrictions and absence of buy authority. Show actual versus required prices with observation times and distinguish a prior close from a current quote. Unknowns alongside a decisive false prerequisite are supplementary limitations, not new required confirmations.

## RD02. Contract and UI

Extend existing run views with optional `planDiagnostics`; no new route or frozen report format. Include source/version identity, effective date, fill/evaluation counts, root-outcome counts, review status, bounded examples and detail availability. Bound examples to eight per plan and 256 overall; label sampling and expired details. Never infer software errors from generic missing facts or classify every zero fill as market failure. Plans rejected before review are not members of a completed run. The summary owns data loading; a dedicated presentation component receives typed readonly diagnostics and renders accessible cards/tables using existing tokens. No new mutation or confirmation controls.

## RD03. Acceptance

Cover the four actual plans, mixed known/unknown predicates, `ANY` alternatives, satisfied signals without fills, missing/expired evidence, fills in later versions, many plans, exact decimal price formatting and optional legacy responses. Check the formal API, generated contracts, frontend tests/type/build, and an isolated real-browser result page at desktop/mobile sizes. Update English and Chinese operations/verification together.
