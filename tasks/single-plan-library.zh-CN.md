# 单份计划准备与已审核计划组合

英文规范版本：[single-plan-library.md](single-plan-library.md)。

## SP01. 已批准范围

实现用户已批准的流程：一次准备一份原文，修改型计划显式关联不可变的已审核前序计划，创建回测时选择已审核计划。保留自动提取生效交易日及模糊日期确认；成文／可用时间仍可省略。不假定固定四份文件。保留已有准备记录和回放协议。不得将 `plans.json` 或 `entry-fields.json` 作为计划证据。

## SP02. 设计与边界

复用带修订号的准备存储、工作线程及冻结时间表，不另建提取引擎。单份准备包含一份可编辑原文；关联前序时，附带由服务端保管、不可改动的已审核前缀。计划库列出已审核单份准备；修改型计划必须绑定准确的前序 manifest hash。组合选择 1–256 项已审核记录，按生效日期排序，拒绝重复日期／不同标的以及缺少或不匹配的前序版本，仅使用首项初始化账户，并保留全部来源证据。后续持仓描述不得重置账户。已有批量记录仍可读取。

已审核计划库条目不可原地修改；更新或替换须创建新准备记录。所有变更保留修订号／幂等检查及共享任务准入。不增加依赖或数据库表。浏览器不得构造权威冻结计划。

AI 请求保留完整原文与证据。回测提取使用专门的完整输出预算和时限。紧凑传输证据引用规范原文片段；确定性展开不得补造策略。无法支持或含糊的内容保持可复核，并在必要时阻止批准。不得静默接受任意未知字段、编造单位、人工补充或虚构事实。

## SP03. 组件与实现顺序

1. 后端计划库命令与已审核依赖；复用准备进度／审核端点。
2. 回测 AI 预算、紧凑提取协议及可操作的证据校验。
3. `usePlanPreparation` 管理当前提取状态；计划库 composable 管理列表、选择和不可变组合。独立计划库组件通过 props/events 暴露原文类型／前序选择及已审核选择。`BacktestNewView` 组合这些界面。原文表单每次仅读取一份文件。
4. 单元／集成／浏览器检查、实际 TXT 原文真实 AI 验证，以及语义一致的中英文文档。

## SP04. 验收与验证

- 新准备每次一份文件；拒绝多选，不拼接。
- 未审核／过期／日期不符的前序在调用 AI 前拒绝；已审核前缀不可编辑或重新提取。
- 刷新后保留计划库与准确依赖绑定。组合不得遗漏修改型计划所依赖的直接已审核前序，不得混入不同标的或冲突日期。
- 冻结／回放保持账户连续，仅使用已批准版本。
- 真实验证使用生效日期 2026-09-24、2026-09-28、2026-09-30、2026-10-09；如策略／账户事实确实未知，应报告，不自动批准。
- 执行针对性的 `python -m pytest`、`npm.cmd run test -- --run --maxWorkers=4`、`npm.cmd run type-check`、`npm.cmd run build`、API 生成检查及相关 Playwright 流程。保留既有拒绝测试，补充成功及对抗性回归。
