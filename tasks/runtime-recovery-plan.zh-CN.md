## 1. 目标与边界

已经配置完成、使用受支持数据源的软件，必须能在任何时刻启动，重建权威本地状态，并在依赖可用后自主恢复符合条件的监控。非交易时段属于正常待机，不是启动失败。依赖不可用时，应展示真实、局部化的状态；能够恢复的情况必须具有实际重试安排。

假设：同一数据库只有一个生产运行所有者，本地配置有效且 SQLite 可用，数据源语义已经受支持，所需行情和权限最终可用。未知数据源的首次安装、无法取得的历史数据、存储损坏、永久撤销的权限，不能保证无需人工干预即可恢复。操作系统故障期间，应用也无法保证继续推进。

- 始终保留计划/结果的规范字节、哈希、激活身份、评估规则、已提交事件顺序，以及业务提醒意图去重。
- 始终将行情源实际响应视为不可信输入，在持久化/评估前校验。
- 已授权编码实现及临时数据库的增量迁移测试。真实数据库迁移、新增依赖、真实行情源验收及部署仍须另行批准。
- 禁止通过修改凭证/证据伪造成功、放宽交易数据校验、删除失败测试、覆盖无关修改，或在设计期间部署/重启用户进程。
- 不包括：新增登录系统、每周自动全量认证服务、通用工作流引擎、新增券商/下单功能，以及重写交易公式或通知渠道。

## 5. 设计决策

### D1. 语义长期有效，运行健康动态确认

新语义记录包含 `schemaVersion`、规范化的 `endpointUrl`、`profileId`、能力/接口范围、周期、`sourceTimeLabel`、适配器兼容标识、`verifiedAt` 和迁移来源。`semanticRevision` 只由影响数据解释的字段计算；验证时间及旧 READY 观察不改变该版本。记录不保存凭证。

不再按年龄硬过期。语义兼容性与已安装适配器及受支持 SDK 兼容映射核对，不能只相信文件中的 SDK 固定字面量。修改凭证使当前权限观察失效，不使时间戳解释失效。更换地址或不兼容语义需要经验证的替代配置；未知语义继续阻止使用。

保留旧证据读取器及完整性校验用于历史审计。专用导入器只接收完整、未损坏、已知格式/配置、规范化地址匹配、时间标签已验证且具有明确评审过的兼容映射的证据。仅在该迁移中忽略年龄；未来日期或其他无效证据不被接受。股票和指数范围分别迁移；未验证/延后的指数保持不可用。导入幂等，不覆盖源文件，不修改原日期/哈希。校验和用于发现损坏，不是安全签名。

当前运行能力从 UNVERIFIED 开始，只能根据经校验的当前操作变为就绪。有效本地参考资料可以满足计划输入，但不能据此声称刚刚访问过行情源。正常请求同时提供健康证据。检测到语义矛盾时阻断相应范围；仅靠成功解析无法排除上游任意静默改变解释规则。首次/不兼容数据源验证继续由操作员明确控制，可能需要合适的交易时段。

### D2. 单一协调器，独立生命周期

本地启动加载配置、打开/迁移存储、恢复持久身份/工作，并绑定读取服务。行情请求在拥有明确归属的协调器中执行，不在 Web 构造或永久决定运行资格的一次性启动检查中执行。

协调器根据当前时段和活动计划核对本地事实，选择有界工作，经现有准入执行，持久化结果，再计算就绪状态。没有市场截止时间时，安排日历/维护协调而不是停止。降级结果是一项状态，不是摧毁协调器的异常。

启动、市场/恢复任务到期、经验证的配置变更、本地计划状态变更，以及有界维护唤醒都会触发协调。拟定维护上限为 30 秒；这是本地检查，不是行情源轮询。等待可中断，持续时间使用单调时钟。休眠唤醒或时钟变化后重算目标；不使用未来数据，也不机械补跑每个错过的定时器。

资源生命周期保持 STARTING/RUNNING/STOPPING/STOPPED 并报告故障。运行模式为 RECOVERING/MONITORING/STANDBY/DEGRADED/BLOCKED，根据实际局部事实派生。任何公开模式都不直接授权评估；精确的计划输入才决定能否评估。

停止时先关闭准入，再排空/等待物理工作结束，最后释放资源。普通网络失败不消耗监督器的崩溃重启预算。程序异常和清理失败保留有界监督及明确故障；旧物理请求仍在运行时不得启动替代工作线程。

### D3. 交易时段目标与局部完整性

| 情况 | 目标和行为 |
|---|---|
| 首个完整分钟产生前 | 恢复参考资料/待完成工作，不要求尚不存在的当日分钟线 |
| 盘中 | 最新已完成且符合条件的目标；先恢复评估必需的回看数据 |
| 午休 | 展示已完成上午事实；等待下午截止时间，不新发陈旧的盘中建议 |
| 收盘后 | 核对正式收盘义务及可取得的完整数据；发布延迟可以重试 |
| 周末/节假日 | 最近已知完成交易日用于展示和待完成收盘；未来开市日用于调度 |
| 日历未知/超出缓存覆盖 | 安排日历刷新；不认定工作日必然开市，也不静默退出 |
| 长时间停机后重启 | 仅恢复有依据的状态及可恢复输入；按受影响计划披露缺失历史 |

除非另行批准，保留现有 90 秒盘中可操作新鲜度规则。按时段展示健康不能将旧数据重新定义为新鲜。正式收盘评估保持独立目标类型，不是新的盘中买卖信号。

根据捕获的 `TradePlan` 或 `ExplicitTradePlan`、激活版本、目标和依赖构造需求集合。股票/指数前置条件分别检查。旧计划参考资料、显式规则状态要求、可选指数条件各自保持原语义。必需指数不可用时，只阻止依赖它的计划；未使用或延后的指数不能阻止无关计划。股票能力缺失不能阻止独立的指数展示，包括受支持时用于成交额的隐藏成分指数。

就绪依据是经验证的持久化覆盖和状态前置条件，不是批次返回码或“没有报错”。空/不完整的当日结果不能认定恢复完成。未解决的待完成收盘只阻止依赖它的状态转换；无关计划继续。

每次获取冻结一个已完成观察截止点；持久化/评估前排除晚于该点的数据。跨日后重新计算当日获取目标，不能用当日接口索取昨天。根据符合条件的交易所日期和缺失的已提交收盘身份发现漏做的旧计划正式收盘义务，不能只看现有 CLOSE_PENDING 标记：15:20 前停止、17:00 后重启不能丢失收盘。遵守实际激活时间/版本，在下一次可操作评估前按时间顺序恢复所依赖的收盘转换。历史输入或激活历史不能证明某次转换合理时，保持该计划被阻止，并明确说明缺少的状态。

参考资料工作身份包含实际依赖集合和有关计划/激活身份，不只使用 `(date, symbols)`。同一股票从 ExplicitTradePlan 切换为 TradePlan 时，即使日期和股票集合不变，也必须请求新增必需历史/涨跌停资料。恢复工作身份不替代两类计划原有评估身份。

### D4. 有界恢复与重试归属

协调器决定重试什么、何时唤醒；请求控制器决定物理准入、节流、冷却和重试权限。保持单个物理行情工作线程、请求开始至少间隔 1.25 秒、15 秒超时，以及零次周期内立即重试。

| 结果 | 行为 |
|---|---|
| 临时连接失败/超时 | 现有 30/60/120/300 秒退避；后续周期在上限继续 |
| 限流 | 共享 300 秒冷却，或经过验证的更长上游要求；进程重启后保留 |
| 权限拒绝 | 阻止普通工作；只有明确配置变化或单次受控复检可解除现有操作封锁 |
| 缺少凭证 | 不请求行情源；维护唤醒时检查本地配置 |
| 预期发布延迟/数据不完整 | 按目标和必需覆盖范围进行有界局部恢复 |
| 语义不兼容/配置无效 | 阻止相应范围，不盲目重试或导入兜底证据 |
| 存储失败/程序错误 | 可见故障及有界监督，不作为普通行情重试 |

拟定权限复检策略：每个操作每 300 秒最多一个符合条件的探测，合并重复请求，经过相同冷却/队列，不执行整套认证。只有该路径可以调用现有 `reset_permission_block`；失败立即恢复封锁。修改凭证时保留限流状态。不能只是把已被永久封锁的普通调用再放进另一个定时器。

跨连续分钟目标使用稳定的故障范围键，避免新目标时间绕过退避。合并正在执行的相同工作，保留现有 32 个等待槽位及 64 个退避键上限。替换过时的展示目标，但不丢弃未解决的业务状态义务。不能通过新循环静默重置现有指数单目标重试限制；区分已达到上限的旧截止点发布工作与未来目标/行情源恢复。

每次恢复只处理有界单元，随后重新考虑截止时间和其他范围。避免启动全股票批次独占行情源。为解除活动计划阻塞所需的最少数据提供公平执行机会；后台历史补齐让位于实时工作。容量不足时展示延迟和待恢复范围，不承诺普遍适用的完整恢复时间。尽量以持久化覆盖作为恢复游标；只有事实无法重建义务时才新增显式工作记录。

### D5. 身份、重新配置与提醒

每个工作单元捕获活动计划/激活版本、目标、语义版本及运行代次。提交前重新核对有关代次。配置重载先暂停准入、等待旧调用结束、校验替代配置，再原子安装。无效编辑使相应范围阻止运行并显示原因；不能静默切到另一数据源。仅刷新证据元数据不替换运行实例。

新代次不意味着可以改写历史评估、复用陈旧的当前投影或再次提醒。当前健康应根据持久化事实和有效当前观察重建。保留评估身份/唯一声明及精确计划激活检查。导入历史分钟只恢复事实，不重放已过期的交易机会。需要历史状态转换的重建，应与新可操作评估区分，保持必需因果顺序，不能假装计划在实际激活前已生效。

停机后发送尚未投递的可操作提醒前，重新校验其有效窗口、计划/激活身份和适用的当前状态。过时的待发送意图保留为可审计历史，并记录终态抑制原因；不删除，也不自动生成替代意图。非操作类/正式收盘通知策略分别保留。发送超时可能已经在外部成功；保留现有不确定投递处理和渠道幂等机制。验收承诺是不重复产生业务意图，不是无法普遍保证的外部严格一次投递。

投递资格独立于评估器输出和哈希。两条评估事务路径必须原子保存状态/声明与投递资格；历史重建不能先提交可无条件投递的意图，再依赖后续 WebSocket 抑制。拟定策略：盘中买卖/就绪提醒在来源截止点加现有 90 秒新鲜度余量后过期，激活失效时提前失效。风险状态通知（包括现有跨日 RISK_BREACH 例外及显式 RISK_ALERT）遵循状态有效性规则，不统一套用盘中过期时间；保留真实风险通知并标明历史日期。在已批准规格中逐一分类现有信号。任何启动投递前，对升级前待发送记录执行相同门禁。投递校验必须兼容旧计划和显式计划加载器。无法确定旧记录有效性时禁止发送但保留记录；已经在外部发送中的消息无法撤回。

风险通知受每个计划的恢复完成门禁约束，只有重建至当前目标所需的全部状态变更义务处理完毕后才能释放。如果停机期间 D1 发生风险突破、D2 已解除，不能在中间的 D1 提交后发送通知。进入渠道 IO 前，再核对最新已提交风险状态、激活版本及恢复完成门禁；积压未解决时，该计划的恢复/待发送风险通知保持暂缓。启动投递前先持久化/重建此门禁，不能将临时暂缓记为终态抑制。不阻止无关计划的通知。外部发送准入后再发生状态变化，不能撤回已经开始的发送。

### D6. 最小持久化变更与安全回滚

在现有实测证据旁使用独立版本化语义记录，原子写入。复用当前历史、健康、评估、指数恢复及发件箱存储。拟定增量迁移：新增有界行情源恢复检查点，按已配置行情源身份及操作索引，保存重试/冷却时间和脱敏原因；以及按现有提醒事件 ID 索引的最小投递资格元数据，用于过期/抑制，不改写事件载荷或哈希。现有覆盖/声明继续权威；仅在无法重建时保存额外待完成工作。迁移编号从实施时的 Alembic 最新版本确定，不能写死本草稿观察到的编号。

生产上线前必须取得迁移批准及可用的一致性 SQLite 备份。导入新文件，不修改旧证据。迁移必须幂等，各边界重启安全。不能随意用升级前数据库覆盖升级后新增业务记录来“回滚”。优先使用经过验证、可读取向前兼容增量结构的旧应用，或停机后经过评审的恢复过程；存在待完成状态时拒绝破坏性降级。旧程序可能重新带回旧认证问题，并非任意时段恢复方案。

### D7. 真实状态与同步协议升级

定义唯一由后端管理的状态契约，包含 `monitorContractVersion`、`runtimeGeneration`、`mode`、`reasonCode`、`nextWakeAt`、`nextRetryAt`、`lastProgressAt` 及有界局部进展。局部视图包含必需目标、数据截止点、原因及就绪状态。不暴露密钥/原始行情异常。个别股票投影为空/缺失不能阻止运行状态展示。

计划尚无首个当前决策时，返回有类型的 WAITING/RECOVERING 条目，保留已经健康的其他条目。按计划家族明确分派投影解析，从专属仓库读取显式规则结果，而不是旧决策头。不能为满足总览结构而将 ExplicitTradePlan 强行交给仅支持旧计划的加载器。

恢复和待机时仍具有运行代次；它标识一次运行实例，不代表就绪。当前决策投影继续使用代次隔离。存活判断依据所属协调器的计划唤醒，或有界活动操作及真实进展；仅发送 WebSocket 心跳不能刷新该判断。区分连接中断与后台仍存活但被阻止。

这是明确的监控契约升级，不能称作无害的可选字段新增：当前健康校验将 DEGRADED 与全局 `readOnly` 绑定，心跳解析要求精确字段。在实现前确定版本协商及旧客户端拒绝规则。后端、生成类型及带哈希前端资源作为同一版本的本地应用发布；不兼容缓存客户端必须要求刷新且保持不可操作。保留事件序号单调性及运行代次变化后的快照刷新；不扩张事件类型，不因每次健康变化而重连。

复用现有总览和 `/system` 展示状态/进展。STANDBY 不显示陈旧数据恢复横幅；只有真实进行中/待执行工作才能显示 RECOVERING；故障必须说明重试时间或必要操作。继续通过现有配置文件配置，维护任务执行经验证的重载；不新增登录、密钥续期界面或必需的恢复按钮。“立即重试”不是自动恢复前提，不纳入初始范围。

用户要求先提高实施效率，再继续实现。本次调整改变工作顺序和验证节奏，不改变 D1–D7、A01–A12、交易规则、证据要求或部署权限。既有 RR001–RR022 和 C0–C5 保持可追踪，保留已完成证据。进度以任务表中的五项业务成果为准，不以提交数量或模型分工阶段为准。

- **同一决策只解决一次。** 编写历史使用方前，集中明确历史截止点/迟到登记、风险来源有效时间和证明预算。新安全决策先评审再编码；没有相反证据时复用已定决策。业务含义不明确时请求用户判断，不自行猜测默认规则。缺失历史对依赖计划明确保持未知。
- **在合适边界测试。** 每次行为修改先有有意义的失败测试，修改后运行受影响测试。每项完整成果运行集成/退出故障用例及相关回归组。最终验收/默认启用前运行第 7 节完整离线门禁；共享代码/契约变更时提前扩大检查。不能删除、跳过、削弱测试或标记预期失败来取得绿色结果。相关输入未变化时不重复已通过检查。
