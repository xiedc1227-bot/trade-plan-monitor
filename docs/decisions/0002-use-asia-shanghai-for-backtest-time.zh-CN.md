# ADR 0002：所有回测时间统一使用 Asia/Shanghai

> 中文审阅版。英文权威版为 `0002-use-asia-shanghai-for-backtest-time.md`；两份文档必须保持语义一致。

- 状态：`Accepted`
- 日期：`2026-08-26`
- 项目：`backtest`
- 模块：`backtest-data`、`backtest-engine`、`backtest-results`、`backtest-jobs`、`backtest-api`、`backtest-web`

## 背景

本产品只服务一名本地用户，没有跨环境或多区域时间展示需求。A 股行情事实、交易时段、事件时间回放及现有实时契约已经使用中国市场时区。但本地尚未提交的回测 MVP 仍会把部分行情存储元数据、结果行、摘要 JSON 和成交 CSV 时间戳规范化为 UTC。该行为是需要迁移的实现基线，不是已批准公开约定。如果在新的回测任务和 REST 字段中继续引入相同 UTC 规则，同一个本地产品内部会出现两套可观察时间约定。

即使两个值表示同一时刻，混合偏移也可能改变规范请求字节、Cursor 签名、幂等哈希、排序、筛选和导出。无时区本地日期时间则会依赖进程或浏览器环境，并可能静默改变交易日含义。

## 决策

1. 每个回测日期时间在内部都使用带时区的 IANA 业务时区 `Asia/Shanghai`。范围包括行情事实、回放事件、模拟成交/outcome/权益、数据集元数据、任务生命周期、授权、审计/幂等记录、lease/heartbeat 截止时间、结果发布、数据库值、API 输入/输出、Cursor、导出和 Web 展示。
2. RFC 3339 输入只接受 `+08:00` 和 0～6 位小数秒，并在任何 identity 操作前规范化。规范持久化、哈希、Cursor 编码、输出和导出文本精确使用 `YYYY-MM-DDTHH:MM:SS.ffffff+08:00`。`Z`、无偏移日期时间文本、超过 6 位小数秒及其他任何偏移均校验失败。
3. 事件范围、`tradeDate`、`warmupStart` 和 `acquiredTradeDate` 等仅日期值继续使用 `YYYY-MM-DD` 中国市场日历。30 秒 lease、10 秒 heartbeat、14 天保留和 90 天保留等继续表示持续时间；实现可以使用单调时钟进行耗时调度，但任何持久化或公开截止时间都使用 `Asia/Shanghai`/`+08:00`。
4. 时间规范化必须发生在规范请求序列化、`requestHash`、幂等比较、Cursor/HMAC 编码、排序键、持久化和导出生成之前。浏览器校验 `+08:00`，并直接展示中国时间，不经过主机/浏览器时区转换。
5. 语义事件时间戳继续遵守现有 identity 规则。当所属契约已有要求时，`receivedAt`、`openAt`、`signalAt`、`filledAt`、`resolvedAt`、`eventAt` 和 `markedAt` 可以参与事实/结果/报告 identity。操作性任务/审计时间戳不进入 `run_id`。
6. 现有 `backtest-run-v1`、`dataset_hash` 和 `backtest-report-v1` 语义 identity 保持逐字节相同，因为其已批准事件时间戳已经携带中国市场语义。当前 UTC 规范化的 `backtest-run-summary-v1`、`backtest-fill-record-v1`、`backtest-detail-record-v1`、摘要 JSON 和成交 CSV 投影成为不可变旧版兼容输入。新的中国时间结果发布使用显式版本化 v2 结果/内容集合/导出 Domain，绝不静默重新解释或覆盖 v1 字节。在另行批准的采纳迁移生成可独立验证 v2 内容前，旧 v1 行不能作为新 API 下已验证可复用/公开结果。

## 已考虑的替代方案

### 任务和审计字段使用 UTC `Z`

拒绝此方案，因为本地中国市场产品没有跨环境需求，拆分约定只会增加转换和契约复杂度，不产生用户价值。

### 接受任意带时区偏移并规范化为中国时间

拒绝此方案，因为在所有层一致应用规范化之前，同一意图的其他偏移可能导致规范请求哈希、Cursor 签名、缓存键和幂等行为漂移。允许范围内的 0～6 位小数秒写法会在这些操作前统一规范为固定六位表示。

### 使用无偏移本地日期时间文本

拒绝此方案，因为其含义依赖环境进程/浏览器配置，无法证明预期的中国市场时刻。

## 后果

- 所有回测界面、API 资源、数据库和导出都展示同一套中国时间约定。
- 边界校验器必须拒绝 `Z`、缺失偏移、`+08:00` 以外的偏移和超过 6 位小数秒；规范输出/存储始终精确使用 6 位小数秒。
- 排序/筛选/Cursor/幂等代码只接收一种规范时间戳表示。
- 仅日期市场范围和耗时阈值保持现有含义与数值不变。
- 现有 UTC 规范化 v1 结果/导出投影保留为不可变兼容 artifact；活动 v2 发布和公开 API 只暴露规范中国时间。
- 以后若改变公开时间戳约定，必须新增替代 ADR、生成契约迁移、Cursor/幂等兼容计划和数据/导出迁移证据。

## 安全与运维影响

封闭失败的时间戳校验可以防止不可信请求把交易事件移动到另一日期，或产生含糊的筛选、Cursor、保留或幂等行为。日志和诊断可以使用相同规范中国时间，但必须继续遵守现有密钥脱敏和有界文本规则。Lease 与超时强制仍适合使用单调耗时测量，并且该值不会作为墙上时间戳公开。

## 回退与迁移

回测 REST/任务设计已在冻结的 42 路径 OpenAPI 契约下实现。只有未来公共字段实际变化时，移除已否决 UTC 提案才需要经过审核的生成契约变更；WEBF13 不作此类变更。任何 Schema 变更前，迁移必须建立验证备份，并只读盘点 UTC 行情元数据和 v1 结果/导出 artifact。排除在 `dataset_hash` 外的行情元数据只能通过经过测试且证明数据集 identity 不变的迁移，转换为等价规范中国时间。参与 identity 的 v1 结果/导出字节继续保留，活动路径写入版本化 v2 中国时间投影。未来实现若再次改变时区表示，必须保留现有 `run_id`、`dataset_hash`、`reportHash`、请求/幂等行为和 Cursor 遍历，并保留或明确迁移每个版本化导出 identity。
