# ADR 0009：只准入一个未完成回测任务

英文权威版；匹配的 `.zh-CN.md` 为中文审阅版。

- 状态：用户明确纠正范围，已接受
- 日期：2026-10-07，Asia/Shanghai
- 关联：ADR 0001、ADR 0008、ML17、IP09、ML-T33、MV18
- 仅覆盖此前多任务队列准入及租约过期释放任务槽的选择

## 背景

执行线程已串行，但准入仍允许 100 个排队任务，选中恢复可授权多个 ID；过期未完成工作可在任务终态前释放准入。用户要求一个未完成任务：新任务及互斥操作必须等待其实际结束。

## 决定

1. 复用任务拥有的 SQLite 写事务，在 `DATA_SYNC`、`DATASET_VERIFY`、`BACKTEST_RUN` 之间最多准入一个未完成操作。`QUEUED`、`RUNNING`、`CANCEL_REQUESTED` 均占此槽，包括过期/未知租约。
2. 新运行读取快照前预留同一任务槽。未解析预留在释放/完成绑定或明确任务拥有的孤儿清理前保持准入占用；仅租约过期不会释放。
3. 不同的新操作以内部分码 `BACKTEST_BUSY` 经既有公开 `409 CONFLICT` 信封返回，不创建第二个任务/预留。相同 key 重放及活动操作去重继续返回既有资源。
4. 请求取消仍是未完成。完成/失败/取消终态释放任务槽。明确恢复最多选一个既有任务，协调器须在下一次领取或替换前排空物理工作。保留 30 秒租约、10 秒 heartbeat、3 代领取以及旧 token/发布保护。
5. 保留历史记录及分页查询。遗留待处理记录须明确核对处理，不会为准入新工作而静默删除、恢复或取消。在线监测及只读状态/历史/结果继续可用。
6. 待完成的单原文准备流程须在未来入口边界遵守同一互斥。本次纠正实现已有任务/预留准入及选中恢复，不代表准备或新 API/UI 控制已实现。

## 考虑过的方案

- 一个执行线程加 100 个排队任务：与用户单任务要求冲突。
- 请求取消或租约过期即释放准入：两者都不能证明任务实际终止。
- 新增调度器、通用跨操作锁或资源框架：现有事务准入边界不需要这些扩展。

## 影响

不同的提交在未完成工作核对结束前收到冲突，重启不会自动释放任务槽。不可变已完成结果、任务身份、保留规则、存储领域、数据结构及既有 API 错误枚举继续兼容。本决定不变更冻结历史回放模式中的原计划替换语义。

## 验证

MV18 记录不同并发提交、同请求幂等、取消中、过期/未知租约、待处理/过期快照预留、选中恢复、物理线程排空及终态释放。生成契约保持不变。完整准备/API/UI 工作流验收仍待完成。
