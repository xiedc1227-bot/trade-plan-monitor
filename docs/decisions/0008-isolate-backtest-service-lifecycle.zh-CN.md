# ADR 0008：使用专用线程隔离回测服务生命周期

英文权威版；匹配的 `.zh-CN.md` 为中文审阅版。

- 状态：用户已授权线程执行及首次使用才准备的实施，最终 API 审阅仍待完成
- 日期：2026-10-07，Asia/Shanghai
- 关联：ML14–ML17、IP09、ML-T30–ML-T39
- ADR 0001 的执行位置、队列身份和原子发布仍适用
- ADR 0009 定义当前单个未完成任务准入及单个选中恢复规则。

## 背景

当前回测资源准备位于 Web lifespan 就绪前，工厂/start 失败通过共同清理停止已启动监控。专用执行线程已经存在，仅再加线程不能纠正生命周期策略。用户确认同进程线程隔离已足够，不要求以后必经子进程阶段。

## 决策

保留一个产品、进程和 Web/API 入口，保留有界专用执行/仓库线程及既有单执行槽。应用启动只注册无副作用路由/状态，首次明确使用才 single-flight 准备资源。元数据 READ_READY 与执行 READY 分开，状态/历史读取不启动任务或付费工作。公开独立健康/能力，局部处理首次使用/任务/协调器错误。账户、时钟、存储和通知出口独立，仅共用不可变规则/应用参与者。

停止/恢复由协作取消、领取校验的原子完成及物理排空控制。旧工作仍可修改存储时不得替换执行器。初始化/关闭超时显示降级/需重启，不强停线程。未知付费结果不静默重试。Windows 检查覆盖故障包容、路径、归属、取消、既有有限工作防护和 10 只股票监控负载。

## 备选方案

自动后台预热仍在启动接触未使用业务，已被否决。只拆模块仍耦合启动清理。每股线程不构成回测隔离。自有子进程、独立部署服务、远程主机边界更强，但当前未选择。仅已接受同进程边界不足时再评估。

## 影响

回测准备失败不再需要阻止 Web/监控就绪。应用启动零回测 I/O/队列恢复，已有待处理工作仅明确选择后恢复，新提交只授权自己的任务。未使用的关闭/状态/预取无副作用，并发首次使用共用初始化。同进程原生崩溃、内存耗尽、卡住线程和共享主机/设备故障为已接受风险。线程资源保护为软保护，不声称进程专用硬 CPU/内存上限或强制取消保证。

## 验证

ML-A19–ML-A24、ML-C11–ML-C13 覆盖独立启动、自有线程、感知排空恢复、取消/完成竞态、存储/供应商边界、可理解降级及 Windows 负载证据。ML-A08 保持在线行为。[部分已执行验证](../verification/monitor-loop-backtest.zh-CN.md) 记录已完成的 ML-T30–ML-T34/ML-C11/ML-C12 及启动解耦 PASS；本 ADR 不声明完整故障/负载验收或最终 API 批准。
