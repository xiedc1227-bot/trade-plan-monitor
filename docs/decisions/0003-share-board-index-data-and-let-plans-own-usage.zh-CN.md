# ADR 0003：共用板块指数数据，使用方式由交易计划决定

> 中文审阅版。英文权威版为 `0003-share-board-index-data-and-let-plans-own-usage.md`；两份文档必须保持语义一致。

- 状态：`Accepted`
- 日期：`2026-09-02`
- 项目：`market-index-context`
- 模块：`index-identity`、`index-data`、`plan-index-conditions`、`monitor-index-view`、`backtest-index-data`、`backtest-index-view`
- 已批准设计：[`PROPOSAL-market-index-context.zh-CN.md`](../proposals/PROPOSAL-market-index-context.zh-CN.md)

## 背景

板块指数条件是 A 股择时的重要输入，但产品必须明确区分“提供市场数据”和“决定交易”。如果工具强制生成统一市场判断，所有计划都会被迫使用同一种解释，计划文档之外还会出现隐藏行为，也无法清楚说明两种策略为什么可以根据同一市场产生不同反应。

监控和回测还需要显示相同的参考指数数据，不能为每只股票分别重复获取和计算同一个指数。同时，共用数据不能导致不同计划共用条件结果或最终判断。

已批准提案把自动板块映射、共用不可变数据、计划负责条件树、Web 投影、可重复回测、迁移和供应商能力作为一个完整架构进行评审。本 ADR 记录其中最重要的责任边界以及被否决的替代方案。

## 决策

1. 工具负责参考指数身份、数据获取、校验、通用数值事实、健康状态、截止时间、修订号和哈希。工具不发布统一市场分类，也不增加隐藏的交易限制。
2. 每份交易计划自行决定指数数据是否以及如何影响计划。已批准的指数条件可以放在 `entry`、`reduction`、`risk` 或 `blockers` 中，并使用现有 `ALL`/`ANY` 树规则。计划可以完全不包含指数条件。
3. 映射到同一板块指数、并在同一截止时间判断的股票使用同一份不可变 `MarketIndexSnapshot`。条件证据和最终判断仍然属于各自计划。
4. 映射版本 `board-index-map-v1` 使用以下准确绑定：
   - 上证主板 → 上证指数 `000001.SH`；
   - 深证主板 → 深证成指 `399001.SZ`；
   - 创业板 → 创业板指 `399006.SZ`；
   - 科创板 → 科创50 `000688.SH`；
   - 北交所 → 北证50 `899050.BJ`。
5. 第一阶段允许 `INDEX_CLOSE_GTE_MA`、`INDEX_CLOSE_LTE_MA`、`INDEX_MA_NON_DECREASING`、`INDEX_MA_NON_INCREASING`、`INDEX_RETURN_GTE` 和 `INDEX_RETURN_LTE`，参数范围使用提案中已经批准的范围。
6. 监控和回测把共用指数事实与计划专属条件结果分开显示。浏览器代码不确定映射、不计算条件，也不改变规则优先级。
7. 指数绑定和条件必须使用明确的 Schema v2 计划。现有 Schema v1 计划和历史结果保持不变。
8. 盘中证据使用已经确认的完整5分钟周期。批准实施前，必须只读检查供应商是否支持已批准指数代码和字段。供应商 token 不能进入报告或日志。
9. 第一阶段只包含板块指数。行业指数分类和规则的数据源及映射尚未决定，因此必须通过另一份已批准设计后才能加入。

## 已考虑的替代方案

### 在工具中强制使用统一市场限制

否决此方案，因为它会产生没有写入交易计划的行为，还会强迫不同策略使用同一种解释，使监控证据不够直接。

### 为每只股票分别获取和计算同一个指数

否决此方案，因为相同板块数据会被重复保存，浪费供应商请求额度，而且时间或清洗差异可能让同一板块股票看到不同事实。

### 允许用户或 AI 任意选择参考指数

第一阶段否决此方案，因为任意选择会降低结果可重复性，还可能产生不一致或编造的绑定。板块参考由股票代码和带版本映射共同确定。

### 第一阶段同时加入行业指数

否决此方案，因为权威行业分类来源、分类日期规则和带版本的行业指数映射都没有批准。现在加入会让回测难以重复。

## 后果

- 一份指数快照可以服务多只股票，同时每份计划仍能独立解释。
- 不同计划根据同一快照得到不同结果属于正常并且预期的行为。
- 删除计划中的全部指数条件后，指数不再影响该计划判断。
- 接口和 Web 设计不能提供暗示统一自动市场结论或交易影响的共用字段。
- Plan Schema v2、路径级证据、公式身份、历史覆盖和哈希会增加实施工作，但能让监控和回放接受审计。
- 没有指数条件的计划在指数数据缺失时继续保持原有行为。使用指数数据的计划只在受影响路径产生 `MISSING_INPUT`。
- 现在可以按照已批准提案中的依赖顺序编写模块规格，但实施仍需单独授权。

## 安全与运维影响

指数供应商响应属于不可信输入，必须在适配器边界校验。股票/指数身份混用、重复 K 线、非规范十进制、错误截止时间、数据缺口、未来数据和公式不匹配必须失败关闭。一个板块指数故障不能影响其他板块。

共用快照不可变，并通过内容寻址。日志、错误、接口、报告和导出不能暴露供应商 token 或不必要的供应商原始响应。即使项目配置中已经保存 token，真实供应商请求仍需单独授权。

## 回退与迁移

以后如果要改变责任边界，让工具重新控制交易，必须新增替代 ADR、新计划结构版本、接口和证据变化，并制定保留现有计划及结果哈希的迁移方案。修改板块绑定必须建立新映射版本和新计划版本，不能悄悄改变活动计划。

Schema v1 计划继续可以读取和执行，`referenceMarket=null`。Schema v2 草稿加入自动绑定，并且只加入来源计划中已有或用户明确审核过的指数条件。历史结果不能使用后来的指数数据或结论重新改写。
