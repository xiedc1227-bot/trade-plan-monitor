# ADR 0007：将恢复交付元数据与提醒身份分离

对应英文文件为正式版；本文为中文审阅副本。

- 状态：接受隔离实现；生产发送仍受门禁约束
- 日期：2026-09-21
- 关联：`SPEC-runtime-recovery`、RR011–RR013

## 背景

恢复可能提交历史判断，其原始提醒必须保留审计，但不能自动发送。提醒/结果的载荷及哈希不可变；已读、渠道尝试和当前交付适用性是不同事实。过去一次成功分类不能证明重启后的当前激活、generation、目标或持仓。

## 决策

迁移 `0019_alert_delivery_eligibility` 接在 `0018_provider_recovery` 后，新增以事件 ID 为键的独立记录。缺失记录表示未分类的 `HOLD`。绑定 session 的仓储按需初始化，或每批最多初始化 100 条。`AlertOutbox.enqueue_recoverable` 为显式启用接口，在调用方事务内创建提醒和初始 HOLD；去重不重置分类，也不把旧事件归属于当前激活身份。

按信号而非严重程度分类。盘中可操作提醒在原始数据截止时间 + 90 秒失效，包含等号。缺失来源截止时间不以创建/评估时间替代。状态风险提醒不统一按年龄过期。分类、捕获的屏障/结果身份、revision 和审计原子持久化。对照规范提醒事实校验元数据；证据损坏为可见故障。写入者在读取前串行化，并按 revision 比较后更新；仓储不独立提交。

`SUPPRESS` 对原始事件为终态；`HOLD` 可恢复。`ELIGIBLE` 仅为历史凭据。后续发送须在认领后、每次渠道调用前建立当前权威事实，避免候选数量上限造成饥饿，并保留发送结果不确定的处理。数据库事务不跨外部 I/O。隔离的显式风险路径不授权旧版风险，独立的旧版纯分类器也不自行持久化或发送。

## 备选与验收

拒绝：改写规范载荷；以已读或渠道失败代替抑制；风险统一按 90 秒过期；在升级 Schema 时回填全部历史；把已存 ELIGIBLE 当作永久许可。

本增量验收包含临时数据库迁移/中断/回滚、有界初始化、提醒字节不变、来源过期、拒绝损坏证据、并发 revision 校验及原子审计。这不是 RR011–RR013 的完整验收：评估器集成、当前权威证据持久化重建及最终发送准入仍未完成。非空表降级拒绝丢弃元数据，包括终态审计；应向前修复或使用兼容备份，不能覆盖更新的业务记录。真实迁移和部署另行批准。
