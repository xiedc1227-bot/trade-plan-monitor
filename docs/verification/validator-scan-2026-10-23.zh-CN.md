## VLS-V02. 表示与归因

保留原模型/解析器约束和规范化规则。实验证明直接接收原 TEXT 的 UTF-8 字节表示，保留全部模型/域/标量/head 检查，增量计算域哈希，并比较包括 EOF 在内的完整规范化字面内容。公共规范化 API 不变。单行辅助函数释放前一行临时模型，选中输出及共享原始输入继续持有。

对于合法的 16,472,833 字节样例，跟踪峰值中位数从 156,429,042 字节（149.18 MiB）降至 24,866,343 字节（23.71 MiB），约降低 84.10%。原始输入和期望输出预建且不计入跟踪；Python/原生分配器保留及进程采样另行看待，不能据此证明可强制执行的内存边界。

2008 行样例的纯校验墙钟/CPU 中位数从 2.1487/2.015625 秒变为 4.7526/4.71875 秒。实验阶段线程 CPU 中位数分别为解析 0.71875、规范化 1.0、编码/哈希 1.75、字面比较 1.125 秒。包含阶段插桩和 Windows CPU 量化误差，独立聚合的中位数不一定等于总量，用户态/内核态计数均已保留。Python 迭代编码路径造成明显 CPU 回退；保留规范化树本身并非主要剩余内存成本，省去整份文档字符串能节省内存，但 Python 层迭代付出了代价。

`iterencode()` 仍生成完整 token，请求排序键仍使用原字符串编码器。把输出 token 切成 8192 字符片段不证明生产者分配有界。刻意保留保守的双代际扫描准入：大行工作区仍为 197,697,036 字节，超过 64 MiB 限额，在 payload 执行前拒绝。新旧完整纯校验器均接受同一大输入。因此，即使测得内存下降，可用性和原生边界门禁仍失败。

## VLS-V03. 并发对比

下表基线是上一轮有序扫描/已获预算共享组 P0，不是原生产实现。所有变体在本轮同一诊断计划中运行，不启动子 worker。分别列出 3 个八读取者批次和 3 个混合批次中位数。每个变体均成功 39/39，全部成功监控/结果的完整输出哈希一致。每变体八读取者批次合计均保留 3 次证明、21 次加入。正常结束状态的字节债务和 owner 在途工作均为零。

## VLS-V04. 正确性与生命周期验证

回归选集 170 项通过，出现 1 条已有依赖警告。补充最后 3 个重新计算根哈希的域篡改用例后，全部 52 个实验测试通过；其中与回归选集有重叠，不能额外算作 52 个独立回归。Ruff 和格式检查通过。

覆盖全部 19 个原始字段与参考接受行为、规范 UTF-8/转义/补充平面 Unicode/EOF、缺失 payload 和非法存储、各域哈希、复杂请求及重算根哈希后的逐 fact 公式篡改。新增的 bar/request/formula 域损坏在重新计算根哈希后仍被拒绝。对于原模型身份契约刻意不检查的字段，保留参考接受行为；独立跟随者相等比较仍覆盖该字段。

内存准入测试保留 payload 分配前拒绝。确定性 8 读取者已获预算共享组在 1、2 个共享扫描槽位下均通过，保留 1 次证明、7 次加入。覆盖物理许可释放、排队取消/截止/停止、预付跟随者撤销、变化快照及正常排空无泄漏。原后置权威、activation、有效期及观察者所有权回归通过。游标清理失败保留全局字节债务和存储关闭，子进程清理失败通过原注入 worker 契约验证。取消保留已提交物理工作及存储围栏直至排空，不声称实验扫描许可已与生产 worker 集成。

CPU 许可覆盖游标 execute/fetch/关闭，获取顺序在现有字节租约之后；在已获预算共享组屏障前释放，等待物理证明时不持有许可。清理失败可以释放 CPU 槽位，但继续保留字节债务和存储关闭围栏，这是两种不同的所有权责任。

## VLS-V05. 复现与下一步

运行新 `scripts.experiments.validator_benchmark`，将 `--monitor`、`--results`、`--run` 和 `--output` 指向已有冻结样例；模块规定全部 3 轮诊断和变体。`scripts.experiments.validator_probe --memory --output ...` 可重新生成大行；去掉 `--memory` 并提供 `--monitor` 可做纯校验 CPU 归因。计时探针须顺序运行。证据记录源码和样例哈希，不发布原始 payload。最终基准清理移除不可达子 worker 记账，同一组变体另做冒烟检查并单独记录。

下一步优先保留扫描准入候选；降低保守输入预留前，先明确有界生产者/解析生命周期及更快的字节等价编码方案。证据不足时不开展大规模 schema 遍历器重写。保留 64 MiB、独立权威检查和物理排空；硬门禁通过后才恢复进程实验及固定 10 对 A/A / 20 组 ABBA/BAAB 验收，保留混合改善 20%、单独结果回退 <=5%、监控/CPU 回退 <=10% 及拒绝/超时不恶化。本轮没有集成候选通过，因此未进入生产/浏览器发布验证。
