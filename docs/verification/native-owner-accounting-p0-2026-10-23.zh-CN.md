P0 为 NOT_QUALIFIED；P1 为 NO_GO。隔离原生扩展已观测 Python RAW/MEM/OBJ、新分配 arena 和实际 SQLite 分配器。这是逻辑域可行性切片，不代表底层内存或所有者资格完成。生产源码和依赖未变。既有 AI 提取、日库存及 README 工作不纳入本次范围。

编译后的扩展在解释器初始化后包装已有 Python 分配器。SQLite 在驱动导入前配置，并核对加载 DLL 路径。原生指针/域记录在跨线程释放和成功 realloc 时保留分配所有者。固定表含 262144 项，占用 8388608 字节，单列为观测存储。溢出后冻结不可靠核算并标记本轮无效；回调继续转发分配/释放。实验仅用于可丢弃进程，不卸载回调。

## NOA-V04. 失败门槛及延期的依赖工作

Python 嵌套域调用重复计算物理存储：SQL 关闭后，所有者总量仍约为 8388608 字节行的两倍。首个观测子进程结束前有 182 次未知释放，包含安装前的对象。Arena 底层归属分配上下文，尚未核对跨池使用者。调用后的 realloc 记录保留逻辑所有权，但无法捕获瞬时新旧底层重叠。Rust 直接分配、CRT/堆碎片以及完整池/结果转移未被该扩展覆盖。逻辑总量守恒不等于物理守恒。

这些具体失败阻止了基于源码的预算修改和有完整预算的大行集成。预初始化启动器、完整 oracle/候选生命周期分离、真实文件数据库查询覆盖资格、底层核对、分配失败注入及合格大行候选尚未完成。既有完整校验器回归不能替代这些新原生门槛。保留原租约及清理债务；不得将此观测器部署为准入分配器。

## NOA-V05. 验证

全部 8 个探针子进程完成断言：迟配置、溢出、3 轮基线和 3 轮观测。观测轮次验证原生跨线程释放、确切 SQLite DLL 选择、返回行生命周期、逻辑域/所有者总量及密集校验错误。既有篡改、死锁/并发、时间边界、存储清理、失败恢复及取消/排空选择通过 166 项，用时 27.85 秒，出现一个既有 FastAPI 警告。每类大行准入的三轮检查保持安全拒绝及最终零债务。不宣称服务/浏览器验收、新生产上界或可用性改善。

## NOA-V06. 提交审查

修复地址复用竞争：realloc 释放旧地址后，其他线程可能立即复用；仅按指针/域删除可能误删新分配记录。记录现增加单调代次，回收必须匹配保存的代次；不匹配将观测判为无效，不删除其他所有者记录。安装前未知 realloc 指针不能回收新跟踪的存储。Realloc 失败保留旧记录。核算丢失更新采用同一把锁；构造指针返回值失败时释放原始分配。

原生测试程序通过 5 种台账场景。在隔离变异版本中移除代次条件，按预期以 22 退出。记录布局变化后占用 10485760 字节；该观测开销不改变应用预算。最终全部 8 个探针子进程及 166 项相关回归通过，后者耗时 28.21 秒。Ruff 通过。原始测量/清单保持为历史证据；审查后的原生/源码哈希及结果单独保存在[提交审查](evidence/2026-10-23-native-owner-accounting-p0/submission-review.json)、[原生测试](evidence/2026-10-23-native-owner-accounting-p0/native-review-tests.json)、[审查构建](evidence/2026-10-23-native-owner-accounting-p0/review-build.json)及[审查测量](evidence/2026-10-23-native-owner-accounting-p0/review-measurements.json)。这些修复不构成合格性能或原生上界批准。P0 保持 NOT_QUALIFIED，P1 保持 NO_GO。
