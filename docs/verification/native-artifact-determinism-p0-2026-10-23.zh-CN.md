## NAD-V03. 实际分配与准入实验

六个隔离子进程分别为 R/I 执行 3 轮交替诊断。每个子进程从解包的实验 wheel 加载精确预期的原生二进制，未安装到服务。两类有效大行均通过完整校验，且等于独立参考结果；R/I 输出指纹一致。所有篡改行均被拒绝。物理校验返回后执行回收和保留状态观测。

| 夹具 | R 校验 CPU 中位数，秒 | I 校验 CPU 中位数，秒 | 观测器开销 | Rust 申请字节生命周期峰值 |
|---|---:|---:|---:|---:|
| 长 Decimal | 0.359375 | 0.359375 | 0.00% | 62108326 |
| 密集对象 | 1.593750 | 1.703125 | 6.86% | 139943398 |

这是诊断性校验 CPU 测量，不是混合负载验收或生产提速。峰值包含进程 Rust 生命周期历史，并非逐请求重置，也未覆盖全部原生内存。观测器跟踪分配/零初始化分配/reallocation/free，计入可能的新旧重叠，使用固定原子计数器，不调用回调或分配事件。核算丢失标志保持为零。释放后的聚合存活字节包含运行时/schema 保留状态，不能证明逐物理所有者的零债务。

单独申请 Python `8388608 B` 后 Rust 计数不变：前/中均为 `[44357288, 44357288, 351167, 0]`。这直接证明缺少 Python 覆盖。实际 SQLite 分配器插桩、底层堆开销/碎片、逐所有者归因、完整失败注入和跨域去重也未合格。不能根据 Rust 峰值降低既有推进预算。

SQL 仍申请 `197697036 B` / `145472808 B`，上限为 `67108864 B`。两类夹具均进行 1 次元数据查询、0 次 payload 查询，最终计费为 0 字节，报告 `availability_failed`。这是未变的保守准入，不是 OOM 结果或合法大行可用性通过。未降低任何内存分类或系数。

## NAD-V04. 验证与限制

专项测试通过 19 项；相关权威/证据/扫描/断连/排空/恢复回归通过 166 项，与专项选择不重叠。反例覆盖字节变化、重复/不安全成员、RECORD 哈希/大小/覆盖、错误源码身份、断链/重复/本地 SBOM 引用、路径搬移、依赖版本变化及失败前提报告。I 源码变异改变原生字节。此前的因子探针保留了缺失 epoch 和可复现链接器设置的对照。相应选择分别出现一个故意构造重复 ZIP 的警告和一个既有 FastAPI 依赖警告。

Ruff、双语稳定 ID/字面量和证据一致性检查通过。已安装运行时 SHA-256 仍为 `5ba0685a9153952ce1b5e1e8e5939685a675c0ca5786e720cfef255cb1b62a3e`。没有集成服务候选，因此不宣称浏览器/性能验收通过。既有 BIR08 的独立前后权威检查和激活重读、全部历史证据、观察者取消、物理排空、清理债务、时间边界及并发要求继续生效。

下一前提：补齐合格的 Python 和实际 SQLite 覆盖以及逐所有者/底层分配核对，再重跑有效行/密集错误/失败注入与清理实验，之后才允许调整准入。初步 Rust 观测器不得作为预算分配器部署。
