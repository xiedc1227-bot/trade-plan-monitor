## R14-P3. 已审阅计划与观察 oracle

原文计划逐字保留 `LITERAL` fixture：`003043.SZ`，仅当**已完成**5分钟K线收盘价在9.80–10.00元闭区间**且**该根成交量至少达到**前五根已完成**5分钟K线成交量算术平均值的1.5倍时提醒 BUY 100；10.80–11.00元闭区间从已登记持仓提醒 SELL 100；低于9.50元发纯风险提醒。这些是历史测试阈值，**不表示对应现价，也不是交易建议**。fixture 的 `humanTestSupplements` 明确补录 `TRADING_DAY=2026-09-14`、`CONTIGUOUS_TRADING_BARS`、每次激活只提醒一次及两项冲突选择；均不能归因于原文。若获批会话移至9月15或16日（包括14日休市的情形），只有在另行审阅对应日期人工补录后才能复用原文，不能暗改计划。任何依现价改阈值的演示计划须单独征求用户审阅和额度授权，不能证明原阈值通过。

在隔离应用中使用常规计划起草/复核/激活界面。保存或激活前，按独立原文值、子句偏移、缺失政策、模糊项和未支持项人工核对 Pro 的真实提取。模型输出即使语法有效也可能语义错误；须由人工 oracle 标记。确认原文处理、当前 `reviewId`、内容 hash、预期 revision 与计划版本。不能激活凭空补量、错改 ALL/ANY、人工补录未确认或复核过期的草稿。如需 SELL 条件，测试持仓仅能另行在隔离库登记；不读写真实持仓。

由于应用从空隔离数据库启动，验收脚本会在首次批准的 `003043.SZ` 激活后，**调用一次现有生产当日恢复服务**。审计明确标为 `TEST_TRIGGERED_PRODUCTION_RECOVERY`，最多占用已允许的三次 `rt_min_daily` 中的一次，不能称为自然启动恢复。须检查其写入的一分钟K线数量、错误和让位实时轮询状态，确认前五根条件有足够连续历史；否则 BUY 均量验证仍未完成。此后五分钟求值仍由正常生产调度器和真实供应商新鲜响应驱动。

对每次行情观察，仅保留脱敏审计及本地数据库证据：端点/尝试数、时间戳和行数、`SourceTimeLabel=END`、单位（价格元→分、成交量股、日量×100、成交额元、日额×1000）、日历、陈旧/空/缺口分类、六根K线沿袭、完整五分钟 cutoff 和结果 hash。未完成、陈旧、缺失、重复、未来或错误股票数据不得触发可执行提醒。对照 SQLite/API 验证浏览器提醒的 `planHash`、版本、当前 `reviewId`、激活 revision、cutoff、条件真值、动作/数量、`resultHash`、`eventId`、首次 IN_APP 投递、通道、浏览器可见与确认后库存不变。仅有 SQLite `DELIVERED` 行不等于用户可见收悉。

**自然触发规则：**若真实K线未自然满足 BUY、SELL 或风险条件，各缺席分支标 `NOT_OBSERVED`；不得向声称真实的会话注入合成K线、移动阈值或标 PASS。因此即使获取有效新鲜数据，实际交易时段链路也可能只是部分通过。真实供应商断线恢复与任意自然语言准确性，未实际观察前仍未验证。

## R14-P4. 执行与清理

从仓库根目录仅使用已安装环境；不安装依赖或编辑配置：

```powershell
.\.venv\Scripts\python.exe scripts\r14_bounded_acceptance.py
.\.venv\Scripts\python.exe -m pytest tests\unit\test_r14_bounded_acceptance.py -q
# 仅在明确批准后、合适时间窗口执行：
.\.venv\Scripts\python.exe scripts\r14_bounded_acceptance.py --execute --authorize R14_3_AI_30_MARKET_IN_APP_15MIN --run-id r14-20260914-a
```

execute 命令只创建 `data/r14-acceptance/<run-id>/monitor.sqlite3`、脱敏的 `audit.json`、SQLite 附属文件和本地 cursor key。`data/` 被 Git 忽略。浏览器页面 `http://127.0.0.1:18765`；业务 API/WebSocket 仅走此地址。应用 AI 客户端仅向 DeepSeek 发送获准的原文提示词；行情 SDK 向经过验证的 `api.quicksync.cn` TLS 身份发送获准操作/日期/股票请求及配置中的 token。凭证不进入 Git、命令参数、日志或 audit JSON。隔离 SQLite 可能包含原文及供应商行情行；仅留本地复核，对外只导出脱敏 hash/状态。若测试计划仍激活，退出前停止/停用；脚本在超时、额度拒绝或操作员停止时只停自身服务。保留脱敏审计和复核记录；仅在证据不再需要后删除经核实归属的测试文件。

本脚本不替用户自动作复核选择，也不强制造成提醒。一次批准只覆盖**一个** run ID/会话及这些固定输入。不由此自动批准重试、次日运行、认证更新、模型替换、外部通道、现价改造计划或额外额度。

## R14-P5. 真实执行后的判断

- 某个真实分支的 `PASS` 要求实际请求/响应记录、当前有效认证和开市日历、完整新鲜数据、正确服务端求值/沿袭，以及 event 匹配的本地浏览器实际收悉和 IN_APP 投递。真实 AI 案例另需人工比对独立 oracle 和当前复核。
- `PARTIAL` 记录实际有效子集；自然未触发动作、权限不足、模型无输出、认证过期或恢复未观察到时，按事实分别保留 `NOT_OBSERVED`／`NOT_RUN`／`FAILED`。
- `FAILED` 包括语义字段错误、未完成数据误提醒、过期复核激活、版本/event/cutoff/数量错误、额度控制失效、外发提醒或无证据却宣称 PASS。退出码0或 `NOT_RUN_MARKET_WINDOW` 永远不是 PASS。

本准备任务没有发出真实请求。待批准的是上述具体外发数据、可能费用/额度和唯一一次本地 IN_APP 会话。金额及输入 token 无硬上限的问题必须先由用户明确接受，或通过账户侧上限解决。
