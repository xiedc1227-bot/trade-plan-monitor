## CNA-V02. 实现与所有权

`fused_c_validator.py` 在同一次遍历中规范化子项并返回保守大小，消除了仅为求大小创建的容器浅副本及重复子项遍历。保留 model_dump/round_trip、Decimal 展开、时间和标量规则、旧生产者、全部域/公式/head/标量/字面量检查及完整历史遍历。候选使用私有命名空间，没有安装生产 monkeypatch。临时返回元组、SizedList 原生转换、排序向量及模型导出重叠仍存在。本实验未混入小行捷径、跨项合批和双消费。

| 分配阶段 | 所有者/释放条件 | 资格 |
|---|---|---|
| SQL 元数据/驱动/原始行 | 原扫描租约持有至 cursor 清理，包含前后代际 | 保留既有保守预留，未证明新的原生驱动边界 |
| 原生解析与模型/错误集合 | 当前证明持有至同步返回和异常释放 | 已识别二进制，解析临时区/错误/原生分配器边界未证明 |
| 模型导出/规范化容器 | 当前行证明；选中模型在排序后保留 | 融合规划消除求大小浅副本，仍核算容器/原生重叠 |
| C writer/UTF-8/比较 | 原遍历租约持有至块同步消费 | 逻辑目标不变，诊断倍数未获认证 |
| 选中结果及替换 | 物理证明/结果消费者持有至真实释放 | 聚合进程上限未验证；追踪排除预建参考输出 |
| 取消/清理 | 原所有者持有至物理排空；失败清理保留债务 | 保留既有策略及回归测试 |

安装身份：Python `3.14.7`、SQLite `3.50.4`、Pydantic `2.13.4`、pydantic-core `2.46.4`、SQLAlchemy `2.0.52`。证据记录原生二进制 SHA256。已安装解析器分发包包含 `0` 个 Rust 源文件；匹配源码/构建的分配资格仍缺失，与提案一致。二进制哈希不是分配器上界证明。不使用替代版本、猜测倍数或进程采样峰值认证原生安全。原生分配故障注入及绝对进程资格仍受阻，未宣称通过。

## CNA-V03. CPU 与内存对比

三轮交替测量使用不变的冻结输入，九次完整输出均一致。CPU 在首轮回归之后、内存探针之前顺序执行。这是诊断，不是固定验收；纯校验计时不包含 SQL 与权威检查。

| 版本 | 墙钟中位秒 | 线程 CPU 中位秒 |
|---|---:|---:|
| 原版 | 2.083152 | 2.046875 |
| 上轮 C256 | 2.445012 | 2.437500 |
| 融合候选 | 2.164538 | 2.156250 |

候选 CPU 比原版高 `5.34%`，比上轮 C256 低 `11.54%`。本次解决了实测规划瓶颈，但不能据此证明混合负载或真实页面收益，不使用跨会话绝对耗时比较。

| 形状/路径 | 原版追踪峰值 MiB | 上轮 C256 | 融合候选 |
|---|---:|---:|---:|
| 长 Decimal / 成功 | 149.16 | 23.88 | 23.88 |
| 密集对象 / 成功 | 196.84 | 137.50 | 136.85 |
| 长 Decimal / 非法 OHLC | 94.26 | 23.95 | 23.94 |
| 密集对象 / 非法 OHLC | 184.20 | 149.53 | 149.53 |

每格仅为一次完整校验追踪，排除预建原始输入/参考输出及未追踪原生分配。六次合法输出均与参考一致；非法输入的外层错误类型一致。候选异常保留 `480`、`40000` 条错误直至显式释放，证据记录释放后追踪存活字节。原版包装器的直接 cause 未暴露 error_count，因此记录 null 而非零。本次没有改善密集错误内存。这些观测不能认证 `768 MiB` 工作集或 `2560 MiB` 私有提交门槛。

## CNA-V04. 大行准入与延期工作

两类合法输入仍通过完整纯校验器。真实隔离 SQLite 预检分别要求 `197697036 B`、`145472808 B`，上限为 `67108864 B`。每个案例执行一次元数据查询、零次 payload 查询，返回 availability_failed，排空后计费为零。这是安全拒绝且可用性失败，不是成功的流式回退。

原生资格是减少预留的明确前置条件。因此证明/比较完整预算集成、加权大行调度、减少预留及子进程传输延期。本实验没有运行新的完整筹资 SQL 路径，也没有宣称解决其潜在嵌套获取死锁。既有 funded-cohort/扫描死锁测试仅提供回归证据。不能通过提高限额、缩小合法输入范围或重分类输入副本制造通过。
