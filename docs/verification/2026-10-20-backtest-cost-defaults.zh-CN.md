# 回测费用默认值验证，2026-10-20

## BCD-V01. 授权与范围

用户要求增加最低费用默认值，随后明确选择实际交易低费用假设、滑点为零，而非所有费用均为零。实现采用可修改的 PR-O08 预设：`commissionRate=0.0001`、`minimumCommissionFen=500`、`stampDutyRate=0.0005`、`transferFeeRate=0.00001`，分／BPS 滑点均为零。佣金是研究假设，不是统一最低报价。税费背景及来源记录在对应[操作说明](../operations/plan-reuse.zh-CN.md#pr-o08-可修改的低费用回测默认值)中。

生产改动仅限 `useBacktestRunForm.ts` 的 6 个初始化字符串及 `BacktestRunForm.vue` 的 1 句说明，原每股分滑点默认值已为零。不包含 API 结构、后端、执行／费用计算、舍入、计划关联、时序、数据库、历史读取或依赖改动。费用仍是 API 必填输入，仅在前端新草稿中预填。

## BCD-V02. 回归与复核证据

两个新增默认费用提交用例在实施前失败，实施后分别通过已有单计划审核及有序时间线入口，未手动填写费用即检查准确默认值及提交的整数分。第三个用例验证明确零值在切换计划后保留，清空佣金仍被拒绝。既有辅助调用保留明确填写的原费用及执行／结果预期。浏览器流程现先断言工作台、原文准备和四计划入口的初始默认值，再填写各自原费用。

临时将默认佣金从 `0.0001` 改为 `0` 时，两个新增默认值用例按预期失败；恢复原始源码字节后，29 项运行表单测试均通过。独立只读复核无阻断：草稿只初始化一次，无新增重填／监听覆盖用户输入，费用／滑点单位与原 API 一致。完整前端 78 个文件、1175 项测试通过，类型检查及生产构建也通过。

首轮完整浏览器测试 20 项通过，发现一个过时的键盘样例：原来依赖空费用触发错误，而新预填表单已合法。该用例现先断言佣金默认值，再明确清空佣金，保留原错误摘要焦点及可访问性检查，另外检查字段无效状态及未提交回测。修复后的用例已通过聚焦浏览器回归。未改变生产校验、审计排除项、超时、重试次数或布局门槛。

## BCD-V03. 保留边界

默认值仅适用于新建表单，不重新计价任何既有结果，不修改历史费用数据。明确修改（包括零值）保留原校验、捕获意图及同一请求重试行为。不按回测日期自动切换费率。测试使用隔离存储／服务商，不停止或重启运行中的监测服务。
