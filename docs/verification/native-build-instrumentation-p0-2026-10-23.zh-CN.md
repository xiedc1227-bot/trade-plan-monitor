## BIR-V02. 失败回收实验

新增 `failure_recovery_probe.py` 在自动 GC 开启的新子进程中运行。两个版本均通过相同调用方捕获交付新的异常。每个子进程执行三次完整失败校验，两边都计入最终物理回收。作用域候选将清理责任保留到该终点，绝不用于授权预算退款。原 `failure_boundary.latest` 保持不变。

每类夹具/版本进行三轮交替诊断，总线程 CPU 秒中位数如下：

| 夹具 | 每次失败全量回收 | 作用域加最终回收 | 差异 |
|---|---:|---:|---:|
| 长 Decimal | 0.937500 | 0.687500 | -26.67% |
| 密集错误 | 2.515625 | 2.375000 | -5.59% |

这些是三次调用合计，不是单请求延迟。工具链安装同时运行，因此不属于空闲机器或混合负载性能验收。早期仅捕获诊断单独保留，交付对比以本轮为准。[最终测量](evidence/2026-10-23-native-build-instrumentation-p0/equal-delivery.json)保留全部尝试、自动 GC 状态、输入摘要和源码身份。不声称获得新的原生内存上限。

循环反例证明仅作用域退出可能留下活对象。省略最终物理回收的测试变异被拒绝。因此本结果不授权删除既有校验器回收、提前释放清理债务或跳过错误/模型处理。仍需原生覆盖和完整失败路径所有权证明。

## BIR-V05. 构建资格

已实际安装 Windows Build Tools `17.14.42`、Rustup `1.29.1` / Rust `1.94.0` 及隔离 maturin `1.13.1`。MSVC 为 `19.44.35229.0`，SDK 为 `10.0.26100.0`。Rust 最初等待 winget 安装队列；取消尚未启动的请求后直接运行了同一份摘要已核验安装器。没有执行重启。[环境证据](evidence/2026-10-23-native-build-instrumentation-p0/provision.json)记录实际身份。这是新准备的目标，不是重现历史官方编译器。

原生构建脚本探针确认 `RUSTFLAGS=Err(NotPresent)` 和 `CARGO_ENCODED_RUSTFLAGS=Ok("-Copt-level=2")`。此前标志报告假设获得了实际构建观测，但仍不能确定历史 PGO 参数。

两个干净发布构建均完成，但 wheel 成员不相同。每个原生二进制为 `5805056 B`，恰有 `19` 字节不同，全部位于 COFF/debug 时间戳和 CodeView GUID。SBOM 差异包括时间、UUID 和源码目录引用，并引起 RECORD 改变。保留[完整构建日志](evidence/2026-10-23-native-build-instrumentation-p0/build.json)及[差异归因](evidence/2026-10-23-native-build-instrumentation-p0/reproducibility.json)。未剥离或忽略二进制/头/SBOM 字节来宣称通过。字节可复现失败。

因此 BIR-T02 仍未获资格，依赖它的 BIR-T03 原生拦截/失败注入**尚未实施或执行**。P0 尚未全部完成。这是 BIR08/BIR-S02 的依赖停止条件，不是成功的分配器实验。下一项必要构建工作是保持依赖来源证据的确定性链接/调试元数据和 SBOM 生成；之后重新执行干净构建，再进入钩子。作用域诊断和保守 SQL 回归可独立执行，已经完成。不启用降低预算的实现或 P1。

Windows 环境准备/构建结果另行记录安装器身份和实际工具版本。`native_build_probe.py` 验证冻结源码归档、隔离 Cargo 缓存和目标目录、关闭编译器包装/增量编译，先锁定获取依赖再离线发布构建，并比较两个干净目录的 wheel 成员摘要。失败如实记录，不据此断言原生资格。需在 x64 MSVC 开发环境使用隔离 maturin 和 Python 执行。

实测启动器因 Windows 将字典键转为大写而报告空编译环境字段；独立环境清单提供了实际版本。最终审查修复该报告、记录启动器身份，并让构建不同的 CLI 返回失败退出码。实测日志实质内容保留；这些报告修正没有声称重新编译原生代码。

本次实施不替换生产 wheel、不重启服务、不提交或推送。三领域拦截和缩减准入仍依赖获资格构建；仅构建或诊断通过不能启用 P1。
