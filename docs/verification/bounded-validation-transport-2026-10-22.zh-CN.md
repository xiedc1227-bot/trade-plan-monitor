# 有界校验传输 P0 验证报告

## BVT-V01. 结论与范围

P0 已完成，**P1 暂缓**。单调用者分块进程显著降低了受控混合负载的结果读取延迟，并符合建议的输入副本计费范围。但当前并发 SQL/比对缓冲还没有接入该全局租约：计入 7 个跟随者后，保守范围达到 99,784,903 字节（95.16 MiB），超过 67,108,864 字节（64 MiB）。生产集成需要先单独设计 SQL 批次分配前的字节准入。绝对生产进程内存额度也尚未确定，输入副本准入不是 RSS 限制。

全部工作隔离在 `scripts/experiments` 和新增测试/文档中。生产代码、权威/完整性逻辑、SQL 行为、运行服务、配置及历史数据均未改变。1024 个既有受版本管理的源码/测试/web/配置/README 文件指纹与基线一致。已有提案/证据保留，没有混入并行 AI 提取或日库存补丁。本轮未提交、未推送。

## BVT-V02. 已实现的实验

实验工作器采用私有 Windows-spawn 管道、版本/任务/代际/序号绑定、有界控制消息、显式标量标签和单个未消费分块。没有引入 pickle 输入、可执行异常载荷、ORM/会话/权威传输、完整子进程输入元组或已完成证明缓存。针对有序流只调用一次未改动的 `_latest_index_records`；`_market_index_from_row` 仍在排序前校验每条历史候选。最终条数/摘要验证只是额外传输检查，绝不替代 canonical 或领域检查。

线缆帧最大 1 MiB，原始块最大 2 MiB，解码源文本最大 1 MiB。传输前父进程为保守副本范围预留 16 MiB。实际冻结输入形成 110 块，而非提案探索性估算的 28 块：分组受解码文本和副本重叠限制，不能只看线缆长度。每次物理证明消费 2008 条候选，累计传输 28,923,969 字节输入并返回 110,797 字节输出。累计传输量不等于同时保留量。

准入计入父进程原始保留量及显式外部租约额度。不支持/超大输入或预算不足时，在提交前选择完整线程校验。提交后失败不能请求回退。既有物理所有者的寿命长于已脱离的观察者；输入/工作器租约保持到消费子进程结果和 `DRAINED`。工作器崩溃/协议失败会隔离代际并确认退出；清理失败保留预留量。没有修改生产超时、并发限制或存储屏障。

已安装 Python 3.14.7 的管道实现，在首次小量读取后、读取剩余载荷前检查超长消息。实际管道超长测试确认拒绝并完成发送方收尾。这只适用于所检查的运行时，不代表跨平台分配保证。计费公式刻意为重叠的输入/接收/编码/输出留额；Python 分配剖析为该夹具提供佐证，但不能证明所有可能的内核/运行时分配。

## BVT-V03. 固定性能对比

预定 300 次尝试全部完成：单独监控、单独结果及混合负载各有 10 组 A/A 和 20 组交替 ABBA/BAAB，即 20 次对照，加线程 40 次和进程 40 次观测。每次均成功，没有回退，完整输出哈希一致。每次监控均保留 2 次独立父进程权威调用并排空证明；单独结果尝试不读取监控权威。冷启动不计入暖态耗时，另行记录。

这些是在冻结只读数据库上使用合成的无所有者权威进行的完整读取，不是真实所有者/浏览器生产测量。单独结果的进程变体中子进程处于空闲状态。父子总 CPU 使用进程计数器测量，包含桥接/传输。没有为了通过门槛而替换样本。

| 中位数指标 | 线程 | 分块进程 | 变化 |
|---|---:|---:|---:|
| 单独监控完成 | 1.9218 s | 1.9848 s | +3.28% |
| 单独监控总 CPU | 1.9063 s | 1.9844 s | +4.10% |
| 单独结果完成 | 1.9565 s | 1.9475 s | -0.46% |
| 混合结果耗时 | 3.8590 s | 2.0064 s | -48.01% |
| 混合监控完成 | 2.2043 s | 2.3359 s | +5.97% |
| 混合整批完成 | 3.9554 s | 2.3361 s | -40.94% |
| 混合总 CPU | 3.9609 s | 4.0156 s | +1.38% |

延迟/CPU 可行性门槛通过。接近零的单独结果差异不作为固有提速结论。不能与不同主机负载下的早期实验直接比较，也不能描述成生产 p95 提升。本次未启用生产工作器或新浏览器路径，因此未执行有条件的 P1 真实所有者/浏览器验收。

## BVT-V04. 内存结果与阻塞门槛

| 保守输入计费 | 字节 | MiB |
|---|---:|---:|
| 早期整批进程输入副本 | 119,382,234 | 113.85 |
| 父进程原始证据 | 30,826,621 | 29.40 |
| 建议分块传输预留 | 16,777,216 | 16.00 |
| 单调用者：原始证据加预留 | 47,603,837 | 45.40 |
| 已观测最大 SQL 预取批次 | 7,454,438 | 7.11 |
| 单调用者加 7 个跟随批次范围 | 99,784,903 | 95.16 |
| 不变的总额限制 | 67,108,864 | 64.00 |

单调用者计划计费比此前整批计费约低 60.13%。这是保守准入数字，不是独立堆大小或 RSS。固定单调用者实验中，外部计费显式为零。并发探针检查现有 128 行设置下的真实 SQLAlchemy/DBAPI 预取缓冲，保守计入重复标量引用，再以算术方式评估同时存活的跟随者范围；没有宣称观测到 7 个峰值批次同时存在。适配器允许单调用者和单跟随者范围进入，拒绝 7 个跟随者范围。当前生产比对扫描在分配 SQL 批次前没有获取新的全局字节租约。即使隔离传输成功，这一缺失的可执行边界仍阻止 P1。

独立新进程测量为每变体 3 次，每 20 ms 成对采集父子数据。采样合计工作集最大值的中位数，线程为 283.27 MiB，进程变体为 506.63 MiB。采样合计私有提交量最大值的中位数分别为 999.20 MiB 和 1938.95 MiB。这里取的是同时刻采样之和的最大值，不是独立峰值相加；抽样可能错过更短的瞬时峰值。消除完整输入重复后，子解释器及导入栈仍有较高成本。私有提交量和驻留工作集是不同指标。

使用完整 always-on 输出集合的独立分配剖析重复 3 次证明。父进程 Python 峰值分配为 1,240,760 至 1,245,278 字节；子进程峰值为 2,147,310 至 2,153,063 字节。子任务返回后的当前追踪分配为 75,990 / 70,304 / 70,204 字节。每次证明的保留租约均归零。这些短程运行没有显示持续增长的 Python 输入集合，但不是长期无泄漏保证。既有父进程原始输入、解释器基线、原生分配及内核缓冲不包含在这些增量 Python 峰值中。剖析耗时不计入固定性能对比。

## BVT-V05. 正确性与失败证据

- 相关回归 150 项通过，仅有既存 Starlette 弃用警告；其中包含 33 项新增编码/传输用例及既有权威、历史完整性、时间边界、保留规则、断连和排空测试。补强固定预算断言后，16 项编码测试再次全部通过。
- 新增覆盖精确标量类型/JSON 字节、空/单条/重复证明、截断/尾随/非法标签帧、字节边界准入、不支持/大输入、旧的未选中 JSON/缺失载荷/head/canonical 篡改、最终条数/摘要错误、序号/代际错配、子进程崩溃/卡死、重复观察者取消、跟随者存活、存储暂停保留、实际管道超长接收、清理失败和提交后编码失败。
- 6 类进程内变异全部被检出：流完成、规范化相等、提前释放、固定预算、预算条件和独立权威 token。变异不修改仓库源码。
- 限定范围 Ruff 通过。冻结数据库哈希及所有受保护已跟踪文件指纹保持不变。实验子进程均已等待退出；没有重启服务，也没有清理历史数据。

保留并披露首次失败。首次编码测试产生过长的大值参数 ID 和初始化错误；改用有界 ID 及获准测试目录后解决。块中途证据拒绝最初使用了已消费分块序号，被误判为传输失败；修正错误序号契约，没有接受坏证据。首次冒烟因输出额度过小而完整回退线程，记录与固定比较分开保留。首次固定预算变异存活，是因为测试导入了被变更的阈值；现在显式断言预算不变，并另加移除预算条件的变异。

固定采样后，注入编码失败暴露了可能误判为提交前回退的问题。处理器现将其转换为物理传输失败，并排空/隔离子进程。精确重建测量时源码确认，工作器唯一改动是异常处理类型及导入，成功路径不变。最终故障回归和分配/内存运行使用修正后的工作器，两份源码指纹均保留。首次分配探针只返回 dashboard 指数：全部历史输入仍已验证，但输出集合不完整，不能直接用于本次比较。该记录单独保留，随后按完整 always-on 集合执行既定重复探针。两次分配运行均不作为延迟证据。

## BVT-V06. 复现与下一步

纳入版本管理范围的实验模块接收明确的冻结路径，绝不启动应用。固定对比接口见 `.venv/Scripts/python.exe -m scripts.experiments.bounded_benchmark --help`。提供 `--monitor`、`--results`、`--run` 和 `--output`，冻结结果数据库必须配有匹配的不可变输入所有权目录。`--memory` 选择独立内存运行，`--smoke` 不计入验收。独立探针接口见 `.venv/Scripts/python.exe -m scripts.experiments.bounded_allocation_probe --help` 和 `.venv/Scripts/python.exe -m scripts.experiments.bounded_concurrency_probe --help`。可移植证据包含所有固定样本、内存采样、分配观测、此前冒烟/探针结果、指纹及日志末尾，不包含数据库或私有证据载荷。

下一步设计必须在每个跟随请求 SQL 分配前预留字节，计入已变更/不匹配快照和仍在排空的证明，保持独立事务及精确比对。不得简单扩张额度、减少完整性检查、缓存权威或缩短排空。同时应基于新的工作集/私有提交量证据明确父子总内存绝对预算。只有这些门槛可以被强制执行后，才推进新的生产集成提案及固定真实所有者/浏览器验收。现有生产全量校验线程路径保持不变。
