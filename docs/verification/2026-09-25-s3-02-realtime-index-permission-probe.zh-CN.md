# S3-02 实时指数分钟权限复核：离线验证

## 范围

`rt_idx_min_daily` 拥有独立维护截止点和持久化 `INDEX_REALTIME_MINUTES` 权限预约。迁移后的旧 `index_minutes` 阻断起初同时拦截 `idx_mins` 和 `rt_idx_min_daily`；当日实时探针成功仅清除实时接口的 latch。探针要求经认证且就绪的 SSE 指数身份、当前已持久化的 SSE 开市日、最早于 `09:35:12` 完成的首根五分钟柱，并复用请求控制器的 300 秒预约、共享 429 冷却、1.25 秒物理调用节流和冻结的市场截止点窗口。它只发出一次只读 SDK 请求，不填充指数缓存，也不发布评估、提醒、发送或指数快照行。

## 响应证明

工作线程先在短日历锁内记录逻辑准入。供应商适配器在实际调用 SDK 接口前紧贴调用点冻结已完成柱的截止时刻，此前再次核验权限依据、epoch 和市场窗口。请求严格使用 `rt_idx_min_daily`、`freq="5MIN"` 与认证字段集。整批响应最多 49 行，必须恰有一个 `ts_code` 或 `code` 身份列、无重复必需列；可选 `freq` 只能为 `5MIN`；按已认证的 `START` 或 `END` 标签解释规范的当日源时间，不得有重复、未完成或未来柱；成交量和成交额有限且非负，OHLC 为有效正值。至少一行必须是真正已完成的五分钟柱。`END` 标签下的 `09:30` 开盘快照可以伴随真实柱，但不能单独证明权限。完整行情覆盖属于另行检查的业务就绪条件，不是接口可读证明的要求。任何坏行均使整批证明失败，并保留 latch 与预约。

## 日历版本与并发

受支持的运行期 SSE 日历写入路径是 `ProductionMonitorPipeline.refresh_references`，它通过 `_commit_trading_days` 拥有工作单元提交。每次 SSE 修正（包括同值重写）在尝试写入前通过短锁撤销旧 token 并提升 epoch。成功提交后安装新的内存日历与 token。事务失败则旧 token 保持撤销；下一次尝试须由 owner 线程重新读取 SQLite 才能启用新 token。SDK 工作线程只在短锁内检查冻结窗口、当前权限依据与 token，不读取 SQLite。修正在其门禁前发生时，不启动 SDK。若调用刚在修正前完成逻辑准入，其物理 SDK 调用可能在修正后才开始，但响应后 owner 会复核 epoch 与持久化 SSE 日历，因此不能清除 latch。锁不覆盖 SQLite 或 SDK 调用。

## 离线证据与边界

临时 SQLite 与假 SDK 覆盖旧迁移阻断继承、成功后作用域隔离、畸形和超限整批、缺失日历与首根柱延后、共享 429、物理节流、队列中的市场窗口否决、工作线程不读 SQLite、排队或在途时同值修正，以及事务失败后的重新启用。未请求真实 Tushare、迁移用户数据库、发布缓存或业务判断、发送通知、推送或部署。结果只证明受控的接口可读性，不断言供应商真实授权或指数行情已达到业务就绪。外部直接 Repository/SQL 日历写入不在此次单 owner 运行期提交保证之内。
