# S3-02 短时跨越市场分钟截止点：离线验证

## 范围

本有界子切片处理已安装运行循环中较早任务等待供应商工作时，跨过的单个仍可执行的 `REALTIME_MINUTE` 截止点。`MarketSessionScheduler.elapsed_market_deadlines` 从原市场游标枚举到观测时钟的原始市场截止点，不使用 `next_deadline` 只保留未来任务的过滤规则，也不包含维护截止点。较早任务返回后，若原始 `bar_end` 距今不超过 90 秒，`RuntimeLifecycleService.run` 可通过现有生产流水线执行恰好一个已到期分钟。原截止点身份与运行代次保持不变；激活、供应商、数据及提交门禁仍决定实际结果。

## 离线证据

真实的已安装 `runtime.run` 循环、临时 SQLite 库和假 SDK 执行 `10:04:12` 市场任务。已启动的 SDK 调用将注入时钟推进到 `10:05:13`，跨过原 `10:05:12` 截止点一秒。修改前，循环静默选择较晚的 `10:06:12` 截止点。测试先因未执行 `10:05:12` 而失败，修改后证明原截止点在同一运行代次下恰执行一次。假响应留下 `10:04` 分钟缺口；`10:05` 任务使持久化股票健康投影推进为 `GAPPED`，不生成判断或提醒。这是现有数据门禁的具体阻断结果，并非伪造判断。聚焦调度测试证明：当 `next_deadline` 只看见 `10:06:12` 时，到期查询仍返回 `10:05:12`。

另外两个离线用例在任务返回后，将注入时钟从 `10:04:12` 回退到 `10:04:11`，或推进到超过两天的回顾上限。它们最初因运行器退出、监督层报告 `RUNTIME_RUNNER_FAILED` 而失败。现在有界调度回顾抛出 `MarketDeadlineReviewError`；`runtime.run` 展示只读 `DEGRADED` 和 `MARKET_DEADLINE_REVIEW_UNAVAILABLE`，清除下一次轮询／重试时间，保留原游标，并等待显式停止。现有生命周期测试的调度器替身已实现到期回顾接口；在途工作期间收到停止请求后，不再启动新的回顾或工作。

## 待补边界

本子切片尚不分类多个已到期截止点、过期分钟、官方收盘尝试、返回时已越过截止点的睡眠，或正常的跨日恢复。上述两个时钟异常用例只保持可见的未处置状态，不恢复遗漏工作。须由 S3-04 的消费者和可见的未处置范围处理后，才能声称完整的跨线恢复。现有 `INDEX_RECOVERY` 游标行为及原多指数恢复／五分钟期限属于 S3-05。未新增待处理表、公开健康字段或端点；未调用真实 Tushare、迁移用户数据库、发送外部通知、推送或部署。
