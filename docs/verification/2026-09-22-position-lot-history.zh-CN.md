# 单批次历史验证 — 2026-09-22

> 英文为规范输入，本文件为中文副本。从 `84c8719` 继续。已验证单批次增量，不是重启验收。

## 范围与契约

只读单批次读取器在一个全新的应用 SQLite 读取快照内，关联严格版本化审计证据、消耗全部记录的唯一哈希链、原始当前行及准确的确定性持仓发布，返回不可变的已证明历史或类型化未知。它不证明完整持仓，不认证已接受日期，不调用评估器，也不授予回放/交付许可。不启用生产消费者、默认切换、真实行情或通知。

两项历史查询都使用行数上限和溢出哨兵，并在获取前限制文本/类型。默认历史预算 256，硬上限 1000，审计详情上限 16384 个 UTF-8 字节，事件载荷上限 4096。参数无效/会话非全新时抛错，已存证据无效保持未知，存储故障向上传播。不猜补来源日期，不按时间戳排序，也不把部分历史判为成功。

## 设计与独立审查

边界明确的实现使用 `gpt-6-astra` / `high`；独立设计及最终审查使用 `gpt-6-astra` / `xhigh`。这些设置不证明主任务的模型/强度。按用户此前选择继续跳过额外跨模型审查。

设计审查确认必须严格验证原始发布/当前行，并增加查询索引。仅靠既有事件/DTO 解码器可能将损坏输入规范化。时钟回拨、延迟登记、关闭/审计分别读取时钟均是既有合法行为，因此不按日期或时间排列链条。递增发布序号允许其他业务造成的全局间隙。与其他事件类型发生聚合 ID 冲突时，保守保持未知。

七天监控回放策略过滤客户端回放，并不删除发布。因此读取器不设时间截止，直接检查已存证据。实际缺失的发布不能由当前状态或审计单独替代。这仍是本地数据库信任边界内的一致性证明，不是针对能改写全部对应记录者的防篡改认证。

## 索引迁移与回退

源码迁移 `0020_lot_history_indexes` 增加审计 `(entity_type, entity_id)` 与监控 `(aggregate_id, sequence)` 两个非唯一索引，不修改历史记录或身份。降级仅移除这两个索引。每个索引都会增加存储及写入维护成本；预期收益是按目标索引查找而不扫描无关历史，并非声称达到某个生产延迟目标。验证只迁移隔离的临时数据库。部署仍须另行备份、安排迁移窗口并获批准；SQLite 创建索引并非无锁在线操作。

最终审查发现一项需要处理的 P1 事务归属缺陷：新 Session 若绑定到另一事务的 Connection，可能把尚未提交的买入返回为已证明证据。直接连接绑定、模型路由绑定及表路由绑定均已复现；新增 3 项回归用例在修复前全部失败。契约现明确要求由同一个引擎绑定、按应用要求配置的 SQLite 快照完成证明，拒绝时不得触碰调用方事务。这与 SQLAlchemy 文档说明的[加入外部事务](https://docs.sqlalchemy.org/en/20/orm/session_transaction.html#joining-a-session-into-an-external-transaction-such-as-for-test-suites)能力及其[绑定解析规则](https://docs.sqlalchemy.org/en/20/orm/session_api.html#sqlalchemy.orm.Session.get_bind)一致。首轮较大范围回归因该修复中断，不计为已完成验证。

修复要求 Session 绑定到 SQLite Engine，并在任何 SQL 之前验证全部四张证明表的模型绑定和表子句绑定均为该同一引擎。3 项连接回归及新增的跨数据库路由回归现已通过；拒绝操作保留调用方尚未提交的事务及其后续回滚行为。第二轮审查未发现遗留可操作问题，并独立复跑 108 项用例通过，耗时 11.87 秒。最终功能回归包含全部 112 项新增测试，未发现新增失败。更大范围的未完成工作及 4 项基线失败仍阻止完整验收，失败不予豁免。
