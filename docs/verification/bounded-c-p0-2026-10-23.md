## BEP-V02. Implementation and ownership

The private normalizer retains model_dump/round_trip, exact scalar policy, Decimal expansion and timestamps, accumulating size information once in local container attributes. Decimal ASCII bounds avoid generic escape inflation. There is no whole-tree size map per hash. Small subtrees use the public C-backed JSON encoder. Large containers emit individually bounded items; cross-item batch fusion and the dual hash/literal sink are deferred. Public canonical APIs remain unchanged.

The adapter evaluates the prior complete experimental validator in a private namespace; ContextVar selects a request-local producer. It does not monkeypatch production or another thread. Original domain, model, scalar, head, full-history and literal/EOF checks remain. All normalized state is local to one proof.

An encoder lease spans the entire generator traversal, including previous/current output overlap and synchronous consumption. Logical targets are 64 KiB/256 KiB; the diagnostic reservation is `12 * target + 4096`. The multiplier is deliberately NOT a certified native allocation bound. Consumers must not retain an unbounded sequence of yielded chunks. Cancellation unwinds the generator; a violated logical bound fences storage and retains debt. Review corrected per-call leasing to traversal leasing; earlier measurements remain separately recorded.

| Phase | Ownership and unresolved bound |
|---|---|
| SQL/raw | Existing global metadata/raw/work leases retained; no reservation lowered |
| Parse | Immutable bytes remain owned through synchronous return; native scratch not certified |
| Model/normalization | Full models and descriptor containers counted in process analysis; raw/conversion input categories not moved |
| C encoder | Preallocated traversal lease, logical chunk sizes checked; native writer growth still unproven |
| Selected outputs | Retained through ranking; excluded prebuilt expected output explicitly identified in measurements |
| Failure/drain | Existing owner/cleanup fences preserved; encoder bound violation retains debt |

C256 CPU remains 22.73% above original, exceeding the 10% ceiling. Improved relative to iterative encoding is insufficient for acceptance. Descriptor construction, container accounting and per-item encoding remain candidates for attribution; no precise CPU split is claimed without profiling.

Single traced full-validator comparisons: the 16472833-byte long-Decimal fixture falls from 149.16 MiB to 23.88 MiB; the 12120814-byte dense fixture falls from 196.84 MiB to 137.50 MiB. All 4 outputs equal the original. Raw inputs and expected results are prebuilt/excluded; untracked native allocations and absolute process peaks are not bounded by these figures. These are not repeated performance medians.

Parser/error-lifetime probes repeat 6 cases across 480 bars with 8500 decimal digits and 40000 bars with 1 digit. Both valid fixtures pass the original full validator. Invalid OHLC produces 480/40000 errors, explicitly retained then released. Dense error storage reaches approximately 149.53 MiB; traced live memory returns near baseline after release. This exposes failure-path storage, not a production leak. The exact values and reproducible probe source are in evidence.

## BEP-V04. Legal large-row admission

Actual isolated SQLite transactions execute metadata preflight for both fixtures. Required work remains 197697036 bytes for long Decimals and 145472808 bytes for dense objects, exceeding 67108864 bytes. Both fail before any payload query, with 0 leaked bytes after drain. Pure-validator success does not make this successful SQL availability.

No new reduced-workspace admission is enabled: neither native parser/driver nor writer bounds were proved, and descriptors/error models remain substantial. Input stays 64 MiB, process ceilings 768 MiB/2560 MiB. Single-trace measurements cannot justify a smaller reservation. Independent comparison/proof workspace separation, weighted large-row sharing and process restoration remain conditional work, not silently completed features. Thus this P0 produces a failed feasibility result, not an available production optimization.
