# 单次监控校验实施报告

日期：2026-10-21。基线：`ba4156e`。[英文主文档](single-monitor-verification-2026-10-21.md)。[规格](../specifications/backtesting/SPEC-single-monitor-verification.zh-CN.md)、[任务](../specifications/backtesting/TASKS-single-monitor-verification.zh-CN.md)、[便携观察](evidence/2026-10-21-single-monitor-verification/measurements.json)。P0 已实施并验证；具体 P1 实验暂缓。

## SMV-V01. 真实 503 与恢复

实施前，正确 version-2 dashboard 和 health 请求返回 503。在重启前观察原进程：读取准入未永久关闭，但有 1 个存储暂停；受管读取、活动校验及保留输入均为 0。真实所有者为 STOPPING/STALLED。心跳失败为 `runtime liveness changed`：期望版本 28033，持久化版本 28034。随后真实 WAL 检查点返回 `(1, -1, -1)`，清理失败，按规则保留暂停。这是所有者失效/清理失败后的拒绝，不是成功的快速读取，也不代表历史数据被删除。

保留异常能确认版本冲突和检查点 busy，但无法识别当时的竞争写入者/检查点所有者。当前检查未发现该进程有借出的 session 或打开的事务。不能推断先前冲突由谁引起，也不能手动解除保护。通过 Python 3.14 [官方诊断接口](https://docs.python.org/3.14/library/sys.html#sys.remote_exec) 只提取限定的类别、栈位置与计数，不记录凭据、证据正文或 SQL 参数。

确认 `READ_READY`、`physicallyDrained=true` 与空 `authorizedJobIds` 后，请求服务正常关闭。原有清理重试完成，包括数据库关闭；然后才用不变配置启动单个标准模块入口。不修改权威规则。新增回归用例复现旧心跳写入者与真实 SQLite reader 阻止检查点完成：清理失败时断言 503/暂停，释放隔离阻塞后验证正常重试清理与 STOPPED health。该夹具证明失败边界，不证明历史阻塞者身份。

规范化修改前，3 次真实所有者 dashboard 成功读取为 3.7509 / 3.7064 / 3.7028 秒，RUNNING/STANDBY，0 个活动 symbol。真实浏览器 list → result → provenance → summary，以及 2 个 result tab 加 health/heartbeat 均成功，业务写入 0、页面错误 0。以这些成功读取建立真实基线，不把先前 503 当作性能数据。

## SMV-V02. P0 边界与等价性

`canonical.py` 使用统一私有校验核心，返回仅当前行存活的规范化基本类型树。原公开完整性函数仍返回 `None`；仓储通过新增 verified-JSON 辅助函数编码已校验树，用于字面相等检查。原公开哈希辅助函数接口不变。保留类型化 JSON 解析/模型校验器、精确 snapshot/bar/tuple 边界、bar 排序、request 排序、带域隔离的哈希、formula/fact-formula 校验、全部行元数据/provider/schema 绑定、head identity 与排序。不保留规范化历史。

仍检查每个历史候选。全部 2,008 个冻结行与原 decoder 相同；18 项差分篡改均以相同方式拒绝。冻结负载含 72,280 个 bar、27,588,993 JSON 字节，没有活动 plans/requests/facts。另有测试覆盖 4 个 request/4 个 fact、合法 requests/facts 重排、类型边界、规范化固定预期及接近 16 MiB 的 payload。大载荷夹具使用重复 bar 验证表示大小，不作为有效市场历史的证明。

读取服务、完整独立权威比较、观察时间、plan/inventory/risk/calendar/proof 检查、activation 重读、2 次尝试预算、socket 行为和共享协调器均不变。保留原有 8-read/1-validator/1-queued/64-MiB/128-row/15-second 上限。不引入完成证明缓存，不改变金融逻辑/API/schema/retention/worker/timeout。

## SMV-V03. 计时与 P1 决策

使用同一冻结只读数据库、显式 BEGIN 事务、有界连接池、合成的所有者缺席权威与固定时钟，隔离历史校验成本，不作为真实所有者验收。每个调用者执行 2 次独立权威检查；完整 dashboard/result 均相同。常规计时排除剖析插桩。保留每轮以及两种实验范围。

最终代码，10 轮独立单次读取交替测试：wall 中位数 **3.6401 → 2.2290 秒**，CPU **3.6016 → 2.1797 秒**（改善 38.8% / 39.5%）。该独立单次读取范围通过 wall/CPU 改善 >=30% 且 <=2.5 秒门槛。最终代码还通过 2/8 monitor 加 result 及错开到达的完整输出/排空复测。

先前 10 轮矩阵交错执行单次与混合负载：

| 负载 | wall 中位数，优化前 → P0，秒 | CPU 中位数，优化前 → P0，秒 |
|---|---:|---:|
| 单次 monitor | 4.6741 → 2.6352 | 4.6094 → 2.6094 |
| 2 monitor + result | 7.3657 → 5.6266 | 7.5156 → 5.7891 |
| 8 monitor + result | 8.8330 → 6.5476 | 11.5547 → 8.9531 |
| 2 monitor + result，错开 0.75 秒 | 7.5063 → 5.5269 | 7.6484 → 5.7188 |

所有混合负载中位数均改善，通过退化 <=10% 门槛。交错矩阵中的单次中位数**未达到 2.5 秒**；保留此局限，不只选择有利轮次。这些测量不构成持续 2.5 秒服务承诺或 p95。最终独立测试在提取统一私有核心后进行，使只需完整性校验的调用者不再额外编码完整 JSON；两种范围及原始观察均保留。

独立 P0 worker 剖析中，`canonical_value` 递归调用从 3,701,644 降为 1,236,442，`canonical_decimal` 从 1,328,368 降为 447,344。解析仍检查全部 2,008 个候选。插桩时间仅用于定位，不能当作延迟结果。

本轮不接入 P1。进程内实验将精确 Decimal-tuple 表示复用限制在单次物理校验的 64 项 / 128 KiB 内，完成即释放。10 轮 P0/实验交替单次测试，wall 中位数反而 **2.4693 → 3.2627 秒**，CPU **2.4375 → 3.2266 秒**。一次校验的 447,344 次调用只有 635 次命中（约 0.14%）；构造键与未命中的成本超过规范化节省。该结果否定这一变体，不否定所有未来表示策略。实验缓存不进入生产代码。

## SMV-V04. 内存

每种实现分别用 3 个新进程测量进程峰值工作集及提交内存；另用新进程测量 Python 临时分配。跟踪峰值为 42,891,879 → 42,890,153 字节。进程峰值工作集中位数为 284,057,600 → 283,934,720 字节，峰值提交内存为 1,036,046,336 → 1,035,931,648 字节。未发现接近 10% 的退化。带分配跟踪的计时不进入性能表。原始输入峰值仍为 30,826,621 字节；排空后保留字节与受管工作归 0。区分总量/临时内存与协调器原始输入计数。此内存结果适用于冻结负载；接近上限夹具另行检查字节/完整性行为。
