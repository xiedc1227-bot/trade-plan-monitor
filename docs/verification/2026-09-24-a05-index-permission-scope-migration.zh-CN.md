# A05 指数权限域迁移（离线）

## 范围

`0023_index_permission_scopes` 是从 `0022_runtime_liveness` 开始的增量数据迁移，不改变检查点表结构。迁移把持久化的 `index_minutes` 权限预约拆为 `idx_mins` 和 `rt_idx_min_daily` 两个独立预约。旧键和混合键集合仅在升级时被接受。运行期仓库读写只接受新的规范域，上限为 75 行，并读取第 76 行识别超限。

现有指数适配器和离线实时认证探测现在向请求控制器传递与实际接口对应的操作。本次映射调整没有新增权限复核探针。现有 work-key 字符串及其 SHA-256 存储身份保持不变。

## 已验证行为

- 完整的旧 74 行集合变为规范的 75 行集合。两种有效混合集合，即旧键加一个新域的 75 行及旧键加两个新域的 76 行，也都变为 75 行。三种集合各自多一行时均被拒绝。已有接口重试时间与旧键重试时间取较晚值。
- 其他权限行、共享冷却、退避键、重试时间字符串、失败次数、原因码和提供方身份均逐字节保持不变。第二个提供方的无效记录会阻止所有提供方的改写。未知域、损坏的原因码或时间戳及过多退避记录都会安全失败，且不改数据或推进 Alembic 版本。重复升级具有幂等性。
- 迁移后的旧阻断即使重试时间已过，仍保持 `BLOCKED_PERMISSION`。指数适配器的两个普通入口都在 SDK 调用前停止。新控制器绑定已恢复仓库后，旧哈希 work-key 仍保留其 `TRANSIENT` 退避期限。绑定前控制器不允许物理请求。仅解除实时分钟权限时，历史分钟权限仍受阻，而新的实时分钟键可独立准入。运行期读取或写入旧域都会安全失败；新检查点不会写入旧键。
- 当任一新域存在时，降级到 `0022_runtime_liveness` 会被拒绝，数据和版本均保持不变。

迁移聚焦文件通过 **14 个测试**。相邻的存储、请求控制、指数适配器、探测、迁移和仓库检查通过 **269 个测试**。已安装生产认证、A06 指数、语义门禁和实时流水线检查通过 **79 个测试**，另有一条既有的 Starlette/httpx 弃用警告。Ruff 检查通过。这些是有界的离线迁移与准入结果，并非完整 A05 验收。冷启动正向权限探针、前端健康扩展、进程中断覆盖和 work-key 稳定性改动属于独立后续工作。未使用真实提供方、外部通知、用户数据库迁移、部署或推送。
