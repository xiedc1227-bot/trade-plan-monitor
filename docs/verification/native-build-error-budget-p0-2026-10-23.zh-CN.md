PATH 无法解析 `rustc`、`cargo` 或 `cl`；常见用户 Rust 编译器和 Visual Studio Installer 发现路径也不存在。这限制本机重建可行性，但不能证明所有位置都没有编译器。没有安装工具链或依赖。可复现插桩构建需要准备并锁定工具，且使用独立资格二进制；本阶段没有完成该构建。

## NBB-V03. 失败生命周期实现

`failure_boundary.py` 不变地调用已有融合完整校验器。离开异常处理器后，将已知精确投影失败转换为冻结的布尔描述，不在其中存储原异常。底层迭代器清理先完成。未知失败与子类继续传播。仅失败时同步回收循环模型校验异常图，再抛出新的本地异常。不取消 worker、不改变权威检查、不归还租约，也不修改存储清理。

这是隔离实验。显式回收作用于整个进程，可能暂停无关工作，未获生产准入，也不能声称没有成本。新抛出的异常仍可能包含调用者/输入栈帧；描述有界不等于调用者拥有的原始数据全部消失。后续集成必须为这些对象保留所有权直到实际排空，并在归还预算前核算失败回收。本实验没有解决错误构造峰值。

## NBB-V04. 测量对比

三轮交替冻结纯校验器 CPU 测量，完整输出相等。计时不含 SQL 与权威检查。基准数据集与两份合成数据库的前后 SHA256 一致。[测量证据](evidence/2026-10-23-native-build-error-budget-p0/measurements.json)保留各轮结果和代码指纹。

| 路径 | 耗时中位数，秒 | 线程 CPU 中位数，秒 |
|---|---:|---:|
| 原路径 | 2.086379 | 2.078125 |
| 本次修改前融合路径 | 2.215568 | 2.203125 |
| 失败边界 | 2.224581 | 2.171875 |

本次诊断中，候选 CPU 高于原路径 `4.51%`，低于融合路径 `1.42%`。这些小差异不是固定性能门槛通过，也不能认定提速成立。

| 形状/路径 | 融合 live/peak MiB | 边界 live/peak MiB |
|---|---:|---:|
| 长 Decimal / 成功 | 7.537 / 23.881 | 7.531 / 23.874 |
| 密集 / 成功 | 73.402 / 136.859 | 73.402 / 136.859 |
| 长 Decimal / 非法 | 23.947 / 23.947 | 0.020 / 23.947 |
| 密集 / 非法 | 149.531 / 149.531 | 0.025 / 149.531 |

每格一次跟踪，不含预建原始输入和期望输出。原生分配未被完整跟踪。非法长 Decimal 线程 CPU 从 `0.203125 s` 增至 `0.296875 s`；密集非法 CPU 从 `1.828125 s` 增至 `2.218750 s`。候选包含回收成本，而基线保留错误图直到 live 测量之后才释放。释放边界不同，展示的是提前物理清理的代价，不是同生命周期吞吐。诊断会话末段附近派发了补充测试；内存阶段耗时不是验收证据。不声称混合负载改善。

## NBB-V05. 实际合法大行准入

两种合法夹具均通过完整纯校验器且输出相等。在隔离 SQLite 中，不变扫描器对长 Decimal 仍请求 `197697036 B`，密集对象请求 `145472808 B`，限制为 `67108864 B`。各执行一次元数据查询、零次载荷查询，结束时计费字节为零。这是安全拒绝与可用性失败，不是可工作的大行回退。

[方案算术](../specifications/backtesting/PROPOSAL-native-build-error-budget.zh-CN.md)依然成立：仅扣解码文本预留，长 Decimal 完整推进预算仍超限。原生/代数所有权尚未获资格，实施更小的预算包会违反门槛。明确延期新的缩减预算 SQL 集成及其并发实验。既有带预算 cohort/死锁测试仅作回归，不证明新的大行路径有效。
