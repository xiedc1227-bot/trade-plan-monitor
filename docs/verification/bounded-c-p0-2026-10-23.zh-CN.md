## BEP-V02. 实现与所有权

私有规范化器保留 model_dump/round_trip、精确标量策略、Decimal 展开及时间戳，在局部容器属性一次累计大小。Decimal ASCII 边界避免通用转义放大，不为每个哈希重建完整树大小映射。小子树调用公共 C JSON 编码器，大容器逐项输出有界内容；跨项批次合并及哈希与字面值双路输出暂缓。公共规范化 API 不变。

适配器在私有命名空间执行上一轮完整实验校验器，通过 ContextVar 选择请求局部生产者，不修改生产或其他线程。原域哈希、模型、标量、头记录、全部历史和字面值及 EOF 检查均保留，规范化状态仅属于一次证明。

编码租约覆盖完整生成器遍历，包含前后输出重叠及同步消费。逻辑目标为 64 KiB/256 KiB，诊断预留为 `12 * target + 4096`。该倍数明确不是已认证的原生分配边界。消费者不得无限保留输出块。取消会展开生成器，逻辑边界失效则围栏存储并保留债务。审查中已把逐次调用租约修正为整段遍历租约，早期测量另行保留。

| 阶段 | 所有权及未证明边界 |
|---|---|
| SQL/raw | 保留现有全局元数据、原始及工作租约，不降低预留 |
| Parse | 不可变字节持有到同步调用返回，原生临时空间未认证 |
| Model/normalization | 完整模型及描述符容器纳入进程分析，不转移原始或转换输入类别 |
| C encoder | 分配前取得遍历租约，检查逻辑块大小，原生 writer 扩容仍未证明 |
| Selected outputs | 排名期间持续保留，测量明确排除预构建期望输出 |
| Failure/drain | 保留原 owner 及清理围栏，编码边界失效保留债务 |

## BEP-V03. 优化前后结果

以下最终计时在测试后串行执行：3 轮交替、2008 历史行、5 个指数，全部 12 次完整输出比较一致。这是纯校验器诊断，不含 SQL、权威或生产集成。此前一次运行与回归执行重叠，其 CPU 数字排除于结论，并保存在证据中。

| 变体 | 墙钟中位数，秒 | 线程 CPU 中位数，秒 |
|---|---:|---:|
| original | 2.4156 | 2.406250 |
| iterative | 5.1593 | 5.156250 |
| c64 | 3.2551 | 3.250000 |
| c256 | 2.9442 | 2.953125 |

C256 CPU 仍比原版高 22.73%，超过 10% 上限。相对迭代编码改善不足以通过验收。描述符构造、容器记账及逐项编码仍需细分归因；没有剖析数据，不声称精确 CPU 占比。

单次跟踪完整校验对照：16472833 字节长 Decimal 样本从 149.16 MiB 降到 23.88 MiB；12120814 字节密集样本从 196.84 MiB 降到 137.50 MiB。全部 4 个输出与原版一致。原始输入和期望结果预构建并排除，未跟踪原生分配和绝对进程峰值不受这些数字约束。这些不是重复性能中位数。

解析与错误生命周期探针重跑 6 种情况，覆盖 480 条行情及 8500 位小数、40000 条行情及 1 位小数。两个合法样本均通过原完整校验器。非法 OHLC 产生 480/40000 个错误，显式保留后释放。密集错误存储约达 149.53 MiB，释放后跟踪存活内存回到基线附近。这揭示失败路径存储，不是生产泄漏。精确数字及可复现探针源码保存在证据中。

## BEP-V04. 合法大行准入

在真实的隔离 SQLite 事务中执行两个样本的元数据预检。长 Decimal 工作区仍需 197697036 字节，密集对象需 145472808 字节，均超过 67108864 字节。两者都在任何 payload 查询之前失败，排空后泄漏为 0 字节。纯校验器成功不等于 SQL 可用性成功。

未启用降低工作区的新准入：原生解析器、驱动及 writer 边界尚未证明，描述符和错误模型仍占较多内存。输入仍为 64 MiB，进程上限仍为 768 MiB/2560 MiB，单次跟踪不能支撑缩小预留。独立比较与证明工作区区分、按字节加权大行共享及进程恢复仍是有条件的后续工作，不声称已经完成。因此，本轮 P0 得出未通过的可行性结果，不是已可用的生产优化。
