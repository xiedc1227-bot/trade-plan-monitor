# A04 已安装运行时重试时间线（离线）

## 范围与方法

这项有界检查安装生产组合，使用临时 SQLite 数据库、已认证的离线股票档案、一个激活的 Schema v1 计划和假 SDK。假 `trade_cal` 请求对同一 SSE 日期范围前四次抛出 `requests.ConnectionError`，第五次返回有效数据。生产请求控制器、恢复仓库、生命周期、调度器和读取服务保持实际安装。测试仅控制 SDK 边界与生命周期重试等待。

测试以同一时间线驱动业务 `Clock`、请求控制的 `monotonic` 与 `pace_sleep`，以及调度器的 `sleep_until`。重试闸门记录计算得到的等待时长和物理调用次数。测试在闸门关闭时检查没有新增物理请求，然后释放闸门并恰好推进该等待时长。心跳、物理工作线程超时和停止排空均未加速。

## 观察结果

- 四次生命周期重试等待分别满足 30、60、120、300 秒下限。每次到期时间均不早于生命周期 `retry_at`、控制器同一键的退避时间及任何控制器冷却时间。
- 前五次物理 `trade_cal` 调用使用相同的 SSE 范围；第六次是随后发出的 SZSE 交易日历请求。所拥有的重试闸门释放前没有物理请求。
- `DEGRADED` 期间组合仍可进行本地读取。恢复为 `RUNNING` 时，生命周期对象、请求控制器、运行代次和存活所有权修订号保持不变；崩溃监督器重启次数为零。
- 调度器而非直接 `run_deadline` 调用处理了 2026-09-08 的 10:09:12 和 10:10:12。激活计划按五分钟目标评估，因此 10:09 轮询没有产生评估或告警。10:10 轮询以激活计划哈希和激活修订号 1 提交一条目标为 `2026-09-08T10:10:00+08:00` 的 `INTRADAY` 结果。没有持久化告警。

新增测试及相邻的生命周期、组合与认证检查通过：**118 passed，另有一条既有的 Starlette/httpx 弃用警告**。这仅是指定交易日历瞬态故障序列的离线 A04 恢复证据，并非完整 A04 或发布验收。未使用真实 Tushare 请求、外部通知、用户数据库迁移、部署或推送。
