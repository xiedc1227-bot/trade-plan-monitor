# 设计提案：共用板块指数数据，使用方式由交易计划决定

> 状态：**已批准——已授权实施**
> 批准日期：`2026-09-02`。同日后续请求已授权配对模块规格、代码/API/Schema/文档修改和离线验证。提交、推送、安装依赖、部署和真实供应商网络调用仍未授权。

## 目标

在监控和回测中加入板块指数数据，同时明确责任边界：

- 工具选择股票的参考板块指数，获取并校验数据，计算可重复使用的数值事实，并把同一指数数据提供给所有引用该指数的计划。
- 工具不生成一个统一的市场判断，也不在计划之外悄悄阻止、允许或改变交易。
- 每份交易计划自行决定是否使用指数数据、检查哪些条件、条件放在哪里，以及条件结果如何参与计划判断。

用户在 Web 页面中不用阅读日志，也必须能回答以下问题：

1. 这只股票绑定了哪个板块指数，具体是哪条映射规则选出的？
2. 在判断截止时间，当时可以使用哪些指数数据和通用指标事实？
3. 这份计划写了哪些指数条件，每个条件的结果是什么？
4. 指数数据缺失是否影响了这份计划，还是指数只用于查看？
5. 监控和回测是否使用相同的数据、公式、截止时间和计划条件？

## 已确定的设计方向

### C1——工具负责数据，不负责交易规则

工具可以提供指数身份、K 线、最新完整数值、数据健康状态、均线、涨跌幅、时间和哈希。这些都是数据事实。工具不能把它们转换成一个统一的大盘结论，再自动控制所有股票。

### C2——计划负责使用方式

在现有规则树允许的范围内，计划可以把指数条件放在 `entry`、`reduction`、`risk` 或 `blockers` 中。计划也可以完全不包含指数条件。条件所在位置以及外层 `ALL`/`ANY` 结构共同决定它的作用。

### C3——数据共用，条件结果属于具体计划

映射到同一指数、并在同一截止时间判断的股票，共用同一份不可变数据快照。两份计划的条件或阈值不同，可以根据同一快照得出不同结果。条件证据和最终判断不能共用。

### C4——板块映射自动完成

工具根据已经校验的股票代码选择参考指数。第一阶段不允许用户或 AI 任意选择其他板块基准。

### C5——监控和回测都展示数据

监控和回测都显示参考指数及其数据。计划条件结果必须与共用指数数据分开显示，让用户能够区分“当时的市场数据是什么”和“这份计划如何判断”。

## 已批准的假设

- **A1：** 第一阶段只包含板块指数。行业分类来源和映射规则还没有批准，因此行业指数属于后续独立能力。
- **A2：** 创业板和科创板是两个不同板块，分别使用不同的参考指数。
- **A3：** 继续支持现有 `.BJ` 股票，因此北交所股票使用北证50。
- **A4：** 工具可以计算 SMA、区间涨跌幅等确定、可复用的事实。只有计划条件引用这些事实后，它们才会影响交易。
- **A5：** 指数条件可以出现在任意受支持的规则树中。条件所在的树决定用途，不能只根据条件类型决定用途。
- **A6：** 现有 Schema v1 计划保持不变。只有 Schema v2 才能保存指数绑定和指数条件。
- **A7：** 盘中判断证据只使用经过确认的完整5分钟周期。未完成分钟或即时价格只能展示，不能满足条件。
- **A8：** 监控和回测使用相同的映射、已校验 K 线、公式、条件计算器、截止规则和证据格式。

用户已于 `2026-09-02` 批准全部八项假设。以后如有重大变化，必须重新进行设计评审；如果变化会修改已接受架构，还必须新增替代 ADR。

## 固定板块与指数映射

映射版本：`board-index-map-v1`。

| 股票分类 | 明确的股票规则 | 参考指数 | 内部指数代码 |
|---|---|---|---|
| 上证主板 | `.SH`，但不包含以 `688` 或 `689` 开头的代码 | 上证指数 | `000001.SH` |
| 深证主板 | `.SZ`，但不包含以 `300` 或 `301` 开头的代码 | 深证成指 | `399001.SZ` |
| 创业板 | `.SZ`，并且代码以 `300` 或 `301` 开头 | 创业板指 | `399006.SZ` |
| 科创板 | `.SH`，并且代码以 `688` 或 `689` 开头 | 科创50 | `000688.SH` |
| 北交所 | `.BJ` | 北证50 | `899050.BJ` |

规则：

- 分类只使用已经校验的股票代码，不能使用公司名称、AI 输出、指数成分股身份或远程分类结果。
- 指数是板块参考，股票不需要是该指数的成分股。
- 无法分类的代码必须校验失败，工具不能猜测其他指数。
- `mappingVersion` 和最终 `indexCode` 是不可变计划内容，并参与计划哈希。
- 修改映射必须建立新映射版本和新计划版本。

## 工具提供的数据契约

### 共用原始事实

对于每个需要的参考指数和判断截止时间，工具提供一份不可变快照，包含：

- 指数代码、显示名称和板块身份；
- 截止时间之前最新一个经过确认的完整5分钟开高低收；
- 计划最长回看周期需要的正式日线开高低收；
- 昨收，以及只有在供应商字段含义经过确认后才提供的成交量或成交额；
- 完整周期截止时间、数据源观察时间、正式/临时来源标记和供应商修订号；
- 数据健康状态，以及明确的缺失、过期、重复、缺口、身份错误或未来数据错误；
- 映射版本、内容修订号和快照哈希。

指数点位和比例在 Python、JSON、TypeScript 之间传递时都使用规范十进制字符串。二进制浮点数不能作为权威证据。

### 通用派生事实

工具可以计算带版本、结果确定、可供多份计划共用的事实：

- 指定允许周期的简单移动平均线；
- 该移动平均线在指定回看距离内的变化；
- 指定窗口的涨跌幅；
- 当前值与一个有名称的历史值之间的比较数据。

每个事实记录公式 id、参数、输入截止时间、结果、单位、来源 K 线哈希和健康状态。这些内容仍然只是数值事实，不包含统一的市场标签，也不包含自动判断影响。

## 已批准的计划条件方向

第一版可以在现有计划允许清单中增加以下已批准条件叶子。准确的请求和存储结构仍由模块规格定义：

| 条件类型 | 准确判断方式 |
|---|---|
| `INDEX_CLOSE_GTE_MA` | 完整指数收盘点位大于或等于指定 SMA |
| `INDEX_CLOSE_LTE_MA` | 完整指数收盘点位小于或等于指定 SMA |
| `INDEX_MA_NON_DECREASING` | 当前指定 SMA 大于或等于回看位置的 SMA |
| `INDEX_MA_NON_INCREASING` | 当前指定 SMA 小于或等于回看位置的 SMA |
| `INDEX_RETURN_GTE` | 指数在指定窗口内的涨跌幅大于或等于阈值 |
| `INDEX_RETURN_LTE` | 指数在指定窗口内的涨跌幅小于或等于阈值 |

允许的参数：

- `index_role`：第一阶段固定为 `BOARD_REFERENCE`；
- `period`：SMA 周期，范围是2至250个正式开市日；
- `lookback`：比较距离，范围是1至60个正式开市日；
- `window`：`FIVE_MINUTE_BUCKETS` 或 `OFFICIAL_OPEN_DAYS`；
- `window_size`：1至250；
- `threshold_ratio`：规范十进制比例，包含边界，范围是 `-1` 至 `10`。

继续使用现有规则树限制：最大嵌套深度4，最多50个条件叶子。每个叶子返回现有结果 `SATISFIED`、`UNSATISFIED` 或 `MISSING_INPUT`。

系统不存在共用的市场条件结果。例如，一份计划可以要求指数收盘不低于 SMA20，另一份计划只要求5日涨跌幅不低于 `-0.03`。两者读取同一快照，但可以得到不同结果。

## 已批准的计划结构方向

Schema v2 将增加一段只读并自动确定的参考市场绑定。准确的序列化方式仍由模块规格定义：

```yaml
schema_version: 2
reference_market:
  selection: AUTO_BOARD
  mapping_version: board-index-map-v1
  index_code: 000688.SH
```

指数条件与其他允许的计划条件使用相同结构。示例：

```yaml
entry:
  conditions:
    operator: ALL
    items:
      - type: NON_DECREASING_CLOSE
        lookback: 3
      - type: INDEX_CLOSE_GTE_MA
        index_role: BOARD_REFERENCE
        period: 20
      - type: INDEX_MA_NON_DECREASING
        index_role: BOARD_REFERENCE
        period: 20
        lookback: 5
```

另一份计划可以把指数条件放在 `reduction`、`risk` 或 `blockers` 中，也可以完全不使用指数条件。

规则：

- 草稿服务根据股票代码和已批准映射生成 `index_code`。
- 第一阶段不允许用户或 AI 提供其他基准代码。
- AI 提取可以提取原计划中明确写出的指数规则，但不能编造条件、阈值、代码或公式。
- 导入和激活时重新计算绑定，发现不一致就拒绝。
- 绑定和所有条件都参与规范 JSON 和不可变计划哈希。

## 判断执行

对每个判断目标执行：

```text
共用指数快照 + 这份计划的条件树
    -> 只计算这份计划使用的指数条件叶子
        -> 使用现有 ALL/ANY 规则与股票条件叶子组合
            -> 使用现有规则优先级
                -> 保存权威判断证据
```

条件位置决定行为。放在 `entry` 下的指数叶子可以影响买入分支；同样的叶子放在 `risk` 下可以影响风险分支。计算器不能在计划树之外额外附加隐藏规则。

每条指数条件证据包含：

- 准确的计划路径和条件类型；
- 指数代码、映射版本和快照哈希；
- 判断截止时间和数据截止时间；
- 公式 id 和参数；
- 实际值、比较值、周期/窗口和单位；
- `SATISFIED`、`UNSATISFIED` 或 `MISSING_INPUT`；
- 不可用时明确的缺失输入代码。

## 实时运行流程

```text
活动计划
    -> 计算不同的参考指数代码（最多5个）
        -> 每个截止时间只获取并校验一次各指数
            -> 每个指数发布一份不可变的共用数据快照
                -> 每份计划只计算自己的指数条件叶子
                    -> 保存计划专属证据和最终判断
                        -> 分开显示共用数据与计划结果
```

具体结果：

- 同一截止时间的5只创业板股票使用一份已经校验的 `399006.SZ` 数据快照。
- 没有指数条件的计划不会因为指数数据不可用而被阻止或改变；页面仍然可以把指数作为信息展示。
- 需要指数数据的计划只在受影响的条件路径上得到 `MISSING_INPUT`。
- 一个指数返回错误时只影响对应板块，其他指数快照继续正常运行。
- 任何使用方都不能修改共用快照，也不能把某份计划的结果写回共用快照。

## 数据供应能力前置检查

当前仓库已经证明股票分钟和股票日线适配器可用，但还没有证明已配置的供应商账户可以提供所需指数数据。批准实施前，必须在获得授权后执行一次只读检查，确认：

- 指数日线和盘中 K 线的准确接口；
- 五个批准代码都受支持；
- 指数身份、时间、开高低收、昨收以及成交量/成交额字段；
- 历史范围和可以支持的最长预热周期；
- 更新延迟、请求限额、账户权限和响应大小上限；
- 实时与历史接口的点位和时间字段含义一致。

检查报告和日志绝对不能复制 token。如果无法获得经过确认的指数5分钟数据，必须返回设计评审。实施时不能悄悄改用股票接口、未完成报价、根据成分股合成的指数或只使用日线的替代方案。

## 数据与持久化设计

使用指数专属类型，不能放宽股票类型：

- `MarketIndexCode`：只允许 `board-index-map-v1` 批准的代码。
- `MarketIndexBar`：在准确截止时间已经校验的指数开高低收和来源信息。
- `MarketIndexHealth`：`LIVE`、`STALE`、`GAPPED` 或 `BLOCKED`，并带有准确问题代码。
- `MarketIndexIndicatorFact`：公式 id、参数、十进制结果、单位、截止时间和来源哈希。
- `MarketIndexSnapshot`：身份、原始事实、请求的通用事实、健康状态、修订号和内容哈希。
- `IndexConditionEvidence`：计划路径、输入身份、事实、比较内容、结果和缺失输入。

实时存储可以让多只股票共用快照。每条持久化判断仍然要保存足够的不可变身份，证明具体使用了哪份快照和公式。回测数据集哈希覆盖所有可能影响该次回测的指数 K 线和事实定义。

### 指数历史

- `GET /api/v1/market-indexes/{indexCode}/bars`
- 必填查询参数：`interval`、`startAt`、`endAt` 和 `limit`
- 更多数据使用带签名的游标分页
- 每页最多2,000个已经校验的点，并限制一次查询的日期范围
- 未知、未批准或身份不匹配的代码使用现有安全错误结构

### 回测投影

- `BacktestRunView.referenceMarket` 保存绑定、覆盖情况、数据集哈希和本次回测使用的条件路径。
- `BacktestAuthoritativeDecisionView.referenceMarket` 保存快照身份和完整的路径级证据。
- `GET /api/v1/backtest-runs/{runId}/market-index-series` 最多返回512个日线展示点，以及各条件结果数量。准确5分钟证据继续放在分页判断明细中。
- 正式导出包含绑定、指数数据哈希、公式哈希、条件路径和结果数量。

### 失效通知

在 WebSocket 事件联合类型中增加 `market.index.updated`：

```json
{
  "entityId": "000688.SH",
  "revision": 42,
  "status": "LIVE"
}
```

事件只通知浏览器重新读取权威数据。浏览器不能根据事件创建快照或计算条件。

## 监控页面设计

### 监控总览

在连接和数据年龄状态下方增加“参考板块指数”区域。对于活动监控股票使用的每个指数，显示：

- 显示名称、代码、最新完整数值、当日涨跌、截止时间和健康状态；
- 已请求的通用事实，例如 SMA20，但不提供自动解释；
- 当前映射到该指数的监控股票数量。

股票列表增加“参考指数”和“计划指数条件”两列。第二列显示该股票活动计划的已满足数量/总数和缺失数量，不能显示一个统一板块结论。

### 股票详情

显示两个分开的区域：

1. **参考指数数据：** 板块映射、指数身份、原始值、通用事实、截止时间、健康状态和独立指数图。
2. **计划指数条件：** 每个已使用叶子的准确计划路径、条件类型、参数、输入事实、结果和缺失原因。

股票图和指数图必须分开，因为单位和刻度不同。

### 加载与故障状态

- 刷新时可以继续显示缓存快照，但必须显示原始截止时间和当前健康状态。
- 指数发生故障时必须继续显示，不能从指数区域消失。
- 一个板块指数故障不能替换或隐藏其他健康指数。
- 没有指数条件的计划显示“计划未使用”，条件进度为零；指数故障不改变该股票判断。
- 颜色必须配合文字和图标。仍需支持键盘访问、表格标题、实时提示以及320/768/1024/1440像素布局。

## 回测页面设计

### 新建回测与数据检查

选择计划和股票后，显示自动确定的指数、映射版本和所有指数条件路径。只有计划确实使用指数条件时，才要求指数历史和预热数据。所需预热长度根据该计划最长的周期、回看距离和窗口计算，不能使用一个全局固定值。

### 已完成回测摘要

显示：

- 参考指数绑定和指数数据集哈希；
- 每个条件的路径、类型、参数和公式 id；
- 每个条件满足、不满足和缺失的次数；
- 每个条件参与适用规则分支的次数。

不能编造一个整次回测统一的市场分类。

### 参考指数页签

提供独立的指数/指标图、数据健康时间线，以及每个计划条件的每日结果数量。选择日期后打开准确判断和产生这些数量的5分钟证据。

### 判断明细与导出

每条判断显示准确条件路径、截止时间、输入事实、比较内容、结果以及快照/公式哈希。正式导出包含相同内容，使用户不连接实时服务也可以审计结果。

## Vue 组件图

使用 Vue 3 Composition API 和 `<script setup lang="ts">`。路由页面只组合职责单一的组件，不能装入完整功能。

| 组件/组合函数 | 单一职责 |
|---|---|
| `MarketIndexDataStrip.vue` | 显示有界共用指数事实和健康状态 |
| `IndexConditionProgress.vue` | 显示计划专属的已满足/总数/缺失数量 |
| `ReferenceMarketPanel.vue` | 显示一只股票的映射和共用数据身份 |
| `MarketIndexChart.vue` | 显示已经校验的指数序列，不计算计划条件 |
| `BacktestIndexConditionSummary.vue` | 显示各路径的回测结果数量 |
| `BacktestMarketIndexPanel.vue` | 组合回测图、健康状态和日期导航 |
| `useMarketIndexSeries.ts` | 管理有界请求、取消、加载和安全错误 |

只读数据通过属性向下传递，用户导航或筛选通过事件向上传递。组件不能推导映射、计算条件、改变规则优先级或渲染不可信 HTML。

## 回测确定性与偏差控制

- 股票判断只能使用截止时间不晚于该判断目标的指数数据。
- 禁止使用未来正式收盘、未完成周期和未来成分股信息。
- 页面显示范围之前的预热 K 线仍然参与数据集身份。
- 监控和回放调用相同的纯事实计算器和条件计算器。
- 任意相关指数 K 线、映射、公式、条件或截止时间改变时，回测身份和报告哈希必须改变。
- 股票数据相同但相关指数数据不同，不能复用已经完成的结果。
- 板块分类来自股票代码，不依赖今天的指数成分股，可以避免成分股存活偏差。

## 故障与安全规则

- 供应商响应属于不可信输入，必须在适配器边界校验。
- 股票/指数身份混用、重复数据、非规范十进制、错误截止时间、未来数据或公式不匹配必须失败关闭。
- 指数数据缺失只让需要它的计划路径产生 `MISSING_INPUT`。
- 没有指数条件的计划继续保持原有行为。
- 一个指数故障不能停止其他板块。
- Web 页面不能把较早的条件结果与更新后或缺失的数据一起使用。
- 日志、错误、接口和导出不能暴露供应商 token 或不必要的原始响应。

## 迁移方案

1. 现有 Schema v1 计划和历史结果保持不变，`referenceMarket` 为 `null`。
2. 新草稿可以转换成带自动绑定的 Schema v2。
3. 只有来源计划明确写出指数条件，或者用户明确审核后，才能加入指数条件。
4. 用户审核后激活新的不可变版本。
5. 历史结果不能使用后来的指数数据或结论重新改写。

任何运行配置变化都不能悄悄给已经计算哈希的活动计划增加指数条件。

## 验证方案

### 单元测试

- 每种允许的股票代码形式只能映射到一个板块指数，非法组合必须失败。
- 每个条件严格实现文档中的等号边界和参数范围。
- 输入缺失、过期、有缺口、来自未来或身份不匹配时返回 `MISSING_INPUT`。
- 两份计划可以根据同一快照产生不同条件结果。
- 没有指数条件的计划保持原有判断行为。

### 集成测试

- 10只股票共用一个指数时，每个截止时间只请求供应商一次。
- 不同板块的故障和健康状态相互隔离。
- 输入相同时，监控和回测生成字节稳定的事实和条件证据。
- 修改一个相关数据点或公式后，数据集哈希和报告哈希改变。
- 只有计划使用指数条件时，指数覆盖不足才阻止回测。
- 获得授权的能力检查确认供应商字段和覆盖可用，并且不暴露 token。

### 前端测试

- 共用数据与计划专属条件结果在页面上明显分开。
- 总览、详情和回测页面都不显示统一市场分类。
- 没有指数条件的计划显示“计划未使用”，并且不受指数故障影响。
- 回测摘要、图表、明细和导出的指数身份与条件路径一致。
- 覆盖加载、缓存、过期、缺失、空数据、窄屏、键盘和读屏状态。
- `vue-tsc`、单元测试、生产构建、Playwright 和 axe-core 全部通过，并且没有严重或致命的无障碍问题。

### 验收标准

- 同一板块股票在每个截止时间共用完全相同的指数数据快照。
- 指数数据对交易产生的每个影响，都能追溯到该计划中一条明确的条件路径。
- 删除一份计划的全部指数条件后，指数不再影响该计划判断。
- 对相同输入，监控和回测显示相同的指数身份、数值、截止时间、公式和证据。
- 浏览器只显示后端生成的事实和结果，不计算交易规则。

## 边界

- **始终执行：** 映射和公式带版本；保留准确截止时间；显示健康状态和时间；对影响判断的输入计算哈希；共用数据保持不可变。
- **先确认：** 能力图、Schema v2、条件清单及范围、新接口字段/端点、报告变化和供应商能力。
- **禁止：** 隐藏的大盘限制；AI 任意选择基准；未完成或未来 K 线；把股票 K 线当作指数 K 线；浏览器计算条件；悄悄改变活动计划。

## 第一阶段不包含

- 行业指数分类和行业轮动规则。
- 用户任意选择参考指数。
- 市场宽度、涨跌家数、估值、新闻、资金流或 AI 市场评分。
- 整个账户的行业仓位限制。
- 券商委托或自动交易。
- 根据多个指数生成综合评分。

该设计保留明确的指数角色边界，以后加入经过批准的行业指数能力时，不需要改变板块指数身份。

1. **D1——位置：** 六种指数条件可以出现在所有受支持的规则树中（`entry`、`reduction`、`risk` 和 `blockers`）。
2. **D2——允许清单：** 本提案中的六种条件类型和参数范围已批准，可用于编写模块规格。
3. **D3——迁移：** 指数绑定和条件通过明确的 Schema v2 迁移实现，不能悄悄修改 Schema v1 计划。
4. **D4——北交所：** `.BJ` 股票使用北证50 `899050.BJ`。
5. **D5——范围：** 第一阶段包含板块指数数据，行业指数继续作为单独评审的能力。
