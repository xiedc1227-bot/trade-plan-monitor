# 规格：source-condition-coverage

状态：已批准实施 — 2026-10-27。属于 [plan-monitor-assurance](SPEC-plan-monitor-assurance.zh-CN.md)；批准、实施及外部操作遵循 PMA-D01–D06。[英文规范版](SPEC-source-condition-coverage.md)。

## SCC-S01 — 保证与范围

在受支持语法及已登记审核范围内，未证明已落实的强制或疑似前向交易义务，不能仅因标为背景而通过当前审核／启用／操作资格。未识别语义继续阻断。这是保守契约，不证明任意自然语言语义，也不取消最终人工审核。

新当前防护须同时覆盖已知 `semantic_context` 捷径及 `can_be_context` 的“未命中关键词”回退。仅删一条捷径、加长关键词黑名单或让另一个AI赞同均不充分。既有历史验证仍按旧规则可复现；新防护是独立、版本化的当前评估。

## SCC-S02 — 原文盘点、原子义务与关系

从完整保留的原文开始，而不是规范化候选或供应商选中的 POLICY 条款。保留既有规范条款标识、准确 Unicode 码点跨度与摘录。AI 的处理类别、语义角色、理由及路径都是不可信提议。服务端正向注册规则可证明完整跨度是元数据、真实历史／账户备注或已有登记非技术排除；未出现交易关键词不能算正向证明。未知文字为 `UNRESOLVED`，包括间接／无关键词前提。

为原子要求及其关系生成 `source-obligation-v1`。至少拥有 `obligationId`、`clauseId`、准确 `start/end`、摘录、作用范围（计划／规则／BUY／SELL／风险／提醒）、类型、极性、比较符／值／单位、周期／offset、有效期／窗口、数量／容量／权限及适用关系／组引用。保留条件前后件、ALL/ANY、否定、例外和独立信号含义。不能通过只绑定一个叶子、却引用整个长句来解除多项义务。跨条款或512码点分块不能静默切断关系，无法准确重建时阻断。

沿用准确数值类型及登记条件语义，不新增执行器或任意表达式执行。“价格条件且换手条件”须覆盖两项及AND，两项叶子被放到ANY下也不合格。“无普通规则”是可核对的缺省／权限声明，不是编造BUY的理由；标题提到交易计划也不产生交易义务。

规范归属为有限、版本化的服务端识别器／语法，以及关系／等价、正向背景注册表，T01冻结、T02–T05实施。必须独立于AI选择的义务表核对整份来源。未消费或语义不确定的余段一律UNRESOLVED，即使识别器产生零原子也一样；“没识别出来”不能等于“没有要求”。注册表须明确受支持语法、正反例及有界工作量。

## SCC-S03 — 处理状态与解除规则

| 状态 | 含义 | 是否允许覆盖完成 |
| --- | --- | --- |
| `MAPPED` | 受支持原文义务及全部相关关系准确对应候选图 | 是 |
| `MAPPED_WITH_REGISTERED_SUPPLEMENT` | 已有允许的准确补充／改定完成绑定，明确显示为人工调整 | 可用于审核，自动忠实提取指标另计 |
| `CONTEXT_VERIFIED` | 完整准确跨度通过窄范围正向非政策处理 | 是，但不计作被监控的交易条件 |
| `SCOPE_EXCLUDED` | 准确既有登记排除及所有技术余段均已处理 | 仅限该已批准排除，明确在监控范围之外 |
| `UNRESOLVED` | 语义、作用范围、原子划分或必要参数未获证明 | 否 |
| `UNSUPPORTED` | 强制内容没有登记执行能力或允许的处理方式 | 否 |
| `CONFLICT` | 原文、关系、候选或补充与声明要求矛盾 | 否 |

通用 `IGNORE`、“已确认”、`COMMENTARY`、`ACCOUNT`、`HISTORICAL` 或自由理由均不能解除义务。混合句按准确跨度切分：有效账户／历史部分不能豁免前向余段。保留已有生成阶段基本面排除，不把它们变为新增运行门槛，也不扩大到任意技术条件排除。

用户可以修复有来源的受支持规则，通过已有登记补充流程填参数，使用已有明确授权改定（包括当前受限的期限改定），或保存澄清后的原文新版本。每次变化使相关覆盖／审核绑定失效。补充须保留准确内容／路径／值／作用范围来源，不能仅靠理由取消不支持的条件。人工变化须明确显示，不能算原文自动提取准确率；强制条件仍不支持时，受影响的新授权继续阻断。

## SCC-S04 — 规范化与语义比较

新供应商提取必须记录来源规范化前候选、规范化后候选、规范化版本及明确变更轨迹。缺原始前像不能计作已验收的原始自动提取。人工／历史草稿声明其来源或前像缺失，不虚构供应商记录；可重新取得当前原文到候选证明，但不能补称过去自动忠实提取。义务判断始终对照原文，并比较规范化前后；原文／Markdown 变换须保留回到原始码点的映射。

尤其不能通过 `evaluation_only` 清空普通规则、恢复／默认字段、移除可选内容或范围排除来抹掉原文义务。安全的登记元数据／默认规范化可以保留并审计。无法解释或不支持的删除生成 `SOURCE_NORMALIZATION_LOSS`。纯提醒原文仍为纯提醒；不能把整份来源改标为仅观察，借此移除前向交易条件。

比较须独立检出：义务缺失、未落实并列前提、AND/OR替换、否定／例外变化、`>`与`>=`、分／元及百分比／比例、日线／分钟／offset、有效日／交易窗口、数量／上限、权限／机会标识、A/B执行与背景边界。等价须由明确版本化等价规则证明，不使用模型置信度或文字相似度。未知等价阻断；产品默认值仍限于已有有限注册值。

A/B分区标签不能豁免整段。B若引入意图约束工具执行的新前向技术前提，既不能补齐缺失的可执行A，也不能忽略后让A通过；须报来源／分区CONFLICT，要求澄清并写入新A版本。真实账户／历史解释、已覆盖内容的解释性重复及登记基本面排除，继续保留原不可执行范围。新增把强制条件从A移到B的变异，删掉或未经许可导入B均不能通过。

## SCC-S05 — 版本化证明与历史兼容

`source-coverage-v1` 确定性哈希覆盖完整有序义务／关系／处理／问题、原文哈希、当前候选／内容哈希、映射／审核证据哈希、规范化轨迹及注册／规则版本。沿用既有原文／内容规范哈希函数。原文义务标识绑定来源／版本／跨度／语义，报价、预算账、请求次数或评估时间均不能产生新交易机会。原文／候选／映射／规范化／注册变化使覆盖及其人工绑定失效。

明确、由服务端赋时的 `source-coverage-review-v1` 回执，将覆盖证据绑定准确既有审核标识、预期版本及人工确认。服务端在权威边界重新派生；客户端 `covered=true`、伪造问题列表或背景标签不是证据。只读计算不产生回执；保存可持久化不完整DRAFT，但不授予权限。确认／启用及后续相关操作除既有门槛外，还要求当前完整已绑定覆盖，仅保留SCC-S06已经授权的历史技术风险连续性窄例外；该例外不创造新普通／例外授权，也不能把未知义务静默当仅BUY。

不能全局收紧历史 `build_daily_review` 后，将新问题与旧 `required_issues_json` 比较，否则可能使旧记录不可读。可信历史验证分派与当前资格分开。保留旧payload字节、映射、问题列表、审核哈希／回执及已完成模拟。客户端版本选择、倒填时间或缺新元数据都不能制造legacy身份。T01在存储修改前冻结可信服务端／存储切换规则，T07在临时升级前数据库验证。

采用增量、独立版本化保证附属表及不可变回执／历史；T01选择下一个可用迁移版本，不修改0027。缺新已审核证明的旧记录显示 `LEGACY_UNASSESSED/NEEDS_REVIEW`，不是损坏，也不是当前PASS。升级不匹配而缺附属存储时，明确 `UPGRADE_REQUIRED/UNKNOWN`。只有要求实施后才开发迁移，实际用户迁移仍单独授权。

## SCC-S06 — 当前授权与风险优先

提取、保存、重读、原文确认、启用及当前计划复用共享同一当前评估。普通模拟及例外决定／消耗在既有权威写入防护内重验准确原文／内容／覆盖／审核／启用绑定；同命令同内容重放原回执，证明／版本变化冲突，供应商I/O在事务外。当前可操作通知在发送时重验适用覆盖。

保守判定义务范围。原文能证明仅适用BUY的前提不能变为SELL门槛。全局缺失约束阻断新计划授权及受影响普通操作；UNKNOWN范围在得到证明前阻断全部新交易授权，不得静默假定仅BUY。按既有已审核分支与授权保留独立技术风险连续性；BUY覆盖／成本缺失本身不得否决该风险SELL或压制明确标注的只读风险提醒。影响风险分支本身的不确定性仍须显示，不能创造清仓授权。重评原文不改冻结数量、不重开窗口、不重置已消耗信号、不批准例外。

对历史活动版本，分别显示历史完整性及当前覆盖。新普通操作／批准不能走legacy零问题捷径。既有只读观察与独立已授权技术风险行为保留原门槛及明确legacy／覆盖状态，不能包装为完整通过新保证的监控。保存不完整替换稿不启用它，也不静默替换活动版本。

## SCC-S07 — 问题、界面与有界 API

建议问题详情：`SOURCE_CONDITION_OMITTED`、`SOURCE_RELATION_MISMATCH`、`SOURCE_CONTEXT_UNVERIFIED`、`SOURCE_NORMALIZATION_LOSS`、`SOURCE_COVERAGE_UNSUPPORTED`、`SOURCE_COVERAGE_REQUIRED`、`SOURCE_COVERAGE_STALE`、`SOURCE_COVERAGE_LIMIT_EXCEEDED`。公开错误code保持不变，这些是结构化原因。跨度有效的语义遗漏返回可检查阻断问题，保留原文／候选／映射；结构／哈希／跨度篡改沿用输出无效／准入处理。传输 `SUCCEEDED` 而覆盖阻断时，明确显示提取完成、但不可审核／启用。

覆盖视图显示原文跨度→原子要求／关系→准确规则／路径或明确阻断／处理，并区分AI提议与服务端处理、规范化变化、来源值与人工改定值、实际监控范围。初始为未决，不预选遗漏豁免。上下文／原文／版本变化丢弃迟到响应；加载、错误、缓存不显示当前完整覆盖。

保留原文／输入／树／字节边界：DailyMapping条款<=512、绑定／补充<=2000，条款摘录<=512码点。建议总义务最多4096、每规范条款最多64；任一超限明确阻断，保留原文，不截断义务。先对完整证明计算哈希，再分页。只读覆盖GET默认 `limit=50`、最多100、单页1MiB，游标绑定原文／候选／映射／规则版本。摘录仍<=512，完整含义通过跨度／关系表示，否则明确未决。界面每次轮询不进行无界全历史扫描。大小／语义超限是准入失败，不是删原文许可。既有32KiB冻结结果项及无关预算不变。

## SCC-S08 — 验收与实施归属

验收对应 PMA-A01–A06、A11、A12。新增聚焦测试应覆盖两种原始语言、三种背景角色、无关键词前提、同句遗漏、有完整绑定但语义错误、跨句关系、规范化丢失、真实背景、允许的排除／补充、边界、篡改及当前／历史分离。HTTP／存储／运行测试须证明确认／启用／普通操作被阻断、草稿可检查、不能降级legacy、重试／竞争正确且保留风险优先。保留准确旧黄金／历史读取，不能重新生成历史期望来迎合新规则。

建议接缝：`ai/source_obligations.py`、`ai/source_coverage.py`、`ai/source_coverage_models.py`及聚焦规范化适配，`state/source_coverage_store.py`和增量迁移，既有审核／计划／运行／通知边界，`web/source_coverage_schemas.py`与原计划工作台。建议文件名属于任务，不表示已实现；本规格不新增生产或测试代码。

## SCC-S09 — PBS来源绑定澄清与接替意图

已批准的[PBS规格](SPEC-plan-buy-suspension.zh-CN.md)增加有界Schema10当前原文处理。完整持续禁买义务包含触发、持久后果、全部计划BUY范围及审核接替恢复。瞬时条件、SELL规则、通用人工事实或客户端背景标签均不能消除该义务。有限识别规则只沿既有分句边界合并完整指令（最多64段／512码点）；独立风险线／低吸区限制及所有未知尾部继续未决。其他表述继续阻断，不猜测含义。

保护缺失或不匹配产生 `SOURCE_BUY_SUSPENSION_REQUIRED`；明确周期／起点或必要人工解释缺失产生 `SOURCE_BUY_SUSPENSION_CLARIFICATION_REQUIRED`。Schema10结构默认值不能提供来源授权。保护补充增加成对的 `source_hash`／`obligation_id`，固定范围／恢复解释需要批准时还须包含 `buy_suspension_clarification="ALL_PLAN_BUY_REVIEWED_REPLACEMENT_ONLY"`；同时继续绑定确切候选内容、路径、值及补充身份。不能覆盖已知原文值。未使用时，这些可选字段不进入历史序列化值。

`POST /api/v1/plan-review-supplements`接受可选 `sourceText`（最多150000码点），来源绑定PBS证据必须提供。服务端从该原文派生实际义务，核验哈希、身份和值后，才写入既有明确人工操作注册记录。补充最多2000项、摘录最多512码点的原有限制不变。客户端／AI映射声明不能创造注册证据：预览只恢复已注册补充，保存及当前读取重新核验对应关系。错误原文／义务／内容／值和陈旧预期修订均拒绝。原始提取证据继续保留在 `CoverageInputs.initial_coverage`；澄清后评估使用 `MAPPED_WITH_REGISTERED_SUPPLEMENT`，不能宣称自动忠实度通过。仅原文评估忽略PBS澄清，但不改变原文哈希、原始含义或义务ID。原始03/04的其他义务继续阻断；这不构成F083/C05验收。

同一注册入口接受可选 `buySuspensionReplacementIntent`，包含确切 `source_hash`、`candidate_content_hash`、`source_start`、`source_end`、`excerpt`、`replacement_reason`、`retire_predecessor_guard`、`acknowledge_unverified_predecessor`及必填 `strategy_effective_from`。策略起点必须明确使用 `+08:00`，不设置新保护的废止分支也一样。仅提供明确接替意图时允许空补充列表。注册要求完整原文声明明确接替前序持续禁买，并明确废止旧保护或提供新保护，同时包含新BUY指令。该有限来源意图核验不识别新底部，也不解析运行前序关系。预览仅通过 `buySuspensionReplacementIntent`展示已注册意图。

意图保存在既有DRAFT补充记录中，再复制到 `review-<version>` 的REVIEW记录，绑定确切已保存原文／内容／版本。注册意图改变使已保存绑定失效。`BuySuspensionReplacementBinding`（版本 `buy-suspension-replacement-v1`）定义有界已审核凭据：确切前序及新版本／计划／内容／原文／审核身份、启用／状态修订、前序定义／未核实区间、新保护、完整意图及确认时间。凭据必须匹配其所属已确认审核。值级哈希不构成运行授权。PBS-T04原先不创建成功运行凭据或保护状态快照，并以 `BUY_SUSPENSION_REPLACEMENT_REVIEW_REQUIRED` 阻断带接替意图的确认。T08现先把有限来源提议／起点证明为强制BUY关系，再根据实际前序／owner／状态和新独立审核生成凭据；来源证明不依赖尚未生成的凭据。

PBS-T08现通过实际凭据链实现服务端前序／启用／真实保护状态绑定和启用原子复核；过滤 `BUY_SUSPENSION_REPLACEMENT_REVIEW_REQUIRED` 绝不构成豁免。原文改变后，不携带另一来源已登记的意图。保留PBS-T04历史注册→预览→底层保存／读取证据；T08现覆盖受保护的公共Schema10保存／审核／启用链。见[当前启用归属](SPEC-unified-plan.zh-CN.md#u-pbs-activation--已审核续版与接替2026-11-15)。来源继承与运行接替授权仍是不同证据。保留Schema5–9、v12、冻结字节及原始样本；不需要用户数据库操作或provider调用。
