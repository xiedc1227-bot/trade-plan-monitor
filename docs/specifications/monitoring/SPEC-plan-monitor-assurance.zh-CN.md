## PMA-S01 — 目标与依据

通过三个独立问题明确计划能否支撑监控：每项重要原文义务是否在提取后保留；准确提取版本是否通过具有代表性、独立标注的语料；准确已保存计划是否得到有效当前评估与通知服务。仅 `SUCCEEDED`、既有问题为零、`ACTIVE` 或离线测试通过，都不能单独回答这些问题。

2026-10-27只读调查在 P3 基线 `a5546ad` 复现：合法 Schema9 夹具有145条原文、128个绑定、零问题；追加 “Only buy when turnover exceeds 3 percent.” 或“仅当换手率超过3%时才允许买入。”，将新条款标为 `CONTEXT/COMMENTARY`、路径为空且理由非空，结果仍为146条原文、128个绑定、零问题。候选结构仍可转为可执行模型，未进行启用。相关代码为 `ai/daily_review.py`、`ai/source_resolution.py`。这是已验证的校验盲区，不证明某份用户计划已经漏提。

同次只读盘点发现本地有三份 Schema5/v9 提醒计划，各含一条提醒、无普通／风险规则，其中一份启用；原文本来就定义观察计划。本地迁移头为0026，P3 代码新增0027。这些带日期的观察说明须区分代码能力、已保存计划范围与安装就绪状态，不能硬编码成测试真值，也不构成升级用户数据的授权。

保留已验收 [P3 边界](SPEC-market-linkage-p3.zh-CN.md)、[当前工作流](SPEC-unified-plan.zh-CN.md)及有限[原文处理](SPEC-source-treatment-review.zh-CN.md)。原提示词仍位于仓库外 `../../../../docs/TradingAgents/reports/新提示词.txt`，规范化 UTF-8 SHA-256 为 `f17e12b88f4c12d7af7b67caabede2e9d7c2712142a64e67a212c7621865f731`；判断范围时不能用修订文档替换原文。

## PMA-S04 — 范围与明确排除

范围内：当前 Schema5–9 原文派生草稿、提取／保存／重读／审核／启用／复用，相关当前普通／例外／可操作通知检查，版本化覆盖账、原文到规则界面、语料评分及只读就绪。保留库存、预算、研究与真实账户隔离；有效但不完整的草稿继续可检查、可保存。

范围外：新增指标或策略、自动发现价位／基本面、券商执行、真实账户／部分成交／委托预留、资金分配、自动修规则或改原文、让第二个 AI 裁判提供批准，以及本请求中的用户库迁移。就绪读取不得补采行情、更新心跳、发通知、确认库存／成本或启用计划。

旧冻结输入／回放继续遵循准确历史契约。本阶段不改其输入／哈希，也不引入冻结运行公式版本。历史／假设回放不能证明当前原文覆盖或真实安装就绪。当前计划复用须经过新当前原文防护；若未来要把新覆盖回执写入冻结输入，须另行规定版本化契约。

| --- | --- |

## PMA-S07 — 实施约定与验证边界

沿用当前 Python3.14、不可变 Pydantic、准确股数／分及既有规范哈希。领域覆盖放 `ai/` 或聚焦的原文政策模块，存储／授权放 `state/`，HTTP 投影放 `web/`，当前证据通过既有 runtime 读取接缝取得。Vue 使用 Composition API `<script setup lang="ts">`，不建议新增依赖。门控示意为 `can_confirm = integrity_valid and coverage_complete and exact_binding`，就绪标记绝不替代该门控。

[任务对](../../../tasks/plan-monitor-assurance.zh-CN.md)定义完整命令、建议测试文件、依赖、24项任务及八个检查点。每片目标3–5文件，较宽任务在编辑前顺序拆分；行为修改前先写独立失败测试。保留 `tasks/plan.md`、`tasks/todo.md`。写草案不等于做过源码变异实验或运行过测试。

始终保留原文、原始失败、旧黄金样例及既有资源／准入限制。明确授权实施后可开发增量迁移并验证临时库，但对用户数据应用迁移仍须单独授权。仅在新语义、真值争议、未授权外发／费用范围、版本／预算扩展或无法避免的兼容变化时请求决定。不豁免遗漏、不虚构READY、不改标签、不静默改历史、不削弱测试来关闭检查点。

完整保存／重读／审核／启用／复用／操作／发送时防护链测试通过前，不宣称当前覆盖能力完成，也不接受其新审核回执。中间适配私有分阶段验证，缺所需保证能力／存储时明确阻断或未知，不能回退后授予新权限。最终公开准入在C03/C04后，用户实际升级另行控制。
