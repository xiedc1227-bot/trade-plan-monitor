## MLP1-01 — 目标与基线

支持 [README 原始提示词](../../../README.zh-CN.md#通用交易计划生成提示词)保留的两条人工复评 BUY 例外，同时避免将相对强势或人工授权变成绕过交易条件的方式。基线：在 `dbeff32` 已完成本地验收的 P0；参见 [P0 规格](SPEC-market-linkage-p0.zh-CN.md)、[确认定义](SPEC-confirmation-selection.zh-CN.md)、[数量规则](SPEC-quantity-policy.zh-CN.md)、[契约](CONTRACT-market-linkage-p0.zh-CN.md)及[验收](../../verification/2026-10-24-market-linkage-p0.zh-CN.md)。

用户应能看清例外为何具备资格、确切数量及其余约束，批准或拒绝本次机会，再单独确认整笔模拟交易。成功标准包括证明缺少授权始终为零权限，重复操作不能增加交易次数。

本包经批准扩展既有 `confirmation-selection`、`quantity-policy` 和 `market-linkage-workflow` 模块，不替换它们已经批准的 P0 行为。用户已一并审核规格与任务清单，并明确指示开始实施。

## MLP1-04 — 共用资格与授权条件

沿用 P0 的大盘分类、参考指数、对齐相对强势计算、S0/S1/S2 定义及时间规则。STRONG 要求三个已知判断全部成立：个股 5 个交易日收益 > 指数收益；个股 20 个交易日收益 > 指数收益；个股 D 日收盘 >= 当日 MA20。任一收益比较相等均不通过。未知证据不能通过人工授权绕过。

S1 要求 D 日完整 S0、相邻应交易日 D-1/D 的收盘均在低吸区、D 日收盘 >= D-1 日收盘、D 日成交量 <= 不含 D 的前 20 日均量、D 日 RSI14 > D-1 日 RSI14，且无更高优先级风险。S2 再要求两日各自的收盘 >= 各自当日 MA20。原有预热、截止时点、来源准入及审核事实范围继续必需。

授权必须同时满足 ALL：

1. 当前计划已经明确审核并启用这条例外路径，完整定义、Q0 和数量约束均绑定原文或人工审核补充。
2. 已完成正式交易日 D 的证据选中该路径，证明 STRONG 及 S1/S2 资格。缺少市场规则、输入、对齐、必要事实，或存在更高优先级风险，均不能批准。
3. 按规则已审核的信号策略，确有独立机会。候选固定证券、计划／审核版本、启用记录、规则、路径、D、执行窗口及实际使用的证据。
4. 已知模拟持仓及剩余额度足以承接完整选定数量。当前计划、审核和候选未被替换、拒绝、过期、撤销或消费。
5. 本地用户看到服务端预览，填写非空理由并明确批准确切数量。服务端时间及既有同源变更保护记录这次本地操作；单用户产品不声称提供经过认证的人员身份或签名。

计划许可、单次资格、批准、执行许可是四个不同状态。批准不改变持仓。`/api/v1/simulated-trades` 仍为独立的明确操作，并重新检查当前全部执行门槛。审核技术事实只能提供其限定的技术判断，不能充当例外批准。原文写着“已批准”也不会成为授权事件。

## MLP1-05 — 路径与数量表

Q0 为既有来源审核确认的正 100 股整数倍，界限为 `9007199254740991`。`m`、`s` 为适用证券／交易日的官方最小量及递增单位。定义 `L = {m + n*s | n 为整数且 >= 0} ∩ {100*k | k 为整数且 >= 1}`；剩余额度 `C = position.max_qty - inventory.total_qty`。使用精确算术。

| 路径 | 共用门槛之外的进入条件 | 数量规则 | 单次批准之前的权限 |
| --- | --- | --- | --- |
| NORMAL_TRANSITION | S0 | 既有 P0 比例 `1` 和合法向下取整 | 既有普通行为 |
| 普通 WEAK | S1；`L` 中存在 <= `0.5 * Q0` 的数量 | 既有的最大符合数量 | 既有普通行为；无需 STRONG |
| `WEAK_MINIMUM` | WEAK；普通减半不足最低量；STRONG；S1；路径已启用 | `Qe = m`，要求 `m ∈ L`、`m <= Q0`、`m <= C` | 零 |
| BROKEN + NOT_STRONG | 无例外资格 | 零 | 零 |
| `BROKEN_STRONG` | BROKEN；STRONG；S2；路径已启用 | 人工输入 `Qe ∈ L`，要求 `0 < Qe <= Q0` 且 `Qe <= C` | 零 |
| 必要输入 UNKNOWN | 无法证明选定路径／条件 | 不授予正数量权限 | 零 |

`WEAK_MINIMUM` 要求 `0.5 * Q0 < m <= Q0`。既有预检必须确认为减半不足最低量，不能是市场规则未知或数量网格不兼容。若官方最低量本身不是 100 股整数倍，则阻断该例外，不替换成更大的交集数量。当前已批准规则库的最低量兼容此要求。支持其他数量须另行修订规格。

`BROKEN_STRONG` 的 Qe 可以小于、等于或大于 `0.5 * Q0`，但绝不能超过 Q0。这是原文上限内提议允许的人工选择，并非建议买满。数量输入初始为空。非法输入直接拒绝，不取整、不裁剪、不预填、不静默替换。批准一条路径不能沿用到另一条。

两条路径中，零代表不批准／不交易，不是可执行的零股操作。额度未知阻断批准；额度不足整笔阻断选定数量。修改 Q0 须新计划版本及审核。常态 Q0 本身不足最低量、普通额度不足、网格不兼容或普通确认失败，均不能转入这两条例外。

## MLP1-07 — 机会生命周期、截止时点及竞争

符合资格的机会产生不可执行的 `PENDING` 候选，不产生普通可执行信号，也没有授权数量。走弱路径的数量已确定；明显破坏路径的数量在预览输入前保持未定。修改未批准预览不会产生额外机会。

允许转换：`PENDING → APPROVED | REJECTED | EXPIRED | INVALIDATED`；`APPROVED → CONSUMED | REVOKED | EXPIRED | INVALIDATED`。其余转换全部拒绝。终态不可重新打开。只有 `APPROVED` 且其余门槛仍满足时，才能给出正数量执行权限。执行在同一事务中写入 `CONSUMED`、原有整笔交易回执和持仓变化。

一次机会至多成功批准一次、消费一次。批准原子冻结 Qe、证据绑定及信号。批准后不能修改数量；用户改变想法时可撤销。拒绝或撤销后不能再次批准该机会。新机会必须满足既有独立信号重置／新事件策略；新日期、路径切换、复制计划、数据修订、通知或重试本身均不足以产生新机会。保留同向规则先后关系及跨版本连续性，不另设可绕过它们的例外计数器。

决策交易日 D 必须已经完成，其记录在评估截止时点前可用。记录准入后即可批准，包括下一交易日开盘前，但最迟只能到该下一交易日收盘。执行限定在下一交易日并继续遵守既有可交易检查。以服务端接收时间为准，用户不能倒填批准时间。迟到证据或迟批准不延长窗口。下一交易日日历未知时阻断权限。重新打开应用不续期。全部时间戳使用带时区的 `Asia/Shanghai`。区分原行情证据截止时点与较晚的授权接收时间：按实际时间追加权限，绝不把此前决策改写成当时已经获批。

实际使用的价格、复权基准、限定事实、计划／审核内容、启用记录、路径或必要规则版本变化，会使待审或已批准权限失效。仅重新抓取的 ID／时间、复权截至日期元数据及等价 Decimal 格式继续按 P0 保持连续性。所用决策窗口以外的新观察本身不会改写 D。当前风险升高按既有风控规则阻断执行。已执行历史不可变。

预览携带当前持仓及权限修订号。批准前修订号变化返回冲突，须重新预览。批准后持仓变化重新校验整笔额度，不改数量、不创建新信号；权限未变且原窗口内额度足够时仍可执行。批准／撤销／执行竞争使用事务内修订校验。若消费先完成，撤销返回冲突，不能撤回交易；若撤销先完成，执行不得成交。

## MLP1-08 — 契约与兼容

Schema 7 使用 `execution_mode=CONDITION_PLAN`、`execution_version=condition-plan-v3`；联动使用 `market_policy.policy_version=market-linkage-v2`、`base_confirmation=S0`、`exception_policy=REVIEW_PER_OCCURRENCE`。在每条联动规则的 `market_policy` 内新增必填 `exception_routes.weak_minimum` 和 `exception_routes.broken_strong`，值均为 `DISABLED` 或 `PER_OCCURRENCE`。两条均可明确关闭，包括通过审核更新撤回许可的情况；这不会静默降级格式。字段缺失绝不代表许可。既有普通 `quantity_policy`、BUY/TACTICAL 限制、最多两条规则、深度 4 和展开后 50 叶子边界继续有效。

新计划许可绑定完整例外含义，不能只绑定枚举标签。启用原本阻断的路径须重新审核 Schema 7 版本。Schema 6 继续 `BLOCK_P1`，其例外仍为 `P1_EXCEPTION_REQUIRED`。Schema 5 固定计划和 Schema 1–4 冻结读取保持不变。不自动升级、不向旧格式补默认字段、不静默丢字段、不增加面向用户的格式选择器。

已实现版本边界：提取 `plan-extract-v10`；审核内容 `plan-review-content-v4`；决策 `market-linkage-evidence-v2`；计算 `market-linkage-calculation-v2`；候选 `market-linkage-exception-candidate-v1`；授权 `market-linkage-exception-authorization-v1`；研究输入 `backtest-run-v8`。既有个股／指数数据及公式版本不变。MLP1-T01 已核对名称冲突，并在双语契约附录冻结读写端清单；技术编码细节保留已批准策略含义。

候选证据绑定 `candidate_id`、稳定 `occurrence_id`、证券、精确的计划／审核／启用／规则身份、路径、D、决策截止时点、原执行窗口、实际使用证据／哈希版本、Q0、官方规则版本／来源哈希、资格及数量约束。完整采集元数据可审计，连续性哈希保留 P0 规范化。授权另绑定 `approval_id`、确切候选摘要、`quantity`、服务端 `received_at`、`actor_kind=LOCAL_USER`、非空理由及命令身份。来源／导入边界拒绝未知字段、格式错误或伪造的批准载荷。

保存只追加的授权／终态事件及事务更新的投影。使用持久唯一的机会／批准／消费约束和命令回执，不能仅依赖进程锁。任何增量存储迁移均在临时数据库测试，绝不重写旧 JSON／哈希。回退保留新记录并明确阻断不支持的操作，不能将其解释为普通／固定数量交易。哈希沿用规范 JSON 及 domain/NUL/SHA-256，加载时验证。

## MLP1-09 — API 与诊断

保留 `/plans` 及既有计划／审核／启用／运行／模拟操作族。增加下列本地命令族，全部输入为严格类型模型，所有变更沿用现有来源／上下文保护及持久幂等。下列名称为已实现契约；准确生成字段及事件审计编码记录在契约附录。

| 方法和路径 | 必要输入／行为 | 输出 |
| --- | --- | --- |
| `POST /api/v1/plan-exception-previews` | `candidate_id`、`expected_revision`、`proposed_quantity`（`WEAK_MINIMUM` 为 null，`BROKEN_STRONG` 为明确数量）；只读重算，不批准 | 不可变 `preview_id`、`preview_hash`、确切数量、额度、证据、到期时间及全部阻断原因 |
| `POST /api/v1/plan-exception-decisions` | `command_id`、`candidate_id`、`expected_revision`、`decision=APPROVE\|REJECT`、理由；APPROVE 必须携带 `preview_id`、`preview_hash`，REJECT 不携带这两项 | 持久决策回执、候选状态、获批时的批准身份／数量；不改持仓 |
| `POST /api/v1/plan-exception-revocations` | `command_id`、`approval_id`、`expected_revision`、理由；只允许尚未消费的当前 APPROVED 权限 | 持久撤销回执；不改持仓 |
| `GET /api/v1/plan-runtime/{symbol}` | 既有读取增加 Schema 7 分支 | 候选、当前权限、冻结数量、执行资格及原因 |
| `POST /api/v1/simulated-trades` | 既有明确信号命令；服务端查找关联批准并原子校验 | 既有整笔模拟回执；绝不接受客户端自称已获批 |

预览证明曾展示的内容，不是可复用许可。批准时服务必须重新验证全部权限及数量门槛。客户端不能在 APPROVE 时提交另一数量。仍为当前 PENDING 候选时，即使没有成功的数量预览也可以 REJECT。

相同命令和正文重试返回原回执；同键不同正文拒绝。不同键也不能重复批准或消费同一机会。正在处理或修订过时冲突返回 `409`；非法／不支持的数量或格式错误沿用 `422` 校验约定；未知资源使用 `404`。保留既有结构化错误格式及服务不可用语义，不能把服务／存储失败包装为空的成功状态。幂等证据至少保留至机会及执行审计生命周期结束，不能靠键过期重新开启事件。

区分 `EXCEPTION_DISABLED`、`EXCEPTION_APPROVAL_REQUIRED`、`EXCEPTION_QUANTITY_REQUIRED`、`EXCEPTION_QUANTITY_INVALID`、`EXCEPTION_APPROVAL_STALE`、`EXCEPTION_REJECTED`、`EXCEPTION_REVOKED`、`EXCEPTION_EXPIRED`、`EXCEPTION_CONSUMED`，并保留既有市场／条件／额度／风控原因。条件为假和证据未知仍须区别。`authorized_quantity=0` 不是可执行操作。常态及普通 WEAK 不增加批准依赖。

## MLP1-10 — 提取与用户流程

1. 提取保留两条例外原文、约束及完整定义。只有原文或审核补充支持时才能草拟路径许可。不能生成批准事件、推断明显破坏路径数量，或把例外改成普通买入／审核事实。更新、准备及计划继承流程也保留此边界。
2. 计划审核展示每条路径的开启／关闭意图及数量含义。明确关闭的路径可以和已启用普通路径共存，但不能删除原文含义。缺少定义／Q0、不支持的时机、伪造批准或遗漏约束均阻断完整审核。允许今后复评的原文不能提供单次批准；明显破坏路径 Qe 在具体机会复评前为空是正常状态。
3. 运行只有在技术资格成立后才显示“符合例外条件，等待你的批准”。同时展示路径、D／到期时间、参考指数、大盘与 STRONG 操作数、S1/S2 证据、Q0、拟批准数量、额度、风险及阻断原因。技术未知不能用批准按钮解决。服务不可用单独显示。
4. 走弱例外数量只读。明显破坏例外数量初始为空，提供合法数量／上限的就地反馈。人工填写理由、预览，再确认展示的确切数量。确认说明批准本身不会发生模拟交易。拒绝和撤销是明确的独立操作。
5. 批准后展示冻结数量、原始窗口及当前执行阻断。模拟仍须既有明确操作。收到通知、确认提醒、刷新、审核和启用均不能批准或交易。重试／重启恢复同一候选及状态。一次机会使用稳定提醒身份，发送时检查并抑制过时的批准／执行提示。独立五分钟提醒不受影响。

## MLP1-11 — 冻结回放与证据

实时评估和回放共用资格、数量和授权策略。回放冻结计划／审核身份、个股／指数／事实数据、官方规则版本、日历，以及有序 `exception_authorization_events` 流。每个事件绑定确切机会及数量，其可用时间不得早于准入证据。批准、拒绝、撤销和消费顺序必须确定。冻结回放绝不查询当前本地批准数据库。

缺少匹配事件时，记录符合资格但未获批准，例外交易为零。导入真实记录使用来源 `RECORDED_LOCAL`。明确假设事件使用 `RESEARCH_SCENARIO`，须在运行前保存，并在设置和结果中标明假设；不能导出为实时权限，或声称是历史人工操作。P1 不增加自动批准所有合格事件的策略。真实记录和研究批准都不单独执行交易：既有明确回放操作脚本仍须在原窗口内请求执行。

只有回放截止时点前已可用的事件和证据能影响决策。晚到批准不能授权较早的成交。拒绝计划／路径／数量／证据绑定不匹配，历史规则／日历范围不可用时明确报告，不猜测。相同冻结输入、操作脚本和授权事件必须在运行适配器与回放中产生相同判断。未来数据／事件变异不能改变此前输出。既有任务互斥、取消、存储限制及原子结果发布继续有效。

## MLP1-13 — 工程约定与验证

保留 Python 3.14、严格不可变 Pydantic 模型、Decimal／整数算术、FastAPI/SQLite、Vue 3/TypeScript、pytest/Vitest/Playwright 和现有依赖锁定。领域规则置于 `src/trade_plan_monitor/domain` 和 `decision`；权限和原子存储置于 `state`；运行／适配置于 `runtime`、`web` 和 `backtest`；UI 置于 `web/src`；确定性测试置于 `tests/unit`、`tests/integration` 和 `web/tests`。不建议新增依赖。

使用 snake_case 及小型纯策略，例如 `validate_exception_quantity(route, base_quantity, proposed_quantity, market_grid)`，显式传入有类型的输入，不隐式读取时钟、数据库或数据商。网络 I/O 放在事务外。先扩展服务端模型再生成前端类型，不在 Vue 重复实现权限。测试命令及已实现测试职责见 [MLP1-P02](../../../tasks/market-linkage-p1.zh-CN.md#mlp1-p02--验证命令目录)；执行结果及最终修复证据记录在验收报告。

始终：保留来源含义、独立信号限制、精确冻结数量及双语等价；验证后才能标记任务完成。数量／到期规则变化、自动批准、扩大执行／数据商范围、新依赖或破坏性存储变更须修订规格。禁止：伪造批准、弱化测试、重写旧权限或使用用户数据库验收。实施已获授权；真实数据商调用、推送和部署未获授权。
