## CS01 — 目标与边界

使用 `market-regime`、`relative-strength` 和既有个股条件，唯一选择一条大盘联动BUY路径。原文须明确授权联动政策及其完整定义。非联动规则不增加隐含指数依赖。P0联动使用 `OFFICIAL_DAILY_CLOSE` 和 `NEXT_EXCHANGE_SESSION_ONLY`；联动五分钟确认属于不支持，不能静默转换。

## CS02 — 确认定义

S0为完整审核的个股入场条件：区域、量价或K线条件、技术辅助证据、明确ALL／ANY、确认方式与独立信号语义。内容由原文决定，不得从S0名称推测阈值。未量化技术判断保留限定范围的REVIEWED_FACT权限，不能由AI认定为真。定义缺失阻止审核；定义完整但技术事实未核验时保留运行时未知。

S1要求ALL成立：相邻有效交易所交易日D-1和D均收盘在低吸区；D收盘 >= D-1收盘；D满足完整S0；D成交量 <= D之前20交易日均量，不含D；D日RSI14 > D-1日RSI14；无更高优先级风险。所需历史、指标预热和来源日期对齐均须通过。停牌／缺失日不能被跳过后构成相邻观测K线对。

S2为S1 AND 两日收盘分别 >= 各自当日MA20。不得把D-1与D日MA20比较。S0未知或不完整不能使S1／S2完整通过。保留计划要求的级别名称和定义，不静默改名。

## CS03 — 封闭路径表

| 大盘／路径 | 确认 | 数量上限 | P0结果 |
| --- | --- | --- | --- |
| NORMAL_TRANSITION | S0 | Q0 | 条件及其余门槛通过后才具备资格 |
| WEAK且存在普通合法折减数量 | S1 | 0.5 * Q0 | 条件及其余门槛通过后才具备资格 |
| WEAK且折减后低于最低合法数量 | S1加STRONG用于判断例外资格 | 无普通数量 | `P1_EXCEPTION_REQUIRED`；即使符合资格也不向上取整 |
| BROKEN且NOT_STRONG | 无 | 0 | `MARKET_BROKEN` |
| BROKEN且STRONG | S2用于判断例外资格 | 无已批准例外数量 | `P1_EXCEPTION_REQUIRED`，S2通过时也如此 |
| UNKNOWN或必要路径输入未知 | 未确定 | 授权为0 | `MARKET_INPUT_UNKNOWN` |

BROKEN且强弱UNKNOWN走最后一行。NORMAL_TRANSITION和普通WEAK不要求相对强势，无关强弱数据缺失不能阻断它们。按需计算必要谓词，保留每个使用事实的证据。例外资格未满足时可同时列出不满足／未知原因，P1授权仍然缺失。

为保持依赖无环，路径选择器从共用纯领域预检读取 `ordinary_quantity_available`，输入为已审核Q0、路径系数及已核验市场／模拟数量规则。预检只返回算术可行性，不返回库存资格或交易权限。路径选定后数量政策复用同一辅助函数，两个模块均不调用对方求值器。预检输入未知走最后一行。

## CS04 — 信号生命周期

条件组是同一普通规则的不同资格路径，不是独立订单或分笔。仅在选中组证据满足后确认。绑定选中路径、信号事件、计划／审核修订、证据集与最终数量。复用既有独立信号、期限、重置及顺序分笔政策；切换路径或更换日期不构成独立信号。

未变化的有效信号保留原下一交易日执行窗口。技术风险按既有规则使普通权限失效。已使用事实发生变化／修订时，待执行联动信号失效；不自动改量、不倒填确认、不因改善自动恢复。新信号必须满足原审核的独立事件／重置语义。计划更新遵循现有替换／保留规则，不能仅复用ID转移权限。
