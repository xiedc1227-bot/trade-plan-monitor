# 规格：daily-plan

英文版本为 canonical；本 `SPEC-daily-plan.zh-CN.md` 是语义等价的中文审阅副本。日期：2026-10-02。设计基线：`b2572b6`。用户已授权设计后实施；能力设计通过不等于批准内容不完整的实际计划。模块边界见[能力地图](../../architecture/CAPABILITY-MAP-daily-plan.zh-CN.md)。

## D01. 目标、证据与边界

**2026-10-02 已授权范围纠正：** 本产品监测计划，并支持用户显式触发模拟交易，不跟踪券商委托或真实券商成交。本修订取代此前日线专用部分成交/订单/占额要求。[清理契约及任务](../../../tasks/2026-10-02-daily-plan-simulation-cleanup.zh-CN.md) 是当前实现交接；2026-10-01 报告保留为当时范围的历史证据。

实现完整、确定性的日线链路：自然语言原文 → 忠实部分候选 → 确定性校验 → 人工内容审核 → 不可变最终计划 → 绑定审核的显式启用 → 日线确认 → 下一时段执行提醒 → 用户显式确认 → 一次原子全量模拟交易。提醒、已读、刷新和调度回调绝不改变持仓，只有用户模拟命令改变持仓。不提交/撤销真实券商委托，不收集券商成交报告。

已完整读取且不修改 `../docs/TradingAgents/reports/新提示词.txt`。模板中的生成计划要求不授权本次实现查询实时行情。春秋航空历史样例提供：持仓100、成本40.70、上限300、建议 CORE100 / TACTICAL0、低吸39.45–39.90、压力41.80–42.20、风险38.18、拟买100。它**没有**提供“明显缩量”“止跌”“冲高回落”“连续受阻”的可复现定义、39.67/41.96为固定还是动态参考的性质，也没有证明底仓划分已在此前确认。必须保留这些缺项。用户恢复任务时确定的新范围覆盖旧原文中的基本面监控要求：这些原文保留为非监控背景，不要求解决后才能进行日线监控。

已核对：`domain/plan_models.py`、`plan_codec.py`；`ai/models.py`、`prompts.py`、`review.py`；`decision/risk.py`；`market_data/models.py`、`indicators.py`；`runtime/service.py`、`explicit_service.py`；`state/models.py`、库存仓库；Web计划/持仓服务及路由。Schema 3 仅支持完整五分钟规则，各最多一条 BUY/SELL/RISK_ALERT、ALL_REGISTERED卖出和两种重复策略。当前已具备审核/启用链路；旧规格标注R12待完成不能证明当前启用仍关闭。`DailyBar`明确为不复权日线；`ta-v1`的MACD柱值为DIF−DEA。旧持仓Web值限制整手，部分lot revision由减少股数推导。这些是兼容边界，不是可直接复用的日线交易语义。

始终保留历史字节、哈希、提示词契约与证据；验证用户/数据源边界；记录消费的所有revision；保持中英文对应。不得虚构策略阈值、把建议当成交、修改源模板、弱化旧测试或启用未接通能力。本次不需要新依赖、数据源、券商接入、现金余额要求、实时行情/AI调用或生产数据修改。金额上限若尚未实现其已审核预算/估值口径及记录，应明确标为不支持并阻断相关买入；仍须能够展示持仓风险。

恢复后的新增日线监控仅允许普通与严重技术风险。基本面由用户在生成交易计划时审核；基本面/公告文字不得形成监控条件、BUY/SELL前提、风险触发、执行阻断或必需的公告核验任务，也不得改名为技术人工事实。可交易性、全天停牌、交易所日历、交收与价格口径证据仍是运行输入，即使其来源为官方公告。大盘指数逻辑暂不处理：本次保持既有指数行为，不新增也不删除。

## D03. 完整计划与部分候选

并列计划保留 `plan_id`、`version`、`symbol`、`name`、`market`、`metadata`、`activation`。新增下列严格字段；禁止额外键、表达式字符串和可执行代码。可选策略必须有显式标签状态，不使用省略后的隐式默认。

| 字段 | 必需语义 |
|---|---|
| `levels` | LOW_BUY/PRESSURE区间使用整数分端点且显式包含两个包含标志；正数 `risk_line_fen`；显式审核 `risk_comparison=LT` 或 `LTE`。要求风险线 < 低吸下沿 ≤ 上沿 < 压力下沿 ≤ 上沿；拒绝没有有效报价刻度的空区间。 |
| `position` | 股数 `max_qty`；已审核的CORE/TACTICAL划分策略及 `EXISTING_CONFIRMED` 或 `PROPOSED` 来源。目标绝不等于实际库存。普通SELL仅限TACTICAL。 |
| `trading_rules` | 仅软件模拟常量：100股单位、`settlement=NEXT_EXCHANGE_SESSION`、`tick_size_fen=1`、`special_state_restrictions=BLOCK_UNVERIFIED`。删除可配置 `buy_min_qty`、`buy_increment`、`sell_increment`、`odd_lot_liquidation`及券商规则 `evidence`/`as_of`。不要求逐计划券商设置/证据日期审核；常量由server产品契约绑定，不是AI猜值。旧schema不变。 |
| `monitoring` | `timeframe=DAILY`、`indicator_formula_version=daily-ta-v2`、`price_basis=QFQ`、来源/复权可比性要求。执行报价仍为真实可交易价格。 |
| `ordinary_rules` | 最多一条BUY与一条SELL，分别显式 `ENABLED` 或带已审核原因的 `DISABLED`。启用规则需稳定 `rule_id`、对应区域、数量、bucket、三个证据组、有效/失效条件及独立信号策略。禁用动作不填虚构触发条件。 |
| `risk_branches` | 恰有 `ORDINARY_TECHNICAL` 和 `SEVERE_TECHNICAL`，各自写明处理范围、是否涉及CORE、每个bucket的确切目标保留股数、证据模式及命名优先级。普通风险还须明确 `suspension_confirmation_policy=RESUME_FIRST_CLOSE` 或 `RESTART_ADJACENT_PAIR`。缺失分支语义仍为候选未解决项。 |
| `execution_policy` | `confirmation=OFFICIAL_DAILY_CLOSE`、`ordinary_window=NEXT_EXCHANGE_SESSION_ONLY`、`same_signal=ONE_PLANNED_QUANTITY`、`risk_priority=SEVERE_THEN_ORDINARY`、`ordinary_conflict=BLOCK_BOTH`。这些是可见的Schema 4产品语义，不是AI替旧原文猜测的策略。 |

启用的普通规则必须同时满足 `price_structure`、`volume_or_candle`、`technical` 三个条件根，以及适用的已审核前提（例如风险收益判断；不得包含基本面或公告审核）。各根内允许显式ALL/ANY。仅处于价格区间或单一指标不能凑成三个维度。不得机械制造费用/收益门槛：原文没有数值规则时，可由计划专属的已审核可行性事实承载计算/证据。辅助证据缺失只阻断实际依赖它的分支；无关日线输入不能隐藏已确认的技术风险义务。基本面或公告信息缺失属于监控范围外，不产生输入缺失结果或执行阻断。

`DailyPlanDraft`以类型化null镜像此契约，并保存原文证据与未解决/不支持项。数量、有效期、端点标志、阈值或分支范围缺失的候选可保存展示。只有完整可执行变体加当前已完成审核才能启用。运行时持仓缺失不使内容审核变假，但会阻断相关执行就绪。最大股数缺失可保留候选并展示风险信息，不能据此给不完整计划通用启用权限。

逐领域字段验证全部日线模拟数量为0或100股倍数：期初CORE/TACTICAL、`max_qty`、持仓目标、普通计划量、风险保留目标、模拟持仓/可卖及显示执行量。执行交易数量还须为正。不兼容完整计划在审核/启用时拒绝，草稿保留明确问题。不全局修改用于revision/计数的 `Qty` 别名。技术风险 `PENDING` 表示等待下一官方收盘，继续保留；仅删除券商订单PENDING/CANCELLED/UNKNOWN。

## D04. 有限日线条件与精确证据

使用有界类型树（深度≤4，全计划叶子≤50），结果为SATISFIED / UNSATISFIED / MISSING_INPUT。ALL任一false即false，否则任一missing即missing；ANY任一true即true，否则任一missing即missing。保留全部分支证据。这些数量上限是资源约束，不是交易阈值。

| 叶子族 | 必填字段与计算 |
|---|---|
| `DAILY_PRICE_COMPARE` / `DAILY_PRICE_IN_RANGE` | OHLC字段、完整K线offset、LT/LTE/EQ/GTE/GT比较符或显式区间、固定价格或动态参考。offset0为已完成的确认K线，不是形成中K线。 |
| `DAILY_VOLUME_RATIO` | 当前完整成交量与PREVIOUS或恰好此前N个完整个股交易时段的算术MEAN比较，排除当前；必填比较符和精确小数比值。不替换为中位数或盘中累计量。缺失/未核验时段或分母为0时为MISSING_INPUT，除非有显式支持并已审核的零基线规则。 |
| `DAILY_CANDLE_RATIO` | 指定下影、上影或实体/振幅比，以及比较符/阈值。下影=min(open,close)−low；上影=high−max(open,close)；实体=abs(close−open)；分母=high−low。振幅为0时比例缺失。阳线或收盘不下降可使用价格比较。 |
| `DAILY_INDICATOR_COMPARE` | 指标名称、精确公式版本/参数、offset、比较符、固定值或该指标另一个offset/参考值。穿越须显式写前后两次比较；“改善”不能自动变成交叉。 |
| `DAILY_CLOSE_SEQUENCE` | 明确N个完整时段、比较符、固定/动态参考或逐对收盘不下降；明确窗口是否包含当前及日期身份。不隐式解释“连续受阻”。 |
| `REVIEWED_FACT` | 类型化事实种类、语义证据要求、适用日期/信号、revision及有效范围。人工确认需具体证据和身份，不能用泛化确认代替。用于不能安全量化的定性结构/量价事实及计划专属技术/交易可行性判断。新增日线事实/条件契约禁止 `ANNOUNCEMENT_CHECK` 和 `FUNDAMENTAL_INVALIDATION`，含嵌套前提、失效及独立事件策略；不得使用其他事实种类承载相同语义。 |

价格/指标参考使用判别对象：`FIXED`包括值、单位、as-of/来源；`DYNAMIC`包括指标名、参数、公式版本及完整K线offset。固定39.67不能静默变成当前BOLL_LOWER；动态BOLL_LOWER不能冻结在39.67。每个已计算叶子记录K线ID、来源/截止/复权口径、操作数、精确参数与结果。普通信号即便完全依赖人工事实，也必须有已核验完整日线OHLC及全部三个独立证据组。

## D05. 日线数据准入与公式

新日线输入需证明股票、交易所日期、官方完整状态、数据源、接收/可用时间≤评估截止时间、同一前复权口径及复权as-of日期。需要时以精确小数保存复权计算价格，不把每根历史复权K线先取整到分。保留不复权报价，并证明它与计划价位/当前报价可比。现有裸 `DailyBar` 本身不满足此契约。缺权息因子或可比性冲突时输出 `PRICE_BASIS_UNVERIFIED`，不替换为裸价。序列必须来自同一已验证来源/口径，不拼接局部历史。

复用已核验交易所日历和停牌事实。窗口使用所需已完成个股交易时段；已证明全天停牌可以在指标窗口中跳过，计划应有而缺失的数据不能跳过。记录实际日期与跳过项，不生成成交量0的虚构K线。计划日期和执行窗口使用交易所交易时段，与指标观察窗口不同。日历/停牌状态未知即输入缺失。时间戳必须Asia/Shanghai；报告时间没时区则仍待核验。

`daily-ta-v2`：完整收盘计算SMA20/SMA60；MACD12/26/9的EMA alpha为 `2/(n+1)`，首个收盘种子、递推adjust=false，DIF=EMA12−EMA26，DEA=EMA9(DIF)，柱值=2×(DIF−DEA)；RSI14/ATR14沿用现有已明确测试的Wilder种子口径；BOLL20/2用总体标准差（`ddof=0`），带宽 `(upper−lower)/middle*100`。保留精确参数和预热证明。尽量取得250个观察值，但不把250作为所有规则硬门槛：MA20需20、MA60需60、RSI14需15个收盘、ATR14需14根；MACD展示预热长度并要求已审核的可靠历史策略，不声称首个EMA样本已可靠。不虚构通用策略阈值。ta-v1保持不缩放。独立v2黄金测试须证明相同有效输入下DIF/DEA相等且柱值恰为两倍。

## D06. 普通信号与执行生命周期（`daily-plan-monitor`）

确认仅消费官方完整日K线，创建持久发生记录：`signal_id`、策略lineage、规则ID、证据指纹、`confirmed_trade_date`、不可变计划数量、原文/审核身份及下一交易所时段日期。形成中收盘、盘中触价或五分钟结果不能确认。在有效窗口导入的既有确认信号，经核验后保留原确认日期；审核/更新不得额外等一天。

执行窗口为下一交易所时段开盘至该时段收盘；收盘即过期，收盘重放不能发送新可执行普通指令。利用既有已核验实时目标检查最新真实报价：仍在对应区域、原确认按已审核失效策略仍有效、无高优先风险，并重核当前模拟库存、T+1可卖、100股模拟单位、固定模拟规则及未消费信号量。离区不追价。同窗口重新入区，仅当原信号未因其他原因失效时恢复就绪，不能产生新指令数量。

普通持久状态为 `CONFIRMED`、`READY`、`SIMULATED`、`INVALIDATED`、`EXPIRED`；发送/已读状态独立。READY提醒不自动改仓。一次成功模拟只消费一次完整不可变计划量；`simulated_qty` 仅为0或 `planned_qty`，绝无部分余量。过期撤销未消费权限，不抹模拟回执。删除日线订单状态 `PARTIALLY_FILLED`、`FILLED`、`EXECUTION_UNKNOWN` 及券商对账逻辑，不允许改名保留同一子系统。

一次确认仅授权一笔计划数量。换日期、辅助输入false/true抖动、同窗口重入区、重启、重新启用、替换版本、发送重试均不是独立信号。规则需显式审核独立信号策略：在更晚完整交易日出现指定重置/回踩条件，再于其后完整交易日形成新确认；或由人工核验独立事件事实，指明新结构/证据与前一信号。仅“条件持续成立”不能重新布置。策略null/缺失阻断重复买入。跨版本保留发生记录lineage及消费量，不能借新版本把同一证据再用一次。仅当显式核验lineage/语义等价，才可将仍有效发生记录带到新审核版本，并保留原日期数量；否则只作历史展示，不给新额度。

节假日样例使用注入的已核验日历：周五确认、周一休市、周二开市 → 仅周二执行。若股票周二全天停牌，则不执行，剩余权限周二收盘到期，不顺延复牌日。若部分时段停牌，仅周二窗口内已核验可交易目标可用。日历缺失不安排日期。重启/迟到数据可恢复状态，但过期后不得发送历史可执行普通指令。

## D07. 风险分支、范围与持续性

先风险后普通动作。`SEVERE_TECHNICAL`优先于已确认 `ORDINARY_TECHNICAL`；合并已生效义务时不得增加某bucket目标保留量。高优先分支不能意外取消低优先分支已确认的减仓。普通执行不能把相关未知风险当作无风险。风险事实/指令独立于成本盈亏和辅助指标过滤。

| 分支 | 确认与最早执行 | 必需范围 |
|---|---|---|
| `ORDINARY_TECHNICAL` | 首次官方收盘满足已审核风险比较即停止新增。**下一交易所时段的官方收盘**仍低于同线确认退出，最早再下一交易所时段执行。不要求收盘更低、量更大或MACD更差。确认前收回进入观察，不自动恢复买入。 | 显式先处理TACTICAL，最新新增优先；仅在CORE持有结构明确失效且审核后可涉及CORE。必须给出CORE/TACTICAL各自目标保留量。 |
| `SEVERE_TECHNICAL` | 首个完整官方日收盘已核验实质结构失效**且**量价恶化 → 下一交易所时段。不强制第二收盘，不虚构通用跌幅/放量/影线阈值。 | 已核验失效结构、恶化证据、影响bucket和确切目标保留量。 |

若LT38.18，38.00后下一时段38.10仍确认普通退出，不能因反弹放弃；等于38.18不算低于。若LTE则等于也算，必须显式选择。保留首次破位时的线和比较符，下移风险线或改计划不能抹除待确认/已确认风险。权息等效换算须证明经济风险不变。

若下一交易所时段因已验证停牌没有有效官方个股日线，不制造第二收盘，也不把以后K线称为“下一日”。继续禁止新增并展示待确认。源模板没有决定复牌后是否延续首次破位，必须显式审核 `suspension_confirmation_policy`：`RESUME_FIRST_CLOSE`在复牌首个有效收盘仍低于线时确认；`RESTART_ADJACENT_PAIR`把复牌低于线收盘视为新的相邻两时段确认对第一日。两者均无默认值。缺选择时仅阻断此时序判断，不阻断独立严重技术风险升级。未核验缺K线属于数据恢复，不等于停牌。UI须展示并测试两个选项；实际计划取值由用户回答决定。

一旦确认，风险跨反抽、普通窗口到期、重启和版本替换保持，直到持仓达到已审核目标，或**单独审核的重新评估**记录新证据确认原原因消除。退役当前计划不能虚构风险解除；历史未完成风险保持可见，替换计划须承接或显式重评。明确停用监控按既有控制停止新监控/发送，但保留未完成义务记录。普通提醒确认、泛化“风险已清除”开关或改计划不能清除此义务。

风险模拟数量按各适用bucket超目标数量重算，受权威模拟T+1可卖及固定模拟规则限制，向下取完整100股且不能低于保留目标。用户确认当前提供的完整风险模拟量；一个事务可执行服务器推导的两bucket内部扣减。以后解锁的交收批次属于剩余义务的新当前模拟，并非订单部分执行。TACTICAL最近新增优先，但不得拖延该分支已要求的CORE退出。记录立即可执行量、暂不可执行量及其下次条件（交收、停牌、流动性或可卖未知）。风险已知而持仓未知时仍发风险提示，数量未知；不得虚构0或隐藏风险。跌停/流动性不足且未认证可交易时不授权模拟。风险退出不要求处于普通价格区间。

## D08. 模拟持仓与原子整手交易

模拟存储与真实/旧库存隔离。使用既有通用daily `POSITION` 和 `SIMULATION` 记录，承载最小模拟持仓、单调daily库存revision及T+1/策略顺序必需的取得日期批次。不把模拟仓位/回执回写共享 `PositionLot`、`PositionInventoryConfirmation`、opening balance或旧库存revision/sync路径，不改变这些旧能力。这是最小模拟状态，不是券商账本或新存储服务。日线UI明确称模拟持仓，与计划目标区分。初始化仅确认100股整数倍的CORE/TACTICAL聚合量，两者之和为总量；只需股票、bucket量及当前库存revision，时间/日历证据由服务器提供。期初基线表示在设置前已交收的模拟持仓，在初始化当日或之后第一个认证开放时段可卖；缺认证时段则可卖未就绪。绝不自动复制真实/旧持仓。重复相同期初为幂等而非加仓。初始化不能覆盖非空模拟持仓、重分后续批次、删除历史或重置信号消费；冲突既有数据显式报冲突。不接受客户lot ID、allocation数组、券商证据、可卖断言或委托完整性字段。T+1可卖从模拟取得/交收日期与认证日历推导，不猜工作日。旧数据交收/分类未核验时显式不支持/未就绪，不能虚构证据。

买入容量 = `max_qty - simulated_total_qty`。新日线链路没有订单、待成交量、执行未知余额或占额。模拟实际总量200、max300时，满足条件的BUY100原子成功到300，下一BUY阻断。普通SELL只扣已交收TACTICAL，不碰CORE。风险SELL遵守适用已审核bucket目标，内部优先最新加仓。服务器选择合格模拟取得日期批次，用户不看也不填写内部扣账指令。当日模拟买入按T+1仅在下一个认证交易所时段可卖。

接受显式模拟命令后，完整提供量必须为正100股整数倍，一次全部成功或零变更。普通量必须等于原未消费信号计划量，容量/可卖只够部分时阻断而非缩量。风险命令必须等于所请求revision下当前完整整手风险动作，保留目标与T+1；不可用敞口仍是风险义务，不是订单余量。服务器使用当前已核验报价及服务器时间，回执标注模拟，不冒充券商成交证明。不要求提交券商成交价/时刻/证据报告。报价/日历/风险/持仓权限不足是零变更业务拒绝，不是待处理模拟订单。

持久化服务器生成 `simulationId`、计划/审核绑定、精确cause/revision、方向、数量、模拟价/时间及库存前后revision。复用既有daily存储，使用独立 `SIMULATION` 回执及带模拟标记的 `POSITION` 记录，采用独立simulation ID，不重解释旧券商持仓payload。未发布0024 CHECK/model可原地新增kind用于新的开发数据库，不追加迁移系列、不改已发布迁移。既有不兼容开发表结构在变更前显式返回不支持，不自动改写。不需要订单实体、券商标识或状态机。原子幂等和普通信号已用权限跨重试、重启、改计划及plan_id保持。模拟回执、模拟持仓、消费量与库存revision一起提交，任何失败全部回滚。提醒发送、已读、提取、审核及启用不能创建回执或改仓。现金余额和单独手工/不关联交易流程不在本轮清理范围。

## D10. 原子运行时、提醒与恢复

在真实生产调度器/`runtime/service.py`、官方收盘和盘中目标、上下文组装、持久化、投影、读取视图与提醒处新增类型化分派。只有纯计算器不算完成。确认评估身份含计划哈希、执行版本、规则/分支、官方交易日期及捕获的启用/审核/数据revision。持久信号身份还包含策略lineage和证据指纹，使修改revision不能重置消费量。执行检查引用已有发生记录及当前目标，不能创建第二笔计划数量。

同一短unit of work中：声明目标，重核当前计划/审核、日历/数据权威、库存/事实revision，保存证据/结果/状态转移及outbox事件。任何不符均回滚重评；外部IO在事务外。唯一发生/模拟key防竞态重试。模拟命令约束飞行中的评估。分别持久化两种技术风险和普通发生记录，不复用旧 `RiskState` 的恶化门槛。新提醒变体保留原信号/确认日期、当前可执行量、到期、风险范围和证据，不塞进五分钟负载。

普通发送资格重查当前窗口、计划绑定、风险和已用数量；过期队列提醒转历史。风险提醒跨日保留锁定风险身份，仍区分当前可交易量与未完成义务。发送失败重试相同event。重启从持久状态恢复待处理风险和信号消费，不恢复已消费模拟量。保留期不得早于相关计划/执行历史擦除去重/消费记录。能力禁用时返回不支持，不静默运行另一模式。

## D11. AI提取与人工审核（`daily-plan-review`）

仅新增 `plan-extract-v7`；冻结v1–v6模板、生成schema摘要和解析器。现有provider/model配置保持。日线提取UI显式选择所支持目标契约，不静默改写明确配置的旧prompt版本。运行时不引入第二次AI决策。

候选保留全部原文分句、精确Unicode跨度、类型化字段值/单位及ALL/ANY结构绑定。技术字面量可绑定Schema 4产品契约；交易值、数量、CORE建议、参考模式、风险范围、重置和有效期必须来自原文或显式人工补充。模板定义不会自动成为另一段历史计划已经声明的值。范围内技术歧义保留null与说明所需证据的必审项；范围内不支持语义保持可见。不得把“明显缩量”变成0.8、“企稳”变成两天，或把全部持仓当TACTICAL。未解析残余语句不能用通用忽略/确认处理掩盖。

基本面和公告审核条款保留精确原文跨度，以 `BACKGROUND` 可见展示，明确说明由用户在生成计划时审核、排除在日线监控之外。不映射到可执行路径，也不得仅因原文出现这些条款而形成 `UNRESOLVED`/`UNSUPPORTED`、缺失事实、审核或启用阻断。不要求公告核验完成确认。混合条款须分别保留技术条件及其所需证据与排除文字，不得把整条混合语句归入背景以掩盖技术要求。服务端须验证此区别，并拒绝把基本面条款绑定到技术事实/前提。范围排除不代表已证明经营信息真实。保持旧分句器不变。使用仅限日线的狭窄处理，绑定精确原文哈希、分句/跨度及固定的基本面范围排除理由；仅有文字理由或任意 `BACKGROUND` 标签不能授权压制技术策略。保留并审核技术剩余跨度及其路径，包含混合句。无mapping预览必须提供相同排除路径，不要求基本面核验；批量人工补充须保留排除，只绑定实际技术路径，不能把所有分句绑定全部字段。采用确定性跨度/覆盖校验及显式审核，不增加LLM分类器或宽泛的关键词语义引擎。

服务端重新推导分句、映射/证据哈希、必填路径与跨字段约束。人工补充绑定当前精确候选，显式区分建议交易策略与模拟持仓初始化。内容审核不能登记持仓、清风险、证明官方数据或声称模拟交易。非法/伪造/过期映射和孤立补充必须拒绝。非空部分候选属于成功提取供审核，不属于可执行计划。

审核界面对照原文证据、候选语义、缺项、三个证据维度、区间端点/AND/OR、固定/动态、日历顺序、CORE保护、风险目标及原子整手模拟行为。完成后由服务器签发审核绑定。启用要求精确当前版本/内容/原文/证据/审核revision并执行单独显式动作。后续任何修改都须当前内容重审，不自动继承旧绑定；历史原文/审核证据保留。
