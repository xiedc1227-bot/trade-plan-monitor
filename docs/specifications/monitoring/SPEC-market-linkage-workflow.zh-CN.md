# 规格：market-linkage-workflow

状态：APPROVED — 用户于2026-10-24批准六项决策及规格，并明确授权按任务清单实施。实施进度按验收记录；未完成任务不代表已交付。
实施证据维护在[验收报告](../../verification/2026-10-24-market-linkage-p0.zh-CN.md)。

## WF01 — 目标与兼容性

让四个政策模块进入真实单一计划流程与隔离回放。新联动计划采用MLP-D01提议的 Schema 6／`condition-plan-v2` 契约。现有 Schema 5 固定数量计划保持原义；Schema 1–4历史解码／回放保留原字节／哈希。不自动升级已保存／活动计划，不增加计划类型选择器或第二套流程。

契约任务MLP-T01须盘点准确的持久化、提取、准备／更新、API、运行时、通知和回放读写端，在依赖实施前定义带版本的规范载荷、摘要和兼容样例。不具备新能力的读取端应明确拒绝新联动载荷，不能删除字段。回退可以禁用新联动启用，但须保留新证据与旧流程；不能把新政策解释为固定数量。数据库变更采用增量方式，先在临时数据库测试，再按单独授权升级用户数据库。

## WF02 — 提取与审核

仅原文明确授权的联动生成 `market_policy` 和 `quantity_policy`。提取或绑定完整大盘状态定义、相对强势定义、S0／S1／S2、Q0、系数、数量规则及P1例外边界。预设版本代表展开后的政策；有预设名称也不能缺策略来源。来源解释、原文字面提取和产品常量保持可区分。服务端派生板块身份、与股票核对并绑定派生依据；AI不能选择其他基准。

AI返回草稿和证据，不能批准。审核展示实际政策值、全部路径效果、缺项及拟议来源解释。缺Q0、缺S0定义、缺必要比较符／窗口、时序错误、固定与政策数量混用、删除限制、伪造人工事实均阻止完整审核。已完整表达的限定范围技术事实可以在运行时仍未知。两类P1例外可明确禁用地保留在其他方面完整的计划中，禁止删除其含义。

审核绑定当前原文、候选内容、政策／公式版本及证据修订；任一编辑使批准失效。保存不启用，启用须明确操作。AI传输／JSON解析成功不等于计划可执行。准确区分处理错误与业务问题。

## WF03 — API、界面与运行时

扩展现有操作族：`/api/v1/plan-extractions`、`/api/v1/plan-drafts`、`/api/v1/plan-review-previews`、`/api/v1/plan-review-confirmations`、`/api/v1/plan-activations`、`/api/v1/plan-runtime/{symbol}` 和 `/api/v1/simulated-trades`。本提案无需新增端点。契约盘点须在实施前记录请求／响应的增量变体及所需生成OpenAPI／TypeScript变更。全部权限由服务端决定。

`/plans`审核和运行视图展示：参考指数／日期、大盘实际操作数／状态、个股／指数收益和强弱谓词、选中S0／S1／S2、Q0／系数／候选／固定数量、剩余额度、原因和证据时间。区分计算与权限；授权数量为零时不提供零股交易。区分待审核、语义不支持、数据不足、条件未满足、P1例外阻断、信号过期和额度不足。普通用户流程隐藏技术格式标识。

生产组合按活动规则获取准确的个股／指数证据，共享兼容的指数请求，遵循既有工作者限制和恢复机制，完成证明绑定双方证据集。非联动独立提醒不依赖缺失指数或模拟库存。数据库事务内不进行网络I/O。启用、计划、审核、来源修订或必要事实变化时，拒绝过期计算及待发送提醒资格。明确整笔模拟在原子事务内重新核对报价、日历、可交易性、T+1、CORE、风险、库存修订、上限、信号和幂等性。

## WF04 — 回放、证据与边界

回放冻结原文版本、政策定义、日历、个股／指数数据集及复权／事实修订，使用与实时监测相同的分类、强弱、选择和数量函数及截止时间规则。不得把当前信息性指数头记录当作历史证据。指数依赖进入回放准入，不能静默省略；历史日历／供应商不可用时如实拒绝依赖范围。

每次判断记录使用证据、选中路径、条件、Q0、系数、候选与授权数量、额度、原因和信号身份；零交易结果也记录原因。未来来源变化不得改变早期事件身份。既有单任务排他、取消、结果原子发布、保留政策和运行时限制保持不变。按需采集应落在既有500日线观测、50叶子、深度4边界内；超出时明确失败。
