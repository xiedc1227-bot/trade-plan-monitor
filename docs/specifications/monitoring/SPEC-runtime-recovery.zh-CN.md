# 规格：runtime-recovery

> 来自已批准提案 D2–D6 / A03–A10，授权日期 2026-09-21。英文为规范输入，本文件为中文副本。依赖 provider-contract。
## 目标

单一运行所有者在任意时段重启后，仍能核对并恢复本地与行情源事实；任何交易决策都不得绕过准确依赖、激活身份和时效校验。
## 契约

- 本地配置/存储启动先于行情工作。协调器在依赖异常时持续运行，包括降级启动和未知日历；这些异常不消耗三次崩溃重启预算。
- 协调器执行小型、合并的范围工作单元，单一所有者，队列最多 32。轮转处理到期恢复任务，避免异常范围饿死其他范围。本地维护唤醒间隔最多 30 秒，不代表每次都请求行情源。
- 临时错误重试使用 30/60/120/300 秒；共享行情源冷却至少 300 秒；每个 operation 每 300 秒最多一次权限重查，进程替换后仍遵守。缺少凭证不产生物理请求。
- 保持物理并发 1、请求启动至少间隔 1.25 秒、超时 15 秒、立即重试 0、退避键最多 64。取消操作不得在线程真正退出前释放物理槽位。
- 根据权威交易所日历冻结已完成截止点：首分钟之前不要求不存在的当日分钟；午休保留上午覆盖；收盘后重建到期义务；休市日使用前一已完成数据。未知日历安排重试，不虚构交易日。
- 就绪要求已持久化数据精确覆盖所需范围。空/部分/仅当日响应不能补齐历史日期；未来行不能满足更早截止点。日期切换重新计算目标。
- 从符合条件的交易日期减去已提交收盘身份，发现漏执行的旧计划收盘任务，包括完全没有 CLOSE_PENDING 的情况。遵守真实激活时间/revision，按时间重放状态转换。所需历史状态未知时，仅阻断受影响计划。
- 参考数据键包含计划类型、所需数据、激活身份与 semantic revision，而不仅是证券/日期。提交时捕获的 generation/激活身份必须仍匹配。
- 两类计划保留不可变评估身份。交付资格与每个结果/outbox 事务原子保存，置于规范哈希之外。尚未发送的盘中操作性提醒在来源截止点 + 90 秒后失效。
- 风险通知依据状态有效性，不统一套用 90 秒。每计划恢复屏障在该计划追平当前目标前暂停风险交付，发送前再次检查最新风险/激活身份。HOLD 不等于终态抑制。过时历史提醒保留审计；外部发送结果不确定时无法保证恰好一次。
- 关闭时先停止准入、等待自有任务/线程退出，再关闭存储。无效替换配置阻断相关工作，不静默回退。
## 注入式增量接口

- `RecoveryCoordinator` 在整个生命周期内只拥有一次 `run(stop=...)` 调用。它同步读取本地 `requirements(now)`，领取一个 `RecoveryTicket`，等待一个有界 `execute(ticket)`，重新读取需求，再仅接受仍匹配当前需求的结果。这些回调不授权评估或发送。`wake()` 是所属事件循环内的合并通知，在下次读取本地快照前清除。
- `execute` 返回 `READY`、`RETRY` 或 `BLOCKED`；`PENDING` 是调度器内部状态，不是工作完成结果。执行或时间跳变期间已过期的重试时间推迟到下一次 30 秒维护唤醒，不导致崩溃或空转。每个工作单元主动让出事件循环。可中断等待除注入的墙钟截止点外，另有单调时间的 30 秒上限。
- 需求 revision 必须随相关激活、配置/凭证可用性、依赖或语义变化而变化。未变化的 `READY`/`BLOCKED` 需求保持合并；单纯维护 tick 不重置权限。预期行情源错误返回类型化结果；存储与程序错误仍作为故障处理。
- 停止操作禁止下一次准入，并等待直接持有的回调完成。取消向该回调传播，且禁止复用协调器。这不代表行情线程已退出：生命周期仍须先关闭准入并等待请求控制器 `aclose()`，才能关闭存储或替换运行实例。
- `RecoveryService.recover_scope` 针对冻结的 `RecoveryTarget`、最多 240 个所需分钟身份和已提交覆盖读取器，一次最多获取一个证券。物理请求开始前及就绪判断前重新校验时间，持久化前过滤未来行，并回读准确的已提交覆盖。当日接口不能补齐更早日期。其 `ready` 仅表示分钟证据，不表示计划/业务就绪。`PERSISTENCE_FAILED` 必须进入生命周期故障处理，不可无休止按行情源重试。
- 若本地校验在行情源 I/O 前拒绝已排队的目标，`RequestNotStartedError` 经过请求控制器直接传播，不记为行情源成功或失败。现有退避次数和权限阻断必须保留；目标跨日不等于行情源恢复证据。
- 这些接口在 RR010–RR014 及提醒门禁完成前保持注入式/离线切片，不启用生产恢复，也不发送历史提醒。

### 遗漏收盘发现增量

`discover_missed_closes` 是纯粹、注入式、按计划隔离的发现函数，不是执行器或数据库权威证据读取器。`MissedCloseScope` 绑定旧版计划、版本、实际激活 revision/时间及同一个观察时间。每次最多扫描 32 个自然日，默认从实际激活日期开始；`next_window_start` 只标识下个窗口。请求后续窗口不证明被省略的前缀已完成。窗口结束或所有行都是 `PROVEN`，均不代表业务恢复完成或允许发送。结果只描述该冻结观察时刻，不是持久化进度检查点：激活/证据变化时重新证明，新义务到期时重新扫描相关日期。

将计划的历史激活策略、权威交易所开市日期及实际激活不晚于 15:00 来源截止点取交集。收盘义务在既有首次计划尝试时间 15:20 到期，包含等号。已过期策略仍可能存在历史收盘义务。不得推断周末休市，也不得将缺少待处理标记作为完成证据。日历或完成证据缺失保持 `UNKNOWN`；存储/程序异常直接传播。

`OfficialCloseCompletion` 区分经确认的 `ABSENT`、已归属的 `PROVEN` 已提交发生记录和 `UNKNOWN`。证据须绑定准确的正式收盘身份、实际激活及观察时间。已证明的发生记录要求完整匹配的结果和适配器对已提交发布的确认；只有哈希的认领或其他激活的认领，不等于不存在，也不能变成已证明。该纯函数验证绑定，不证明持久化发布/激活来源。已认领但被阻断的结果仍不证明历史业务状态完整。

发现结果保持日期顺序：同一窗口内，缺失收盘后出现非缺失证据，或未知早期证据后出现已证明记录，均标记可能的因果历史缺口。回放前，调用方还须证明跨窗口连续性。现有评估使用当前持仓/风险、单调前进的决策头及风险转换中的恢复写入时间；简单按日期排序调用，不等于历史重建。持久化证据读取器、因果状态重建、执行及生产装配仍属 RR009 的独立后续工作。发现过程不改变行情请求、事务、通知或生产默认行为。

### 持久化遗漏收盘证据增量

`LegacyCloseRecoveryReader.discover` 在一个新建、自有的只读快照中，将扫描器与 SQLite 证据组合。它从当前激活指针、状态为 `ACTIVE` 的规范计划版本及完整的有界激活事件/审计链推导旧版范围，不接受调用方猜测的激活。它与旧版提醒来源读取器共享既有审计链及监控序列高水位校验。缺失/未激活/显式计划/无效范围返回类型化未知，而不是经证明的空结果。新证据不得晚于观察时间。存储故障直接传播，不刷新或提交调用方状态。

读取器获取有界窗口内已持久化的 SSE 日历；缺失或损坏行保持未知，不使用工作日推断。每个准确收盘认领都与完整规范结果及确定性快照发布核对。发布必须属于推导出的当前激活区间，不能只匹配计划哈希。仅哈希认领、不完整/损坏/过大的结果及错误激活的发布均保持 `UNKNOWN`。已证明的发生记录不证明持仓批次历史、历史业务就绪，也不授予回放/发送权限。

证明 `ABSENT` 时，认领和结果必须都不存在，且孤立发布检查不得发现矛盾证据。按需执行的单证券快照发布扫描，每个窗口只执行一次，最多读取 1000 行及额外一行溢出哨兵。它使用每条发布的结果哈希和请求身份重新计算规范事件 ID，不按恢复写入时间过滤。发布历史损坏、过大或溢出时，原本可能缺失的候选仍保持未知；不会抹去能直接证明的准确发生记录。正常长期运行的盘中历史也可能耗尽这一保守回退预算。在生产启用承诺超出此证明预算仍能推进前，仍须建立直接持久化来源；不得静默扩大或取消上限。激活事件和审计各自保留独立的 1000 行证明预算。

全部证据只属于该数据库快照和观察时刻。激活、日历、目标或 generation 变化后，以及后续修改/准入前须重新读取。历史状态重建、跨窗口连续性、按时间顺序执行及生产集成仍属后续工作。既有提醒来源读取器在后来停用或重新激活后，仍可证明原始归属；共享校验不会将来源证明变成当前交付权限。

### 持仓批次变更证据增量

版本 1 快照字段固定为：`id`、`symbol`、`bucket`、`quantity`、`remaining_qty`、`acquired_trade_date`、`cost_fen`、`related_alert_id`、`closed_at`。未来 DTO 结构变化不得静默重新定义这个已存储版本。

未来的 `POSITION_BUY_RECORDED` 和 `POSITION_REDUCTION_RECORDED` 审计在既有详情中追加 `recoveryEvidence` 对象。其 `schemaVersion` 为 1；`effectiveTradeDate` 是已接受且规范化的买入/减仓日期，而非审计写入日期。买入的 `before` 为 null，减仓的该字段为完整变更前 `PositionLotRecord` JSON 快照；`after` 为完整变更后快照。快照字段沿用既有记录的 snake_case 名称及 JSON 编码。既有顶层 `bucket`、`quantity`、`symbol`、动作/实体元数据、批次哈希算法、监控事件身份和变更规则不变。

这记录的是已接受的业务事实，不独立证明交易所开市，也不证明完整历史持仓。`created_at` 仍是审计写入时间；`closed_at` 仍是既有清仓写入时间。延迟或乱序录入不使这些时间等同于 `effectiveTradeDate`。审计证据、批次变更、监控事件和持仓 revision 保持同一事务。回滚不会提交该次变更的任何部分，应用幂等重试不追加另一条审计。不增加 API 字段、迁移、行情请求或通知。

不改写或猜补旧审计行。其缺失的来源日期/完整状态对未来历史重建仍为未知。后续读取器消费新证据前，必须验证版本、动作/实体绑定、准确的前后哈希和变更不变量，再独立证明逐批次顺序及完整持仓覆盖。旧哈希覆盖批次快照，不覆盖新增日期/对象：它们是一致性检查，不是有效日期的真实性认证。仅有写入器不授予历史状态、回放或发送许可。期初余额、持仓确认历史、风险来源有效日期、旧版证据解码及按时间顺序重建仍属独立后续工作。

### 持仓批次证据解码增量

`decode_position_lot_mutation` 是单条审计的纯粹、有界解码器，输入为动作、实体类型/ID、前后哈希、详情 JSON 及写入时间戳。它返回不可变的已验证变更或类型化 `UNKNOWN`，区分旧版证据缺失、版本不支持和内容无效。`VALID` 仅表示变更证据内部一致，不证明已提交发布、有效日期真实性、完整批次/持仓历史、时间顺序，也不授予回放/发送许可。不执行数据库、行情或通知操作。

解析前要求详情为文本且不超过 16384 个 UTF-8 字节。拒绝重复 JSON 键、非标准数值常量、多余/缺失字段、强制转换的数字/布尔值、无效日期和无时区时间戳。版本 1 严格沿用写入器固定快照字段、既有可接受标识/证券/类别、正数量/成本及合法剩余/关闭状态。不强加 UUIDv4、固定 100 股单位、写入日期等于有效日期，或清仓时间戳等于审计时间戳。时间戳契约验证表示形式，不证明时钟单调性或交易所日历权威性。

批次/实体 ID 接受 1–128 个无首尾空白字符，包括既有自定义 ID 工厂产生的非 UUID 标识；关联提醒 ID 保留仓储的 1–36 长度限制。首尾空白保守判为无效，不静默裁剪。这不扩大变更准入：既有批次查询/减仓长度上限仍为 36。数值字段包括版本必须是真正整数，不能是布尔值、浮点数或数值字符串。日期必须往返转换为相同 ISO 日期；时间戳使用既有 ISO 日期时间表示或其 UTC JSON `Z` 形式，不接受宽松的其他分隔符/紧凑日期。分配 UTF-8 字节前先检查字符长度；损坏 Unicode 和过深 JSON 嵌套返回无效证据。

要求批次身份、证券和类别在行元数据、顶层详情及前后快照间一致。按既有表示重新计算批次哈希，不改变算法或时间戳偏移。买入没有前状态/哈希，初始剩余数量等于正操作数量/原始数量，未关闭，有效日期等于买入日期。减仓从未关闭批次开始，保留全部不可变字段，剩余数量准确减少正操作数量，有效日期晚于买入日期；剩余为零要求关闭时间戳，剩余为正禁止关闭时间戳。不得用写入时间填补缺失的旧版证据。后续数据库读取器仍须在加载前限制行数，验证已提交链条/当前行/发布一致性，并独立证明覆盖完整性。

### 持久化单批次历史增量

`PositionLotHistoryReader.read(lot_id, max_mutations=256)` 自行管理全新的应用 SQLite 会话及单个显式 BEGIN 读取快照。上限必须是真正整数且在 1 至 1000 之间；参数无效或工厂返回非全新会话时抛错，存储故障向上传播，证据缺失/版本不支持/内容无效或历史预算耗尽返回类型化 `UNKNOWN`。不可变 `PROVEN` 结果包含当前批次、按哈希链排序的全部变更、对应发布序号及快照内监控序号高水位。它仅证明该批次的已存历史，不证明完整持仓、来源日期真实性、历史适用性，也不授予回放/发送许可。

工厂必须将全部证明表绑定到同一个按应用要求配置的 SQLite 引擎，而非外部持有的连接/事务或路由数据库。任何证明查询前拒绝无效绑定，不刷新、提交、回滚或关闭调用方事务。仅有新的 Session 对象并不能证明事务归属或所见数据已经提交。

读取准确批次/实体范围的全部审计，不按动作筛选。要求恰好一个买入根节点、消耗全部记录的唯一连续链、严格正减仓量，以及与严格解码的原始当前行一致。拒绝重复、分叉、孤立记录、缺口及末端不一致。不得按审计 ID、写入时间或有效日期排序；既有准入允许延迟登记，因此连续减仓的来源日期可能倒序。顺序执行仍须另外解决来源有效时间语义。

读取该聚合的全部发布，不使用按近期过滤的回放页。要求与既有确定性持仓事件 ID 一一对应，存储载荷/身份为准确规范表示，事件类型/版本、证券/状态及审计发生时间一致。正序号必须沿哈希链严格递增且不超过快照高水位；允许其他业务造成的全局序号间隙。与其他事件类型发生聚合 ID 冲突时保守返回未知。七天回放窗口不会删除已存事件，也不是证明截止点。即使审计和当前行一致，发布实际缺失时仍保持未知。

两项历史查询各最多获取上限加一条溢出哨兵。详情上限为 16384 个 UTF-8 字节，事件载荷上限为 4096；解码前通过 SQL 截断及存储类型/长度检查，防止超长值或内嵌 NUL 隐藏尾部数据。同时限制元数据/当前行文本长度，避免 ORM 日期/类型强制转换。通过 `0020_lot_history_indexes` 增加非唯一索引：审计 `(entity_type, entity_id)` 与监控 `(aggregate_id, sequence)`。索引支持范围查询而非整表扫描；迁移不改写记录，降级只移除这两个索引。仅在临时数据库验证升级、重复升级、降级保留数据、元数据一致性及查询计划。不包含真实数据库迁移、新写入器、生产消费者或默认切换。

## 显式风险交付规则 — 2026-09-21 已批准

用户明确批准按最新状态处理未发送的 `RISK_ALERT`：恢复追平后，仍有效的风险可以发送；已解除的风险保留记录但抑制发送；信息不足保持非终态 HOLD。这不改变评估器，也不创建新的提醒意图。

注入式纯分类器使用原始且已验证的 `ExplicitAlertEvent`、权威当前计划/激活、最新且已验证的 `ExplicitEvaluationResult`、请求的已完成目标、运行 generation 及类型化恢复屏障证据。`active=None` 表示权威确认不存在，绝不表示读取失败；缺失/不可读的权威信息不得伪装成不存在。屏障绑定证券、计划哈希、激活 revision、generation 和准确目标，要求无待处理状态转换义务且已协调到该目标。该值是未来持久化屏障重建的接口，不表示当前已存在该持久化能力。

| 按顺序检查 | 交付结果 |
|---|---|
| 权威确认计划停用/替换/重新激活/过期，或原始规则/动作不匹配 | `SUPPRESS`，保留审计原因；不将旧计划的跨日例外扩展给显式计划 |
| 屏障缺失/不匹配/不完整、generation/目标过时、无最新结果或证据来自未来 | `HOLD`，不得终态抑制 |
| 当前结果未准确匹配激活计划/哈希/revision/证券/目标/规则/动作 | `HOLD` |
| 所选风险规则出现超出条件/安全证据的未知或矛盾阻断 | `HOLD` |
| 必要条件/安全证据的任一根节点结果为 `MISSING_INPUT` | `HOLD`，包括已知假根节点与未知根节点并存的情况 |
| 否则必要条件/安全证据的任一根节点结果为 `UNSATISFIED` | `SUPPRESS`，风险已不满足 |
| 全部必要根节点结果是 `SATISFIED` | `ELIGIBLE`；发送前仍由交付流程再次校验持久化激活/屏障/状态 |

只有激活规则本身未声明安全条件时，缺少安全证据才是中性。保留评估器既有的三值条件树语义：即使某子节点缺失，`ALL` 根节点也可能为假；即使某备选节点缺失，`ANY` 根节点也可能为真。交付判断不递归推翻这些根节点结果。评估器对应的 `CONDITION_UNSATISFIED`、`SAFETY_UNSATISFIED`、`CONDITION_INPUT_MISSING`、`SAFETY_INPUT_MISSING` 阻断跟随其证据结果，不统一视为 HOLD。其他规则的 BUY/SELL 阻断不重新定义当前风险规则。`ONCE_ALREADY_EMITTED`、`TARGET_ALREADY_EMITTED` 及空 `signal_intents` 仅涉及重复发出，不表示当前风险解除。交付资格独立于规范结果/提醒字节与哈希。持久化屏障重建及发送集成仍各自受门禁约束。

## 旧版风险交付规则 — 2026-09-21 已批准

用户批准只补发仍适用于恢复后最新风险状态和当前目标持仓的旧版官方风险提醒。已被后续状态替代的提醒保留审计，但不逐条重放。此批准不改变风险/价格/指标公式，也不授权真实通知发送。

- 判断适用性前，按时间顺序恢复全部到期官方收盘任务。待处理收盘表为空不证明恢复完整。原始激活归属、所需历史证据、当前持仓或权威日历缺失时保持 `HOLD`，不猜测当前状态。
- 将原始事件绑定到其已提交结果和真实激活 revision。旧版载荷不含该 revision，因此仅匹配计划哈希不足以证明身份。权威确认停用、替换或重新激活的身份被抑制；身份不可读时保持 `HOLD`。
- 仅为 `RISK_BREACH` 保留既有跨日例外：同一活动身份，事件创建日期晚于 `trading_date`，且激活配置在该历史日期有效。两种退出提醒均不获得该例外。
- 风险已解除（`CLEAR`）或已属于另一轮跌破时，抑制旧提醒。已知后续待卖出、待可卖或风险解除阶段替代更早的跌破提醒。完整的普通 `WAIT` 不得使早期阶段重新有效，也不单独证明风险解除。特别是 `RISK_EXIT_READY` 不一定更新 `RiskState`；仅检查 `risk != CLEAR` 不安全。
- 退出提醒交付必须仍指向同一适用原因、目标持仓批次、仓位类别和数量。按照既有评估器的持仓优先级，检查权威当前持仓与可卖事实；不得为旧提醒改换目标或替换数量。已证明耗尽/被替换/不再适用的目标被抑制；适用性未知时保持 `HOLD`。
- 用户另外批准：跨交易日重复出现的相同 `RISK_EXIT_READY` 指令只补发最新一次。在已证明为同一计划/激活、跌破原因、目标持仓批次、仓位类别和数量的范围内，较新的已提交官方收盘提醒替代较早的未发送提醒。较早记录保留替代审计原因；恢复屏障通过后，最多发送仍适用的最新指令。按照原始官方交易日期排序，不按恢复写入时间排序。不合并不同原因、持仓批次、数量或激活 revision，也不授权在适用性未知时发送。
- 实现必须区分支持该指令的完整结果与缺失/阻断证据。旧版缺少 `signal_intent` 本身不是通用风险解除依据。盘中 `WAIT` 不替代官方收盘结果。后续官方收盘 `WAIT` 若无法证明退出指令仍适用，保持 `HOLD`，不自动保留或抑制该退出提醒。同一规范官方收盘身份不能同时存在原始结果与另一份不同的权威结果。不得从风险 `updated_at` 推断来源日期顺序，因为它可能反映恢复评估时间。启用旧版分类器或发送器前，仍须评审历史归属和当前适用性的证据判断。

本节记录已批准的业务规则与源码约束。显式与旧版的独立纯分类器使用注入的权威事实实现各自策略；旧版当前证据重建、持久化抑制和最终发送准入仍待完成。

### 旧版当前适用性接口

`classify_legacy_risk_delivery` 是注入式纯策略，不是数据库读取器或发送器。输入包括已证明/未知的原始来源、权威激活身份（含类型化未知，与 `None` 不存在不同）、`LegacyCurrentEvidence`、`LegacyInventoryEvidence` 及恢复屏障。任何永久抑制之前，先使用 `origin_plan` 与 `origin_result` 重建原始载荷；原始证据无效时，即使当前身份不同也须保持 `HOLD`。

后续读取器须通过权威交易所日历，认证请求的已完成目标在注入的 `now` 时刻是当前目标。活跃身份/当前状态/屏障/持仓的 `observed_at` 均等于该统一逻辑读取时间；调用方须重新读取并认证，不能给旧快照改时间标签。休市日的新快照可以沿用前一交易时段目标；风险没有统一年龄上限。调用方认证最新到期官方日期、没有遗漏收盘义务的完整已提交历史，以及普通 `WAIT` 期间保留的最新风险阶段。规范结果矛盾或证据未知/阻止时保持 `HOLD`。

持仓必须是当前、完整、按既有评估器优先级选中的目标，不能复制历史提醒/结果的持仓摘要。`settlement_trade_date` 是日历认证的 `now` 时刻适用交易时段日期，介于目标日期与当前日期之间。取得日期不能晚于该认证时段，休市日也不例外。可卖状态须符合 `acquired_trade_date < settlement_trade_date`；矛盾的 T+1 事实保持 `HOLD`。重复退出提醒的替代判断要求独立证明新 occurrence 的身份/指令、更新的官方来源日期，以及不晚于当前/屏障观察时间的发布时间。这些类型化值描述读取器的义务；纯分类器本身不建立日历真实性，不重建持久化当前历史，也不授予渠道发送许可。

### 旧版来源证据接口

只读来源读取器仅在现有已提交记录对原始计划版本/哈希、官方收盘评估身份/结果哈希、重建提醒语义及激活区间一致时，才能返回 `PROVEN`。采用持久化监控事件的 sequence 顺序，并以激活审计佐证，不仅依赖墙钟顺序。验证提醒和结果发布属于同一激活区间；同哈希重新激活属于不同来源。校验持久化 `MonitorSequence.last_sequence`，拒绝依赖超过该高水位的 sequence。原始激活还须满足既有评估器截止点约束：不得晚于官方 15:00 来源截止点或评估时间。该读取器只证明来源，绝不证明当前交付资格。

读取器持有全新的应用配置会话及单一读取快照，绝不刷新或提交调用方状态。双向核对激活/停用事件与审计，要求 revision 连续，且链末端匹配当前激活状态/活动计划指针，避免区间边界或尾部历史丢失后误将最后残存事件视为权威。这些当前指针用于证明链完整，不用于替换原始来源。每个证券的激活事件集合和激活审计集合读取上限各为 1000 行，复用既有回放行数预算但不使用其时间范围；检测额外一行后返回 `UNKNOWN`，不得将截断链视为完整。超出该有界证明的历史，后续通过直接持久化来源处理。

历史证据缺失、冲突或无法解析时返回类型化 `UNKNOWN`，由交付适配器保持等待；存储失败仍作为可见故障，不伪装成权威不存在。迁移 `0006` 未重建历史激活事件，`0007` 未重建完整激活历史，`0009` 可能保留仅哈希的评估认领而没有完整结果。不得为这些记录虚构来源或改写不可变身份。监控回放查询时限不证明更早的持久化事件已被删除。该切片保持只读、离线注入；增量来源持久化与经过验证的回填仍是独立工作。

## 存储与启用

### 交付元数据增量

`0019_alert_delivery_eligibility` 新增独立的 `alert_delivery_eligibility` 记录，以既有事件 ID 为键。绝不改写提醒/结果载荷、哈希、确认状态或渠道尝试。缺少元数据表示未分类的 `HOLD`，绝不表示允许发送。注入式、绑定会话的仓储按需或每批最多 100 条初始化；不在结构升级时回填全部历史。初始化幂等，绝不替换已有分类。

交付类别按信号而非严重程度确定：旧版 BUY/压力减仓与显式 BUY/SELL 使用 `INTRADAY_ACTIONABLE`；三种旧版官方风险信号及显式 `RISK_ALERT` 使用 `STATE_RISK`。来源截止点取原始显式目标或旧版 `market_data_at`；旧版缺失截止点时保持未知，不以评估/创建时间替代。操作性提醒恰在来源截止点 + 90 秒时失效；风险提醒没有仅按时间失效的规则。即使处于时效窗口内，初始记录也保持 `HOLD`。

隔离仓储可使用注入的权威输入，持久化既有显式风险分类器的判断及其捕获的 `RecoveryBarrierEvidence`。`ELIGIBLE` 记录是历史分类凭据，不是持久有效的发送许可；后续发送器仍须重新核对重启/generation 变化、目标推进及当前权威状态。旧版记录不能通过此仅支持显式计划的路径变为 `ELIGIBLE`。来源持久化和旧版适用性集成仍是独立工作；去重命中不得获得当前激活身份的来源归属。

每次变更比较预期 revision、递增 revision，并在同一个调用方事务内追加 `AuditLog`。抑制对原始事件为终态；HOLD 可恢复。仓储不提交或回滚调用方事务。写入者在读取前串行化；已打开的过时快照或数据库失败仍作为可见故障。损坏的元数据不解释为缺失/可发送。降级拒绝丢弃任何交付元数据，包括抑制审计状态。空表降级/升级路径和升级中断仅在临时数据库测试。

`AlertOutbox.enqueue_recoverable` 是显式启用的调用方事务辅助接口，同时创建提醒与初始 HOLD；现有入队与发送器默认路径不变。去重保留已有元数据，回滚保留此前已存在的规范提醒。读取时重新加载规范提醒，复核来源/分类/过期时间、封闭的状态/原因组合，以及 `RISK_TRUE` 和 `RISK_FALSE` 均需的完整绑定五分钟屏障/结果证据。持久化凭据不能悄然借用其他激活身份的证据。后续发送必须避免 HOLD 记录在查询数量上限处使后续候选饥饿，在认领后、每个渠道 I/O 前重新核对权威事实，并保留现有发送结果不确定语义。SQLite 事务不跨渠道 I/O，不引入外部投递恰好一次保证。存储决策与回滚边界见 ADR 0007。

仅增量增加行情恢复检查点和交付元数据。0018_provider_recovery 接在已核实的 0017_market_index_recovery 后；后续交付迁移接在届时实际 head 后。键/原因有界且安全，不含秘密。拒绝丢弃待处理状态的降级。已授权临时数据库迁移测试；真实迁移、备份和部署另行批准。所有提醒、生命周期和传输门禁通过之前，不切换生产默认实现。
### 显式启用的评估事务增量

`RuntimeEvaluationService` 与 `ExplicitRuntimeEvaluationService` 接受严格的仅关键字参数 `recovery_delivery: bool = False`。设为 `True` 时，在既有旧版盘中、旧版官方收盘和显式计划新提醒写入点选择 `AlertOutbox.enqueue_recoverable`。初始 HOLD 元数据及审计与判断的认领、结果、转换和提醒事件共享原有工作单元事务。失败时回滚该判断事务，不得发布其判断/提醒事件。此前已提交的行情事实或收盘待处理准备保持持久化，不属于失败的判断事务。

此选项只增加存储，不分类当前风险，也不授权或强制渠道发送。生产工厂/装配不启用它；现有发送器尚不识别该元数据。RR013 和上线门禁通过前，不得将此隔离的可选路径连接真实发送器。`False` 保持既有行为及哈希。重复评估仍走读取/不变更路径，旧版意图去重跳过仍保持跳过：不得改写已有抑制、回填归属或假定当前激活拥有旧事件。历史缺失元数据仍需独立的有界初始化/重建路径。没有意图就没有交付记录。提交时激活和可变安全事实校验保持不变。
