## 审核状态

**已实施——用户已授权实施。** 本文档记录已交付范围与验证边界；不授权超出该范围的供应商配置、API、依赖、推送或部署变更。

## 目标

在“监控总览”增加四指数走势区域，让用户查看以下指数的当前方向和近期路径：

| 展示顺序 | 展示名称 | `indexCode` | 板块 |
|---|---|---|---|
| 1 | 上证指数 | `000001.SH` | `SSE_MAIN` |
| 2 | 深证成指 | `399001.SZ` | `SZSE_MAIN` |
| 3 | 创业板指 | `399006.SZ` | `CHINEXT` |
| 4 | 科创50 | `000688.SH` | `STAR_MARKET` |

无论活跃交易计划引用哪些板块，四张卡片都始终存在。卡片只展示市场事实，绝不增加大盘强弱标签、建议或隐藏交易闸门。

## 范围与产品决策

### 首版包含

- 在连接/数据年龄条下方、监控计数上方放置固定的两列两行卡片网格。
- 只显示当前交易日，不提供时间范围选择器。
- 当日走势只使用已认证完成的 `FIVE_MINUTE` 收盘点位。
- 每张卡显示名称、代码、最新完成点位、会话涨跌比例、数据截止时间、健康状态和紧凑折线图。
- 尚无指数 K 线时，四张卡仍显示带标签的空走势图区域，不得消失。
- 图表标注：权威快照提供时显示昨收虚线基准、最新点标记、“当日”标签，以及明确的健康文字/图标。
- 每张卡提供一个可展开的无障碍数据表，包含后端准确返回的时间与收盘点位。
- 刷新或单指数故障时保留缓存 K 线，同时保留原截止时间并显示陈旧/错误状态。

### 首版不包含

- 用户自选指数、北证50、行业/主题指数、成分股聚合、K 线/成交量视图、技术指标、历史范围切换、跨指数归一化、比较排名、大盘结论和交易信号。
- 浏览器端收益率、SMA、条件或策略计算。
- 新供应商端点或新的公共 Web API 契约。

## 数据与运行时设计

### 固定展示兴趣

运行时定义一个封闭的 `DASHBOARD_INDEX_CODES` 元组，包含上述四个代码。在每个正常完成的五分钟截止时间，把该展示兴趣与计划拥有的指数需求合并：

```text
四个总览代码 + 不同活跃计划参考指数代码
  -> 每个不同指数和截止时间只采集一次
  -> 不可变、已校验的快照/K 线
  -> 计划判断只使用计划拥有的事实请求
  -> 总览/历史读取模型使用相同的已存事实
```

展示兴趣只请求原始已完成 K 线和昨收，不能向计划引入指标事实请求，也不能让计划依赖原本只是信息展示的指数。每个 `(indexCode, cutoff)` 的采集继续去重，并按指数隔离故障。

没有计划判断到期时（包括没有活跃计划），生产运行时仍在已完成五分钟边界准备并持久化四个纯展示指数。官方收盘第一次尝试也会刷新这些指数。股票判断与纯展示指数采集保持结果独立。

总览读取服务在检查计划状态之前读取展示快照，投影四个展示代码的最新快照，并单独计算 `mappedSymbolCount`。因此卡片显示 `mappedSymbolCount=0` 是合法状态。如果展示快照已经存在，而数据库没有计划、没有活跃计划或计划仍在等待首次评估，总览会返回这些指数和空的股票集合。没有任何展示快照时，前端仍显示四个固定 identity 和空走势图。采集缺失绝不能删除卡片或影响任何计划判断。

### 持久化当日走势源

生产组合把 `GET /api/v1/market-indexes/{indexCode}/bars` 绑定到持久化历史源。该数据源读取请求截止范围内由 SQLite 当前 head 指向的不可变快照，选取所请求周期的 K 线，使用与投影层相同的最新快照顺序解决重复 `barAt`，并返回严格递增的序列。规范内容哈希冻结每次遍历，现有安装级本地签名游标阻止范围或 identity 被重新绑定。缺少 K 线时沿用现有未找到结果，四卡 UI 会把它显示为空图/错误图，但不会移除卡片。

该数据源不会调用 Tushare，也不会把历史查询转换成供应商请求。它只使用实时运行时已经校验并提交的 K 线重建当日折线。

### 供应商请求经济性

`rt_idx_min_daily` 继续作为热路径，在每个已完成五分钟截止刷新。上一交易时段的 `idx_mins` 数据帧和盘中的 `index_daily` 参考数据帧在同一交易日内保持稳定，因此供应商按指数与交易日期各缓存一份已校验原始数据帧，并在后续截止使用防御性副本。`15:00` 及之后的 `index_daily` 绕过盘中缓存，确保官方收盘校正始终执行新的供应商读取。该策略不改变端点或数据语义，同时让正常指数在每日预热之后，从每个截止三次供应商调用降为一次热请求，另加官方收盘刷新。

### 复用现有 API

不需要增加端点或响应字段：

- 摘要与权威健康：现有 `DashboardResponse.marketIndexes`。
- 走势 K 线：现有 `GET /api/v1/market-indexes/{indexCode}/bars`。
- 刷新：新的总览快照或原生重试触发当日卡片的受限重新获取。

总览连接为 `CONNECTED` 时，浏览器针对上海当前交易日最多并发四个走势请求。每个查询使用 `interval=FIVE_MINUTE` 和 `limit=64`，低于现有端点的 `2,000` 点限制。请求接受带零到六位小数秒的规范 `Asia/Shanghai` 时间戳，使用 `AbortController` 和请求代次保护，并且不自动翻页。

## Vue 组件与状态设计

| 单元 | 单一职责 | 契约 |
|---|---|---|
| `DashboardRouteView.vue` | 组合既有总览快照、指数 API 和走势功能 | 只读数据向下传递；不映射图表 |
| `MarketIndexDataStrip.vue` | 渲染固定顺序和响应式当日网格 | Props：摘要和按代码组织的走势状态；发出 `retry` |
| `MarketIndexTrendCard.vue` | 渲染单指数摘要、图表状态和无障碍表格披露 | identity、快照、K 线、加载、错误的类型化 props |
| `MarketIndexSparkline.vue` | 渲染准确 K 线时间/收盘坐标和标注 | 不发请求，不包含健康策略、指标或交易推断 |
| `useDashboardMarketIndexTrends.ts` | 构建固定当日请求、获取四页数据、刷新时保留成功状态并取消旧代次 | 返回只读、按代码组织的 `IDLE|LOADING|READY|EMPTY|ERROR` 状态 |

风格示例：

```ts
const orderedCards = computed(() =>
  DASHBOARD_INDEX_CODES.map((indexCode) => state.value[indexCode]),
);
```

源状态保持最小。展示顺序和状态文案由 `computed` 派生；网络副作用放在组合函数中。组件使用类型化 props 向下传递、类型化事件向上传递。十进制字符串保持权威；只允许在图表渲染边界转换为有限 JavaScript 数字，而且转换结果绝不能反馈到展示证据或判断。

- `>=640px` 使用两列网格；低于 `640px` 使用一列。`320px` 时内容换行，页面级不出现横向溢出。
- 图表使用约 `160px` 的固定紧凑高度；关闭动画并遵循减少动画设置。
- 涨跌数值可按中国市场习惯使用红涨绿跌，但方向还必须通过正负号、文字和图表标签表达。中性/未知使用普通文本颜色。
- 每张图的无障碍名称包含指数名、“当日”、最新点位、涨跌、截止时间和健康状态。展开表格是准确的非视觉等价内容。
- Y 轴使用各自独立的点位范围。禁止叠加造成原始点位可直接比较的暗示。

## 加载、空数据与故障状态

- 有缓存的 `LOADING`：保留上次图表，增加“刷新中”，并保留原截止时间。
- 无缓存的 `LOADING`：显示明确的加载状态和指数 identity。
- `EMPTY`：保留带标签的空走势图区域并显示“该时段暂无已完成指数点位”；绝不绘制零值线。
- 尚无摘要时把卡片标为“暂无快照”，图表显示“当前暂无当日五分钟数据”；不得暗示请求正在无限等待。
- 有缓存的 `ERROR`：保留图表，标为陈旧/错误，并提供原生重试按钮。
- 无缓存的 `ERROR`：保留卡片和摘要健康，显示“走势暂不可用”。
- 一个指数故障或延迟不能阻断另外三个指数。
- 总览断开连接时，缓存图表不能标为实时。
- 总览断开或连接未知时不发起新的走势请求；可继续显示缓存点位，并标为“已缓存”。

## 性能与经济性约束

- 四个请求并行且有上限；组件卸载或收到更新的失效代次时取消旧请求。
- 同一视图刷新进行时按代码保留最后成功页；当日查询绝不请求历史翻页。
- 仅注册本功能需要的 ECharts `LineChart`、`CanvasRenderer`、`GridComponent`、`MarkLineComponent`、`MarkPointComponent`、`TooltipComponent` 和 `AriaComponent`。
- 不增加图表依赖；复用已安装的 ECharts。
- 目标：本地验证中，总览数据就绪后，四张缓存/fixture 图在 `500 ms` 内稳定。

## 测试策略

- Python 单元/集成测试证明四个展示代码在没有活跃计划时仍会采集、每个截止时间只采集一次、与计划兴趣去重，即使映射股票数为零也会投影，为历史读取持久化，并按供应商故障隔离。
- Vitest 证明固定顺序、当日查询边界、四请求上限、取消/代次保护、成功/错误状态保留、十进制转换失败关闭、标注文案、表格等价性和全部状态组合。
- Playwright 证明在 `320/768/1024/1440` 宽度显示四张当日卡片和图表，单卡故障与三张健康卡并存，200% 文本无页面溢出、键盘操作、减少动画，并且 axe 严重/致命问题为零。
- 构建和生成契约检查必须通过。本变更不能增加 API 字段、供应商端点、浏览器策略计算或新依赖。

## 边界

- **始终：**显示四个 identity、来源截止时间、健康、“当日”、准确表格替代和隔离错误；复用已校验 K 线和既有契约。
- **先确认：**修改四代码清单、增加历史范围、修改周期/刷新频率、端点/Schema、供应商配额配置，或增加计算型/解释型标注。
- **禁止：**合成缺失点位、使用未完成报价、归一化/比较原始点位、隐藏故障指数、推断大盘强弱、改变计划判断或渲染供应商错误文本。

## 成功标准

1. 即使总览投影或指数 K 线尚未可用，“监控总览”仍始终准确包含 `000001.SH`、`399001.SZ`、`399006.SZ` 和 `000688.SH` 四张有序卡片及走势图区域。
2. 每张健康卡从权威已完成五分钟 K 线渲染当前交易日的可见走势，并显示最新点位、带符号会话涨跌、截止时间和健康状态。
3. 一个不可用指数保持可见，且不能阻止其他图表加载或更新。
4. 没有活跃计划时，已完成五分钟截止仍会采集并持久化四个纯展示指数；它们不能影响任何计划的事实需求、证据、哈希或判断。
5. 功能不增加公共 API 契约或依赖，并通过上列命令。
6. 键盘、屏幕阅读器/表格替代、减少动画、响应式布局和 200% 文本验收均通过。
