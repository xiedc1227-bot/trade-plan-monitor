# Specification: Unified Plan Historical Replay

## UR01. Authority and objective

Baseline: `6118569`; date: 2026-10-03, Asia/Shanghai. This additive contract belongs to `backtest-engine`, with necessary adapters in `backtest-results`, `backtest-jobs`, `backtest-api` and `backtest-web`. It supersedes their legacy-plan-only assumptions solely for Schema 5. The current monitoring authority remains `SPEC-unified-plan.md` U01–U08. The user authorizes design, internal review, sequential implementation and independent final review without another stage approval.

Replay one complete reviewed `UnifiedTradePlan` (`CONDITION_PLAN`, `condition-plan-v1`) against immutable historical evidence through the existing offline run, job, result, CLI and Web entry points. A live activation is unnecessary. Success means current monitoring semantics are reproduced and tested, not merely that a historical legacy engine accepts a new Python type.

## UR02. Scope and dependency boundary

One capability, ordered implementation: frozen research input → shared monitoring replay → persisted result → CLI/API/page → parity acceptance. Retain legacy replay unchanged. Reuse `unified_conditions`, `unified_lifecycle`, `daily_risk`, and current accounting/operation checks. Inspect actual call paths; do not copy their policies into a second evaluator.

Preferred reuse is a private ephemeral research session that calls the current runtime and shared operation participants with frozen time, deterministic identities, isolated repositories and no delivery sink. It must not construct the production composition or depend on live state. A small extraction of a pure transition/operation participant is permitted only where needed for isolation, with online regression evidence. Research scope belongs under `backtest/`; do not make the online plan API a second research API. A research-only adapter may suppress notification enqueueing; online defaults and behavior stay unchanged.

## UR03. Frozen inputs and identity

Introduce a strict, bounded, immutable `research_input` / `researchInput`, required for Schema 5 and forbidden for legacy plans. Version it `unified-research-input-v1`. It contains an explicit research start, initial inventory authority, frozen supplemental evidence and an ordered operation script. No omitted field authorizes an action. Preserve existing initial lot quantities, acquisition dates, cost bases and stable lot keys; optional plan bucket allocations are not mandatory inventory caps. The maximum position and applicable CORE policy remain enforced.

Freeze a content-bound reviewed research declaration (`reviewed_at`, evidence and explicit confirmation); API submission independently checks the server's current immutable review binding. The declaration attests the research input, not that the plan was truly reviewed at the historical start. A plan reviewed today may be studied over past dates. It never supplies historical manual facts or real operation authority. Unknown initial inventory cannot coexist with non-empty initial lots. Initial acquired dates retain T+1 semantics rather than becoming immediately sellable baseline inventory.

Use `backtest-run-v4` for Schema 5, including the exact plan hash/version, dataset identity/range, initial cash/lots, execution assumptions, context/formula versions and the full normalized research input in the hash. Use `backtest-report-v3` for its complete output. Legacy `backtest-run-v1/v2/v3`, report v1/v2, datasets, plan bytes and export domains remain byte-identical. Omit absent additive fields from legacy serialization. Operational job IDs, attempts and wall time remain outside semantic hashes. Research-internal authority IDs derive from the frozen plan and start, never the entire future script or full dataset hash, so future mutations cannot rename earlier decisions.

`plan_version_id` remains lookup/audit metadata and is excluded from v4 identity, just as for legacy inputs. The isolated session uses content-derived identities, so distinct storage UUIDs for identical reviewed content do not change research results.

The operation script uses stable unique operation IDs, explicit `+08:00` timestamps and a deterministic tie order: newly available market/manual evidence → lifecycle operation → evaluation → explicit operation → recorded resulting state. Reject ambiguous duplicate ordering and operations outside the run. Supported operations cover scoped positive/negative technical facts, independent-event and signal-invalidation facts, explicit risk reassessment, full-quantity simulation requests and ending ordinary authority by deactivation/replacement. A simulation request names a rule/risk and exact occurrence/quantity, never an automatic 'trade every signal' policy. Unknown, stale, partial or unsupported requests produce a visible blocker/outcome; never silently drop them.

Replacement ends this run's original ordinary authority and preserves latched risk. It does not trade a second strategy; replaying a replacement's ordinary rules requires a separate run. A replacement termination must carry the explicit reviewed replacement identity. Saving another draft is not a termination event. Risk removal needs its own frozen, scoped explicit reassessment evidence and cannot be inferred from subsequent prices.

## UR04. Market evidence and time

Advance by available frozen event time, respecting `received_at`, `available_at`, completed official daily close, exact five-minute completeness and session calendar. No wall clock or later fact enters an earlier context. Warm-up contributes context only, never signals, inventory operations or returns. Keep existing bounded rolling context and formulas. A later-received correction is a new event, never rewritten history.

For an intraday start, the current monitor may confirm from an already completed same-day bucket when an event occurs after `started_at`; no event, operation or valuation is emitted before that start. Per-event calendar context has at most 512 rows and includes forward rows only through the first next open session. Missing historical daily-session coverage remains an admission blocker. The frozen historical minute profile retains its deterministic 12-second receipt grace; arbitrary delayed/gapped source batches cannot become ready datasets under that profile.

Existing datasets contain unadjusted daily bars, while current monitoring consumes certified comparable daily series. Supplemental research input must freeze certified daily evidence or explicit adjustment proofs with availability times, exact symbol/source/dataset binding and quote comparability. Reuse the current admission/series validators. Never label raw unadjusted bars as QFQ or invent unit factors. Only evidence available at each cutoff can be used; a future adjustment anchor is invalid. Minute-only plans may replay without daily proof; daily-dependent conditions with missing proof are explicitly blocked. Reject incompatible supplemental facts rather than accepting two conflicting market truths. No provider, profile or dataset identity change is authorized.

Daily signals use `NEXT_EXCHANGE_SESSION_ONLY`; five-minute signals use `CURRENT_SESSION`. `PLAN_ACTIVE` removes only the rule date filter. `DATE_RANGE`, plan activation windows, source cutoff, signal expiry, independent occurrence/deduplication, risk priority/confirmation/latching, explicit removal and unknown-input blocking retain current behavior. Ending ordinary authority invalidates its actionable signals while keeping risk obligations visible. Daily equity/valuation stays research output; no fabricated fill is used to create returns.

## UR05. Simulation and research accounting

Default explicit research script can contain no simulation requests, yielding signals and unchanged inventory. Reminders, acknowledgement, review and evaluation never change holdings. An explicitly scripted simulation applies exactly the full authorized positive multiple of 100 shares, once per occurrence, after revalidation of time/window, current authority, risks, quote, CORE, maximum position and T+1. Initial inventory must explicitly be known or unknown; unknown inventory blocks operations.

Legacy `execution-model-v1` automatic next-minute fills and fee/slippage assumptions remain historical research semantics. They cannot authorize current monitor operations. For Schema 5 distinguish (a) current explicit simulation state transitions and (b) monetary research valuation/cost projections. Use frozen execution assumptions only for the latter and label them as research. No partial cash-limited quantity may replace an authorized full operation. An unsupported execution assumption must be rejected with a stable error, not silently ignored. `MANUAL_EVENT_RISK` cannot become a current fundamental blocker; reject it for this current contract rather than inventing semantics.

## UR06. Output, persistence and entry points

The approved mapping retains the v2 summary/detail envelope and set hash domains. `DECISION` payloads use `unified-research-decision-v1` (`ResearchDecisionEvent`); `EXECUTION_OUTCOME` uses `unified-research-operation-v1` (`ResearchOperationOutcome`). `DAILY_EQUITY` uses a typed research monetary projection with shared equity numbers for charts. The full report is `backtest-report-v3`, the JSON summary export is `backtest-report-summary-v4`, and the research valuation ledger CSV is `explicit-simulation-valuation-v1`. Legacy export bytes remain unchanged. Monitor receipt price/time is distinct from research slippage price/cost. Insufficient research cash blocks valuation with `INSUFFICIENT_RESEARCH_CASH`, leaves the full monitor receipt intact, and makes subsequent returns invalid/null. Unknown inventory remains unknown with `VALUATION_EXCLUDES_UNKNOWN_HOLDINGS`. Unsupported `FULL_SESSION_SUSPENSION` facts have an explicit blocked outcome and report limitation; they cannot silently alter the frozen traded sessions.

Retain existing routes, jobs, result isolation, atomic publication, cancellation, retention and export integrity. Add bounded typed current decision/operation evidence that preserves event ID/time, signal occurrence, condition evidence, confirmation/execution window, blockers, inventory before/after, risks and explicit request outcome. Do not coerce it into misleading legacy strategy fields or expose arbitrary dictionaries. Use a discriminated additive projection; choose a new projection/export domain only where byte meaning changes and document that mapping before writing those bytes. Completed reports must list unsupported/missing evidence and research limitations.

In current decisions, `signals`, `risks` and `risk_action` describe the evaluated state; `resulting_signals`, `resulting_risks` and `inventory_after` describe the state after that event's explicit script. `alerts` preserves actual runtime reminder evidence. CSV separates `monitor_status` from `valuation_status`. All computed public money, including cumulative fees, must remain safe integers; overflow fails explicitly with `RESEARCH_VALUATION_SAFE_NUMBER_EXCEEDED`. At 70,000 decision events, further evaluation fails with `RESEARCH_EVENT_LIMIT_EXCEEDED` before calling the runtime again.

`POST /api/v1/backtest-runs` accepts `researchInput` for current snapshots; server review validation remains authoritative and inactive reviewed plans are eligible. The worker uses only its frozen request. CLI `backtest run` accepts a local research input file; API accepts no file path. Existing `/backtests/new` exposes explicit research input and explains an empty script; `/backtests/:runId` displays current evidence and blocked operations. Provide usable fixtures and commands. Known malformed/current unsupported input maps to a understandable validation/conflict response, never a type error/500. Preserve existing response size, pagination and safe-number boundaries. Update both OpenAPI artifacts and generated types together when necessary.
