## ERS02. 大行表示重叠

对于长度为 N 的 JSON，`shape()` 约预留 `2 * (4N + N + 4N)`：驱动文本、编码字节、校验器解码文本及前后两代重叠。因此接近上限的样本被计入约 18N 加标量/容器开销，即 282.80 MiB。这包含真实生命周期重叠和保守 Unicode 估算，不能证明该 ASCII 样本实际分配了 282.80 MiB。

首先追踪存活对象：SQL 行、原始文本、编码字节、在途证明保留行、比较器局部变量、解码行、校验器上一轮迭代及异常堆栈。另行测量解析模型、规范化树/字符串、选中输出及原生分配。即使不属于输入账本，它们仍影响进程内存门槛；不能悄悄把既有受计费输入类别移出 64 MiB 限额。

首选候选：以 UTF-8 字节捕获 JSON，同时保留其原始 SQLite 存储类型。跟随者直接比较字节及标量类型，不解码 JSON；仅为原完整校验器解码。消除驱动文本转字节的往返，在推进前释放查询和跨迭代引用。租约转移必须有唯一物理所有者；重复引用不能造成重复分配计算或提前退款。在真实生产者/消费者生命周期证明不再需要之前，不删除两代系数。

在专用且明确拥有所有权的读取路径上评估带类型字节捕获：条件 BLOB 投影或受控驱动适配器。不能修改共享池连接的 `text_factory`。保留 TEXT 与 BLOB、NULL、数值类型、非法 UTF-8、内嵌 NUL、非规范 JSON 及全部选中标量；不支持的形状应失败关闭，不能被转换为合法规范文本。元信息相同仍不足以共享。

整行捕获对合法的接近上限 Unicode 或多代保留输入仍可能失败。此时评估同一连接/事务上的只读增量访问，用于字节比较及提交前流式路径。SQLite 增量句柄支持 rowid 表中的 TEXT/BLOB 值，但需要能力、编码、失效及清理测试。无论 `substr` 还是返回的小块，都不能证明原生分配有界。分块读取也不会使原完整 JSON/模型/规范化校验器自动变为增量校验器。如果该校验器仍无法满足冻结的内存/可用性门槛，应停止集成，另行制定生命周期/流式校验设计；不能默默扩大预算、拒绝受支持输入或削弱校验。

## ERS03. 共享失效与有界协调

生产实现会在开始 CPU 校验前等待收集期间的比较完成。P0 为避免字节等待环移除了这种协调：发布输入后立即校验。跟随者获得工作区并完整扫描，但只有在 `future.done()` 之前完成相等性确认才能加入共享。证明先结束就会触发再次申请主请求，随后唯一排队位置拒绝竞争请求。进程执行提供了不同的比较机会，但不能证明其调度契约已足够可靠。

当前 `mismatches` 同时统计输入不相等和完成竞争失败。因此该测量值不是篡改次数，完成竞争占比仍需要时间线确认。记录收集、工作区等待/授予、发布、比较开始/结束、实际相等性、物理校验开始/结束、队列准入/拒绝及释放。分开统计内容不相等、作用域不同、错过完成边界、超时/取消及预算等待，绝不记录载荷。

候选方案：在物理校验前，由已获预算的有限比较组进行协调。先预留主请求的收集/供给/排空推进空间，把旧证明借用者及元信息纳入同一账本。发布时，原子选择并资助收集期间已具备资格且声明工作区能容纳的跟随者。只有这些已获预算的令牌可以延迟物理校验开始。关闭组成员准入，让这些比较在既有截止时间内完成或取消，然后校验。仍在等待字节的请求不属于等待组，迟到请求不能延长等待。不能通过休眠制造重叠，也不能为已完成证明增加宽限期。

字节等待期间不能持有协调器/数据库清理锁。比较者先拥有工作区再借用原始输入；等待唯一排队主请求位置之前，先释放游标、临时行及借用引用。仅作用域相同不能加入共享。每个跟随者扫描自己的事务，并比较全部有序字面输入。不相等时完整重新校验，不能只校验后缀。保持 8 个读者准入、1 个物理校验者及 1 个排队主请求；降低比较并发不能被表述为降低受支持读者数。如果合法并发场景新增超时或拒绝，可用性门槛仍失败。

## ERS04. SQL 放大

本次在 SQLite 3.50.4 上的只读检查发现，2008 个候选被拆成 666 次载荷查询：组大小为 1 至 18，中位数为 2。原查询、元信息查询及首个载荷查询都使用 head 上的映射/指数身份组合索引，再按 payload 哈希查找。尽管存在定位符过滤，载荷查询并未选择直接按 head rowid 查找。因此反复范围遍历/过滤是具体疑点，不能先假定缺少索引。

单轮仅载荷的带探针读取返回了相同的有序定位符：原查询约 64,300 条虚拟机指令，P0 约 3,253,800 条，约为 50.6 倍。观察耗时分别为 0.03549 s 和 0.06207 s。这不含元信息、Python 估算/比较及完整校验；执行顺序/缓存和探针开销未受控。该探针支持 SQL 工作量放大的判断，但不能解释总耗时中的秒级延迟或确立提速目标。查询计划文本仅用于诊断，不是稳定的应用接口。

生命周期估算完成后的首选候选：在同一显式事务内执行一次完整元信息预检，再使用一个有序载荷游标。预检计算全部选中列的保留输入总预留量及同时存活的行/转换工作区最大值。在 execute 前预留该工作区，并持有至游标关闭。采用取行/预读有界且经过测量的驱动路径，不能恢复未按字节准入的 128 行 ORM 缓冲。游标可沿既有有序索引推进，不再为每个极小分组重建查询。目标是 1 次元信息查询加 1 次载荷查询，不含编码检查；这是待验证假设，不是已实现成果。

验证 execute 时预读、当前/下一行重叠、排序物化及原生页缓存。载荷游标不能排序或预读未获预留的大值。保留相同基数、缺失关联、标量类型和顺序。如果运行时无法建立所需上界，再比较按字节准入的键集分页或有界定位符驱动关联；对任何页/排序缓冲计费，并防止漏行/重复行。不能保留无界元信息、在缺少计划证据时加索引，也不能仅为少一次查询而跳过最初完整预检。分别测量元信息、载荷执行及精确比较的成本。

## ERS05. 不变的正确性与生命周期契约

每个请求保留独立的前后权威检查、激活状态重读、原事务/观察时钟和 2 次尝试行为。保留 15 秒等待截止时间及 90 秒有效性，任何等待都不能刷新时间。共享仅覆盖完整字面相等后仍在进行的纯证明，不能共享权威状态或已完成结果。

校验每个历史候选，包括旧行、缺失载荷、head 身份、规范字节及所有既有领域哈希/公式检查。不走仅最新记录捷径，不信任存储哈希或元信息证书。主请求使用既有完整校验器；任何后续校验器重构都需要独立的等价规格和差分测试。

取消仅移除观察者/尚未启动的工作。活跃 SQL/字节访问、比较引用、传输及已提交校验仍被持有，直到真实清理完成。保留 `DRAINED` 或受监督子进程退出及桥接清理。跟随者不能取消其他请求的证明。停止/存储暂停先封禁准入、唤醒等待者，再排空物理工作。游标/句柄/工作进程清理失败时，预算欠额和存储屏障必须跨代保留；不能重置计数器或提交后回退。

## ERS06. 下一轮实施顺序与门槛

1. **P0-A 归因：** 冻结双语规格/任务；补充缺少的共享原因/时间线及生命周期/原生分配探针。复现合法大输入、相同/变更快照及混合读取。分开记录证明、转换、比较、SQL、等待和队列成本。不以单次 SQL 探针宣称优化成果。
2. **P0-B 表示：** 使用原校验器试验字节捕获及显式引用释放。测试受支持的接近 16 MiB 行、Unicode、NUL、异常类型/UTF-8、大的非 JSON 列、上一条选中记录及异常引用保留。合法输入不能容纳时，停止集成并评估独立大行设计。
3. **P0-C 已获预算的共享：** 使用已证明的最小表示改动；通过快速证明/慢比较、迟到请求、大工作区、变更快照、取消和清理失败验证封闭的已获预算比较组。与立即校验策略独立对比。确定性重叠同输入样本必须恢复 1 次证明和 7 次共享，不能让物理完成等待未准入工作，也不能接受已完成证明。
4. **P0-D 有序扫描：** 独立比较单游标候选，再与表示/共享组合比较。记录 SQL/虚拟机次数、原生预读、完整输出、字节高水位、事务时长和 WAL 压力。保留参考路径及全部失败尝试。线程可用性/正确性门槛通过后才重新加入进程传输。
5. **P1 决策：** 保持冻结的 64 MiB 输入限额、768 MiB 工作集 / 2560 MiB 私有提交实验上限，以及原生/所有权证明门槛。采样峰值本身不能证明可强制执行的边界。保持完整校验结果、独立权威、取消排空及合法输入可用性。任何硬门槛失败即停止固定性能验收并公布失败门槛。

候选通过硬门槛后，保留 10 组 A/A 和 20 组 ABBA/BAAB，覆盖相同/变更的 1/2/8 读者输入、混合结果读取、迟到请求及回退。进程集成要求混合结果至少改善 20%，独立结果退化不超过 5%，监控/总 CPU 退化不超过 10%，拒绝/超时率不得变差。报告全部失败及等量完成工作。真实所有者/浏览器验收仅在集成候选获准后进行；保留每个变体 100 次尝试，成功数不足 100 时不宣称 p95。

## ERS07. 来源与限制

SQLite 在[核心函数](https://sqlite.org/lang_corefunc.html#octet_length)中说明基于元信息的列字节长度及编码依赖，在[增量读取句柄](https://sqlite.org/c3ref/blob_open.html)中说明存储限制，在[查询计划](https://sqlite.org/eqp.html)中说明其诊断用途。Python 说明了[只读 blob 访问及连接文本转换](https://docs.python.org/3.14/library/sqlite3.html)。这些资料确立候选 API 的语义，不能证明本应用的内存上界或等价性。

本次分析仅增加双语方案和脱敏的只读探针证据。不修改运行时/测试代码或服务状态，不执行浏览器验收，不新增端到端性能或原生内存保证。冻结输入字节保持不变。完整的分原因并发时间线和大行生命周期测量属于下一轮实验，并非已完成工作。
