# 原生底层分配生命周期优化方案

状态更新 — 2026-10-23：按用户要求 PAUSED。保留本方案及全部既有实验作为研究证据，不再推进原生核算、分配器插桩及依赖它们的准入工作。当前方向改为重新测量生产结果/监控读取，选择具有明确收益及停止条件的最小优化。

## NBL01. 决策与范围

本轮仅规划，依据为 `c7ba0d4`。P0 仍为 `NOT_QUALIFIED`，P1 仍为 `NO_GO`。先验证嵌套域身份、启动分配来源和执行中的分配/释放核算，再推导新的大行预留。纠正偏大的计数本身不代表节省内存。当前不提出立即部署运行时、分配策略、输入上限或生产校验的改动。

本方案细化[上一方案](PROPOSAL-native-owner-accounting.zh-CN.md)及[报告](../../verification/native-owner-accounting-p0-2026-10-23.zh-CN.md)中未完成的覆盖与所有权工作，不将这些门槛标记完成，也不覆盖其他计划。使用配套[任务表](TASKS-native-backing-lifecycle.zh-CN.md)，实施前更新双语规格。AI 提取、日库存和 README 改动继续排除在范围外。

## NBL02. 审查后证据实际证明了什么

[分析记录](../../verification/evidence/2026-10-23-native-backing-lifecycle-next/analysis.json)重新计算已有审查测量并记录所读输入的指纹，没有运行新的原生实验。

| 观察 | 证据 | 影响 |
|---|---|---|
| 返回行被重复计数 | SQL 关闭后，`8388608 B` 返回行留下 `16778428 B` 所有者计数；释放返回行后为 `2524 B`，`3` 轮审查测量均如此 | RAW 和 OBJ 视图不能作为不同底层块相加 |
| 未知释放仍存在 | 普通轮次没有丢失记录，但子进程结束时未知计数为 `182`、`182`、`175` | 来源尚未证明，缺失记录不能自动视为启动分配 |
| 错误阶段包含初始化 | 所有者保留 `15624682–15625406 B`，其中观测到的 arena 为 `5242880 B`；此阶段导入 Pydantic 并创建 TypeAdapter | 不能据此证明错误对象图泄漏或其清理成本 |
| 观测器固定成本明显 | 加入代际修复后，`262144` 条记录占用 `10485760 B` | 必须为全部核算结构提供预算，扩大记录结构不是零成本 |
| 准入仍在读取载荷前拒绝 | 对 `67108864 B` 预算请求 `197697036 B` / `145472808 B` | 可用性仍失败，这些数值不是实测 OOM |

返回行快照包含探针分配，域计数差值不是精确的逐指针轨迹。域合计等于所有者合计，只是对同一批记录重新分组，不是独立的物理内存校验。历史子进程耗时中位数为不安装钩子的 `0.266607 s` 和安装钩子的 `0.280583 s`，包含启动和导入，不能证明 CPU 归因或服务性能。

当前 `release`、`arena_free`、`sql_free` 在调用底层分配器前删除账本记录；`resize`、`sql_resize` 在调用返回后才登记新分配。代际修复避免误删复用地址的新记录，但没有覆盖这些时间缺口，也没有在底层 realloc 执行期间把保存的原所有者传递给嵌套回调。

## NBL03. P0-A：区分逻辑视图和底层块

分别维护逻辑视图、唯一底层分配和预留记录。拟使用的身份字段为 `allocation_id`、`generation`、`operation_id`、`parent_operation_id`、`backing_id`、`origin_owner`、`charge_owner`、`epoch` 和 `state`。用有界原生操作栈关联回调，线程身份不等于分配所有权。

版本对应的 [CPython 分配源码](https://github.com/python/cpython/blob/v3.14.7/Objects/obmalloc.c)在小对象分配不成功时转到 RAW，并在对象 realloc 中调用内部的分配/释放函数。这支持当前重复计数的解释，但不证明已安装二进制的完整构建来源。

对于已证明返回同一分配的 OBJ/MEM 到 RAW 回退，保留逻辑视图，底层块只收费一次。要求回调关系、分配器身份、地址/范围和代际一致。不能直接忽略全部嵌套 RAW 回调，因为分配器元数据可能是另一个仍存活的分配。arena 内的小对象是逻辑占用者，不是额外的 arena 底层存储。独立分配的副本即使内容相同也必须分别收费。

先使用确定性原生夹具，让底层分配器独立记录实际存活块，与观测器对照。验证别名、独立嵌套元数据、跨线程释放、地址复用和错误代际回收。刻意删除去重或代际匹配，证明测试能够发现问题。这些夹具通过只代表核算逻辑成立，不代表实际分配器或 CRT 总量已验证。

所有映射、待完成操作槽位、线程栈和输出缓冲区均声明容量并检查算术溢出。容量、深度或代际耗尽时，使本轮无效并继续保持分配器委托语义。钩子内不扩表、不调用 Python、不动态记录日志。使用新结构前提供预算，并保留明确的核算丢失状态。

## NBL04. P0-B：建立启动分配来源，不能隐藏未知内存

先创建不启用观测的原生启动器，在相同配置下与现有可执行程序比较完整输出。记录 Python DLL、SQLite DLL/驱动、CRT、core、启动器、观测器、分配器配置、编译输入及哈希。发生变化的产物需要独立的可复现性和行为证据。

依次评估以下安装时点：

1. 在 `Py_PreInitialize` 之后、`Py_InitializeFromConfig` 之前安装包装器，作为保留更早分配缺口的对照。
2. 对已捕获且兼容的配置，设置 `PyPreConfig.allocator = PYMEM_ALLOCATOR_NOT_SET` 并在预初始化前安装。[对应版本的初始化契约](https://github.com/python/cpython/blob/v3.14.7/Doc/c-api/init_config.rst)明确允许此情形。使用原生静态/启动存储，预初始化前不调用 Python 分配 API。

每个初始化阶段后检查包装器函数与上下文身份。[预配置源码](https://github.com/python/cpython/blob/v3.14.7/Python/preconfig.c)显示，环境分配器选择和开发模式可能触发分配器配置。检测不兼容设置及被覆盖的钩子，不能悄悄关闭设置或切换分配策略来通过测试。保持[分配器契约](https://github.com/python/cpython/blob/v3.14.7/Doc/c-api/memory.rst)，包括包装现有分配器及线程安全要求。

区分启动、运行时初始化、模型/缓存、校验、返回结果和观测器阶段。阶段切换不重置存活字节、代际或未完成操作。释放/realloc 查询原来源，不能把旧存储归给当前调用者。预热池跨请求继续收费。将分配分为已知的钩子前记录、已知的钩子后记录和未解决记录，不能仅凭时间就把后来出现的未知释放归为基线。

提前安装仍不覆盖一切：DLL/CRT 启动、不支持替换的默认分配路径和直接分配路径需要覆盖清单。在有源码支持的上界或更早观测建立前，保留未解决的启动债务。当前校验存在未知所有权时，即使保守保留了一笔收费，也不能通过资格验证。不能把采样得到的启动工作集当作全输入上界扣除。如果公开钩子无法建立覆盖，明确最小的版本固定原生插桩点及其构建等价测试，不声称完整覆盖，也不替换服务运行时。

## NBL05. P0-C：arena 所有权与释放完成

建立有界区间表，记录 arena 地址、范围、代际和生命周期。将已证明属于该 arena 的块关联起来，不读取任意指针附近的池头。arena 容量由有预算的共享运行时/池所有者承担，请求的逻辑占用另记。空闲槽位、对齐、头部和保留容量包含在 arena 分配中，单独分配的元数据单独收费。请求结束不能退还共享 arena 或分配器空闲列表中的存储。报告逻辑占用时不再次把既有 arena 存储加进进程总量，输入副本类别保持不变。

CPython 可能保留空 arena，Windows arena 回调通过没有返回值的接口调用 `VirtualFree`，源码未向上传递结果。[Windows 文档规定了成功/失败返回值](https://learn.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-virtualfree)。因此必须区分回调完成和已确认的操作系统释放；只看调用后的快照也可能遇到地址复用竞争。

先将 arena 释放保持为待完成，直到回调返回。要证明底层释放，需在独立标识的插桩构建中，于实际调用点捕获原生释放结果和分配代际；否则继续保留未确认金额为债务。不能改变分配策略，不能根据对象数归零推断释放成功。普通堆 free 返回只结束调用者所有权，分配器保留页仍属于底层总量。

测试覆盖共享占用、最后一个逻辑对象释放后 arena 仍保留、新请求复用、arena 地址复用、释放阻塞和原生释放失败。用屏障观测调用中间状态。未知 arena 或未确认释放阻止采用降低后的上界预留，也不能通过转移到无预算的池来消失。

## NBL06. P0-D：在操作完成前核算占用

拟采用状态机 `LIVE -> REALLOC_PENDING/FREE_PENDING -> LIVE/RELEASED/DEBT`。操作开始时，在独立且有界的待完成记录中保存旧分配身份、大小和所有者。转移既有收费，不能退款。允许旧代际仍待完成时，复用地址出现新代际。调用底层分配器期间不持有账本锁或应用预算锁。

realloc 委托前保留旧容量，并预留有源码支持的新增目标/临时空间上界。嵌套回调继承操作保存的原所有者，消耗该操作预留，不新增一份独立预留。目标实际分配后，原子地替换对应待分配额度。失败时保留旧分配，只退还未用的目标额度；移动成功只回收旧代际。原地缩小不能在缺乏证据时代表底层容量缩小。保持各域的零大小、空指针、溢出及分配失败语义。

同时记录待完成的 malloc/calloc/arena 分配：大分配可能已在底层调用中存在，但包装器尚未记录返回。对于 free，只在相应释放边界后回收保存的代际，未确认的底层占用继续作为债务。回调不能等待应用租约；后续准入实验在分配钩子外预留完整前进预算，观测器只验证消耗，覆盖不足则使实验无效。

上界账本使用互不重叠的类别：包含待释放分配的存活唯一底层块、尚未物化的操作额度、未解决债务和观测器存储。预留转为存活块后不能重复相加。这是保守核算设计，不是精确的采样峰值。`xRoundup` 和 `xSize` 描述的是 [SQLite 分配器接口](https://www.sqlite.org/c3ref/mem_methods.html)，单靠它们不能证明 CRT 元数据、保留堆页或瞬时临时空间的上界。[CRT realloc 语义](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/realloc?view=msvc-170)还要求在对应层区分失败和零大小释放。剩余部分没有上界时，资格仍不通过。

测试必须观测分配/free/realloc 阻塞、成功移动、原地结果、失败、小对象到大对象转换、嵌套所有权、旧地址复用、并发操作和反复溢出。增加提前退款和遗漏目标待分配收费的变异测试。缺少这些中间状态的事件轨迹不足以验收。

## NBL07. P0-E：隔离生命周期测量与有条件的大行准入

将夹具创建和独立参考校验移出被测候选进程。完整期望输出/规范化流保存在外部并在外部比较。哈希仅标识产物，不能替代证据校验。拆开冷启动导入/模型创建、预热保留池、SQL 捕获、校验成功/失败、返回输出和物理清理。快照构造使用已提供预算的观测器存储，不污染请求所有权。

用实际 SQLite 模块重跑真实文件数据库的元数据和载荷路径，包含 TEXT 到 BLOB 转换、返回行生命周期、缓存底层存储和密集非法输入。先报告覆盖和核算丢失，再报告各阶段耗时/CPU、锁/回调成本、唯一底层占用、待完成峰值、池/债务保留和进程内存。保留原始历史测量。去重后总量变小只能标记为核算纠正，除非实际分配或生命周期也发生改变。

所有覆盖/生命周期门槛通过后，才能根据源码支持的上界重建完整同时存活的前进预算。不能因为探针重复计算了一行，就把现有 `197697036 B` / `145472808 B` 预留减半；这些预留来自独立推导。SQL、原始数据代际、解析、模型/错误、规范化、编码、跟随者比较、返回结果和清理仍在原类别中收费。保留原子准入和完整校验回退，不允许持有原始数据租约后再等待无预算升级。合法行仍无法容纳时，记录可用性失败并停止 P1。

## NBL08. 验收与不变安全契约

| 门槛 | 通过条件 | 失败后果 |
|---|---|---|
| P0-A | 独立底层分配参考能发现重复/漏记和复用错误 | 不生成底层总量结论 |
| P0-B | 早期钩子稳定、来源清单完整、未解决基线有预算 | 不声明整个运行时覆盖 |
| P0-C | 共享 arena 核算及有依据的释放确认 | 保留债务，不提前退款 |
| P0-D | 操作中间态上界、原所有者、有界结构且无死锁 | 不缩减预留 |
| P0-E | 实际查询/校验器生命周期覆盖、源码上界及合法行前进 | P1 继续关闭 |

前一门槛通过不代表后一门槛通过。启动、CRT、Rust、VFS/映射或返回结果中的任何剩余部分没有上界，都阻止整个进程的资格通过，即使 Python 域核算已正确。

保留 [BIR08](PROPOSAL-native-build-instrumentation.zh-CN.md)：每个请求独立执行前后权威检查并重读激活状态。校验全部历史证据、`19` 个原始字段/类型、依赖、严格模型、规范化 UTF-8/EOF、bar/request/root/formula 和逐事实值。不使用已完成证明缓存，不信任存储哈希。

取消只让观察者离开或阻止尚未开始的工作。待完成分配操作、SQL/校验工作、返回结果和传输必须保持所有权，直到实际释放或转给有预算的所有者。清理失败保留债务并阻止后续代际。最后观察者离开不能退还在途内存，也不能提前终止同步工作线程。

保持 `64 MiB` 输入、`768 MiB` 聚合工作集、`2560 MiB` 私有提交、`1` 个物理校验、`1` 个排队所有者、`8` 个读者、`15-second` 等待、`90-second` 资格和 `2` 次尝试。覆盖 `1/2/8` 读者、时间边界两侧、延迟/重新哈希篡改、领导者/跟随者取消、最后观察者离开和清理失败。失败时允许 `3` 轮明确标注的诊断；资格验证需要 `10` 对 A/A、`20` 个 ABBA/BAAB 块、`20%` 混合进程收益，结果最多回退 `5%`、监控/总 CPU 最多回退 `10%`，且拒绝/超时不能恶化。浏览器验收仍要求每方案 `100` 次尝试，达到 `100` 次成功后才声明 p95，混合 p95 改善 `20%`。本方案不声明新的性能或浏览器验收通过。
