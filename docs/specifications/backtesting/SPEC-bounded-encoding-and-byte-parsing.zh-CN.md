# 有界编码与字节解析 P0 规格

## BEP-S01. 范围

按双语提案实施隔离实验，保留全部已有文件、权威与完整性策略。不注册生产路径，不重启，不修改 AI 提取或日库存。P1 为条件推进，本轮实现不提交、不推送。

## BEP-S02. 生产者

规范化沿用原 model_dump、Decimal、枚举和时间戳策略，在行内局部容器一次累计保守编码大小。每次 C 编码调用产出前准入，试验 64 KiB 和 256 KiB 逻辑目标。生产者缓冲通过不变的 64 MiB 账本内独立实验租约计费。逻辑输出边界不能证明原生 writer 边界。计入排序向量、描述符、上一块及 UTF-8 转换。保留所有域哈希和含 EOF 的完整字面值比较，禁止已完成缓存或宽松解析器。

## BEP-S03. 解析与准入

测量长 Decimal 和密集对象行成功及错误生命周期，明确排除预构建输入。模型与原生分配继续纳入进程门槛，不重分类已计费输入副本。对接近 16 MiB 的合法输入验证完整 SQL 预检路径。原生和驱动生命周期证明前，不降低保守扫描预留；安全拒绝仍是可用性失败。保持 64 MiB 输入、768 MiB working set、2560 MiB private commit、8 读取、1 物理证明、1 排队 owner、15 秒等待、90 秒资格和 2 次尝试。

## BEP-S04. 验证与决策

验证全部历史记录、全部 19 个字段及类型、头身份、缺失 payload、规范字节及 bar/request/snapshot/formula 哈希。差分验证篡改、大行与密集行、块边界、取消、物理排空、并发隔离、期限和清理失败，运行原权威、保留规则及生命周期回归。记录源码与输入指纹及前后测量。原生边界或可用性任一失败即阻断 P1 和固定性能验收，仅运行 3 轮诊断。否则要求 10 对 A/A、20 个 ABBA/BAAB 块、20% 混合进程收益、结果回退 <=5%、监控及 CPU 回退 <=10%、拒绝与超时不变差。浏览器验收需集成候选且每变体 100 次尝试；成功不足 100 次不报告 p95。
