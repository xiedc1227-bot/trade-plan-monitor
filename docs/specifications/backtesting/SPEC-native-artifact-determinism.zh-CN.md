# 原生产物确定性 P0

## NAD-S01. 契约

实施双语方案中的 NAD01–NAD09。保留既有权威、证据、取消/排空和预算门槛。生产集成保持关闭。排除 AI 提取、日库存与 README 改动。

## NAD-S02. 原生门槛

固定源码和工具身份、非 PGO 参数、源码派生的 `SOURCE_DATE_EPOCH`、`/Brepro` 及路径映射。在 3 个干净根目录构建 R，包含空格/非 ASCII 路径和改变 mtime。比较完整原生字节，记录实际命令及每次失败。未解释的差异阻止依赖的 SBOM 资格验证与分配器工作。禁止屏蔽字节或复制产物。

## NAD-S03. 封装门槛

仅在 NAD-S02 通过后，在 wheel 序列化前实现经审查的 SBOM 身份映射。保留依赖来源和图等价性。验证唯一且安全的 ZIP 成员及精确的 `RECORD` 哈希/大小；比较完整 SBOM、原生二进制和 wheel 哈希。拒绝畸形包、重复成员和篡改。验证源码/依赖变异及仅路径变化对照。

## NAD-S04. 下游门槛

仅合格的 R 与 I 配置允许进行原生插桩实验。改变合法大行预留前，必须完成 Rust/Python/实际 SQLite 分配覆盖和物理所有权验证。既有 BIR08 阈值继续生效。失败前提如实报告为失败或未执行，不得称为原生上界或浏览器验收通过。全部门槛通过前 P1 保持 NO-GO。

## NAD-S05. 诊断实现边界

隔离的 maturin 补丁在 wheel writer 前调用已固定的 Python SBOM 转换器。保留原始/生成 SBOM，并证明反向映射恢复完整原始 JSON 图。初步 Rust `GlobalAlloc` 观测器统计申请的存活/峰值字节与次数，计入可能的 reallocation 新旧重叠。它不是三个域的内存上界，也不是逐证明所有权台账。即使全部 R/I wheel 相同，缺少 Python/SQLite/底层堆覆盖仍阻止降低预算。在隔离子进程导入中执行 3 轮完整有效/篡改行与不变的 SQL 准入诊断，禁止将实验 wheel 安装到服务中。

## NAD-S06. 审查补强

解压前拒绝非规范 ZIP 路径、Windows 保留名称、大小写不敏感冲突、文件/父目录冲突及非普通文件成员。产物准入除要求相等标志和所选 wheel 的独立审计外，还要求 3 组一致的原生与 wheel 哈希。子进程执行前原子保存尝试记录；超时保留命令、变体/轮次及部分输出，不得标记完成。构建超时同样保留部分诊断信息。这些实验控制不改变服务取消/排空或预算所有权。
