# 回测创建交互

状态：实施契约。对应英文：`SPEC-backtest-creation-ux.md`。

## BC-01 问题与参考证据

创建页目前将来源选择、时间线历史、原文准备、审核和运行设置堆在一个长流程中。复用已审核时间线时，用户必须扫过与本次任务无关的准备控件。

2026-10-20 核查的参考：

- [FreqUI 回测页面](https://github.com/freqtrade/frequi/blob/main/src/pages/backtest.vue) 分开运行、历史和分析；[BacktestRun](https://github.com/freqtrade/frequi/blob/main/src/components/ftbot/BacktestRun.vue) 先选策略再设参数，折叠可选策略参数，并提供明确的开始动作。采用渐进展示以及选择、配置、启动分阶段的方式。
- [Hummingbot 回测](https://github.com/hummingbot/hummingbot-site/blob/main/docs/dashboard/backtest.md) 先配置策略，再设置日期范围与费用，最后明确启动回测。采用此顺序。其旧 Streamlit dashboard 仅作为交互参考，不引入为新依赖。
- [QuantConnect 启动回测](https://www.quantconnect.com/docs/v2/cloud-platform/backtesting/deployment) 区分明确提交和已接受、运行中、结果反馈。保留现有服务端回执、自动数据准备和结果跳转。

使用产品现有 mineral/graphite/amber tokens 与组件。不复制品牌，不增加 UI 依赖，不再次重构结果页。

## BC-02 选择与信息层级

- 保留现有默认工作台来源和通过 `preparationId` 直接恢复的行为。
- 简短来源名称解释工作台复用与已审核时间线复用。压缩标题和研究边界。
- 展示已加载的时间线/记录数量、股票名称/代码搜索，以及明确的刷新/新建动作。
- 每条时间线显示股票名称/代码、稳定序号、起点审核时间、更新次数和生效日期范围。不同分支分别显示准确末端，绝不合并独立链或分支。
- 每页保持十条完整时间线。搜索仅过滤已有元数据，重置页码并保留选中的末端。定位已选项会清除筛选并进入所在页。
- 默认折叠更新记录和审核证据。选择时间线是读取动作，不会组合准备或启动回测。

## BC-03 渐进准备与设置

- 首次进入时间线模式只显示计划库和下一步指引，不显示未使用的原文表单或空闲准备进度。
- 选择已审核时间线后显示现有运行设置，读取完成后将键盘焦点移到设置区域。
- 新建/更新才明确打开准备区，并聚焦其标题。更新保留准确的已审核前序。
- 恢复中的未完成准备、错误和不确定变更结果保持可见。审核完成后转入运行设置；历史 `inspect=1` 保留只读证据。
- 可收起尚未修改且未保存的准备区。此控件不能隐藏或替换脏草稿。保留现有草稿、提交、准备和不确定结果锁定。
- 运行设置、费用、准入、自动补齐数据、幂等与后端解释保持不变。
- 冻结账户摘要在费用输入上方占据整行。逐份计划的生效日期明细默认折叠，避免长时间线拉高第一行费用输入。

## BC-04 状态与可访问性契约

区分加载中、成功但为空、首次读取失败、保留的旧结果、搜索无匹配、已选、脏草稿、忙碌和不确定状态。读取失败不得暗示历史已删除，也不得显示已确认的零数量。搜索无匹配时提供清除搜索，不引导重建历史数据。

使用原生按钮、带标签的搜索、文字加颜色的选中状态、可见键盘焦点，以及至少 44px 的操作目标。验证 320/768/1024/1440px 宽度和 200% 文字，不出现页面横向溢出。

## BC-05 组件分工与验证

- `BacktestNewView`：现有 API 编排和组件组合；负责准备区的显式显示与焦点，不渲染时间线内部。
- `ReviewedPlanLibrary`：接收列表、选择与请求/锁定状态；负责元数据搜索/分页，发出 `open`、`update`、`new`、`refresh`。
- `PlanTimelineCard`：接收单个不可变分组、序号、末端、禁用状态与可选详情 API；发出准确末端的 `open`/`update`，渲染历史折叠区。
- 现有准备/审核/运行组件保留业务契约。

测试覆盖搜索/分页中的选择身份、分支、读取失败、显式准备入口、脏草稿、恢复和审核后进入设置。浏览器验证键盘操作、重排、无非预期写入，以及使用隔离测试存储的现有创建/更新/查看完整路径。真实历史核验只读。
