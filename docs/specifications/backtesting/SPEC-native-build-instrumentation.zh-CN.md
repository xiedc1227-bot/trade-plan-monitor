# 原生构建与插桩 P0

## BIR-S01. 契约

在隔离实验中实施 [BIR01–BIR08](PROPOSAL-native-build-instrumentation.zh-CN.md)。其数值门槛及完整权威/完整性/排空要求均为规范且保持不变。所有门槛通过前禁止生产集成。保留并行 AI 提取、日库存与 README 改动。

## BIR-S02. 构建

准备 Windows x64 工具；锁定 Rust `1.94.0`（源码最低 `1.88`）、Rustup `1.29.1`、Build Tools 安装器 `17.14.42` 和 maturin `1.13.1`。单独记录实际编译器/SDK 版本：安装器版本不能锁定组件载荷。验证源码归档、锁文件和二进制。两个干净的未改动发布构建必须匹配；明确不使用 PGO。插桩构建不能认证不同运行时。缺工具、下载或构建失败均为前置失败，不能算通过。

## BIR-S03. 分配

通过有界原生遥测、跨线程所有权和保守重分配重叠，认证 Rust、Python 及实际 SQLite 领域。原生覆盖和源码上界闭合前不能降低预算。不得用 Python 记账模拟替代原生拦截。失败注入仅在受监督的一次性子进程执行。

## BIR-S04. 失败实验

在自动 GC 开启的隔离子进程中，对比全量回收和仅作用域捕获。计时到相同校验/释放终点，并单独计入最终回收/债务。包含密集/Decimal 非法夹具、重复调用与对抗循环。仅作用域捕获属于诊断：不得成为生产校验器或退款。全部支持的失败分支获资格前保留原循环清理行为。

## BIR-S05. 准入与验收

重跑合法大行完整校验及实际隔离 SQL 准入。资格失败时保留既有预留，明确报告可用性失败。运行篡改、并发/死锁、独立权威、时间边界、取消与清理失败回归。浏览器验收仅适用于获资格的集成候选；不能凭单测宣称浏览器/性能通过。双语报告记录每次结果、源码/输入摘要、失败及前后对比。
