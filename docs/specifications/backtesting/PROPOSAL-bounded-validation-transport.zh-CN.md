# 纯指数校验的有界传输方案

[英文规范版](PROPOSAL-bounded-validation-transport.md)。本方案基于 `f430c96`，属于分析提案，不代表实施批准或已测得的生产提速，承接[CPU 归因报告](../../verification/active-monitor-cpu-2026-10-22.zh-CN.md)。

后续获准工作见[规格](SPEC-bounded-validation-transport.zh-CN.md)及[验证报告](../../verification/bounded-validation-transport-2026-10-22.zh-CN.md)：P0 已完成，P1 因并发输入预算门槛暂缓。下方保留原始分析。

## BVT01. 证据与建议

建议分阶段实验：保留父进程现有的不可变输入，继续支持在途精确共享；通过按字节限额、由消费者拉取的迭代器向单个子进程校验器供给数据。不构造完整序列化批次，也不在子进程重建完整输入集合。先采用私有管道、仅允许一个未消费分块；共享内存和流水线预取留待测量证明值得增加相应资源所有权规则后再评估。

已被否决的整批传输实验，输入副本合计 119,382,234 字节（113.85 MiB），超过不变的 67,108,864 字节（64 MiB）门槛。受控混合负载的结果读取中位数从 5.2224 降到 2.7358 秒，但单独监控完成时间退化 9.05%，混合总 CPU 增加 4.57%。分块可能因握手增多而损失部分收益，必须重新测量。

现有 `_latest_index_records` 已经逐条消费迭代器，只保留各请求指数最新的已验证记录。`_market_index_from_row` 在排序前对每条候选执行完整类型、规范化字面值和领域校验。因此可以保持这些函数不变，只把输入迭代器替换为有界传输适配器。每块单独调用校验器会丢失全局排序及同分顺序语义，不采用这种方式。

[离线数据形态分析](../../verification/evidence/2026-10-22-bounded-validation-transport-analysis/geometry.json) 仅使用上次冻结的只读数据库：2008 条候选，保留量 30,826,621 字节，最大单条保留量 37,206 字节。逐条 pickle 编码最大为 36,295 字节；暂按 1 MiB 分组可形成 28 块，最大块原始保留量为 1,153,404 字节。这只是数据形态估算，未计帧开销，使用的也是探索性编码，不代表最终协议或实测峰值。此前真实输入更大：2238 条候选 / 35,441,065 字节保留量。持久化允许指数 JSON 达到 16 MiB；已观测的小记录不能成为所有记录都能放入分块的假设，损坏的持久化输入也可能超过写入时限制。

## BVT02. 边界与传输

权威前后检查、时钟检查、数据库事务、激活重读和响应组装均保持父进程现有所有权。子进程只接收不可变候选标量字段及请求的指数代码，不接收会话、引擎、凭据、运行时所有者或权威对象。保持原 SQL 过滤、排序和读取快照。

建议版本化协议：`START`、`NEED`、`CHUNK`、`END`、`RESULT`、`ERROR`、`DRAINED`。每条消息绑定 `workerGeneration`、`jobId`、`sequence`、字节长度和候选范围。`START` 声明完整候选数及校验代码版本。`END` 绑定总条数、总字节和有序传输摘要；传输摘要用于发现截断或串流，绝不替代领域校验或共享所需的字面值精确比对。拒绝缺失、重复、乱序、超长、过期代际和尾随帧。意外 EOF 是错误，不能当作迭代结束。完整输入尚未消费或最终协议检查未通过时，父进程必须拒绝结果。

采用无损标量编码，保留精确类型、`json_is_text`、载荷缺失状态和原始 JSON 字节。父进程不解析重写 JSON、不把字节强转成文本、不规范化数字，也不移除损坏的旧证据。不支持的编码在提交子进程前选择原有全量校验线程路径。使用 `RawIndexCandidate.exact` 检查编解码往返，针对异常值及帧做模糊测试。前面的 pickle 测量只用于估算形态；正式测量前必须选定并约束真实编码器。

除数据帧外，管道中只传输有界控制消息。每个管道方向只有一个生产者。父进程桥接工作归属于已有工作线程，不阻塞事件循环，不创建无人管理的发送任务。子进程消费当前块后才请求下一块；禁止队列自动预取、重建完整 `list`/`tuple` 或累积 pickler memo。输入和输出方向都需要有界帧及独立的进度/错误处理，防止双方同时发送而死锁。

Python 文档说明了队列后台供给缓冲、管道阻塞，以及终止进程时损坏通道的风险：[multiprocessing](https://docs.python.org/3.14/library/multiprocessing.html)。队列条数限制不是字节限制。固定接收缓冲区也不能单独证明超长消息不会触发额外分配；需检查已安装 Python 3.14.7 的传输实现并测试超长路径。共享内存作为备选，需要明确槽位租约以及 Windows 全句柄关闭规则：[共享内存](https://docs.python.org/3.14/library/multiprocessing.shared_memory.html)。

## BVT03. 内存准入与回退

使用统一租约账本，覆盖父进程、子进程及仍在排空的证明中同时存活的输入与传输副本。先预留再分配，不能先序列化完整批次再计量。包括父进程原始证据、编码临时空间、帧头、发送/接收缓冲、已知内核/瞬时副本、子进程重建候选、解码后的源文本、生成器跨块残留和输出传输副本。分析中也应计入尚未释放的精确比对/SQL 批次，不能为每个观察者隐含增加未报告的额度。共享同一不可变对象的引用不形成第二份原始载荷，但容器及引用开销仍需计算。保留现有保守原始大小算法。

首轮实验建议最大编码块为 1 MiB，在现有 64 MiB 总限额内预留 16 MiB 给传输及副本。这是待证明的预留值，不是宣称适配器已经能满足它。父进程证据和其他同时计费的输入分配最多可占 48 MiB。按此前真实输入，父进程证据加建议预留约为 49.80 MiB，其他计费输入分配还剩约 14.20 MiB。这些算术值不是 RSS，也不是验收证据。无法证明保守上界可容纳时，缩小帧或拒绝进程路径准入；绝不为每个进程分别增加 64 MiB 额度。

不能在收到分块或仅仅请求下一条时就归还整块租约。未修改的校验器请求下一条候选时，仍持有上一条 `candidate`、解码后的 `row` 和 `head`，并跨块保留选中的已解析快照。必须为可证明的重叠范围计费，必要时包括上一条候选或上一块。确认消息只能归还已实际消除引用的字节。任务完成时，只有消费完有界输出/错误并收到 `DRAINED` 后才能释放子进程输入租约；父进程原始证据则需等待物理完成及现有全部比对租约释放。即使下一所有者获准进入，也要继续计算旧证明租约。

提交前逐条检查候选，通过不复制完整载荷的方式计算安全帧长和展开上界。任何候选或剩余额度无法满足时，整次证明选择现有线程校验器。首版不切分 JSON token，不因进程传输块较小而拒绝合法大记录，也不先在子进程验证前缀再悄悄在线程完成后缀。超大或损坏源数据是否可接受，仍由现有全历史校验判断。所有性能统计必须保留回退样本。

64 MiB 账本不是进程总内存：解释器/模块、已解析领域对象、分配器保留及其他服务工作也占内存。P0 需测量同时刻的父子进程工作集/私有提交量、保留的已解析结果，以及连续任务的高水位表现。生产 P1 前冻结绝对进程内存额度；RSS 抽样检查和分别峰值相加都不是硬分配上界。若无法证明输入副本边界或合理的进程内存余量，就停留在可行性阶段。

## BVT04. 完整性与在途共享

对完整有序流只调用一次 `_latest_index_records`；对每条候选调用未改动的 `_market_index_from_row`，包括旧的、最终未选中的证据。保留类型解析、全部领域哈希、head/provider/formula/metadata 绑定、规范 JSON 字面值相等、缺失载荷拒绝、顺序及排名规则。传输完成本身不能认证证明。子进程结果绑定原始物理任务，每个观察者返回仍受父进程独立权威/身份检查约束。

保留父进程原始集合，直到现有所有者释放。每个跟随请求仍读取自己的快照，并对完整候选序列执行 `RawIndexCandidate.exact`。只有证明尚在执行且完整精确相等时才可加入；请求键或摘要都不足以获得资格。保留现有完成屏障、不匹配路径、8 个读取准入、1 个物理校验器、1 个不同的排队所有者，以及不缓存已完成证明的约束。共享仅限纯证明工作，不共享权威或已组装响应。

## BVT05. 取消、失败与物理排空

显式建立物理任务状态：`ADMITTED → TRANSFERRING → VALIDATING → RETURNING → DRAINING → RELEASED`，传输和校验交替进行。HTTP/socket 观察者取消时，经现有所有者脱离；不能停止发送器、释放输入租约、取消跟随者的证明或标记任务已排空。保留现有 leader/follower 取消策略；首版原型让已经获准进入的纯证明继续到物理完成，不新增全部观察者退出后的中止策略。

保留现有截止时间、15 秒协作准入/等待检查点及 2 次权威尝试。截止时间可以结束观察者，但不能释放仍在使用的物理资源；帧处理需要有界监督策略，且不能在重试时重置请求截止时间。物理所有者继续持有工作器/会话/读取许可及相应存储暂停，直到其工作和通信完成。子任务完成与工作进程关闭是两回事：常驻空闲子进程不必在每次证明后退出，但服务停止时必须关闭通道并等待子进程退出。

校验错误通过有界、允许列表中的错误码保持原有拒绝语义，不传输原始异常 pickle 或私有证据文本。管道损坏、子进程崩溃、协议异常或代际不符都使证明失败，并隔离相应工作器代际。提交后不偷偷切回线程重试，不产生重复物理校验。恢复只能在确认清理完成后接受新的读取。发生卡死时，保留既有失败屏障，直到受监督的拆除确认进程退出、桥接工作完成和资源关闭。如需强制终止，必须作为明确应急路径，丢弃通道，不能把 `terminate()` 返回当作已排空。清理失败保留存储屏障，不能为了让健康检查通过而清除它。

## BVT06. 实施顺序与决策门槛

双语规格及任务获得批准后，先只实现隔离的 P0 原型，按以下顺序推进：

1. BVT-T01：冻结总账、实际编码器、资源所有权状态机、回退规则、已安装运行时的传输行为及实验顺序。实施前恢复双语一致性。
2. BVT-T02：使用不变的纯校验核心证明候选无损往返和流结束校验；测试后段历史篡改及分块边界。
3. BVT-T03：证明单块背压、先预留后分配、跨块残留计费、超大输入回退，以及连续任务没有保留量增长。测量并提出绝对进程内存额度。
4. BVT-T04：验证跟随者/领导者离开、重复取消、收发阻塞、完成消息丢失、子进程崩溃/卡死、停止竞争和清理失败；断言不提前释放存储/字节/工作器资源。
5. BVT-T05：固定次数比较线程与分块子进程，分别记录冷启动、编码/解码、ACK 等待、校验、父/子 CPU、同时刻内存、完整输出哈希及回退率，决定是否有理由推进 P1。
6. BVT-T06：仅可行性通过后，规定生产工作器所有权并以默认关闭的开关集成，再做真实所有者及浏览器验收。不混入 AI 提取和日库存改动。

测量前冻结正确性场景：正常输入、空流、单条、分块临界、接近 16 MiB 的持久化 JSON、预算临界、父进程证据接近 64 MiB、不支持的标量类型、超大损坏存储值、缺失/重复/乱序/截断帧、过期任务 ACK/结果，以及后段历史证据无效。覆盖激活/代际/配置/进度变化、时钟/目标/90 秒边界、保留/发布变化和共享证明不匹配。变异测试必须检出跳过最终条数/摘要检查、遗漏规范化校验、绕过权威、提前归还字节和提前排空。

沿用既有测量纪律：10 组 A/A 对照和 20 组交替 ABBA/BAAB，对单独监控、单独结果和混合负载，各变体测量 40 次。比较前固定初始 1 MiB 单块配置；任何调优需另行声明实验，不能替换失败样本。计入回退、失败及取消结果，不能将成功子集变快描述成总体提升。要求混合结果中位数至少改善 20%，单独结果退化不超过 5%，监控中位数及父子总 CPU 退化不超过 10%。即使延迟达标，内存、完整输出相等和生命周期门槛仍必须通过。

生产设计/集成后，真实所有者混合验收预先声明每变体 100 次尝试；每变体至少有 100 次成功观测后才可提出 p95 改善结论，保留所有失败的分母并披露不确定性。保留现有真实混合 p95 至少改善 20% 的目标、受保护拒绝率不恶化且没有新增超时/泄漏。验证结果/来源/刷新/返回监控、心跳/重连和 2/8 客户端并发。内存、正确性或生命周期门槛失败时，继续采用现有全量校验线程路径。

## BVT07. 本轮分析范围

本次仅新增双语提案及脱敏离线形态数据。生产代码、现有测试、配置、在线数据库和服务均未改动；不宣称运行时提速、重新执行浏览器验证或测得新的 IPC 峰值。此前 469 项后端和 25 项浏览器结果属于上次 P0 发布。本提案检查双语一致性、源码/证据引用及 JSON 有效性。新实现必须收集自己的测试和测量。
