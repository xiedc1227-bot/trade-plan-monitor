# 分配器资格验证前的原生产物确定性

## NAD01. 决策与范围

按原生二进制、SBOM、完整 wheel 的顺序闭合可复现性，先使用已安装工具链，再考虑升级。当前失败有明确的元数据原因，小型构建也已验证可行的链接器与时间配置。完整 pydantic-core 资格验证仍未通过；分配器插桩、降低准入预留和 P1 继续受既有门槛约束。

本方案接续 `e74605d` 与[上轮 P0 报告](../../verification/native-build-instrumentation-p0-2026-10-23.zh-CN.md)。本轮增加双语方案与[分析证据](../../verification/evidence/2026-10-23-native-artifact-determinism-next/analysis.json)，包含[自包含探针配方和结果](../../verification/evidence/2026-10-23-native-artifact-determinism-next/canary.json)。只执行无第三方依赖的隔离诊断构建。未修改生产代码、替换依赖、重建完整核心、实现插桩、降低预算、提交或推送。保留已有 AI 提取、日库存及 README 工作。实施本方案前补齐双语规格和任务。

## NAD02. 实际失败在哪里

上一轮 R1/R2 原生二进制均为 `5805056 B`，恰有 `19` 个字节不同。全部差异位于 COFF 时间戳、调试目录时间戳或 CodeView GUID。两者内嵌的 PDB 路径已经都是 `_pydantic_core.pdb`；这对二进制没有观察到绝对 PDB 路径差异。这只能解释本次差异，不能证明运行行为等价或后续构建确定性。

SBOM 在 `serialNumber`、`metadata.timestamp`、`metadata.component.bom-ref`、`metadata.component.components[0].bom-ref` 和 `dependencies[0].ref` 上不同。后三项包含不同的绝对源码目录。原生二进制与 SBOM 的变化进一步导致 `RECORD` 不同。

验证器也存在缺口：`native_build_probe.members()` 比较解压成员哈希组成的字典，不能证明 ZIP 全部字节相同，字典还会隐藏重复文件名。本轮检查确认，原始 wheel 的成员顺序、日期、权限、压缩方法、额外字段和注释一致；ZIP 日期已为 `1980-01-01`。因此 ZIP 时间戳不是这对产物新发现的原因，但仍须补齐完整 wheel 门槛。

## NAD03. 新增受控观察

六次无第三方依赖的 Rust 二进制 wheel 构建使用 Rust `1.94.0`、已安装 MSVC 工具链、maturin `1.13.1`、独立源码和目标目录、离线构建、fat LTO、一个 codegen unit 及既有 release strip 策略。所有变体采用相同的编译器路径映射规则。下表每行比较两个全新目录。它们是可执行文件探针，不是 pydantic-core/Python 扩展或分配器测试。

| 变体 | 原生 SHA-256 相同 | SBOM 差异 | 完整 wheel 相同 |
|---|---|---|---|
| 未固定 epoch，未指定可复现链接器选项 | 否 | 时间、随机序列号与路径引用 | 否 |
| 固定 `SOURCE_DATE_EPOCH` | 否 | 仅路径引用 | 否 |
| 固定 `SOURCE_DATE_EPOCH` 加 `-Clink-arg=/Brepro` | 是 | 仅路径引用 | 否 |

最后一对 SHA-256 均为 `2096ce4914f9bd97fb495014524a3187df19ded190a991db4d4d6b2e0aa9b0da`，CodeView GUID 一致，并出现调试类型 `16`。原生大小从 `116224 B` 变为 `116736 B`，包含可复现元数据。这是诊断产物大小，不是内存包络变化。固定 epoch `1700000000` 是合成测试输入，不代表实际发布日期。首次启动器尝试在任何构建开始前未能定位 `rustc.exe`；改用绝对可执行文件路径后，后续六次构建全部完成。

已安装链接器报告版本 `14.44.35229.0`，常规帮助未列出 `/Brepro`。将其视为这套精确工具链上经过实验支持的选项，不能泛化为跨版本保证。Microsoft 的 [PE 规范](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format#debug-type) 说明，可复现调试条目使用从内容计算出的日期字段。不要把它们解释为真实构建时间，也不要在链接后清零。仅有类型标记不够，必须比较完整二进制。

## NAD04. 正确使用已有 SBOM 支持

[maturin `v1.13.1` 锁文件](https://github.com/PyO3/maturin/blob/v1.13.1/Cargo.lock) 固定了 `cargo-cyclonedx 0.5.9`；原始 SBOM 自身也报告该版本。其[匹配的生成器源码](https://github.com/CycloneDX/cyclonedx-rust-cargo/blob/e58bd5590212f82c5b7e16dd3e2e819b0dbea5b1/cargo-cyclonedx/src/generator.rs) 已支持 `SOURCE_DATE_EPOCH`：固定时间戳并省略可选的随机序列号。探针确认了已安装工具的这两项行为。解决这两个字段不需要升级或禁用 SBOM 生成。[CycloneDX 1.5](https://cyclonedx.org/docs/1.5/json/) 推荐序列号，但并非必填；保留上游的可复现模式，在外部构建台账中以完整摘要标识产物。

生成器使用 Cargo package ID 作为组件引用。Rust 路径映射不会改变这张元数据图；开启映射后，探针仍恰好在三处路径引用上不同。[Rust `1.94.0` 文档](https://github.com/rust-lang/rust/blob/1.94.0/src/doc/rustc/src/remap-source-paths.md) 说明映射是文本替换，不能覆盖全部链接器或外部工具路径。不能指望一个编译器参数同时解决 SBOM 身份和未来的 PDB 路径。

## NAD05. P0-A：固定时间、输入与原生生成过程

冻结已验证源码归档、`Cargo.lock`、依赖哈希和 features、Python ABI/import-library/DLL、编译器/链接器/SDK/CRT、Rust 与 maturin 可执行文件身份。纳入运行器、构建专用补丁及明确的非 PGO 策略。使用经过验证、来自源码且写入配方的 epoch，不能使用当前时间或随意照搬探针日期。实际开始/结束时间与物理路径写入独立构建台账，并绑定产物哈希；在台账中解释可复现时间戳策略。

采用构建环境白名单并检查 Cargo 上级配置。明确控制链接器选择、wrapper、`LINK`、`_LINK_`、编译器覆盖项、按 target 设置的 Cargo 选项、profile 配置和参数优先级。记录实际编译器/链接器参数与响应文件，不能只记录期望的环境变量。对含空格参数统一使用 `CARGO_ENCODED_RUSTFLAGS`，包括路径映射与 `/Brepro`；即使链接器成功退出，出现未知或忽略选项警告也须失败。保持关闭增量编译和增量链接。证据不得包含环境密钥。

从两个独立干净根目录构建完整未插桩目标 R，逐字节比较 `.pyd`，不屏蔽时间戳、GUID 或任何节。若不同，定位新增差异并停止该门槛。不要同时更换编译器、链接器和优化 profile。增加第三次干净构建，使用长度不同且包含空格/非 ASCII 字符的路径、不同源码 mtime，并记录时区设置。保持 release 调试策略不变；若未来 I 目标需要 PDB，另行验证 PDB 身份与 PE/PDB 对应关系，不能删除调试信息来制造通过。

## NAD06. P0-B：保持来源证据的确定性 SBOM

优先在 maturin 的 [SBOM 生成边界](https://github.com/PyO3/maturin/blob/v1.13.1/src/sbom.rs) 增加小型、经审查的构建专用补丁：依赖图生成之后、JSON 序列化和 wheel 写入之前处理。保留核心源码和所有依赖检查。在隔离构建环境中固定补丁后端的源码、锁文件、补丁及可执行文件哈希；不修改服务环境，也不静默使用浮动替代版本。

将已知本地 package ID 显式映射为稳定且经过碰撞检查的引用，身份依据为已验证源码/补丁摘要、包相对 manifest 路径、名称和版本。目标子组件须保留各自的后缀/身份。registry 与 git 依赖身份保持完整。已验证源码闭包以外的路径必须有独立固定的源码清单，否则失败。明确处理 Windows 分隔符与 URI 编码；不能全局替换任意类似路径的文本，也不能合并不同来源的同名包。

将映射应用于所有 schema 定义的组件/依赖引用，包括嵌套组件和图边。拒绝重复身份、未解析引用与未处理的本地引用形式。验证映射前后的图等价，保留全部包版本、校验和、许可证、依赖边、scope、property 及 target 信息。原始 SBOM 和映射清单作为外部审计证据保存。仅允许已知身份字段与上游已说明的 epoch/serial 行为变化；不得丢弃组件或承载完整性的信息。

若无法接受补丁维护，可以评估在独立重建的 Windows 环境内使用固定逻辑根目录。复用一个脏目录或在比较时隐藏路径差异不等价。优先显式映射，因为它支持独立本地构建根目录，并使来源转换可审查。本轮尚未实现或验证该映射。

## NAD07. P0-C：最终产物门槛与反例验证

由现有 [wheel writer](https://github.com/PyO3/maturin/blob/v1.13.1/src/module_writer/wheel_writer.rs) 写入生成的 SBOM，并根据实际字节计算 `RECORD`。比较完整 `.pyd`、SBOM、所有 wheel 成员及整个 wheel 的 SHA-256。独立检查 `RECORD` 哈希/大小、唯一成员名、安全成员路径、确定的顺序/权限/压缩、完整 SBOM 图和 schema 合法性。若后续引入签名/证明时间戳，应置于明确分离且绑定未签名产物的封装；不能在宣称签名产物相等时静默排除它们。

必须覆盖的反例：去掉 `/Brepro` 或固定 epoch 能暴露对应的非确定性；修改参与编译的源码必须改变原生字节；修改依赖/版本/校验和或本地源码身份必须改变其来源证据；仅搬移相同源码不应改变结果。篡改一个二进制字节、删除一条 SBOM 边、重复组件/成员、破坏引用、修改 `RECORD`、传入非法或越界 epoch，都应被对应独立门槛拒绝。拒绝不支持的格式、缺失产物、意外的额外 wheel 和不完整尝试。构建错误/超时向上传播之前保存失败信息及所有已完成测量。

验收要求干净 R 构建全部一致且反例验证通过。不能用规范化后的比较、删除 SBOM、强制常量 GUID、复制输出产物或仅语义相同代替。同源码可复现建立的是稳定的目标身份，不是源码正确性，也不是与当前已安装官方 wheel 的生产行为等价。

## NAD08. P0-D 与 P1：先验证所有权，再允许合法大行

R 通过后，以独立、最小的分配观测补丁构建 I；R 与 I 本来就应是不同产物。分别验证每个配置自身可复现、严格的成功/失败行为和规范字节等价，并核算插桩对分配行为的影响。继续已有 Rust/Python/实际 SQLite 覆盖计划：有界且不分配的遥测、跨线程所有权、reallocation 重叠、溢出检测、密集错误和受监督的失败注入。缺少完整覆盖和源码推导上界时，观察到的峰值仍不能授权降低预留。

随后为实际未插桩候选推导阶段/所有者上界。SQL 预留仍为 `197697036 B` 和 `145472808 B`，上限为 `67108864 B`；这是读取 payload 前的拒绝，不是已测得的 OOM。已安装运行时哈希仍为 `5ba0685a9153952ce1b5e1e8e5939685a675c0ca5786e720cfef255cb1b62a3e`。新的 R/I 证明不能降低另一个运行时的预算。任何候选替换均须在集成前单独完成隔离服务比较。

将等生命周期失败 CPU 测量与可复现构建工作分开。对存在循环或未验证的失败保留物理回收/债务；构建成功不授权移除 GC。原生上界闭合后再重新评估完整资金保障的推进预算。P1 要求既有准入、CPU、并发和浏览器门槛全部通过，不能仅以 wheel 相同放行。

## NAD09. 不变的安全与验收契约

[BIR08 契约](PROPOSAL-native-build-instrumentation.zh-CN.md#bir08-阶段与不变门槛) 继续生效：每个请求独立执行前后权威检查与激活重读。保留全部历史、`19` 个原始字段和 SQL 类型、缺失依赖检查、严格模型、规范 UTF-8/EOF、bar/request/root/formula 及逐事实校验。不缓存已完成证明，不信任存储哈希。取消仅分离观察者或阻止未开始工作；物理工作、传输与保留输出一直持有所有权直到实际释放。清理失败保留债务并隔离后续代次。

保持 `64 MiB` 输入、`768 MiB` 聚合工作集、`2560 MiB` private commit、`1` 个物理证明、`1` 个排队所有者、`15-second` 等待、`90-second` 资格窗口与 `2` 次尝试。存在实现候选后重测 `1/2/8` 读取者、重算哈希后的篡改、时间边界、leader/follower 取消、最后观察者退出、死锁和清理/存储失败。失败门槛仍只允许 `3` 轮诊断；合格性能候选要求 `10` 组 A/A、`20` 个 ABBA/BAAB 块、`20%` 混合进程收益，结果最多回退 `5%`、监控/总 CPU 最多回退 `10%`，且拒绝/超时不能恶化。浏览器资格仍需每变体 `100` 次尝试、`100` 次成功后才能宣称 p95，并达到 `20%` 混合 p95 改善。

本轮核验六次探针结果、证据一致性、双语一致性和已安装运行时未变。未重跑服务/浏览器验收，也不宣称分配器上界或合法大行可用性已经通过。
