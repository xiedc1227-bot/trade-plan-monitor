# 原生分配覆盖与物理所有权

## NOA01. 决策

在 `e688dba` 之后，实测 R/I 配置已证明产物可复现；原生上界和合法大行准入仍未通过。下一步先验证 Python 与实际 SQLite 分配器覆盖，再核对物理所有权及底层分配，之后才能修改预留。生产集成和 P1 保持关闭。本方案及其[任务](TASKS-native-owner-accounting.zh-CN.md)不授权替换运行时或降低预算。

[上一轮报告](../../verification/native-artifact-determinism-p0-2026-10-23.zh-CN.md)继续作为性能基线。本次增加[计数器证据](../../verification/evidence/2026-10-23-native-owner-accounting-next/analysis.json)：在一个全新、可丢弃的进程中仅使用内存数据库，顺序执行 3 轮。未替换分配器、重启服务、访问生产数据库或修改应用代码。排除 AI 提取、日库存和 README 改动。

## NOA02. 门槛仍未通过的原因

- `native_alloc_observer.rs` 统计整个进程的 Rust 申请量，不覆盖 Python 对象、SQLite 缓冲区、底层堆容量或物理所有者。生命周期峰值不能证明单次请求边界。
- `native_allocation_child.py` 在候选计时前构造输入并运行独立参考校验器，候选校验期间仍持有参考结果。因此分配器峰值包含参考/输入历史以及预期输出的重叠。后续 SQL 夹具准备也发生在同一进程。保留这些历史测量，不得改称隔离的候选峰值。
- `ByteScan._byte_shape` 去掉了驱动 Unicode 存储，但有意保留两代数据及最坏校验解码。SQL 在 payload 查询前仍申请 `197697036 B` / `145472808 B`，上限为 `67108864 B`。这是可用性失败，不是实测 OOM。
- 早先假设删除完整解码文本后，推进预算仍为 `69195268 B`，比输入上限多 `2086404 B`。补齐原生覆盖本身不会消除该重叠，也不能证明其余部分能放下。
- 现有应用租约管理预留类别及清理债务，没有把分配器指针映射到所有者。游标关闭或校验返回不能证明返回的 bytes、模型、错误、arena 或缓存已物理释放。

## NOA03. 新观察到的边界

实际运行时为启用 GIL 的 CPython `3.14.7`，SQLite 为 `3.50.4`。证据保留了加载模块身份、源码 ID、编译选项和 DLL/驱动哈希。选项包含 `SYSTEM_MALLOC`、`OMIT_AUTOINIT`、`THREADSAFE=1` 和 `DEFAULT_MMAP_SIZE=0`；不能据此断言内存映射永远不会启用。

| 首轮阶段 | SQLite 当前字节 | Python 跟踪当前字节 |
|---|---:|---:|
| 仅 Python 申请 8388608 字节 | 0 | 8388929 |
| 内存 SQLite 表持有 8388608 字节 BLOB | 9072792 | 2808 |
| Python 行已取出且仍持有 | 9072792 | 8392247 |
| 连接已关闭，行仍持有 | 0 | 8390025 |
| 行已释放并完成回收 | 0 | 1608 |

首轮 fetch 时 SQLite 高水位达到 `17477816 B`。它不与 Python 采样峰值同时发生，不能相加成为精确总量。后续轮次保留 SQLite 生命周期高水位。跟踪包含探针自身开销并遗漏部分原生内存；这是覆盖/生命周期反例，不是生产画像、分配器钩子合格证明或全部输入上界。内存表也不等同于真实文件数据库负载。

匹配版本的 [CPython 游标源码](https://github.com/python/cpython/blob/v3.14.7/Modules/_sqlite/cursor.c)从 SQLite BLOB 数据创建 Python bytes 对象。因此，返回 bytes 避免 Unicode 解码，但不保证端到端零拷贝。观察到的连接/行生命周期差异要求区分所有者，不能在关闭游标时提前归还。

## NOA04. P0-A：受控启动器与 Python 覆盖

在隔离目录构建小型原生启动器/观测器，将 Python DLL/导入库、SQLite DLL、驱动、核心 R/I、CRT 和观测器身份绑定到运行。先在关闭观测时证明启动器不改变有效输出、规范字节和失败类别。改变运行时或观测器后需要单独验证可复现性，不能复用旧 I 身份。

以原生包装器包住现有 RAW/MEM/OBJ 分配函数，并观测 arena 分配/释放。优先在预初始化之后、完整解释器初始化之前安装；更早分配计入基线所有权。保持实际分配器策略。包装器必须线程安全，保留零大小/reallocation/失败语义。禁止 Python 回调或为简化数字而改变 `PYTHONMALLOC`。匹配版本的 [CPython 内存契约](https://github.com/python/cpython/blob/v3.14.7/Doc/c-api/memory.rst)要求完整初始化后必须包装已有分配器。其默认小对象 arena 与较大分配的 RAW 回退需要对嵌套调用和 arena 去重。

验证小型/密集对象、大 bytes、字符串、Decimal 规范化、错误和循环。区分逻辑对象释放、保留的池/arena 及实际底层释放。`tracemalloc` 仅作交叉检查。指针表必须识别安装钩子前的分配，不能把其释放悄悄算成本次证明。若公开钩子无法证明 arena 归属/保留，停止上界声明，再单独评估范围受控、版本匹配的 CPython 插桩构建；不能通过关闭 arena 宣称覆盖。

## NOA05. P0-B：实际 SQLite 覆盖

解析驱动将使用的确切 DLL，在 SQLite 初始化前通过 `SQLITE_CONFIG_GETMALLOC` / `SQLITE_CONFIG_MALLOC` 安装原生包装器，再验证导入的驱动使用相同模块。保留并转发完整 `sqlite3_mem_methods` 契约，包括大小、取整、初始化和关闭。[SQLite 契约](https://www.sqlite.org/c3ref/mem_methods.html)描述了这些方法；[配置规则](https://www.sqlite.org/c3ref/c_config_covering_index_scan.html)要求检查返回码和初始化顺序。

必须早于 `_sqlite3` 或应用模块导入：匹配版本的[模块初始化源码](https://github.com/python/cpython/blob/v3.14.7/Modules/_sqlite/module.c)会调用 `sqlite3_initialize`。迟安装反例必须失败。禁止在活动服务中关闭/重配 SQLite，也不能把另一份 SQLite 库的计数当成驱动覆盖。

观测实际元数据查询、有序 payload 查询、TEXT-to-BLOB 表达式、列转换、语句缓存、页缓存、lookaside、排序/临时存储和连接销毁。初期保持 SQL 与快照语义不变。可用时交叉核对全局/连接统计，但不能将 SQLite 计数视作驱动/Python 覆盖。缓存底层分配归连接/池所有者，子分配归逻辑使用者，避免重复计费。识别外部提供的 page/lookaside 缓冲区，以及未经过所选钩子的映射/VFS/CRT 分配。默认 mmap 配置本身不能证明不存在此类分配。小探针之后必须验证真实文件数据库夹具。

## NOA06. P0-C：物理所有者台账与核对

分开维护逻辑域台账和去重后的底层台账。当 Rust 申请、Python 对象、arena 容量和 SQLite 底层存储描述同一分配时，不得当成独立内存相加。操作系统工作集/私有提交量用于独立总量核对；未解释差额仍属于未合格部分，不能变成测量系数从预算中扣掉。

| 所有者 | 持有内容 | 释放或有预算保障的转移边界 |
|---|---|---|
| 运行时/池 | 基线 schema、arena、连接/语句/页缓存 | 证明池已释放，或明确转入已计费的保留池 |
| 独立扫描 | 元数据、SQL step/转换、驱动行及跟随者比较 | 游标及行引用释放；保留缓存继续计费 |
| 物理证明 | 原始输入、解析器/模型/错误图、规范化表示、编码 scratch、传输 | 物理完成并清理；选中结果带预算转移 |
| 返回结果 | 观察者持有的选中模型及序列化/导出结果 | 最后持有者释放；仅证明完成还不够 |
| 清理债务 | 循环错误、关闭/排空失败、未解决缓冲区 | 实际清理确认；失败隔离后续代次 |

使用原生预分配有界表，以分配身份和复用代次为键，保存域、物理所有者和大小。线程局部入口上下文为分配指定所有权；free/realloc 按保存的所有者处理，包括跨线程释放。在线程/子进程交接处显式传递所有者令牌；仅有 `ContextVar` 或线程 ID 不够。共享不可变别名指向同一分配并维护持有者计数；不同进程中的副本属于不同分配。池 arena 被多个所有者共享时，不能全归首次请求，也不能在该请求结束时抹除。

观测表/缓冲区使用前先计费。钩子不得执行 Python 回调、动态日志或无界分配；溢出/未知所有权/核算丢失将本轮标记无效，并保留未解决债务。钩子不能展开异常或阻塞等待应用预算。Reallocation 在底层调用前预留可能的新旧重叠，失败保留旧所有权，成功后才转移。清理/所有权锁须规定顺序；分配期间持有协调器锁时，回调不得重入该锁。

先把参考校验和夹具构造移到独立 oracle/准备进程。完整输出和规范流在候选测量之外比较；哈希用于标识夹具，不能替代运行时证据比较。冷初始化与热池保留分别测量，均保留在进程总量中。在尝试新准入公式前，验证结果转移、跟随者离开、延迟跨线程释放、指针复用、未知所有权和清理失败。

## NOA07. P0-D：推导并验证有完整预算的大行路径

覆盖/所有权门槛通过后，才能结合源码推导各阶段同时存活分配的上界。采用分配前可得元数据及已证明的最大 schema/形状展开；实测峰值不能单独证明全部输入上限。输入预算仍为 `64 MiB`，聚合工作集 `768 MiB`，私有提交量 `2560 MiB`；不得把输入副本换个类别来制造通过。观测存储和保留池仍计入相应聚合总量。

payload 前原子预留完整推进预算，再分配给 SQL 捕获、解析、规范化、编码和清理。禁止持有原始数据租约再等待无预算的编码器升级。准入绑定确切合格的无插桩运行时；I 的证据不能自动降低已安装 wheel 的预算。

只优化已证明的共存：所有权允许时，在前进前释放前一代驱动/原始行；复用相同不可变 bytes；保持现有 C 快路径并限制规范编码批次；只串行化并发扫描/比较中预算不足的部分。不得遗漏历史、跳过跟随者相等比较、用 token 计数替代完整校验，或将 SQL 分块送入仍需要整行的解析器却不计重建内存。即使完全校验的回退路径也无法容纳单行时，继续记录可用性失败并关闭 P1。

## NOA08. 验收与停止条件

| 阶段 | 必需证据 | 停止条件 |
|---|---|---|
| P0-A | 固定启动器、分配器探针、行为等价 | Python 分配/arena 行为或运行时身份未解释 |
| P0-B | 确切 SQLite 模块、早期配置、真实查询覆盖 | DLL 错误、迟安装、外部缓冲区或驱动缺口 |
| P0-C | 逐所有者守恒、结果/池转移、底层核对 | 丢事件、本次证明所有权未知、提前归还或死锁 |
| P0-D | 源码支持的完整预算路径、有效大行/密集行、有界并发读取 | 行超预算、拒绝/超时恶化、原生剩余部分无界 |
| P1 | 前序全部通过及真实服务/浏览器对比 | 任一门槛未解决 |

保留 [BIR08 契约](PROPOSAL-native-build-instrumentation.zh-CN.md)：每个请求独立进行前后权威检查和激活重读。验证全部历史证据、`19` 个原始字段/类型、依赖、严格模型、规范 UTF-8/EOF、bar/request/root/formula 和逐事实值。禁止完成结果缓存或信任存储哈希。

观察者取消只分离观察者或阻止未开始的工作。物理校验、返回对象和传输在释放或带预算转交其他所有者之前继续受所有权约束。最后观察者离开不授权终止同步 worker 或归还债务。分配失败注入只在受监督的可丢弃子进程执行；异常退出不产生证明，父进程债务保留到确认退出/传输排空。清理失败隔离新代次。

验证密集错误、合法大行、旧证据/重算哈希篡改、Unicode/NUL/类型差异、分配失败和溢出、游标关闭后的结果存活、保留 arena/缓存、跨线程释放、主/跟随/最后观察者取消、时间边界和存储清理失败。保持 `1/2/8` 个读取者、`1` 个物理证明、`1` 个排队所有者、`15-second` 等待、`90-second` 有效边界及 `2` 次尝试；保留小行 `1` 个证明加 `7` 次加入。

失败门槛仅允许 `3` 轮诊断。合格性能保持 `10` 组 A/A、`20` 个 ABBA/BAAB 区块、`20%` 混合进程收益，结果退化不超过 `5%`、监控/总 CPU 退化不超过 `10%`，拒绝/超时不恶化。观测开销与 R 性能分开测量。浏览器验收保持每变体 `100` 次尝试且 `100` 次成功后才能宣称 p95，并要求 `20%` 混合 p95 改善。本轮分析未进行服务/浏览器验收，不宣称性能收益。
