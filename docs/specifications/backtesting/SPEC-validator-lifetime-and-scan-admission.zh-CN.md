# 校验器生命周期与扫描准入 P0 规格

## VLS-S01. 范围

承接 72bd925 和双语方案的隔离实验。保留已有文件指纹、权威/activation/事务/时钟边界及全部历史完整性校验。不注册生产入口、不重启服务、不提交或推送。不修改 AI 提取及日库存。

## VLS-S02. 变体

A：归因解析、规范化、编码/哈希、字面比较、扫描等待和 CPU。B：直接字节 JSON 解析，保留原模型和规范化树规则，增量域哈希和规范化字面比较；保留现有公共 API。编码器片段可能很大，切分消费不构成生产者有界证明。保留保守扫描计费并报告该失败门禁。C：元数据/payload 游标生命周期共享 FIFO 扫描许可，在 8 个读取者下比较 8/2/1 槽位。先预留字节再取许可，持有许可时不再申请字节。关闭游标后释放许可，等待已获预算共享组前释放。保留原截止时间、取消及停止信号。清理失败时即使 CPU 槽位释放，账本债务和存储围栏仍保留。

## VLS-S03. 正确性

每个跟随者在原事务中独立执行完整预检和有序字面比较。验证全部 19 个选取字段、存储类型、规范 UTF-8、全部历史模型、head 身份、formula/bar/request/snapshot 哈希、缺失依赖和排名。不使用完成缓存、可信存储哈希或仅最新记录捷径。保留 2 次尝试、15 秒等待、90 秒有效期、1 个物理证明和 1 个排队所有者。取消不返还仍在执行的物理工作预算，排空及失败债务仍为权威依据。

## VLS-S04. 验收

验证接近 16 MiB 的合法输入、Unicode/转义/类型、各类哈希/标量篡改、旧行、缺失 payload、时间边界、8 读取者共享/死锁、取消及游标/worker 清理失败。运行原生命周期/权威回归。记录冻结输入哈希、完整输出等价、墙钟/线程/进程 CPU、跟踪/进程内存及字节峰值。保留 64 MiB 输入、768 MiB 工作集及 2560 MiB 私有提交上限；采样不证明原生边界。任一可用性/原生边界失败即阻断 P1 及固定性能验收，随后仅运行 3 轮 1/2/8 读取者及混合读取诊断。硬门禁通过才执行 10 对 A/A、20 组 ABBA/BAAB，要求进程混合改善 20%、单独结果回退 <=5%、监控/总 CPU 回退 <=10%、拒绝/超时不恶化。仅集成候选执行真实 owner/浏览器验收：每变体 100 次尝试，p95 需要 100 次成功。阻断候选如实报告，不集成生产。
