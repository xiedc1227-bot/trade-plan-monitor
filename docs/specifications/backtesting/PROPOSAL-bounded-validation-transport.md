# Bounded transport for pure index validation

[Chinese review copy](PROPOSAL-bounded-validation-transport.zh-CN.md). This is an analysis proposal against `f430c96`, not implementation approval or a measured production speedup. It follows the [CPU attribution report](../../verification/active-monitor-cpu-2026-10-22.md).

Subsequent authorized work is recorded in the [specification](SPEC-bounded-validation-transport.md) and [verification report](../../verification/bounded-validation-transport-2026-10-22.md): P0 completed; P1 deferred by the concurrent input-budget gate. The original analysis below is retained.

## BVT01. Evidence and decision

Recommend a staged experiment: retain the parent's existing immutable input for exact in-flight sharing, but feed a single child validator through a byte-bounded, pull-driven iterator. Do not build a complete serialized batch or a complete child input collection. Start with a private pipe and one outstanding chunk; defer shared memory and pipelining until measurement justifies their additional ownership rules.

The rejected buffered experiment retained 119,382,234 bytes (113.85 MiB) across input copies against the unchanged 67,108,864-byte (64 MiB) gate. Its controlled mixed result median improved from 5.2224 to 2.7358 seconds, but isolated monitor completion regressed by 9.05% and total mixed CPU increased by 4.57%. Streaming may lose part of that gain through additional handshakes; it must be measured again.

The current `_latest_index_records` already consumes an iterator and keeps only the latest validated record per requested index. `_market_index_from_row` performs the complete typed/canonical/domain checks for every candidate before ranking. These functions can remain unchanged while the source iterator becomes a bounded transport adapter. A separate call per chunk would lose global ranking and tie-order semantics; it is excluded.

The [offline geometry](../../verification/evidence/2026-10-22-bounded-validation-transport-analysis/geometry.json) uses only the previous frozen read-only database: 2008 candidates, 30,826,621 retained bytes, maximum candidate retention 37,206 bytes. Individually pickled candidates have a maximum of 36,295 bytes; a provisional 1 MiB grouping gives 28 chunks, with a maximum raw chunk of 1,153,404 bytes. These are shape estimates, excluding frame overhead and using an exploratory encoding, not a wire-format decision or measured peak. The earlier live input was larger: 2238 candidates / 35,441,065 retained bytes. Persistence permits index JSON up to 16 MiB; the small observed rows do not justify assuming all rows fit a chunk, and corrupt persisted inputs may exceed write-time limits.

## BVT02. Boundary and transport

Keep authority-before/after, clock checks, database transaction, activation reread and response assembly in their existing parent ownership. The child receives only immutable candidate scalar fields and requested index codes. It must not receive sessions, engines, credentials, runtime owners or authority objects. Keep the original SQL filter/order and read snapshot.

Suggested versioned protocol: `START`, `NEED`, `CHUNK`, `END`, `RESULT`, `ERROR`, `DRAINED`. Bind every message to `workerGeneration`, `jobId`, `sequence`, byte length and candidate range. `START` declares the complete candidate count and validation-code version. `END` binds total count, total bytes and the ordered transport digest; a transport digest detects incomplete/crossed transfer and never substitutes for domain verification or literal sharing comparison. Reject missing, duplicated, reordered, oversized, stale-generation and trailing frames. Unexpected EOF is an error, never iterator exhaustion. The parent must reject a result before the complete stream is consumed and the final protocol checks pass.

Use a lossless scalar encoding that preserves exact types, `json_is_text`, missing payload and original JSON bytes. Do not parse/rewrite JSON in the parent, coerce bytes into text, normalize numbers, or remove malformed old evidence. Unsupported encodings select the original fully validating thread path before submission. Compare codec round trips with `RawIndexCandidate.exact`; fuzz malformed values and framing. Pickle measurements above only estimate geometry; an implementation must select and bound its actual encoder before timing.

Only a bounded control message crosses the pipe outside the data frame. One producer owns each pipe direction. The parent bridge runs inside owned worker work, never blocks the event loop, and does not create detached senders. A child asks for another chunk only after consuming the current one; no automatic queue prefetch, complete `list`/`tuple` reconstruction or accumulated pickler memo is allowed. Input and output directions both need bounded framing and independent progress/error handling to avoid send/send deadlock.

Python documents queue feeder buffering, pipe blocking, and the risk of corrupting channels during termination: [multiprocessing](https://docs.python.org/3.14/library/multiprocessing.html). A queue item limit is not a byte limit. Fixed receive buffers also do not by themselves prove bounded allocation on an oversized message; inspect the installed Python 3.14.7 transport and test its oversize path. Shared memory remains an alternative, with explicit slot leases and all-handle cleanup on Windows: [shared memory](https://docs.python.org/3.14/library/multiprocessing.shared_memory.html).

## BVT03. Memory admission and fallback

One aggregate lease ledger must cover concurrently live input and transport copies across the parent, child and any still-draining proof. Reserve before allocation; do not serialize a complete batch and measure afterward. Include parent raw evidence, encoding scratch, frame headers, sender/receiver buffers, known kernel/transient copies, child reconstructed candidates, decoded source text, generator carry-over and output-transfer copies. Count outstanding exact-comparison/SQL batches in the analysis too; they must not become an unreported allowance per observer. Sharing references to the same immutable object does not create a second raw payload, but their container/reference overhead still needs accounting. Retain the current conservative raw-size accounting.

For the first experiment propose a 1 MiB maximum encoded chunk and a 16 MiB transport/copy reservation inside the existing 64 MiB total. This is a reservation to prove, not an assertion that the adapter already fits. It leaves at most 48 MiB for parent evidence and other simultaneous charged input allocations. On the earlier live input, parent evidence plus the proposed reservation is about 49.80 MiB, leaving about 14.20 MiB for other charged input allocations. These arithmetic values are not RSS or acceptance evidence. Reduce frame size or reject process admission if a conservative bound cannot fit; never add a separate 64 MiB allowance for each process.

Do not return a chunk's entire lease on receive or merely at the next iterator request. The unchanged validator retains its previous `candidate`, decoded `row` and `head` while asking for the next candidate, and retains selected parsed snapshots across chunks. Charge a proven overlap envelope, including the previous candidate/chunk where applicable. Acknowledgment returns only the bytes whose references are actually gone. At job completion, release child input leases only after bounded output/error consumption and `DRAINED`; release parent raw evidence only after physical completion and all existing comparison leases release. Account for old proof leases even if the next owner is admitted.

Before submission, inspect every candidate without copying its entire payload to compute a safe frame/expansion bound. If any candidate or remaining headroom cannot fit, choose the current thread validator for the whole proof. Do not split JSON tokens in the first version, reject a valid large record merely because the process transport is small, or validate a prefix in the child and silently finish the suffix locally. The current full-history validation still decides whether an oversized/corrupt source is acceptable. Keep fallback in all performance statistics.

The 64 MiB ledger is not total process memory: interpreter/modules, parsed domain objects, allocator retention and other service work also matter. P0 must measure synchronized parent-plus-child working set/private commit, retained parsed results and high-water behavior across repeated jobs. Freeze an absolute process-memory allowance before any production P1; neither a sampled RSS check nor separately summed peaks is a hard allocation bound. If input-copy bounds or acceptable process headroom cannot be demonstrated, stop at feasibility.

## BVT04. Integrity and in-flight sharing

Call `_latest_index_records` once over the complete ordered stream; call the unchanged `_market_index_from_row` for every candidate, including old/unselected evidence. Preserve typed parsing, all domain hashes, head/provider/formula/metadata binding, literal canonical equality, missing-payload rejection, ordering and ranking. Transport completion alone never certifies a proof. A child result is bound to the original physical job, and the parent's independent authority/identity checks still gate each observer's return.

Keep the parent raw collection until its existing owners release it. Every follower still reads its own snapshot and performs `RawIndexCandidate.exact` over the entire candidate sequence. Only a complete exact match while the proof remains in flight can join; neither a request key nor a digest alone qualifies. Preserve the existing completion fence, mismatch path, 8-read admission, 1 physical validator, 1 distinct queued owner and no completed-proof cache. Sharing applies only to pure proof work; no authority or assembled response is shared.

## BVT05. Cancellation, failure and physical drain

Model the physical job explicitly: `ADMITTED → TRANSFERRING → VALIDATING → RETURNING → DRAINING → RELEASED`, with validation interleaved with transfer. A cancelled HTTP/socket observer detaches through the current owner; it does not stop the sender, release the input lease, cancel a follower's proof, or mark the job drained. Preserve the current leader/follower cancellation policy; the first prototype continues an admitted pure proof to physical completion rather than adding an all-observer abort policy.

Keep existing deadlines, 15-second cooperative admission/wait checkpoints and 2 authority attempts. A deadline can end an observer without freeing live physical resources; framing must have a bounded supervision policy, but it must not reset request deadlines on retry. The physical owner retains worker/session/read permits and the corresponding storage pause until owned work and communication are complete. Child job completion and worker shutdown are separate: a persistent idle child need not exit after every proof, while service stop must close channels and join the child.

Validation errors preserve their established rejection semantics through a bounded allowlisted error code, never raw exception pickles or private evidence text. Broken pipe, child crash, invalid protocol or wrong generation fail the proof and quarantine that worker generation. No silent thread retry after submission and no duplicate physical validation. Recovery is a fresh later admission only after confirmed cleanup. On a hang, keep the existing failure fence until supervised teardown confirms process exit, bridge completion and resource closure. Forced termination, if needed as an explicit emergency path, discards channels and never treats `terminate()` returning as proof of drain. Cleanup failure retains the storage fence; do not clear it to make a health check pass.

## BVT06. Ordered work and decision gates

First implement only an isolated P0 prototype after bilingual specification/tasks are approved. Work in this order:

1. BVT-T01: Freeze aggregate accounting, actual codec, ownership state machine, fallback rules, installed-runtime transport behavior and experiment schedule. Restore bilingual parity before implementation.
2. BVT-T02: Prove lossless candidate round trips and end-of-stream validation using the unchanged pure core; test late historical corruption and chunk-boundary cases.
3. BVT-T03: Prove one-chunk backpressure, reserve-before-allocation, carry-over accounting, oversize fallback and no retained growth over repeated jobs. Measure an absolute process-memory budget proposal.
4. BVT-T04: Exercise follower/leader departures, repeated cancellation, blocked send/receive, missing completion, child crash/hang, stop races and cleanup failures. Assert no early storage/byte/worker release.
5. BVT-T05: Run fixed thread-versus-chunked-process measurements; separately record cold start, encode/decode, ACK wait, validation, parent/child CPU, synchronized memory, complete output hashes and fallback frequency. Decide whether P1 is justified.
6. BVT-T06: Only if feasibility passes, specify production worker ownership and integrate behind a default-disabled switch; then run real-owner and browser acceptance. Do not mix AI extraction or daily-inventory changes.

Freeze correctness workloads before measurement: normal input, empty stream, single row, near chunk boundary, near 16 MiB persisted JSON, budget boundary, parent evidence near 64 MiB, unsupported scalar type, oversized corrupt stored value, missing/duplicate/reordered/truncated frames, stale job ACK/result and late invalid historical input. Include changed activation/generation/configuration/progress, clock/target/90-second boundaries, retention/publication changes and shared-proof mismatch. Mutation tests must catch skipped final count/digest checks, missing canonical validation, authority bypass, early byte release and early drain.

Use the existing measurement discipline: 10 A/A control pairs and 20 alternating ABBA/BAAB blocks, 40 observations per variant for isolated monitor, isolated result and mixed work. Choose the initial 1 MiB single-chunk configuration before the comparison; any tuning requires a separately declared experiment, not replacement of failed samples. Include fallback, failures and cancellation outcomes; do not call faster successful cases an overall improvement. Require at least 20% mixed result median improvement, at most 5% isolated result regression, and at most 10% monitor median and total parent-plus-child CPU regression. Memory, full-output equality and lifecycle gates are mandatory even if latency passes.

After production design/integration, predeclare 100 attempts per variant for actual-owner mixed acceptance; require at least 100 successful observations per variant before a p95 improvement claim, retain all failures in the denominator and disclose uncertainty. Keep the existing at least 20% real mixed p95 target, no worse protected rejection rate and no new timeout/leak. Verify result/provenance/refresh/return-to-monitor, heartbeat/reconnect and 2/8-client concurrency. A failed memory, correctness or lifecycle gate leaves the current fully validating thread path in place.

## BVT07. Analysis scope

This change adds only the paired proposal and sanitized offline geometry. Production code, existing tests, configuration, live databases and services are untouched; no runtime speedup, browser rerun or new IPC peak is claimed. The previous 469 backend and 25 browser results belong to the prior P0 release. Check document parity, source/evidence references and JSON validity for this proposal. A new implementation must collect its own tests and measurements.
