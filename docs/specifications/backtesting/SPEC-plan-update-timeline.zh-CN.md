# 规格：计划更新时间线首期调整

## PUT01. 状态、目标与前提

状态：**已于2026-10-19获用户确认并授权受控实施；结束日期默认 Asia/Shanghai 当前日期且可修改。** 日期：2026-10-19，Asia/Shanghai。既有 `backtest-web` 边界内的一项能力：将手动选择已审核计划改为维护和回测计划更新时间线。英文规范输入：[SPEC-plan-update-timeline.md](SPEC-plan-update-timeline.md)。

已确认业务流程：提交首份交易计划 → 提取并审核股票与条件 → 按生效日期追加已审核计划更新 → 使用同一个连续账户按时间回测条件变化。股票代码／名称继续由既有提取和审核流程获得，不增加先选股票或单独维护股票的功能。

已确认的首期边界：

- 调整 `/backtests/new` 当前已准备计划／原文准备路径。保留现有计划工作台单版本回测入口，不将工作台库和准备库拼接为新的跨库时间线。
- 时间线代表已审核交易计划的更新序列，不代表一条历史回测。对其回测会生成新的不可变结果。编辑原文或保存草稿不代表审核通过，也不会改变正在运行的回测。
- 复用现有按交易日生效语义。起点沿用首份计划／账户及既有可用时间规则；新建表单时将 `endDate` 预填为 Asia/Shanghai 当前日期，允许修改，刷新不能覆盖用户输入；清空时保留原服务端默认处理。本期不做任意起始日期裁剪或盘中更新调度。
- 支持追加更晚的更新。同日替换、回插历史、重排、删除、合并，以及从任意历史节点创建分支均不纳入本期。

| 已审核计划库及 `planLibraryPresentation.ts` | 加载既有计划库全部分页，沿准确准备 ID／清单哈希追溯前序，保留原文与完整审核版本元数据。 |
| `POST /api/v1/backtest-plan-library/compositions` | 回测前在内部冻结选定的准确路径，保留既有逐条审核／风险复核、时间顺序及同股票检查。用户不再逐条选择组合成员。 |
| 既有自动数据准备、`prepared-loop-plan-v2`、工作进程和结果读取 | 使用当前引擎运行冻结时间表，在生效日期切换条件且不重置账户，保留历史与导出。 |

已审核末端记录本身包含完整时间表，但首期有意为新回测保留既有组合校验边界。移除页面组合操作不代表删除组合 API，也不绕过准入检查。这样无需数据库迁移、公开 API 变更、新执行模型或修改历史编码／哈希。

## PUT03. 用户流程与页面展示

| 操作 | 页面行为 | 复用的既有依据 |
|---|---|---|
| 新增计划时间线 | 直接打开首份原文表单，不先选股票。提取、修正、确认生效日期并审核后，展示提取到的股票及首个时间线节点。 | `reviewed_base=null`；原准备／审核命令。 |
| 打开时间线 | 展示股票、首次生效日期、最新审核生效日期、更新次数及审核身份。按时间展示生效日期、审核时间、原文及规则变化摘要／详情链接。 | 准确起点和选定审核末端；完整冻结时间表与既有条目／审核视图。 |
| 更新交易计划 | 为当前展示的审核末端接续一份新原文，只读展示前序。审核通过后追加节点，并可回测更新后的时间线。 | 准确 `reviewed_base`；既有日期递增、同股票、依据及审核检查。 |
| 开始回测 | 展示冻结的首份计划／账户起点、可选结束日期、响应及费用设置。一次用户操作自动冻结选中路径的全部节点，准备数据并提交原回测命令。 | 原组合、数据准备及回测提交 API。 |

将本路径的逐条复选框、手动组合按钮和通用前序下拉选，改为时间线选择、**新增计划时间线**、**更新交易计划**和**开始回测**。更新操作直接从所选时间线确定前序，不要求用户重新拼接。原文／审核修正和未完成准备的恢复保留在原上下文中。

使用现有新增／修改／保留／取消审核详情展示变化，不依据哈希推断交易规则差异。哈希／ID 核对信息保留在可展开详情中。新提取草稿显示为待审核更新，审核通过前不替代有效审核末端。准备或审核回测原文不会激活实时计划。

## PUT04. 时间线身份、存量记录与分支

- 沿准确 `preparationId` + `manifestHash` 前序引用推导时间线起点。股票、名称、原文哈希、内容版本 ID 或审核时间本身都不是时间线身份。不新增时间线表，不改写既有准备记录。
- 对线性的起点至末端链，末端就是最新已审核节点。页面选择绑定准确末端及其完整前序路径，不能跨独立起点按全局最大日期选版本。
- 既有同一起点有多个末端时，标明可选路径并要求选择一个末端，不合并分支或猜测哪次审核有效。可以继续更新已明确选定的末端路径；本期不新增分支创建／合并编辑器。
- 缺失／不匹配前序、循环、混合股票、重复来源 ID／日期、非法时间顺序或超过 256 份计划的路径，不推断为自动时间线。展示原因并保留既有记录／结果入口。新回测准入仍以服务端既有组合检查为准。
- 已核查的八条本地记录展示为**同一股票的两条独立时间线，各含四次计划更新**，同时保留审核／版本区别。不去重、合并、自动选较晚审核或重新认可任何一个版本。
- 保留原 `preparationId` 深链接、旧批次／组合准备读取、进度／恢复及结果链接。历史节点可查看；查看本身不改变所选回测末端，也不创建分支。
- 刷新或发现新更新不能静默替换当前展示的末端或进行中的请求，用户确认较新路径后才作为新的回测输入。

## PUT05. 回测快照与失败行为

1. 打开／查看时间线只读。加载其已审核末端及核对准确路径所需的计划库全部分页，不能仅打开卡片就组合、提取或运行。
2. 点击**开始回测**时固定准确有序引用、展示末端、不可变表单值及原幂等键。为该意图调用一次原组合 API，再将冻结回执交给原自动数据准备／回测提交过程。此步骤不调用 AI、不重新审核。
3. 提交前若所选路径／草稿变化，应使已准备的新回测选择失效，不能混用新旧输入。结果不确定时保留原锁定并使用同一命令／键重试。组合回执已确认后，数据／运行重试复用该回执，不再次创建组合。
4. 每次已接受回测继续持有已复制的冻结输入。后续计划更新不改变已接受／运行中的回测或旧结果；之后明确发起的回测使用新确认路径。行情、费用、T+1、风险及资金语义不变。

内部冻结快照继续是既有 `COMPOSITION` 准备记录，不属于额外的计划更新。保留旧组合 API 供既有调用者使用，仅移除调整页面中的手动成员选择交互。

## PUT06. 范围、结构与风格

预计生产修改限制在既有时间线展示模型／组件、`usePlanLibrary.ts`、`BacktestNewView.vue`，以及为安全打开准确准备记录而需要的 `usePlanPreparation.ts` 小型加载／选择接缝。复用 `useBacktestRunForm.ts` 和原文／审核组件，仅在必要时修改一个窄集成接缝。确认后新增或扩展聚焦单元／浏览器测试及双语操作／验证文档。本次不纳入无关的运行列表／筛选／结果操作改动。

沿用 Vue 3 Composition API、`<script setup lang="ts">`、类型化只读输入、原 ID 和明确操作。纯时间线推导返回数据，不修改输入或触发写操作，例如：

```typescript
type TimelineEndpoint = Readonly<{
  preparationId: string;
  manifestHash: string;
}>;
// Select one exact path; source extraction and run commands retain their existing models.
```

- 始终：保留当前服务端依据、完整分页、待定／不确定操作锁、同请求重试、防溢出和可访问性检查；同步维护中英文文档。
- 需要修订方案的范围变化：新增公开 API／schema、数据库表／迁移、依赖、工作台／准备跨库关联、任意起始日期或实时激活／执行变更。
- 禁止：改写／删除原审核记录或结果，自动合并独立链，修改存储哈希／编码公式，放宽测试门槛，后续计划更新重置账户，或在回测中发送订单／通知。

## PUT07. 验收标准

- **PUT-A01：** 空计划库时用户无需先选股票即可提交首份原文；审核后由提取结果形成股票及首个时间线节点。
- **PUT-A02：** 两份同股票的后续更新追加到准确已选前序；只允许编辑最新原文，可查看既有新增／修改／保留／取消。草稿本身不生效。股票不一致或生效日期非法由原审核／校验拒绝。
- **PUT-A03：** 已核查八条记录展示为两条四节点时间线。同名、同日、内容版本 ID 相同不能合并独立起点或审核。分支需选一条路径；断链／缺失／循环引用和多分页计划库不能静默产生不完整路径。
- **PUT-A04：** 调整后的流程没有手动计划成员复选框／组合操作。查看时间线无业务写请求。开始回测自动准确冻结所选路径，不触发提取，同一已接受意图只创建一个运行。待定／不确定重试保留原路径／键／请求体及已确认组合回执。
- **PUT-A05：** 原四计划连续回测保留准确预期：四个版本、一个账户、两笔成交、最终现金 `1019000` 分、剩余数量 `0`、费用 `1000` 分、已实现盈亏 `19000` 分及准确七点权益序列。既有 `POSITION_LIMIT_ONLY` 默认和历史资金模式不变。
- **PUT-A06：** 回测后更新时间线不能改变该次复制输入、结果响应、权益、导出或深链接。旧单份／批次／组合准备及工作台单版本回测仍按原资格规则可读／可用；API 快照和编码不变。
- **PUT-A07：** 刷新通过原准备链接恢复准确已选审核末端或未完成更新上下文；导航、后台读取和迟到响应不能混用时间线或静默改变冻结表单。保留原取消审计及 320/768/1024/1440px 检查；根字号 200% 展开详情不溢出。
- **PUT-A08：** 验收测试不修改生产库。保留原断言，不跳过测试、扩大容差、减少覆盖、屏蔽失败请求或降低阈值。适用时比较既有归属结果文件／读取响应，并复核最终差异无无关改动。
