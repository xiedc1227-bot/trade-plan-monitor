# 活动监控 CPU 归因与隔离规格

[英文规范版本](SPEC-active-monitor-cpu-isolation.md)。[方案](PROPOSAL-active-monitor-cpu-isolation.zh-CN.md)。用户于 2026-10-22 授权实施；基线 `7a7ac88`。

## AMC-S01. 范围

P0 增加默认关闭的有界归因及隔离单进程可行性实验。P1 取决于实测验收。保留已有改动，排除并行 AI 提取和日库存工作。本实施阶段不提交/推送。不改变公开 API、依赖、配置格式、金融语义或历史数据。

## AMC-S02. 归因契约

记录权威健康、投递 SQL、配置/语义检查、进度及依赖采集，不改变同步顺序、不在采集中让出执行、不导出权威对象。记录指数扫描/收集、精确比较、主从等待、完整校验、输入数量/字节及物理身份。扫描活动时间排除消费者工作，包含子阶段的区间明确保留其包含关系。一个物理证明只记录一次追踪，跟随者关联它，不重复计物理 CPU。每个拥有的读取仅记录一个事件循环延迟聚合区间，退出时取消定时器，不产生脱离管理的任务。GC 分析可选，与验收计时分离。

保留 1800 秒、1024 条追踪、64 个活动追踪、64 个区间、128 条已完成记录、1 MiB 文件及 2 个备份。仅记录固定阶段、不透明 ID、时间、数量及字节。关闭、耗尽或失败的诊断不能授权/拒绝数据、改变重试/取消或保留证据。捕获的 >=5 秒请求对齐到服务端耗时的 5% 以内，否则披露差值。CPU 时钟较粗，墙钟减 CPU 不能独占解释成 GIL 等待。

## AMC-S03. 保护语义

每次读取保留独立前后权威检查、时钟、BEGIN 快照、激活重读、全部当前计划/库存/风险/日历/证明检查及 2 次尝试预算。保留类型解析、全部域哈希、元数据/head/提供器/公式绑定、规范字节直接相等、全历史遍历及排序。保留 8 个读取、15 秒协作等待/检查点、1 个物理校验器、1 个不同输入排队所有者、64 MiB 保留证据、当前结果/元数据截止时间及仅在途精确输入共享。取消仅分离观察者；实际工作、许可、字节、会话及存储暂停持续保留到物理排空。重复取消、错误传播及清理失败围栏保持不变。

## AMC-S04. 固定实验设计

计时前冻结只读监控/结果输入。比较线程内未改变的纯 `_latest_index_records` 核心与 1 个 Windows spawn 进程，使用相同完整输入及完整输出哈希。权威和会话留在父进程；ORM、engine、凭据或活动所有者不得跨 IPC。实验不进入生产。单独测量冷导入/启动、热 IPC/复制、父子进程 CPU、完整结果完成、监控完成及合计内存。记录全部尝试及失败。

针对隔离监控及错峰结果/监控混合场景，采用 10 对 A/A 及 20 个交替 ABBA/BAAB 块（每版本 40 个样本）。混合结果在物理校验器提交后启动，不向校验注入 sleep。完整读取的诊断开关开销采用 20 个交替 ABBA/BAAB 块。不延长运行直到达标。每版本单独进行 3 次新进程内存观察，分析器计时排除。采集前冻结已声明顺序。

初次真实前后两轮采集后的补充声明：跨重启的混合中位数由 4.675 秒增加至 6.010 秒。追加严格固定的 20 个交替 ABBA/BAAB 块（每版本 40 次），在同一个运行中的 P0 进程执行真实混合 HTTP 请求。仅在每次样本完全排空后切换诊断中间件窗口，保留同一所有者、校验及输入。记录进程 CPU、完整结果哈希、状态及全部尝试。本项追加调查不替换原始观测，也不放宽任何门槛。

## AMC-S05. 门槛与 P1 决策

P0 诊断开销目标为 <=2% CPU / <=5% 墙钟。P1 可行性要求混合结果中位数改善 >=20%，隔离结果回退 <=5%，监控中位数及父子进程合计 CPU 回退 <=10%，完整结果一致且生命周期安全。将实际输入、序列化及重建副本合计与原有 64 MiB 边界比较，不给每个副本单独配额。缓冲实现超限即不通过，即使很快也不能推进。不静默替换成未测量的流式设计。生产 P1 前另外固定绝对进程内存预算。未达标则暂缓 P1，保留当前校验路径。

仅在可行性通过后，制定并实现生产工作进程所有权，再针对主要真实所有者混合验收每版本固定 100 次尝试。只有每版本 >=100 次成功观察且披露不确定性时，才要求 p95 改善 >=20%；否则报告覆盖不足。分母保留全部拒绝。拒绝率不能变差，不新增超时/泄漏、不削弱完整性断言。P0 本身不声称生产提速。

## AMC-S06. 验证与真实浏览器

先写失败诊断测试。覆盖正常/错误/耗尽/关闭追踪、迭代器关闭与取消、精确共享证明关联、独立权威变化、全历史篡改、时间边界、存储清理失败及物理排空。对新观测边界和既有权威/完整性闸门做进程内变异。可行性进程测试覆盖输出相等、旧输入损坏、取消所有权、实际完成及关闭；探索性进程测试不冒充生产验收。

运行相关后端套件、限定范围 Ruff 及前端类型检查。运行既有监控总览、流完成和回测浏览器套件。在真实服务中采集 20 次独立结果和 20 次活动监控 HTTP/结果尝试，另覆盖活动心跳及有界 2/8 客户端流程，保留失败和实际重叠资格。在可行时以相同输入比较 P0 追踪关闭/开启，并区分真实观察耗时与受控开销。使用正常启动/关闭/排空，不清除存储围栏或历史数据。发布双语报告、脱敏可移植样本、源码指纹和有依据的 P1 决策。
