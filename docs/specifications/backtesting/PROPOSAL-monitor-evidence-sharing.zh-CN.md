# 监控证据共享：CPU 竞争与下一步优化方案

状态：仅分析，2026-10-21；基线 `4c71bccfdeb5525e166d98b14dc9bc0c777d609d`。[英文规范版](PROPOSAL-monitor-evidence-sharing.md)。[上轮验证](../../verification/result-read-concurrency-2026-10-21.zh-CN.md)。[本轮隔离观测](../../verification/evidence/2026-10-21-monitor-sharing-analysis/measurements.json)。未修改生产代码、配置、服务所有权和真实证据。这是方案，不是实施批准或验收。

## MSH01. 分析结论

`RuntimeStatusReadService._read` 在所属事件循环捕获权威状态，在工作线程组装一个已提交的 SQLite 快照，重读激活身份，再捕获权威状态，最多尝试两次。比较包含 token、generation、configuration、lifecycle、阻塞/待机原因、owner 缺席、plans、dependencies 与 progress 状态。每个请求必须继续保留这些检查。

`get_dashboard`、`get_health`、股票集合/详情/健康状态都会进入这个昂贵读取。`RuntimeStatusEventStream._current_heartbeat_frame` 对每个 socket 心跳调用 `get_health`。一条 SELECT 已解决 N+1 开销，但每次物理组装仍校验全部历史指数 payload。默认 `to_thread.run_sync` 不会合并这些组装。在启用 GIL 的进程中，它们与结果审计校验争抢 CPU；增加线程不会消除重复 CPU 工作。

本轮只读实验冻结了真实监控数据库的一致副本：2,008 个候选 head，没有活动计划。这不同于上轮 1,928 个 head 的样本。运行时权威状态采用稳定的模拟缺席 owner，时间固定，真实不可变结果投影保留原校验。实验测量重复工作与收益上界，不证明真实权威状态正确性或已上线共享。

| 隔离场景 | 墙钟秒数 | 进程 CPU 秒数 | 监控物理组装数 |
|---|---|---|---|
| 两次监控读取 | 7.8355 | 7.8125 | 2 |
| 两次监控 + 结果，第 1 轮 | 10.3930 | 10.6250 | 2 |
| 一次共享组装 + 结果，第 1 轮 | 6.0348 | 6.0781 | 1 |
| 两次监控 + 结果，第 2 轮 | 10.1057 | 10.3438 | 2 |
| 一次共享组装 + 结果，第 2 轮 | 6.4013 | 6.4375 | 1 |

有效实验中的完整 dashboard 与完整结果响应一致。单次监控组装 CPU 约 3.8–4.1 秒。共享实验保留 `_read` 和观察者权威/身份探测，但未实现生产准入、时间边界、取消或关闭。约 40% CPU 收益空间是上界观测，不是预测。初次针对变化中的真实数据库进行的一致性实验被丢弃，因为背景指数发布改变了输入。受限环境中的一次辅助运行未进入测量就停止；有效运行使用获准的本地执行环境。

另一次有序扫描绑定每个原始 head/payload 字段与字面 `snapshot_json`，不解析或验证内容：2,008 行 / 32,402,117 编码字节，墙钟 0.1555 / 0.1298 / 0.1305 秒，中位数 0.1305 秒。这证明新鲜内容比较具有可行性，尚未测量拟议注册表、精确比较、保留内存或端到端候选实现。

## MSH02. 选项与建议

| 选项 | 安全性/成本 | 决策 |
|---|---|---|
| 共享已完成 dashboard 或使用 TTL 缓存 | 可能掩盖证据损坏、生命周期变化与时间过期。 | 拒绝。 |
| 按 token/sequence 共享整个进行中的 `_read` | 后到请求可能继承更早的快照、健康观测或可操作状态。当前 token 相等不代表全部数据/时间相等。 | 不直接实施。 |
| 在捕获权威/时间/数据库快照前封闭同批请求 | 避免后到请求歧义，但错峰请求需等下一批，且需要重试/生命周期所有权。 | 必要时可测的安全备选，不作为首个实施项。 |
| 每个请求证明原始内容相同后，仅共享在途指数证据校验 | 命中实测 CPU 热点，同时保留各请求的快照、观测、权威状态和响应格式化。增加有界原始输入所有权与新鲜比较扫描。 | 推荐首个切片。 |
| CPU 独立进程或复用已完成类型对象 | 生命周期、一致性和内存复杂度更高。 | 等本切片测量后再评估。 |

共享函数保持纯粹：有序不可变 head/payload 值 → 校验全部候选 → 已验证排名 → 不可变选中记录。必须复用 `_market_index_from_row` 与 `list_latest_market_index_snapshots` 相同的类型/规范化/哈希/provider/head 绑定检查。不接收 ORM session、运行时 owner、依赖当前时钟的资格计算或权威状态提供器。不建立监控代码对回测线程生命周期的依赖。

## MSH03. 准入与内容证明

1. 每个调用方仍执行自己的 `_read`：所属循环捕获权威状态及自身观测时间；使用带显式 `BEGIN` 的新鲜独占 session；在该快照检查计划、证明、库存、风险、规则和日历。不共享整个响应、`get_health` 输出或可操作标记。
2. 在同一事务扫描请求范围内全部历史 head/payload 候选，保留左连接与缺失行可见性。稳定 head 键顺序仅用于内容比较；选择仍使用已验证 `snapshot_rank`，不用 SQL 元数据最大值。
3. 私有命名空间包含 composition/数据库身份、validator 契约、`MAPPING_VERSION`、公式定义与请求指数范围。保守首版还可分开 generation/configuration 命名空间。不假设任意 `RuntimeReadAuthority.token` 都可哈希。摘要仅作查找预筛，不能代替验证或充分的相等证明。
4. 加入者必须将完整有序原始行与活动任务的不可变输入逐字节比较，覆盖字面 JSON、全部 head/payload 字段、缺失 payload 标记与候选数量。摘要碰撞、部分/前缀相等、文件名相同或仅存储哈希相同都不能准入。比较以 128 行批次流式执行，不额外保留完整输入副本。
5. 只在物理校验仍进行时加入。已完成 future，包括完成/清理之间的竞态，不能服务新调用方。如果比较时任务已经完成，执行新的完整校验。内容不同走调用方同一快照中的独立验证；可能需要在该事务重新扫描，以恢复已消费的前缀。不能遗漏已扫描行或跳到另一个事务。
6. 领导者校验每个候选，包括未选中的损坏历史，只返回不可变选中记录及内部完整性元数据。跟随者继续在自己的事务组装自己的 dashboard/health/detail 响应。不能在线程/消费者之间共享 SQLAlchemy 身份映射或可变响应对象。

后到调用方因在自己的快照重读了相同的完整输入，可以共享昂贵的纯校验。这不允许它继承领导者更早的快照或时钟。证据缺失/不同必须失败或完整重验，不能退回此前有效响应。

## MSH04. 权威、时间与心跳边界

每个调用方（包括跟随者）保留所有既有权威状态前后比较、激活身份重读和最多两次尝试。重试预算按调用方计算，不能共享两次之后再私下尝试两次。提供器失败表示权威状态不可用，不能转换成 owner 缺席。权威提供器仍在所属循环调用。

各请求保留自身 `observedAt`、progress 状态、期望目标、健康观测/年龄及资格/截止时间计算。不能给旧 dashboard 换时间戳或重置动作有效窗口。指数制品验证不依赖调用方当前时钟；实时计划/输入证明及时间敏感投影仍独立执行。已有条件计划 90 秒窗口、日期/交易时段切换和命令预检不变。

每个 WebSocket 仍使用自己已投递的重放游标构造心跳。共享指数证明或 dashboard 高水位 sequence 不能替换这个游标、认证进度或跳过重放。心跳周期与持续发布下的防饥饿保护不变。

隔离边界夹具说明了捷径风险：证据被修改时，事件序号保持 7；固定观察连接的 `PRAGMA data_version` 从 2 → 3，新连接却返回 2。写连接自己的提交不会改变其自身数值。持有的 WAL 读取仍看到旧字节，新事务看到新字节。SQLite 文档规定 data version 只能在同一连接比较，WAL 读取保留自身快照。这些值最多作为可选失效提示，不能证明内容相同。参见 [SQLite PRAGMA](https://sqlite.org/pragma.html#pragma_data_version) 与 [SQLite 隔离](https://sqlite.org/isolation.html)。

真实 `RuntimeProgress` 夹具在截止时间后从 `WORKING` 变成 `STALLED`，权威 token 却相同。token 相等不能替代既有 progress 状态比较。只按完整内容共享的指数校验器避免缓存这些依赖时间的权威事实。

## MSH05. 有界所有权与关闭

建议初始限制，需在双语实施规格中定稿：1 个活动物理指数校验、1 个待执行的不同内容组、8 个已准入监控观察者、全部任务合计 64 MiB 原始输入保留预算。比较以 128 行批次流式执行。实验的 32,402,117 字节是编码内容量，不是 Python 保留内存或 RSS；需明确计入 DTO/字符串/字节对象开销。预算紧张时，在同一有界物理准入内切换完整流式校验，或返回既有 `SERVICE_UNAVAILABLE`，不能部分验证或回退旧响应。不允许无界物化或隐藏的 8 × 全量输入副本。

先判断能否加入，再申请仅领导者需要的校验许可。跟随者不能持有领导者所需许可。在已有工作线程中使用同步 future/condition 或等价的受控桥接；不新建大型 CPU 线程池，也不阻塞 owner 事件循环。保留调用方期限，不重置排队年龄，并观察全部异常。调用方取消仅释放自己的观察资格，不能取消其他请求、提前移除物理任务或在线程完成前释放字节预算。参见 [AnyIO 线程取消](https://anyio.readthedocs.io/en/stable/api.html#anyio.to_thread.run_sync) 与 [Python shield](https://docs.python.org/3.14/library/asyncio-task.html#shielding-from-cancellation)。

所有权属于监控读取服务/composition。除共享校验，还要跟踪整个物理组装/身份读取。关闭顺序为拒绝新读、撤销当前运行时权威状态、排空已拥有的工作与 session，再允许数据库检查点/销毁。超时不能报告成功排空或释放仍运行线程的所有权。需审查 `MonitorWebComposition.stop` 与运行时数据库关闭顺序；当前服务没有可直接复用的共享任务关闭边界。

## MSH06. 实施顺序与验收门槛

- MSH-T01：记录双语规格/任务；分项测量来源端点/心跳、原始扫描/比较 CPU、物理校验、共享命中/未命中原因、权威重试、排队/排空和保留字节/RSS 峰值。日志不记录证据正文或凭据。建立相同冻结样本与真实请求重叠基线。
- MSH-T02：隔离不可变指数输入与纯校验器，先在无共享情况下证明字面输出/哈希/错误/排名等价，再实现有界在途注册表与精确比较。默认保留独立仓库行为，显式注入由监控拥有的校验器。
- MSH-T03：接入 HTTP 与心跳消费者，保留各自 `_read` 检查；实现取消、重试预算、关闭与存储失败行为。不改变 API/schema、心跳周期、超时、保留规则或结果审计。
- MSH-T04：执行安全矩阵和真实浏览器路径，对比 CPU 与耗时，只保留测得收益的改动。本切片不扩展到整包响应共享。

强制安全矩阵：共享任务期间活动 owner/配置/generation 变化；STOPPING/STALLED 与权威不可读；激活 ABA；库存/风险/规则/日历/证明变化；90 秒/目标/日期边界与时钟回退；同长度/同时间戳 SQL 篡改；规范字节/domain/hash/formula/provider/head 绑定损坏；未选中历史缺失；删除/保留；强制摘要碰撞；完成/清理竞态；相同/不同范围；领导者/跟随者/全部观察者取消；准入/字节预算满；持有工作线程时关闭；心跳游标/周期/重放。每次拒绝共享仍须完整校验或失败关闭。已有结果事件集合、pin、保留与物理排空回归仍必需。

建议性能门槛：2 个和 8 个相同内容的重叠监控调用加一次结果读取，共享遍历只校验一次全部 2,008 个候选；完成后的每个新请求都重新遍历。至少 10 轮交替受控测量，进程 CPU 中位数下降至少 25%，单监控场景回退不超过 10%。同时报告真实 HTTP 结果延迟、监控等待、事件循环/服务探测、准入拒绝与 RSS，保留现有心跳/客户端期限。这些是拟议门槛，尚未在生产候选上达到。如果实际重叠很少或字节/生命周期开销不达标，保留原路径，再单独评估表示层/进程优化。
