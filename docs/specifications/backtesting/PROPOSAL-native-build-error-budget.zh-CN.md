# 原生构建证据、密集错误生命周期与有预算保障的大行准入

## NBB01. 决策与范围

继续独立 P0；P1 维持 NO-GO。下一步应确认实际原生构建和分配契约，区分错误构造与错误持有，证明所有权后再替换旧预留。继续调整编码器不是首要依赖。

本方案承接 `487f517` 的[已提交 P0 报告](../../verification/c-native-p0-2026-10-23.zh-CN.md)。[本次分析证据](../../verification/evidence/2026-10-23-native-build-error-budget/analysis.json)包含源码/安装包指纹、只读获取诊断、各路径一次错误生命周期探针和准入算术。本次仅新增双语方案和证据。生产代码、实验实现、真实数据、服务及并行 AI 提取/日库存工作均未改变。不提交、不推送，也不声称浏览器性能改善。实施前补齐双语规格与任务。

[官方发布元数据](https://pypi.org/pypi/pydantic_core/2.46.4/json)指向正确源码。[发布工作流](https://github.com/pydantic/pydantic/blob/cf67d4b3193c3fe43ede18612ed62785eee11382/.github/workflows/ci.yml)使用浮动 Rust `stable` 工具链；`rust-version = 1.88` 是最低要求，不是实际编译器。其 Windows/Python 作业和 [PGO action](https://github.com/pydantic/pydantic/blob/cf67d4b3193c3fe43ede18612ed62785eee11382/.github/actions/core-build-pgo-wheel/action.yml)声明生成/使用性能剖析数据。作业成功不能解释本机二进制的 PGO 标志，也不能将其字节绑定到该作业。这是尚未解释的来源差异，不是篡改证据，也不能证明 PGO 导致此前的性能结果。

目标作业日志请求返回 `410`；按名称查询产物未返回任何产物。源码包和 wheel 的 [PyPI Integrity API](https://docs.pypi.org/api/integrity/) 请求均返回 `404`，包括规范化项目名称后的请求。这些是本次观察到的获取限制，不能泛化为其他来源证据都不存在。不能替换成临近版本、假定当年的工作流使用今天的编译器，或凭 wheel 文件名推导分配器契约。

## NBB03. 密集错误持有远不止外层回溯

发布源码给出了具体所有权链：元组校验收集逐项错误；`ValidationError` 拥有 `Vec<PyLineError>`；每条错误保留输入对象。内部错误转换时可能实体化 Python 输入对象。函数校验错误还保留抛出的 Python 异常。我们的 OHLC 后置校验器在 bar 模型构造后抛错，因此错误对象可能继续持有输入、模型与栈帧。各类所有者的精确占比仍需分配插桩；本次探针没有把全部字节归因于某个原生向量。

`hide_input` 和 `errors(include_input=False)` 控制显示/导出，不阻止错误对象构造。调用 `str(error)`、`errors()` 或 `json()` 可能继续分配输出；缩短最终响应不能消除构造峰值。快速失败或截断校验会改变本任务要求的行为，本方案不采用。

原路径离开 `except` 后才抛出 `ProjectionError`；实验路径在处理器内用 `from error` 抛出。本次探针同时追踪 `__cause__` 和 `__context__`、按身份去重，且不格式化或导出错误。原路径没有这两种链接；候选路径保留一个含 `40000` 条错误的 `ValidationError`。此前错误数为空不代表没有错误。

| 可追踪内存，MiB | 原路径 | 融合候选路径 |
|---|---:|---:|
| 构造/返回峰值 | 184.2095 | 149.5323 |
| 持有失败，垃圾回收后 | 34.7044 | 149.5291 |
| 清空外层原因/上下文回溯，继续持有错误 | 0.0247 | 149.5246 |
| 释放完整外层链并回收后 | 0.0246 | 0.0252 |

这是基于已有密集对象合成夹具、每条路径一次的顺序诊断，不是吞吐比较。不包含预建原始输入和未追踪原生分配。清空外层回溯只是诊断操作，不遍历藏在原生逐项错误中的 Python 异常。它证明候选路径的错误对象图在外层栈帧清理后仍被持有。此前峰值可以作为各实现的观测值，但两条路径的失败后所有权策略不同，不能据此证明失败内存行为等价。

下一步实验分别测量解析/错误构造、失败边界捕获、游标关闭、物理排空、观察者投递和最后观察者释放。完整校验返回后，由物理 worker 在独立作用域内生成有界且不可变的失败描述，释放所持对象图，再发布结果。保持失败类别与含义，单独处理清理失败。各观察者获得新的本地异常，不能共享可变回溯。不能清理运行中任务的栈帧，也不能在观察者取消时归还租约。去掉异常链持有可能缩短高内存持续时间，不能解决此前的构造峰值。

## NBB04. 大行拒绝仍由旧算术决定

这两个夹具的 `ByteScan` 预留为 `12 * N + 23040` 字节。其调整仅扣掉驱动 Unicode 存储。剩余 JSON 项为 `2 * (N + N + 4 * N)`：两代驱动字节、原始捕获和解码文本。字节解析消除了显式的整段 Python 输入解码，但解析器字符串、原生树和错误输入属于独立责任，不能从账目中消失。

| 字节 | 长 Decimal | 密集对象 |
|---|---:|---:|
| 原始 JSON | 16472833 | 12120814 |
| 当前工作区预留 | 197697036 | 145472808 |
| 假设仅扣除解码文本项 | 65914372 | 48506296 |
| 加上元数据与当前 256 KiB 编码器预留 | 69195268 | 51787192 |
| 相对 67108864 的余量 | -2086404 | 15321672 |

附加项是 `131072` 字节元数据和 `12 * 262144 + 4096` 字节编码器预留。因此，只去掉旧文本项，长 Decimal 行仍超出约 `1.99 MiB`。编码目标为 `64 KiB` 时，假设总量为 `66835972` 字节，未计其他所有者前仅剩 `272892` 字节。这不构成准入通过：编码器系数自身未经证明，原生所有权不完整，算术也未包含并发/跟随者工作区。缩小编码目标还必须重新测量 CPU。

当前元组切片复用不可变字节对象。这使别名去重成为候选优化，但不能直接扣预算：需证明驱动值、原始行、生成器、前后两代、所保留选中结果和失败路径的身份与生命周期。SQLite execute/step/cast 缓冲并未证明是别名。每份物理分配只计一次，同时保留其所有者和转移重叠。不能悄悄把输入开销移到模型类别、将代数减半、提高上限或缩短可接受数据来换取通过。

## NBB05. 建议实验与停止条件

| 阶段 | 具体工作 | 门槛 |
|---|---|---|
| P0-A | 双语规格/任务；产物至源码/构建清单；依赖源码校验和；编译器/CRT/分配器及模式身份 | 证明更小预留前，解决实际构建证据 |
| P0-B | 错误生命周期分阶段测量及有界失败结果实验，完整校验不变 | 证据接受/拒绝与失败类别不变；证明对象图真实释放；不能把持有量下降称为峰值下降 |
| P0-C | 源码推导的分配/生命周期表，以及成功、密集错误、清理失败原生插桩 | 闭合各临时分配/重分配/所有者路径及聚合上限，否则停止缩减预算的集成 |
| P0-D | 按阶段核算、完整预付的证明/比对预算包；合法大行 SQL 与并发实验 | 合法夹具在原限制下完成载荷读取、完整校验、排序和物理排空；无部分租约死锁 |
| P1 | 条件式集成及混合负载/浏览器测量 | 之前的正确性、内存、可用性与性能门槛全部通过 |

P0-A 必须有明确替代路径，不能无限搜索源码。优先恢复官方构建清单与产物绑定。若不可得，评估使用锁定发布源码与依赖，在隔离环境中进行可复现构建，声明编译器/选项/分配器，并生成插桩伴随构建。这是独立的资格目标与二进制摘要，不能用来认证本机 wheel。需对照目标发布二进制解释插桩开销和行为差异；不能悄悄替换生产依赖。如果两条路线均无法闭合契约，应报告具体未覆盖的分配器/构建路径，维持 NO-GO。

P0-C 覆盖 SQLite/驱动缓冲、不可变原始数据所有权、解析临时区/树/字符串缓存、模型、错误向量/输入转换/内层异常帧、dump/规范化容器、排序向量、C writer 增长、UTF-8 副本、选中结果、替换重叠与保留的失败结果。同时提供源码推导的分配前上界和分配器/进程观测。`tracemalloc`、工作集采样和压力测试通过均可帮助发现违规，但任何一项都不能单独证明瞬时上界。覆盖当前输入范围内的所有畸形持久化输入。若需要结构计数预扫，它必须有独立有界启动预算并计入 CPU；不能认证证据、跳过检查或引入新的接受限制。

P0-D 在载荷执行前预留完整推进预算包，编码与阶段转换从包内子分配；不能让扫描持有原始租约，再阻塞等待未获预算的编码升级。先保障一个证明所有者，再准入能够容纳的比对工作区。保留八读取者准入，按字节限制实体化并发并实施有界公平等待；不承诺同时持有八份大缓冲。跟随者必须独立读取全部原始字段/类型/行，并与仍在运行的证明精确比较后才可共享。保留小行 `1` 证明加 `7` 加入场景。禁止完成缓存、只比较摘要或把重复物理证明当作回退。非阻塞升级/重试保留原时钟与尝试预算。只有单行完整推进预算已证明可容纳时，才能把完整校验流式路径作为回退。

## NBB06. 不变量与定向验证

每个请求保留独立的前后权威检查、激活状态重读、自身事务/观察时钟及尝试次数。保留所有历史行、全部 `19` 个原始字段及 SQL 类型、头部/缺失依赖、严格模型、规范 UTF-8 与 EOF、有序 bar/request 域、根哈希、公式定义和每个 fact 的公式哈希。不能信任存储哈希或只校验最新行。

测试长 Decimal、密集合法/非法对象、好坏项混合、每项多个字段错误、末尾篡改、畸形 UTF-8、深层/重复/额外 JSON、Unicode 扩宽及标量/分块边界。区分初始错误构造、错误导出与对象图持有周期。验证失败结果精简前后的完整校验行为不变，包含连贯重算哈希的域篡改，以及删除域/字面值/权威检查的源码级变异。

并发覆盖 `1/2/8` 个读取者、相等/变更/晚到 cohort、领导者/跟随者取消、最后观察者离开、大小行公平性及预算满载推进。检查准入前、原生解析/编码中、比对中及资格/截止边界两侧。取消只能脱离观察者或阻止未开始工作；同步原生工作直到返回前始终有所有者。债务保留至游标关闭、物理 worker/bridge 排空、结果消费与对象图实际释放。存储清理失败保留债务并隔离后续代；不能提前返还、返回部分证明或取消其他观察者的工作。

## NBB07. 保持量化门槛

保留 `64 MiB` 输入、`768 MiB` 聚合工作集、`2560 MiB` 私有提交、`1` 个物理证明、`1` 个排队所有者、`15-second` 等待、`90-second` 资格和 `2` 次尝试。独立扫描并发作为单独变量。不能把原生/输入分配藏入其他类别，或从进程总量中漏掉保留结果与错误所有者。

未通过门槛时仅允许 `3` 轮明确标注的诊断。具备资格的候选执行 `10` 对 A/A 与 `20` 个 ABBA/BAAB 区块，混合进程收益至少 `20%`，结果与监控/总 CPU 回退分别不超过 `5%`、`10%`，且拒绝/超时不得恶化。真实所有者/浏览器验收每版本需要 `100` 次尝试，不足 `100` 次成功不得声称 p95，保留原 `20%` 混合 p95 目标。此前融合方案 CPU 改善作为历史证据保留，不算新的混合负载通过。

## NBB08. 复现与限制

证据嵌入获取与错误探针源码、产物/源码指纹、观察到的获取失败、精确字节算术和冻结夹具 SHA256。归档获取只读官方包，不安装或执行包内代码。在项目环境中针对 `.pytest_cache/cna-measurements/dense.sqlite3` 运行嵌入的错误探针；它仅写临时输出，并在前后检查输入哈希。清理栈帧阶段仅用于诊断，不建议作为生产回调。仓库源码指纹标识本次检查的代码。

本次分析推进了源码来源证据，并解释密集错误持有和确定性的预检拒绝；没有证明原生分配上界、实现更小的 SQL 预留、重跑性能验收或验证浏览器行为。下一次实施应逐阶段报告通过、失败或明确延期，不能继续把源码可得性与实际构建资格合并称为同一个证据缺口。
