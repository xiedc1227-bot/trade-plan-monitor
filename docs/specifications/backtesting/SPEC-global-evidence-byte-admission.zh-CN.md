# 分配前全局字节准入实验规格

## GBA-S01. 范围

P0 是基于 1748555、位于 scripts/experiments 的隔离实验。保留全部生产代码及现有分析。不重启服务或修改真实数据。实施本身不提交或推送；后续提交审查可在用户明确授权后执行。P1 必须通过全部可行性门槛。

## GBA-S02. 准入

注入一个账本，覆盖各读者及排空证明的保留输入、传输、SQL/转换工作区和元信息。保持 64 MiB、8 个读者、1 个物理校验者及 1 个排队主请求。载荷 execute 前预留。每个扫描器预留 128 KiB 元信息，采用 32 行元信息页及初始 1 MiB 扫描工作区。在原显式事务内用 typeof 和 octet_length 对全部选中列估算，检查 UTF-8 能力。载荷查询仅限获准行定位符。不能以元信息替代精确比对或原校验。原生/内部分配仍是独立测量门槛。

## GBA-S03. 所有权

借用证明前预留推进空间；主请求不等待尚未准入的比对。不匹配主请求排队前，释放比对行/游标及借用。保持每个请求事务、前后权威及激活检查、2 次尝试、15 秒等待截止时间及 90 秒有效期。租约覆盖生成器遗留引用、取消以及子进程 DRAINED/确认退出。清理失败隔离账本。禁止提交后回退、完成证明缓存或刷新截止时间。过大的保留输入可在提交前使用完整校验的预算流式读取；单行无法准入时失败关闭，并判定可用性门槛失败。

## GBA-S04. 冻结门槛

输入预算保持 64 MiB。采样前冻结实验父子工作集上限 768 MiB、私有提交量上限 2560 MiB，以此前进程观测 506.63 MiB / 1938.95 MiB 加余量确定。这是实验上限，不是部署内存保证。要求完整证明/输出等价、独立权威、无死锁或提前清理、不新增合法样本拒绝。包含接近 16 MiB 的受支持输入和畸形超大值。任一硬门槛失败时，P1 不推进并停止固定性能验收；改采集 1/2/8 读者对比的 5 轮诊断和 5 对交替混合诊断，明确排除在性能验收之外。不得替换失败或放宽限制。

## GBA-S05. 性能

硬门槛通过后，对原线程、预算线程、预算进程的每组两两工作负载采用 10 对 A/A 和 20 个 ABBA/BAAB 区块，包含孤立及混合读取。进程集成要求混合结果至少改善 20%，孤立结果回退不超过 5%，监控/总 CPU 回退不超过 10%。记录准入等待、SQL 次数、共享、不匹配、租约、失败及完整完成时间。父子同步内存与 Python 分配分别测量。未证明的原生边界或未明确的部署所有权仍阻塞 P1；浏览器/真实所有者验收以集成为前提，每方案 100 次尝试，不足 100 次成功不声称 p95。

## GBA-S06. 验证

测试精确字节边界、execute 前申请、类型/长度往返、旧/缺失/规范化篡改、变更快照、8 读者推进、排队主请求压力、截止时间、重复取消及清理失败。复用未变更的权威/保留规则/所有权回归，并验证进程传输排空。变异检查必须检出缺失预留、提前释放和绕过字面比对。发布双语报告，包含源码/输入指纹、全部诊断尝试和明确限制。
