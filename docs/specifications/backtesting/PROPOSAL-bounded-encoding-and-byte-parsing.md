# Bounded encoding producers and byte parsing proposal

## BEP01. Decision and scope

Recommend another isolated P0: a size-planned C encoding producer, a separately proven byte-parser lifetime envelope, then revised byte admission. P1 remains blocked. Do not integrate the previous Python token encoder or merely reduce its reservation multiplier. Start from `786950f`; preserve existing files and parallel AI extraction/daily-inventory work. This change contains analysis, paired proposal documents and sanitized probe evidence only. No runtime/test change, service restart, commit or push.

The [previous report](../../verification/validator-scan-2026-10-23.md) demonstrated lower traced memory but failed CPU, valid-large-row availability and native-bound gates. [New analysis evidence](../../verification/evidence/2026-10-23-bounded-encoding-analysis/analysis.json) includes the probe source, all diagnostic results and fingerprints. Its frozen database remains unchanged. These observations identify experiments; they do not establish a production memory guarantee or fix the real-page tail latency.

## BEP02. CPU regression and alternatives

The installed CPython `JSONEncoder.encode()` invokes the C encoder through its one-shot path. The previous `iterencode()` call uses Python container traversal, produces many small strings, then encodes each piece to UTF-8. Even the first 1887-byte historical row produces 230 tokens. A C one-shot call is not a bounded stream: it completes a Unicode writer before returning its output. Splitting that output afterward does not bound its allocation.

The new probe keeps all original model, domain, scalar, head, historical-row and literal checks. It substitutes only the experimental producer in process-local memory. There are 3 alternating rounds over the same 2008 rows and 5 index codes. All 15 complete output comparisons match the original validator. Timing excludes SQL, authority and fixture construction.

| Variant | Median wall seconds | Median thread CPU seconds | CPU change versus original |
|---|---:|---:|---:|
| Original full validator | 1.9233 | 1.890625 | 0.00% |
| Previous Python token producer | 4.1880 | 4.171875 | +120.66% |
| Byte parser with whole-document C producer | 1.9803 | 1.968750 | +4.13% |
| C subtrees, 64 KiB logical output target | 2.3640 | 2.328125 | +23.14% |
| C subtrees, 256 KiB logical output target | 2.3694 | 2.343750 | +23.97% |

The whole-document variant is an attribution control, not a memory-safe candidate. The subtree probe first traverses the normalized tree to estimate output, stores a container-size map, and uses C encoding for fitting subtrees/list batches. It repeats planning for each domain and literal traversal. This restores much of the lost CPU but still exceeds the 10% regression ceiling; increasing the target alone does not solve it. Its size map, Unicode writer, batch slices and UTF-8 allocation are not covered by an enforced lease. Do not copy this diagnostic as the implementation.

Keep the original generic model/normalization policy. First evaluate size information accumulated once during normalization, bounded batch planning and a small-document C fast path. If a residual repeat-encoding cost remains, separately trial one canonical traversal feeding both the snapshot-domain hash and literal comparator, with explicit handling of the excluded `snapshot_hash` member and commas. The complete literal still includes that member. Bar/request domains and every formula check remain independent. No cached proof or trusted stored digest is introduced.

## BEP03. Valid scalars are bounded; valid containers are not small

The current exact models bound normalized Decimal expansion to 10000 characters and `display_name` to 32 characters. Remaining normalized scalar types are bounded identities/enums, hashes, constrained integers and canonical timestamps. This gives a plausible schema-derived scalar envelope after successful model validation: a Decimal string token requires at most 10002 UTF-8 bytes including quotes. Audit every field and custom validator before treating this as a complete bound. The generated JSON Schema alone omits the custom Decimal expansion constraint.

There is no declared array-length maximum on `five_minute_bars`, `official_daily_bars` or `indicator_facts`. The 16 MiB write limit does not make an entire normalized snapshot or encoded array small. Keep the existing accepted input set: do not add a bar-count or Decimal-precision restriction to make admission pass. Also account for sorted reference vectors, request ordering keys, model-dump containers and retained selected models. A schema/version change must invalidate the optimized envelope and block its use until requalified; it must not silently use an old bound.

Use a public C-backed encoding call on a proven-fitting normalized subtree. Preserve `ensure_ascii=False`, `allow_nan=False`, sorted keys, compact separators, canonical Decimal and microsecond timestamp semantics. Batch by conservative encoded size, not fixed row count. Start with 64 KiB and 256 KiB logical targets for measurement; these are not total memory limits. Include worst-case Unicode width, writer growth/reallocation, UTF-8 conversion, batch containers, comparison buffers and the preceding yielded chunk. Do not call private `_one_shot=True` on an arbitrarily large root and label it streaming.

Additional byte-equivalence checks cover the large Decimal fixture, Unicode/control characters and a large array. All 6 comparisons pass. The generic `6 * len(string)` planning rule makes the large Decimal fixture emit 24081 chunks at 64 KiB versus 1041 at 256 KiB. This is another reason to carry validated scalar kind/length information from normalization: canonical Decimal digits are ASCII and do not need the general escaped-string expansion factor. This refinement must follow verified type policy, not a guess about raw JSON. Neither emitted chunk sizes nor these checks prove producer/native allocation bounds.

## BEP04. Byte parsing needs shape and failure envelopes

Direct `model_validate_json(bytes)` removes the full decoded Unicode input, but still builds validated objects. The API accepts a complete JSON input; byte input is not a resumable parser or a promise of zero native copies. Keep the immutable input owner alive throughout parsing. Do not switch to `model_construct()`, partial parsing, or `from_json()` plus Python validation: JSON-mode and Python-mode strict behavior can differ.

The following single-run traced probes start after raw input construction. Both valid fixtures pass the unchanged full validator. The dense fixture uses fixed `+08:00` timestamps satisfying the existing model contract; an initial fixture-construction attempt using historical timezone rules failed before measurement because of daylight-saving offsets, and is recorded separately.

| Shape | Raw JSON bytes | Contents | Text-input parse peak MiB | Byte-input parse peak MiB | Byte-input invalid-OHLC peak MiB |
|---|---:|---|---:|---:|---:|
| Long Decimals | 16472833 | 480 bars, 8500 decimal digits | 94.26 | 7.54 | 23.94 |
| Dense small objects | 12120814 | 40000 bars, 1 decimal digit | 107.95 | 73.27 | 149.53 |

The invalid variants replace every high price with an invalid OHLC value. They produce 480 and 40000 errors respectively. Error objects are deliberately retained until explicit release; traced live storage then returns near baseline. This is a parser/error-lifetime diagnostic, not evidence of a production leak. The existing flight outcome sanitizes the enclosing projection error instead of retaining its traceback. Measure the peak before that sanitization as well as after drain; shortening an eventual message cannot undo an already allocated error collection.

These measurements exclude prebuilt raw input and untracked native allocations. They are not end-to-end memory peaks, enforced bounds or timing acceptance. In particular, the previous 23.71 MiB complete-validator measurement on long Decimals cannot be generalized to all legal rows. A byte-length-only coefficient calibrated to that fixture is insufficient. Evaluate a documented envelope over raw bytes, structural cardinality, Decimal digits, Unicode/escaping, temporary native values, validation errors and retained results. Pin the installed parser build and audit its allocation/cleanup behavior. If a bounded structural prepass becomes necessary, measure its extra full scan and prove it never certifies evidence or changes valid-input acceptance; do not introduce a new parser implicitly in this P0.

## BEP05. Admission and lifetime design

The current byte scan still reserves approximately `12 * N + fixed_overhead`: two generations of driver bytes, raw bytes and a worst-case `4 * N` decoded input. The supported 16472833-byte row therefore requests 197697036 bytes before payload execution and fails the unchanged 64 MiB input limit. This is a conservative old-path reservation, not a measured requirement of the new byte parser. It must not be replaced by a measured average or a guessed `2 * N` bound.

Prepare an allocation/ownership table for each phase: metadata; SQL execute/fetch; immutable raw capture; parser input/temporaries; model and normalization; encoder/hash/literal comparison; selected-result retention; exception/drain. Identify every allocation, preallocation lease, overlapping owner, transfer and physical release condition. In particular:

1. Preserve the established input ledger scope: retained raw inputs, SQL/input conversion, canonical/transport input copies, comparison work and metadata across all readers and draining generations. Parser models/native memory and selected outputs also remain in the aggregate process-memory gate under the existing accounting contract. Do not reclassify previously charged input text as model/output memory to manufacture a fit. The 73.27 MiB model-heavy parse result does not, by itself, mean the 64 MiB input ledger was breached.
2. Remove only a proven-absent decoded-text allocation. References to the same immutable bytes can share one owner; extra buffers and containers cannot. Retained collection storage and SQL cursor buffers must not be confused with aliases. Keep previous/current-generation allowances until iterator, driver and consumer lifetimes prove they cannot overlap. Use phase maxima only when phases cannot coexist; otherwise add their live reservations.
3. Reserve the full progress envelope before execute/parse/encode. Use separate comparison-only and physical-proof workspace plans: a follower compares all raw fields but does not run its own model parser when joining a live proof. This separation must not skip its metadata scan, literal comparison or authority checks. Do not acquire additional bytes while holding a scan permit or coordinator/cleanup lock.
4. A large row may use a larger weighted workspace with fewer simultaneous physical scans while all 8 readers remain admitted. Reserve leader progress before funding followers, fund only comparisons whose complete workspace fits, and release scan permits before cohort/proof waits. Test large/small fairness, changing scopes and deadlines; do not promise 7 simultaneous large comparison workspaces. The existing deterministic small-input cohort must still achieve 1 proof and 7 joins.
5. If the complete retained collection cannot fit, select fully validating, budgeted thread streaming before any child submission. This is useful only if an individual supported large row actually fits its proven envelope. Release incompatible raw pins first; do not carry an unbounded retained prefix into fallback. A failed single-row admission remains a failed availability gate, not successful fallback. No post-submission duplicate proof is allowed.

The input limit remains 64 MiB; aggregate working-set/private-commit experimental ceilings remain 768 MiB/2560 MiB. Include all 5 selected indexes, mixed result reads, old selected models during replacement, exception chains, child memory and allocator retention where applicable. Samples and `tracemalloc` do not prove native bounds. If the full supported shape range cannot satisfy the unchanged limits, report the specific blocker and keep P1 blocked instead of raising limits or quietly narrowing the accepted domain.

## BEP06. Authority, integrity and cancellation

Every request retains independent before/after authority checks, activation reread, the original transaction/observation clock and 2 attempts. Preserve the original 15-second waiting deadline and 90-second eligibility boundary through byte/scan waits. Evidence sharing is only for a still-running pure proof after complete independent equality. No completed-result cache, shared authority/preflight certificate, stored-hash trust or latest-only validation.

Retain all historical rows, missing-dependency and head checks, all 19 raw fields and storage types, strict model validation, canonical UTF-8 including EOF, sorted bar/request domains, snapshot hash, formula definition and per-fact formula hashes. Producer segmentation or a dual sink must generate exactly the reference bytes, including empty lists, optional values, escaped/control/supplementary Unicode, negative zero and Decimal extremes.

Cancellation detaches an observer or revokes unstarted work. It never refunds a live SQL buffer, raw pin, native parser call, encoder chunk, transport or selected physical result. Synchronous parser calls need ownership through their actual return; a cancellation flag is not physical interruption. Check cancellation between bounded producer units without granting a partial proof. Keep leases until resource release and, for a child, `DRAINED` or supervised exit/bridge cleanup. Another observer cannot cancel a shared proof. Cursor/worker cleanup failure keeps byte debt and the storage fence across generations, even when a CPU permit becomes free.

## BEP07. Next implementation sequence

1. **P0-A: contract and attribution.** Restore paired specification/task parity before coding. Freeze parser/encoder/schema fingerprints and per-phase ownership categories. Extend the fixtures to long Decimals, dense arrays, all 5 selected indexes, Unicode/escapes and error-heavy inputs. Measure raw/model/normalized/error retention, native allocations and parser/producer thread CPU separately. Establish the preallocation bound before changing any reservation.
2. **P0-B: C producer.** Compare original, previous token producer and size-planned C variants separately. Accumulate reusable size information during the existing normalization pass; bound descriptor storage and avoid another complete tree index per hash. Use a small-document fast path and size-bounded batches for large arrays. Only then consider a separately tested snapshot-hash/literal dual sink if needed. Retain all original canonical APIs and validation policy.
3. **P0-C: parser and admission.** Retain direct byte parsing and explicit immutable ownership. Prove success/failure input-copy bounds, model/native process bounds and actual cleanup. Introduce proof/comparison workspace distinctions and ownership transfer only after that proof. Exercise supported near-16 MiB input through SQL preflight, payload, full validation, ranking and drain; a pure-parser success is insufficient. Keep the earlier 2-slot scan candidate independent until these gates pass.
4. **P0-D: combined gates.** Test 1/2/8 readers, equal/changed/late cohorts, large/small mixed workloads, memory boundaries, deadlock/starvation, authority/time changes and cleanup failures. Then compare with and without scan admission and, only when prerequisites pass, process transport. Any hard failure stops performance acceptance; permit 3 clearly labeled diagnostic rounds to locate it.
5. **P1: conditional integration.** Only after correctness, supported-input availability, ownership and native bounds pass, restore 10 A/A pairs and 20 ABBA/BAAB blocks. Keep process mixed gain at least 20%, isolated-result regression at most 5%, monitor/total CPU regression at most 10%, and no worse rejection/timeout rate. Real-owner/browser acceptance follows an approved integration candidate: 100 attempts per variant, every failure retained, no p95 claim below 100 successes, and the existing 20% real mixed p95 target.

## BEP08. Required verification

Differential-test full outputs and failure classes against the unchanged validator. Cover all domain/scalar/head tampering, rehashed-root corruption, old rows, missing/extra/reordered evidence, SQL TEXT/BLOB/NULL/numeric distinctions, invalid UTF-8, duplicate keys, noncanonical spelling and trailing data. Exercise exact scalar/batch boundaries, huge valid Decimals, many small objects, large non-JSON columns, normalization expansion and writer rollover. Include request/bar sorting and schema drift.

For memory, verify reserve-before-execute/parse/encode, planner and buffer growth, previous/current row retention, selected-model replacement, exception traceback lifetimes and repeated drains. Mutation checks must catch unbudgeted allocations, missing literal/authority checks, accepting partial output, completed-proof reuse and early refund. Cover cancellation before admission, during native parsing, during encoding and on both sides of 15-second/90-second boundaries; test follower detachment, last observer departure, stop and cursor/child cleanup failure. Retain existing authority, retention and cancel/drain suites. Do not claim browser verification for an unintegrated diagnostic.

## BEP09. Sources, reproducibility and limits

The measured runtime is Python 3.14.7, Pydantic 2.13.4, pydantic-core 2.46.4, SQLite 3.50.4 and SQLAlchemy 2.0.52. CPython's matching [Python encoder](https://github.com/python/cpython/blob/v3.14.7/Lib/json/encoder.py) and [C encoder](https://github.com/python/cpython/blob/v3.14.7/Modules/_json.c) explain the dispatch and complete writer allocation. Pydantic documents [JSON parsing and partial parsing](https://pydantic.dev/docs/validation/latest/concepts/json/) and [direct JSON validation](https://pydantic.dev/docs/validation/latest/concepts/performance/); these APIs do not guarantee a bounded parser workspace. Python documents the scope of [traced allocations](https://docs.python.org/3.14/library/tracemalloc.html). Public pydantic-core source at the exact installed tag was unavailable during this analysis, so no version-matched native allocation proof is claimed.

Evidence embeds the corrected diagnostic source and its runtime/source/input fingerprints. To reproduce, save it under `.pytest_cache/encoder-analysis-20261023/probe.py` and run `.venv/Scripts/python.exe .pytest_cache/encoder-analysis-20261023/probe.py cpu` and `.venv/Scripts/python.exe .pytest_cache/encoder-analysis-20261023/probe.py parser` sequentially from the repository root. The CPU mode uses the existing frozen monitor fixture. The parser mode constructs only local synthetic inputs. Raw evidence payloads are not published.

Only the producer's output was varied in the CPU diagnostic, with full valid-fixture output equality. The probe has no full tamper/lifecycle/native test coverage and is not a candidate ready for integration. Parser timings use tracing and a single run; CPU results are 3-round medians, not performance acceptance. The current proposal deliberately leaves P1 blocked and records the remaining proof obligations instead of treating smaller output chunks as a memory guarantee.
