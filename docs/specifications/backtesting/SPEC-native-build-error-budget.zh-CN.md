# 原生构建与失败所有权 P0 规格

## NBB-S01. 范围

按 [NBB01–NBB08](PROPOSAL-native-build-error-budget.zh-CN.md)实施隔离实验。保留已有工作。不注册生产路径，不混入并行 AI 提取/日库存改动。P1 为条件阶段，门槛失败时不强行推进。

## NBB-S02. 构建与内存资格

记录本机二进制、官方 wheel/源码身份、运行时构建标志、依赖锁/SBOM、可用编译器和产物证据。缺少构建/分配器来源则为 NOT_PROVEN。重新构建的二进制是不同资格目标。不得隐式安装或替换运行依赖。原生/进程观测与 Python 跟踪分开记录；采样峰值不能证明瞬时上界。保持 `64 MiB` 输入、`768 MiB` 聚合工作集及 `2560 MiB` 私有提交。

## NBB-S03. 失败边界

运行不变的完整校验器直到返回或失败，包括迭代器清理。仅把已知精确投影失败类捕获为不可变有界描述，退出异常处理器生命周期后交付。失败结果不得保留原异常、输入、模型或回溯。每个调用者获得新异常。意外清理错误继续传播，不能将清理失败变为有效证明。显式核算失败后的循环垃圾回收；观察者取消或逻辑完成均不能提前归还物理所有权。

## NBB-S04. 准入与不变量

通过实际 SQL 预检测量合法长 Decimal 和密集夹具。原生资格通过前保留保守预留。仅算术推导的更小预算包属于诊断，不是可执行准入策略。记录元数据/载荷次数、拒绝及最终债务。不能持有部分租约再阻塞等待无预算的编码器升级。

保留独立前后权威检查、激活重读、全部历史行、所有 `19` 个字段/类型、严格模型、规范 UTF-8/EOF、bar/request/root/formula/per-fact 校验及原时钟/次数。保持 `1` 个物理证明、`1` 个排队所有者、`15-second` 等待、`90-second` 资格及 `2` 次尝试。取消和清理失败保留所有权直到实际排空；清理失败隔离后续代。

## NBB-S05. 验收

验证成功结果等价、密集失败生命周期、新异常、缺失依赖、所有原始字段、重算哈希篡改、清理失败、并发隔离、取消、死锁和时间边界回归。执行三轮交替冻结 CPU 和独立跟踪内存对比，标记为诊断。原生与可用性通过后才执行 `10` 对 A/A、`20` 个 ABBA/BAAB 区块、`20%` 混合收益、结果与监控/总 CPU 回退不超过 `5%` 和 `10%`，且拒绝/超时不恶化。浏览器验收需已集成，每版本 `100` 次尝试，达到 `100` 次成功才可声称 p95。明确报告未执行门槛。
