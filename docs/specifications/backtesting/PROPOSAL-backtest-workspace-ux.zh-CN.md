# 方案：补齐回测工作区的交互流程

状态：待评审方案，尚未批准实施。日期：2026-10-20。基线：`2be0a8b`。[英文主文档](PROPOSAL-backtest-workspace-ux.md)。

## BW01. 目标与范围

将刚完成的创建流程和最小结果原因定位闭环延伸到其余回测页面。用户应当能够找到某次运行、判断任务是否在推进、区分读取失败与记录不存在，并从数据或计划证据返回相关结果。

检查 `/backtests`、`/backtests/data`、在 `/backtests/:runId` 展示的任务状态、共享服务控制，以及审计、来源、权益等剩余区域。保留 `SPEC-backtest-creation-ux.md` 的创建流程和 `SPEC-backtest-review.md` 的证据契约。

本文是基于调研的方案与能力划分，不修改应用代码，不授权迁移，也不替代现有规格。下文 P0/P1/P2 表示本轮优先级，不表示上次已验收最小范围中仍有未完成工作。

## BW02. 检查依据与限制

### BW02.1 浏览器观察

2026-10-20 使用独立 Chrome，以 1440 × 1000 视口只读检查 `http://127.0.0.1:8765`：

- 运行列表返回 HTTP 200，包含 5 次已完成运行。可见记录的股票、区间和结果时间相同，主要依靠很长的运行 ID 区分。5 条记录的最终权益和收益率都显示不可用。单凭这一现象，不能判断每个缺失指标是预期限制还是异常。
- 第一条记录接近首屏底部。页头、服务状态条、重复导航、研究提示和大块筛选表单都排在记录前面。
- 历史数据页显示没有已验证数据集，但运行列表仍有上述 5 次运行。代码确认该页读取的是已验证数据集目录，并非全部历史存储；连续闭环数据读取器明确不改写旧市场数据目录。目录为空不能证明历史数据或结果全部被删除。
- 服务管理可以正常展开，并报告历史可读取。刷新、查看待恢复任务、停止服务的操作处于相近的视觉层级。
- 从列表打开一次结果，在 15 秒等待窗口内仍未出现结果标签。另一次直接访问，在观察 5 秒后仍显示加载提示。未观察到页面异常；截图时尚未观察到汇总响应。这是读取延迟现象，不是稳定延迟测量，也没有据此定位后端原因。
- 首轮运行列表和数据页检查记录到零次非 GET/HEAD 请求、零次页面异常。未触发运行、数据下载、恢复、取消、保留状态修改或清理。

成功加载的结果子页以及运行中、失败等任务状态，本轮依据源码和已有测试检查，未通过真实任务重新演练。本次不是完整浏览器验收报告或用户可用性研究；仅新增方案，因此未重跑现有自动化测试套件。

## BW04. 建议的能力划分

以下是现有回测模块内的工作流 ID，不是新增服务。

| Module ID | 职责 | 依赖 |
|---|---|---|
| `backtest-read-feedback` | 统一读取状态、慢读取反馈、安全刷新和服务操作层级。 | 现有读取/服务契约 |
| `backtest-run-discovery` | 紧凑结果历史、筛选、有效行摘要及返回导航。 | `backtest-read-feedback` |
| `backtest-data-discovery` | 解释目录范围，改进数据集浏览，再提供有界覆盖证据。 | `backtest-read-feedback` |
| `backtest-task-workspace` | 查找活动/终态任务，解释进度，打开正确任务/结果并显式恢复。 | `backtest-read-feedback` |
| `backtest-result-exploration` | 精简审计/来源/权益视图，精确时间筛选与受支持的结果操作。 | `backtest-read-feedback` |

建议顺序：统一读取反馈 → 运行历史与数据范围 → 任务工作区与数据清单 → 深入结果浏览。对比能力是结果浏览的后续可选扩展。范围确认后，再为各工作流补充双语实施规格和任务。

## BW05. P0 — 找到记录，看懂读取状态

### BW05.1 运行记录

采用紧凑页头，保留一个主要“新建回测”动作。默认显示股票代码与快捷保留筛选，日期范围放入“更多筛选”。展示已生效筛选标签和“清空筛选”。保持现有日期含义：按回测截止日筛选，不是程序实际执行日期。

默认行结构：**股票 + 回测区间｜结果摘要｜成交数｜保留状态｜查看结果**。以短运行 ID 尾缀辅助区分，完整 ID 放到详情/复制入口。仅在权威来源返回股票名称时展示名称。股票/日期标题只是展示层组合；可编辑名称与备注后置。

根据资金模式和可用性选择指标。说明 `POSITION_LIMIT_ONLY` 不计算本金收益率或净值回撤，并与估值无效、证据不可用、读取失败区分。展示真实可用的盈亏、费用或计数，不把缺失值当成零。比例统一以明确的百分比单位展示，详情中保留精确源值。

为已访问游标提供上一页/下一页/首页。从结果返回时恢复筛选、页码和原行焦点。直接打开深链接且不知道前一游标时，不伪造上一页。区分从未有运行与筛选无匹配；当前页计数必须标明范围，不能当成全局总数。

### BW05.2 历史数据范围与浏览

路由保持稳定。导航使用“历史行情数据”，明确当前内容是**已验证数据集目录**。说明已完成运行、计划历史是另外两类记录，并提供直接入口。

针对本次观察到的情况，空态表达应为：“此处尚无已验证数据集，不代表之前的回测或计划记录被删除。”提供“查看运行记录”和“新建回测”。不能保证某个缺失区间一定能成功下载。

使用日期控件，保持现有精确筛选语义：数据集开始日期不早于下界，结束日期不晚于上界。解释这是目录范围筛选，不是证明某个目标回测区间已被覆盖的查询。未来“覆盖我的回测区间”需单独的后端契约。

数据集行优先显示股票、带标签的日期区间、验证时间和后端报告的状态。展开后再看预热日期、7 个计数、Schema、哈希和原始阻断代码。补齐清空筛选、重试、上一页/下一页/首页；区分读取失败、筛选无匹配、目录为空。

### BW05.3 读取与服务反馈

统一状态词汇：加载中、显示上次数据并刷新、读取较慢、读取失败、没有匹配、历史/目录为空、证据过期/缺失。服务状态读取成功，不等于某条结果已经读取成功。

建议慢读取行为：10 秒时提示读取较慢并保留返回入口；30 秒时允许中止/替换读取后重试，并防止旧响应覆盖。这里仅影响读取请求，不取消或重新提交回测任务。在宣称性能修复前，应单独定位本次真实结果读取延迟。

同一查询刷新时保留上一版数据，并标注最后成功读取时间；筛选变化时，不把旧行伪装成新条件的结果。研究提示保持简短，协议等技术解释移到详情/帮助。

服务正常时保持紧凑；受阻时展示影响、一个推荐操作和可展开诊断。停止服务放入高级管理，并在确认前说明影响。保留明确选择任务恢复、修订检查、不确定写入沿用同一请求重试的规则；修复服务不会自动恢复任务。

## BW06. P1 — 任务连贯性与有用的数据证据

### BW06.1 任务工作区

在运行记录内部区分“结果”和“任务”。复用 `GET /api/v1/backtest-jobs`，通过服务端有界条件筛选类型/状态。用紧凑区域优先显示运行中/待处理任务，并能访问已完成、失败、已取消任务。任务 ID 与运行 ID 始终是不同身份。

任务卡回答：正在做什么、当前阶段、服务端最近更新时间、允许的下一步。复用已有阶段与单位字段；总量已知时展示真实比例，未知时展示不定进度，不虚构百分比或预计耗时。

“查看任务”只读取已接受任务；只有响应提供匹配运行 ID 时才提供“查看结果”。读取失败提供读取重试，取消结果未知时重试同一取消请求；失败/取消的运行不能出现暗示自动续跑的“继续”。保留取消确认，并区分已请求取消与确认取消。

现有自动准备链路部分由创建页 composable 持有，因此不能承诺关闭/刷新浏览器后每个准备步骤都会继续。持久化跨任务流程以及“复制设置重试”需要校验后的存储意图/上下文契约；P1 最小范围是可靠发现、重新打开已被接受的任务。

### BW06.2 数据清单

P0 澄清范围后，按后端能力逐步提供三类明确分开的证据：本地行情覆盖、已验证数据集、已完成运行引用的冻结数据。先显示股票、区间、数据类型和已记录的可用性/阻断原因，再显示标识符。

现有数据集目录无法证明这三类内容。新的有界读取投影需要明确来源身份、覆盖范围、可用性和关联运行引用。不能在浏览器合并日期区间后宣称数据完整，也不能为每一行读取一份大型报告。历史冻结快照是否有效，与现在能否开始新的回测，是不同事实。

已知阻断代码映射为说明和具体下一步；未知代码保留中性解释与原始代码。浏览和筛选不启动下载，自动数据准备仍由现有显式开始流程负责。

## BW07. P1 — 补齐结果浏览

### BW07.1 审计与时间定位

将大事件卡片改为紧凑时间行：时间、事件类型、一句话结果、“查看”。只有服务端支持整次运行的筛选语义时，才按日期、类型、计划版本分组或筛选。按需展开已记录内容/ID，并复用现有原因面板。

精确日期定位契约具备前，将参考指数操作改名为“查看决策记录”，避免暗示可以定位当天。契约具备后，携带选中日期进行有界查询并聚焦对应行。不能只筛选已加载页却声称是全量结果；保留已有跨页精确原因跳转。

### BW07.2 计划与来源

优先显示紧凑的生效日期时间线。选择一个版本后，展示规则及已有对照；技术 ID、哈希收进“证据详情”。期初账户、运行假设、来源证据分别按需展开。复用 `ResultRuleChanges.vue` 的显式读取；对照缺失或读取失败不能标成“无变化”。

在影响解释的位置保留历史可用时间假设。选择版本只改变查看上下文，不修改冻结运行或本次使用的计划。

### BW07.3 权益与结果操作

为权益/现金/市值增加图例开关和有界时间范围浏览。精确值表放入明确的展开区域，保证键盘可达。资金模式或估值受限时显示有意义的不可用原因，避免只留下空图。

图表与成交/日期联动需要后续有界查询和身份契约，不是纯视觉修改。重采样点仅用于展示，不能替代精确证据；不在浏览器推导缺失收益率、回撤或单笔交易盈亏。

在运行身份附近放置紧凑保留动作，说明它保护明细免于常规过期清理，不把它当成收藏。保留修订和未知结果保护。实际支持的格式放进“导出”；不支持的格式说明原因，不放无效按钮。扩展闭环报告导出属于 P2，需真实后端契约。

## BW08. P2 与明确边界

后续候选能力：用户命名/备注、将运行设置复制为可编辑的新建草稿、2–3 次运行对比，以及受支持的闭环结果导出。

比较指标变化前，必须展示股票、区间、计划版本、资金模式、响应规则、费用和冻结数据差异。不能对不可比或不可用收益率排名。复制设置不自动运行，并保留草稿的复制来源。

首批不包含：参数寻优、浏览器虚构财务归因、强制补建历史、历史数据删除，以及大范围重写刚验收的创建页。
