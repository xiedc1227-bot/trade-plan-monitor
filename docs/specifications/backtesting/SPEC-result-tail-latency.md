## RLT-S01. Objective and questions

Implement P0 first: distinguish observer latency, admission waiting, physical execution, evidence verification and response delivery on the real result page. Which stages account for a successful request >=8 seconds? Does a shared physical read explain several logical requests? Does an abandoned observer leave owned work draining correctly? P1 is conditional on measured duplication and its unchanged acceptance gate. Existing edits and historical evidence are preserved.

## RLT-S02. Trace contract and bounds

Opt in with `TPM_READ_TRACE_DIR`; unset means no sink, new files or diagnostic headers. A local window lasts 1800 seconds, admits at most 1024 traces and 64 simultaneously active traces. Each trace retains at most 64 fixed-name spans/points. Keep at most 128 completed traces in memory. JSONL records are <=16384 UTF-8 bytes; rotating files use 1 MiB with 2 backups. Unknown fields/stage names and oversized records are rejected by observation only. All limits affect diagnostics, never business admission, authorization or verification. Trace initialization, recording and sink failures cannot change business responses.

Use generated opaque trace/physical IDs, fixed entry-point/stage/status categories, monotonic timestamps, durations, thread CPU for synchronous workers, counts and byte lengths. No source/plan/evidence bodies, SQL values, raw URLs, user-provided IDs, authority tokens or credentials. HTTP response header `X-Read-Trace-ID` links browser timing to the root; shared result observers reference the same physical trace, whose CPU is recorded once. Async waiting never claims event-loop CPU as its own. Physical work remains visible after cancellation; no completed-proof reuse is introduced.

An epoch anchor correlates browser wall clocks with server traces; all durations/deadlines remain monotonic. The WebSocket accept header also exposes only `X-Read-Trace-ID`, linking the connection trace to heartbeat/read children without changing frames, cursor or cadence. Thread propagation binds diagnostic context only; caller authority/session context is never copied to physical backtest workers. ASGI body timestamps describe handoff completion, not remote receipt. A response-stage residual includes framework validation/encoding, middleware and scheduling; it is not measured as exclusive serialization CPU.

## RLT-S03. Stages and protected boundaries

Observe HTTP ingress/header/body completion; metadata/result admission; worker submission/start/end; result joins/observer cancellation; immutable input, report/binding, full audit/diagnostics; explicit public response validation. Record endpoint return separately from response headers so framework response validation/encoding plus middleware/scheduling is an explicit residual, not falsely labeled pure serialization CPU. Browser records request/first-byte/body completion/ready separately and associates header IDs. Instrument monitor reads and heartbeats with independent before/after authority spans and snapshot/activation reread spans without changing cadence.

Preserve per-request authority, clock/BEGIN snapshots, activation reread, plan/inventory/risk/calendar/proof checks and retry budget. Keep monitor bounds, in-flight-only sharing, result caller metadata checks, event schemas/canonical bytes/hashes, ordered retained event-set checks, retention/pin behavior, cancellation/physical drain, 5-second metadata and 60-second result admission waits. No cache TTL, worker increase, shortened retention or deferred verification.

## RLT-S04. Measurements and P1 gate

Measure actual successful reads before/after P0 and enabled/disabled overhead in >=10 alternating isolated rounds; target <=2% CPU and <=5% wall overhead. With the actual owner healthy, collect >=20 successful observations per isolated/startup-dashboard/existing-client-heartbeat/staggered/queued-abandoned scenario and bounded 2/8-reader stress. Separate failures, cancelled observers and physical completions. Browser requests use the unchanged monitor protocol. For captured >=8-second successful reads, reconcile intervals within 5% or report the unattributed gap. No artificial sleep/injected delay may masquerade as a real slow request. If the original outlier is not reproduced, state that limitation; publish all samples, medians and ranges/maxima rather than a small-sample percentile.

Only then evaluate P1 row-local canonical-byte reuse: >=10 alternating unprofiled rounds, >=10% median CPU and wall improvement, <=10% peak-memory regression and no >10% mixed-scenario regression. Keep all typed/storage/event/sequence/count/report/input bindings. The earlier 9.2% exploratory wall gain does not pass. If insufficient, defer P1 with evidence instead of lowering the gate.

The new 10-round feasibility comparison improves wall by 11.34% and CPU by 10.94%, authorizing formal P1 evaluation within the approved scope. The decoder's shared private core returns the already verified canonical text; the diagnostic row iterator passes at most 256 KiB of encoded bytes, including bytes-object overhead, directly to the common ordered-set verifier. Oversized events fall back to original canonical encoding rather than being rejected. Existing public helpers retain their return values and all checks. No object-identity cache or externally supplied preverified flag is added. Production acceptance still requires the original timing/memory/mixed/tamper gates.

The first formal 10-round wall result is 9.998%, below the gate without rounding. To resolve measurement variation, predeclare exactly 20 additional alternating rounds and evaluate all 30 together, retaining the initial samples. Do not repeat until green or lower 10%. The encoded-byte bound is checked conservatively before allocation, including non-ASCII worst-case size; each digest and producer releases its previous row before requesting the next. Publication/data/clock semantics remain unchanged.

Decision after the fixed 30 rounds: wall improves 10.53%, CPU 9.85%; the simultaneous 10% gate is not met. P1 is deferred and its candidate source is preserved outside production. The final code retains original audit decoding and event-set hashing; enhanced independent integrity tests remain. Do not infer that P0 alone accelerates verification. Final browser regression also synchronizes existing date-filter removal and advanced-service disclosure assertions, without changing product UI or weakening audits.
