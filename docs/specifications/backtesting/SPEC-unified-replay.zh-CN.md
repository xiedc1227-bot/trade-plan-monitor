# 规格：统一计划历史回放

## UR01. 权威与目标

基线：`6118569`；日期：2026-10-03，Asia/Shanghai。本增量契约属于 `backtest-engine`，必要适配涉及 `backtest-results`、`backtest-jobs`、`backtest-api` 和 `backtest-web`。仅对 Schema 5 替代这些模块中“仅旧计划”的假设。当前监测仍以 `SPEC-unified-plan.md` U01–U08 为准。用户授权设计、内部审核、顺序实施和最终独立审核，无需再次阶段确认。

通过既有离线运行、任务、结果、CLI 和 Web 入口，使用不可变历史证据回放一份完整已审核的 `UnifiedTradePlan`（`CONDITION_PLAN`、`condition-plan-v1`）。不要求实时激活。完成标准是复现并验证当前监测语义，而非仅让旧历史引擎接受新的 Python 类型。

## UR02. 范围与依赖边界

单一能力，实施顺序：冻结研究输入 → 共用监测回放 → 持久化结果 → CLI/API/页面 → 一致性验收。旧回放保持不变。复用 `unified_conditions`、`unified_lifecycle`、`daily_risk` 和当前记账/操作检查。检查实际调用路径，不复制策略建立第二套评估器。

优先使用私有临时研究会话，以冻结时间、确定性身份、隔离仓储和无发送出口调用当前运行与共用操作参与者。不得创建生产组合或依赖实时状态。只有隔离确有需要时才允许最小提取纯状态转换/操作参与者，并提供在线回归证据。研究逻辑位于 `backtest/`；在线计划 API 不成为第二套研究 API。研究专用适配器可禁止通知入队；在线默认行为保持不变。

## UR03. 冻结输入与身份

引入严格、有界、不可变的 `research_input` / `researchInput`，Schema 5 必填，旧计划禁用。版本为 `unified-research-input-v1`。包含明确研究起点、初始库存依据、冻结补充证据和有序操作脚本。字段缺失不能授权操作。保留既有初始批次数量、取得日期、成本及稳定 lot key；计划可选的分仓配置不能变成强制库存上限。最大持仓及适用 CORE 策略继续执行。

冻结绑定内容的已审核研究声明（`reviewed_at`、证据及明确确认）；API 提交独立核验服务端当前不可变审核绑定。声明证明研究输入经过审核，不声称计划在历史起点已经真实审核。今天审核的计划可以研究过去日期。声明不能提供历史人工事实或真实操作权限。未知初始库存不能与非空初始批次共存。初始取得日期保留 T+1 语义，不能变为立即可卖的基准库存。

Schema 5 使用 `backtest-run-v4`，哈希包含精确计划哈希/版本、数据集身份/范围、初始现金/批次、执行假设、上下文/公式版本和完整规范化研究输入。完整输出使用 `backtest-report-v3`。旧 `backtest-run-v1/v2/v3`、report v1/v2、数据集、计划字节和导出域保持逐字节一致。旧序列化省略缺失的增量字段。任务 ID、尝试次数和墙上时钟不进入语义哈希。研究内部权限 ID 从冻结计划和起点导出，绝不能取决于完整未来脚本或整个数据集哈希，确保未来变更不重命名早期决策。

`plan_version_id` 继续作为查找/审计元数据，与旧输入一样不进入 v4 身份。隔离会话使用从内容导出的身份，因此相同已审核内容在不同存储 UUID 下不改变研究结果。

操作脚本使用稳定唯一操作 ID、明确 `+08:00` 时间和确定性同刻顺序：新可用市场/人工证据 → 生命周期操作 → 评估 → 明确操作 → 记录结果状态。拒绝含糊重复排序及范围外操作。支持限定范围的肯定/否定技术事实、独立事件及信号失效事实、明确风险重评、整单模拟请求，以及因停用/替换结束普通权限。模拟请求须指定规则/风险及精确发生次数/数量，不能使用“每个信号自动交易”策略。未知、陈旧、部分或不支持的请求产生可见阻断/结果，不得静默丢弃。

替换结束本次运行原计划的普通权限并保留锁存风险，不交易第二套策略；新版本普通规则需单独运行。替换终止必须携带明确的已审核替代版本身份。仅保存草稿不是终止事件。风险解除需要独立冻结、限定范围的明确重评证据，不能根据后续价格推断。

## UR04. 市场证据与时间

按冻结事实可用的事件时间推进，遵守 `received_at`、`available_at`、正式日线收盘、完整五分钟与交易日历。墙上时钟和未来事实不得进入早期上下文。预热仅提供上下文，不贡献信号、库存操作或收益。保留既有有界滚动上下文及公式。后到修订成为新事件，不能重写历史。

日内启动时，当前监控允许在 `started_at` 之后的事件中使用当日已完成的桶进行确认；启动之前不生成事件、操作或估值。每事件日历上下文最多 512 行，前向记录只保留到首个下一开市日。缺失历史日线交易日覆盖仍是准入阻断。冻结历史分钟 profile 保留确定的 12 秒接收宽限；任意延迟或缺口的源批次不能在该 profile 下成为 ready 数据集。

既有数据集包含未复权日线，当前监测消费已核验且可比的日线序列。研究补充输入须冻结已核验日线证据或明确复权证明，包含可用时间、精确股票/来源/数据集绑定及报价可比性。复用当前准入/序列校验。不得把未复权原始日线标为 QFQ，不得编造单位复权因子。每个截止只能使用当时可用的证据；未来复权锚点无效。纯分钟计划可以没有日线证明；缺证明的日线依赖条件明确阻断。不兼容补充事实须拒绝，不能接受两套冲突市场事实。不授权供应商、标签协议或数据集身份变更。

日线信号使用 `NEXT_EXCHANGE_SESSION_ONLY`，五分钟使用 `CURRENT_SESSION`。`PLAN_ACTIVE` 仅取消规则日期过滤。`DATE_RANGE`、计划激活窗口、来源截止、信号到期、独立发生/去重、风险优先级/确认/锁存、明确解除和未知输入阻断维持当前行为。普通权限结束使其可操作信号失效，同时风险义务保持可见。每日权益/估值属于研究输出，不能用虚构成交创造收益。

## UR05. 模拟与研究记账

明确研究脚本可以不包含模拟请求，此时产生信号但库存不变。提醒、已读、审核和评估均不改变持仓。明确脚本模拟每次仅应用完整授权的正数 100 股整数倍，逐次发生只执行一次，并复核时间/窗口、当前权限、风险、报价、CORE、最大持仓及 T+1。初始库存须明确已知或未知；未知阻断操作。

旧 `execution-model-v1` 自动下一分钟成交及费用/滑点假设保留历史研究语义，不能授权当前监测操作。Schema 5 区分（a）当前明确模拟状态转换与（b）研究货币估值/成本投影。冻结执行假设仅用于后者并标为研究。不能用现金限制后的部分数量替代授权整单操作。不支持的执行假设必须稳定报错，不能静默忽略。`MANUAL_EVENT_RISK` 不能成为当前基本面阻断项；当前契约拒绝该值，不编造语义。

## UR06. 输出、持久化与入口

已批准映射保留 v2 summary/detail 外层及集合哈希域。`DECISION` 内容使用 `unified-research-decision-v1`（`ResearchDecisionEvent`）；`EXECUTION_OUTCOME` 使用 `unified-research-operation-v1`（`ResearchOperationOutcome`）。`DAILY_EQUITY` 使用强类型研究货币投影，共用权益数值供图表。完整报告为 `backtest-report-v3`，JSON 摘要导出为 `backtest-report-summary-v4`，研究估值账本 CSV 为 `explicit-simulation-valuation-v1`。旧导出字节不变。监测回执价格/时间与研究滑点估价/费用明确区分。研究现金不足以 `INSUFFICIENT_RESEARCH_CASH` 阻断估值，保留完整监测回执，后续收益无效/null。未知库存保持未知，并标记 `VALUATION_EXCLUDES_UNKNOWN_HOLDINGS`。不支持的 `FULL_SESSION_SUSPENSION` 事实明确返回阻断结果和报告限制，不能静默改变冻结的已成交交易日。

保留既有路由、任务、结果隔离、原子发布、取消、保留期及导出完整性。增加有界强类型当前决策/操作证据，保留事件 ID/时间、信号发生、条件证据、确认/执行窗口、阻断、库存前后状态、风险及明确请求结果。不得硬塞进含义错误的旧策略字段，不公开任意字典。采用可辨识的增量投影；仅在字节含义变化时使用新投影/导出域，并在写出前记录映射。完成报告必须列明不支持/缺失证据及研究限制。

当前决策的 `signals`、`risks` 和 `risk_action` 描述评估状态；`resulting_signals`、`resulting_risks` 与 `inventory_after` 描述该事件明确脚本执行后的状态。`alerts` 保留实际运行的提醒证据。CSV 区分 `monitor_status` 与 `valuation_status`。所有计算得到的公开资金值，包括累计费用，都必须保持安全整数；溢出以 `RESEARCH_VALUATION_SAFE_NUMBER_EXCEEDED` 明确失败。达到 70,000 个决策事件后，后续评估在再次调用运行服务之前以 `RESEARCH_EVENT_LIMIT_EXCEEDED` 失败。

`POST /api/v1/backtest-runs` 对当前快照接受 `researchInput`；服务端审核校验仍是权威，未激活已审核计划可用。工作者只读取冻结请求。CLI `backtest run` 接受本地研究输入文件；API 不接受文件路径。既有 `/backtests/new` 提供明确研究输入并解释空脚本；`/backtests/:runId` 展示当前证据及被阻断操作。提供可用夹具和命令。已知格式错误/当前不支持输入映射为可理解的校验/冲突响应，不能产生类型错误/500。保留响应大小、分页及安全整数边界。必要时同步两份 OpenAPI 和生成类型。
