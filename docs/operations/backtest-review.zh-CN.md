# 回测结果审阅

## BR-OPS01. 阅读结果

打开已完成运行。概览展示适用事实；**成交与原因** 中点击 **查看原因** 打开证据面板。**未成交原因** 展示有界的逐份计划诊断，选择示例可定位准确审计序号。**审计事件** 支持按身份定位父／子记录。浏览器后退恢复选择。**计划与来源** 保留冻结版本和详细设置。

`POSITION_LIMIT_ONLY` 不计算本金收益率和回撤。未知成本与过期证据明确展示。计划示例为代表性记录，每份最多 8 项、总计最多 256 项。证据面板从当前事件页最多展示 100 项条件依据。不推导全运行原因总数或逐笔盈亏。

## BR-OPS02. 缺少查询元数据的旧结果

新暂存的监控闭环结果自动包含派生查询元数据。旧运行可能显示 `NOT_READY`，原成交／审计页面仍可读取。对已有结果数据库，停止回测服务并进入其正常的停止／检查点维护状态，然后从项目根目录执行：

```powershell
.venv/Scripts/python scripts/rebuild_backtest_review.py --database <result.sqlite3> --run-id <runId> --limit 100
```

输出为 `{"nextAfter": "<detailId>", "hasMore": true}` 或 `{"nextAfter": null, "hasMore": false}`。使用上一批返回的 `--after <detailId>` 重复相同命令，直到 `hasMore` 为 false。每次最多读取 100 条保留中的已验证事件；拒绝未索引的继续边界。命令只接受已存在的结果数据库。此操作修改派生元数据和可选结构，不修改规范载荷／哈希、交易决策或缺失证据，也不修复损坏记录。重启服务后重新打开原因面板。

## BR-OPS03. 可用性

`EXPIRED` 表示明细已被清理，仍保留的成交继续展示回执。`NOT_RECORDED` 表示没有记录该产物。`NOT_READY` 表示查询元数据尚未完整建立。`PARTIAL` 表示至少一条关联缺失或查询不完整。这些状态不表示条件不满足或零成交。分页 `hasMore` 与已知缺失关联相互独立。

## BR-OPS04. 初始化失败后运行记录不可用

检查 `GET /api/v1/backtest-service`。`DEGRADED`、`canRead=false` 且 `reason=SERVICE_REPAIR_REQUIRED` 表示元数据准备尚未建立可读取的服务；即使数据库结构为当前版本，列表也可能返回 `503`。普通列表刷新复用已失败的服务代次，不会重新初始化。

当 `physicallyDrained=true` 时，通过**服务管理 → 重新准备回测服务**明确重试元数据准备。这不授权恢复历史任务或提交新运行。确认服务为 `READ_READY`、`canRead=true`，且 `GET /api/v1/backtest-runs?limit=20` 成功；不要把错误解释为空历史。若准备再次失败，检查本地 `Backtest metadata preparation failed` 警告：包含异常类型、可用时有界的大写迁移错误码、操作系统错误编号、异常起始函数/行号和服务代次。省略原始异常消息、数据库路径和源代码行。`UNCLASSIFIED` 不能确定根因；看门狗超时有独立警告。这些诊断仅保留在本地，不加入 API 响应。

仅有空 WAL/SHM 遗留文件不能证明损坏，也不能解释过去的故障。预检报告阻断时，应保留数据库保护并使用现有已验证维护流程；不得手动删除 SQLite 伴随文件。如果首次故障缺少足够详细的记录且已无法复现，应记录这一限制，不要根据后续重试成功推断确定根因。
