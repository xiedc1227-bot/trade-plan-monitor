## MLP3-O01 — 来源与政策审核

使用 `/plans` 和 `plan-extract-v12`。原文明确定义金额上限时，A 必须明确选择 Schema9 / condition-plan-v5，并保留完整 P0/P1/P2 日线联动 TACTICAL BUY 政策。上限覆盖该证券 CORE+TACTICAL 模拟持仓。金额使用整数分，数量仍为正的100股整数倍，并与适用官方最小买入量／递增单位取交集。来源或政策变化必须重新绑定准确内容审核。

`position.limit.mode=CAPITAL_ONLY` 要求 `capital_policy`，禁止 `max_qty`。`QUANTITY_AND_CAPITAL` 另要求在 `position.limit` 内提供正的100股整数倍 `max_qty`；Schema9 没有根级 `position.max_qty`。两项限制同时检查完整选定数量。原文必须明确选择一种含义：

| 政策 | 按当前已准入价格 p 检查完整拟买数量 q |
| --- | --- |
| `OPEN_COST_CAP` | K+B(q,p)<=C，K 为保留的历史模拟预算成本，B 包含明确估算的买入费用／滑点 |
| `MARKET_VALUE_CAP` | (N+q)*p<=C，N 为全部当前 CORE+TACTICAL 股数；估值为 `CURRENT_ADMITTED_QUOTE` |

两种政策均使用 `policy_version=capital-policy-v1`、`currency=CNY`、`scope=SYMBOL_CORE_AND_TACTICAL`、`account_scope=SIMULATION` 和正整数 `cap_fen`。成本上限即使费用模式为 NONE，也要求完整、有日期与证券范围的 P2 `buy_cost_schedule`；如果 P2 同时提供费用表，两份内容必须完全一致。市值上限禁止该成本费用表，也不要求开仓成本。仅写“总投入预算”而未明确会计含义时保持未决；B 不能补政策、初始化成本或授权。累计终身买入、净投入现金、组合或分桶金额上限需要另一份规格。

## MLP3-O02 — 初始化数量并明确确认成本

模拟库存、模拟预算账、历史真实持仓与研究盈亏分别保存。先明确确认预期模拟 CORE/TACTICAL 数量。金额面板列出完整当前批次标识与数量，开仓成本输入初始为空。OPEN_COST_CAP 下存在非零持仓时，逐批提供保留成本、观察时间、来源、摘录与原因，再明确确认开仓／校正。不得自动使用 B、当前报价、研究成本或真实账户余额替代。

服务端检查当前已审核计划、完整准确批次、库存／预算版本及非未来观察时间；在同一事务中写入版本化预算账与记录，并赋予接收时间。同一命令重试返回原回执。回执包含 `inventoryChanged=false` 和 `authorityGranted=false`，不产生库存、信号、批准或模拟。未知成本仍为 UNKNOWN。明确初始化的零持仓可使用已知 K=0，无需成本声明；首次另行确认的买入在事务内创建并借记预算账。

卖出释放实际所选批次的历史成本。400股成本450001分时，卖出100股释放112500分，余下300股保留337501分，最终全卖准确释放337501分。卖出收入或利润不增加 C。旧计划买入缺少兼容成本证据时，该批成本变为未知；准确卖出未知批次后可能恢复已知合计成本。数量／预算不匹配时不会自动重建成本。替换计划保留共享证券库存与预算账，不重置预算。

## MLP3-O03 — 数量、授权与当前执行

P2 先得出 Q0，P0 选择普通大盘数量，P1 仅保留原文允许的两条例外。金额条件检查准确整笔数量，不选择 Q0、不按剩余金额缩量、不向上取整、不产生第三条例外。等于上限通过。K450000分、q100、p1000分、最低佣金500分及其他费用／滑点0时，B=100500分，K+B=550500分，在 C550500分时通过；p1001得出550600分，整笔拒绝。N400、q100、C500000分时，p1000通过，p1001按500500分拒绝，p990按495000分通过，数量始终不变。

`WEAK_MINIMUM` 仍要求明确计划许可、STRONG、S1 和 `0.5*Q0 < minimum <= Q0`，批准量恰为兼容官方最小量。`BROKEN_STRONG` 仍要求许可、STRONG、S2，以及另行人工输入不超过 Q0 和适用股数上限的合法 Qe，输入初始为空。预览不授权、不预留预算。每个机会必须明确批准，再在原下一交易日窗口内另行整笔模拟；批准与执行分别复核当前预算／报价。不引入自动批准、按金额减量、部分执行或新窗口。

界面区分冻结数量与当前金额资格，并在上下文变化后丢弃迟到响应。执行串行化库存／预算写入，检查当前报价、准确政策、预算、库存及授权，再一并提交库存、批次成本、信号／批准消耗和回执。校正仅能在原窗口内阻断或恢复资格，不能改量、重新武装或延长已消耗信号。发送时检查抑制过时的可执行 BUY 提醒。仅持仓超额不产生 SELL，BUY 专用金额／费用失败不阻挡实际有来源授权的技术风险 SELL。

## MLP3-O04 — 当前 API

| 路由 | 用途与边界 |
| --- | --- |
| `GET /api/v1/simulation-capital-books/{symbol}` | 有界读取预算账／当前库存；成本尚不存在时也返回完整 `inventoryLots`，最多500批，不推断零成本 |
| `POST /api/v1/simulation-capital-openings` | 明确审核的完整批次开仓／校正；同源、幂等、服务端赋接收时间；不影响库存／批准 |
| `POST /api/v1/plan-capital-previews` | 使用服务端报价／预算／库存只读评估当前整笔数量；字面值 `authorityGranted=false`，不写入 |

预览接受 `planVersionId`、`ruleId`、可选 `occurrenceId` 与 `proposedQuantity`。例外 `occurrenceId` 是服务端 candidate_id；仅 BROKEN_STRONG 接受人工 proposedQuantity。调用方的报价、总成本、版本或批准声明不能替代服务端权威。开仓接受准确预期库存／预算版本及完整明确批次成本／来源，写事务内重新读取审核和库存。请求错误返回422，当前准确授权缺失／过时返回409，资源不存在返回404，沿用结构化本地 API 契约。预览或开仓回执不能作为模拟令牌。

## MLP3-O05 — 冻结研究、恢复与兼容

Schema9 使用 `backtest-run-v10`、`unified-research-input-v3`、显式 `capital-replay-program-v1` 和 `capital-exception-program-v1`。开仓／校正区分 RECORDED_LOCAL 原始回执与 RESEARCH_SCENARIO 声明，绑定准确 OPENING(lot_key) 或 BUY_SIGNAL(signal_id) 引用，保留 observed<=received<=available 时间。未来声明不能补较早缺口，完整批次缺失或错误会阻断声明。运行开始前已可用声明仅可初始化匹配、明确已知的开仓持仓。不读取当前用户预算账、费用供应商或实时批准。

准备回测表单提供可选高级入口“预算与复评研究记录（可选）”，初始留空，仅接受含 capitalProgram 和／或 exceptionProgram 的 JSON 对象；须填写完整冻结记录，不能提供客户端价格或总额。已审核准备／选择上下文改变后须明确重新输入。公开准备命令省略 capitalProgram 时，会在必填 v10 字段冻结显式空程序，不补零成本，不读取当前账，也不借用研究成本。非零持仓成本未知仍阻断依赖成本上限的买入。填写的声明须通过准确来源、批次、时点、顺序及分类校验，授权与操作仍分开。

预算声明、例外授权与独立操作具有唯一时间／顺序。两条私有工作器调用共享当前服务，研究现金／费用／盈亏与估算预算成本保持独立。报告保留来源／分类／私有回执哈希，并解析、重校验共享完整证据。引用缺失或篡改会在发布／重读时失败。原32KiB结果项、8MiB来源／输入及其他限制保留。旧 `POSITION_LIMIT_ONLY` 资金值取消可花现金约束，Schema9 计划金额条件仍生效，不虚构可用现金余额。

存储迁移0027增加独立版本化附属表。实施／测试使用临时数据库。操作用户数据库迁移仍须单独授权，在已批准的升级或降级前备份。旧读取器拒绝9，不将其改标签。降级拒绝丢弃非空新证据。重启读取相同准确预算／库存版本；旧二进制或外部数量不匹配会使成本未知。Schema1–8 字节、哈希、冻结输入与授权保持不变。

## MLP3-O06 — 原提示词剩余边界与验证

G05 仅在隔离、单证券模拟范围内支持。真实账户／部分成交／在途订单预留／聊天推断持仓（G06）、非100股执行／零股清仓／普通规则建立 CORE（G07）、自动基本面／新闻判断（G09）、自主组合／Q0 选择及任意表达式（G12）仍排除或人工处理。自动价位／证据发现（G04）、任意按波动调整确认（G02）、事件相对期限／公司行为换算（G08）、日线联动五分钟确认（G11）、未认证供应商／BSE覆盖与自动规则维护（G10）需要另行审核能力。G03 的费用发现／目录更新及主观可行性仍人工。A/B 格式适配和完整来源检查保留 G13/G14 边界。强制约束不支持时阻断受影响可执行规则，不删除条件或替换成提醒。

使用实际 [V01–V08任务检查](../../tasks/market-linkage-p3.zh-CN.md)与[验收状态](../verification/2026-10-26-market-linkage-p3.zh-CN.md)。后端单元／集成／契约进程分开以避开既有重名；live 测试排除，不伪装成已认证。容量检查单独运行，保留120秒／证券、768MiB工作集增量、512MiB行情及192MiB结果限制。本地验收使用合成价格／费用和临时数据库，不认证真实数据／费率、实际成交或部署。
