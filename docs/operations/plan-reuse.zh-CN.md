# 已审核计划复用

## PR-O01. 工作台来源

打开**回测 → 新建回测 → 工作台已审核计划**，选择准确的已审核版本。计划可以未启用；未审核草稿不可选。选择计划不会调用 AI 或启动运行，需要时可核对原文。

确认生效交易日、历史可用时间（可选，默认该日09:30）、信息截止时间、期初持仓时间、库存是否已知，以及核对依据或明确研究假设。这些日期描述研究假设，不是计划历史发布证明。库存未知继续保持未知并阻止模拟交易；有依据时才选择已核对空仓。已知批次使用 CORE/TACTICAL 分仓和100股单位数量，可选填元单位总成本、取得日期及可卖数量。未知事实留空。资金使用 `POSITION_LIMIT_ONLY`，无现金预算，不读取实时持仓。

确认一次研究上下文后，设置响应、费用及可选结束日期，开始回测。复用现有历史数据自动准备及监测循环。`FOLLOW_REMINDERS` 模拟满足条件的操作，`OBSERVE_ONLY` 不产生成交，现有阻断和执行规则继续生效。含 `selectionId` 的链接可恢复冻结上下文，之后工作台编辑或启用状态变化不会改变它。保存或提交结果不确定时，使用页面提供的同一请求重试，保留原 key／请求体。

## PR-O02. 已有准备计划与结果

次级**计划更新时间线与原文准备**入口保留现有计划库、原文准备、提取／审核、未完成准备恢复及多计划连续回测，当前链条上限为256项。首期每次运行使用一个工作台版本，不支持跨来源混合或多个工作台版本日程。两套计划存储保留当前编写／审核职责。

已有 `preparationId` 链接、历史结果链接、明细及导出继续可用。新增工作台结果展示真实计划版本／审核及冻结研究选择。已接受运行拥有复制输入，执行及结果读取不再依赖任一来源计划存储。删除当前 JSON/YAML 计划导入：`POST /api/v1/plan-imports` 返回404，直接客户端／表单同步移除。内部编解码和原文准备继续支持。

## PR-O03. 存储及运维边界

首次使用准备存储时，带标记 schema 1 通过事务升级到2，仅增加 `backtest_plan_selection`。原准备文档和幂等回执保留准确字节。测试不会修改生产数据库。旧程序会拒绝升级后的存储；如果部署后可能回退程序，应事先保留一致数据库备份。不增加监控／行情／结果 SQL 迁移、供应商、依赖、工作线程所有者或并发上限。

新增复制输入使用 `monitor-loop-stored-input-v3`，其绑定选择的输入使用 `workbench-loop-input-v1` 和既有 `backtest-run-v5` 执行公式。既有输入／报告编解码、哈希、导出及准备链语义保持不变。准确契约及实际检查见[设计](../specifications/backtesting/SPEC-plan-reuse-unification.zh-CN.md)及[验证记录](../verification/2026-10-19-plan-reuse-unification.zh-CN.md)。

## PR-O04. 可复现的浏览器验证

浏览器测试使用隔离 Chrome for Testing `157.0.8103.6`，版本固定在 `web/test-browser.json`。此版本包含 Chromium 在 main revision `1712735` 的[完整 no-store 响应修复](https://chromium-review.googlesource.com/c/chromium/src/+/8508456)，所选构建 revision 为 `1717349`。系统 Chrome `155.0.8059.80` 会把已完整读取的响应报告为 `net::ERR_ABORTED`，无需修改应用请求处理或过滤这些事件。

从项目根目录先准备一次测试浏览器，再执行检查：

```powershell
.venv/Scripts/python.exe scripts/setup_test_browser.py
npm --prefix web run test:e2e -- tests/e2e/streamCompletion.spec.ts
npm --prefix web run test:e2e -- tests/e2e/backtests.spec.ts tests/e2e/monitor-loop-backtest.spec.ts
```

Python 已在 PATH 时，`npm --prefix web run setup:test-browser` 等价。安装脚本从官方地址下载准确版本到已忽略的 `web/.test-browsers/157.0.8103.6/` 缓存，并复用完整安装。它不安装／更新系统 Chrome，普通测试运行也不会下载文件。浏览器缺失时直接提示准备命令，不静默回退到受影响版本。Chrome for Testing 属于开发验证前提，不是产品运行依赖。

现有 Chrome 项目、视口、断言、5秒期望超时及零重试保持不变。新增回归要求1000次完整流读取且无失败请求，检查单独到达的响应结束，并确认真实调用方取消仍产生失败请求。取消审计结果见验证报告 PR-V05，后续窄屏布局修复见 PR-V06。


## PR-O05. 维护计划更新时间线

提交首份原文建立时间线，股票代码／名称由提取获得并在审核时确认。打开已有时间线，点击**更新交易计划**，将生效日期更晚的新原文接续到准确已审核末端，保存前核对既有新增／修改／保留／取消差异。仅最新原文可编辑，草稿不改变已审核时间线。同一股票的独立审核线保持分开；存在多个末端时明确选择一条路径。

时间线页面替代逐份复选框和手动组合按钮。**开始回测**自动通过原服务端组合检查冻结完整所选路径，再复用自动数据准备和连续回测。打开时间线只读。新建表单时，结束日期默认 Asia/Shanghai 当前日期且可修改；清空时保留原服务端默认处理。首份计划／账户起点及费用、风险、资金、T+1 规则不变。

历史原文／规则链接打开独立只读页面，不能编辑、审核或发起运行，不改变原页面的已选末端和表单。冻结／运行回执不确定时使用页面提供的同一请求重试，解决前保持路径、设置及键／请求体锁定；已确认冻结回执在之后的提交重试中继续复用。

新增审核更新不会改写已接受／运行中的回测或历史结果，重新回测更新后的时间线会生成新结果。原准备／结果链接及导出继续支持。本次无数据库迁移、公开 API 或实时计划激活变更。工作台单版本回测入口继续保留；跨库组装时间线、同日替换、回插历史、合并／删除／重排及任意起始日期裁剪不在本期。见[已确认范围](../specifications/backtesting/SPEC-plan-update-timeline.zh-CN.md)及[验证记录](../verification/2026-10-19-plan-update-timeline.zh-CN.md)。

## PR-O06. 只读交易条件详情

点击**查看计划及本次调整**，查看计划日期、所属股票、前序计划，以及已审核的保留／修改／新增／取消变化。价格以元展示。独立时间线及不同更新路径仍分别选择，通过日期、审核时间和展示顺序区分。页面不再以文字显示内部准备／版本 ID 和哈希；内部关联、选择及回测资格检查仍使用原准确引用。

展开一项时，仅读取既有已审核准备记录及对应原文的详情。展示变化必须与所选审核清单、原文、生效日期、修订及对应已审核证据一致；不匹配或读取失败时明确提示重试。缺少逐项变化证据的旧记录继续提供已审核原文与交易条件链接。展开详情不触发提取、审核、组合或回测提交，不改变已选末端及表单。原独立只读原文页面继续保留。

## PR-O07. 浏览紧凑的时间线列表

计划库每页展示 10 条完整时间线。每条默认展示股票、日期范围、审核时间及更新次数；点击**查看更新记录**展开已审核更新，再点击**查看计划及本次调整**查看原交易条件详情。不同末端路径仍保留在所属时间线内，展示编号跨页连续。

翻页或展开记录不会改选回测末端或提交任何操作。列表上方持续提示当前选择，必要时点击**定位已选时间线**返回其所在页。原**打开时间线**及**更新交易计划**操作保留准确末端引用和行为。分页仅限制已完整加载分组的展示，不截断计划链，不改变连续回测或历史结果。

## PR-O08. 可修改的低费用回测默认值

新建**创建回测运行**表单时，预填以下费用假设。佣金是低费用研究预设，不代表券商统一最低报价，应按实际券商约定调整。费率采用 0 到 1 的比例。

| 字段 | 默认值 | 含义 |
|---|---|---|
| `commissionRate` | `0.0001` | 佣金 0.01%，即万分之一 |
| `minimumCommissionFen` | `500` | 最低佣金 5 元 |
| `stampDutyRate` | `0.0005` | 印花税 0.05% |
| `transferFeeRate` | `0.00001` | 过户费 0.001% |
| `buySlippageFen`, `sellSlippageFen` | `0` | 每股滑点 0 分 |

保留的脚本研究表单中，两项 BPS 滑点也默认 `0`。所有值均可修改，包括明确设置零费用。清空必填费用仍按原规则校验失败，不在提交时暗中兜底。切换计划不重填费用。这些仅是新表单前端默认值：API 仍要求明确费用，原费用计算／舍入不变，已保存的历史费用／结果不改写。

印花税及过户费率参考[上交所股票投资服务](https://one.sse.com.cn/onething/gptz/)，核对日期为 2026-10-20。预设不会自动调整历史税制或券商特定费率。

## PR-O09. 只读查看历史费用参数

单计划、工作台及连续回测的结果汇总均展示**本次回测费用参数**。读取该次回测保存的 `costs`；较早格式读取已保存的 `assumptions.executionConfig`。不读取新建表单默认值，也不以默认值替代历史保存的零值。

佣金、印花税和过户费率以精确百分比展示，例如 `0.0003` 显示为 `0.03%`。最低佣金显示每笔元金额（`500` 分显示为 `5.00 元/笔`），连续回测滑点显示每股元金额（`1` 分显示为 `0.01 元/股`）。较早格式的比例滑点保留其含义：`1.25` BPS 显示为 `0.0125%（价格比例）`，不换算成固定每股金额。十进制费率和分金额的展示不经过二进制浮点舍入。

该区域没有编辑或提交控件。查看时不重新计算结果，也不写入历史数据。既有运行／报告标识、费用计算、计划链执行及历史接口保持不变。**累计费用**仍表示结果总额，与这些输入参数分开展示。

## PR-O10. 区分历史不可读取与计划库为空

计划库读取失败时不得显示**还没有计划时间线**。只有成功响应确认列表为空时才显示空态；读取失败时应说明历史尚未加载、暂时无法确认是否有记录，并禁用该状态下的新建时间线操作。重试期间隐藏上一次错误。如果成功读取后的刷新失败，保留已加载记录及所选末端版本，并标明列表为上次成功读取的数据。重试成功后清除错误。

HTTP `503` 时，引导用户检查页面上方的**服务管理**。查询 `/api/v1/backtest-service`；`DEGRADED` 且 `canRead: false` 表示读取能力故障，不能据此判断计划被删除。当 `physicallyDrained: true` 时，通过既有 `RETRY_PREPARATION` 恢复操作并传入 `resumeJobIds: []`，再刷新计划库。不得用 `RESUME_JOBS` 或重新创建计划来恢复列表读取。恢复必须显式发起，列表不会自动提交恢复命令。
