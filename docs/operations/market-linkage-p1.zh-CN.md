# 大盘联动 P1 操作说明

[英文权威版本](market-linkage-p1.md) · [规格](../specifications/monitoring/SPEC-market-linkage-p1.zh-CN.md) · [任务](../../tasks/market-linkage-p1.zh-CN.md) · [验收](../verification/2026-10-24-market-linkage-p1.zh-CN.md)

## MLO1-01 — 计划许可与逐机会批准

使用 `/plans`：原文 → `plan-extract-v10` 草稿 → 原文审核 → 保存 → 确认审核 → 明确启用。Schema 7 / `condition-plan-v3` / `market-linkage-v2` 要求 `REVIEW_PER_OCCURRENCE`，并分别声明 `WEAK_MINIMUM` / `BROKEN_STRONG` 许可，各为 `DISABLED` 或 `PER_OCCURRENCE`。保留市场、相对强势、S0/S1/S2、数量与授权定义的完整来源绑定。定义缺失或混用固定数量／策略数量会阻断完整导入与审核，不得从版本标签推断许可。Schema 5 仍为固定数量；Schema 6 保留 `BLOCK_P1`，不能取得例外批准。

计划审核仅允许使用某条路径。每个独立机会从 `PENDING` 开始；AI 提取、计划启用、事实核验、提醒、已读及重新打开应用都不能批准它。P0 的市场、相对强势、确认条件及[官方数量单位](market-linkage-p0.zh-CN.md#mlo02--官方数量规则)门槛继续适用。

## MLO1-02 — 两条数量规则

Q0 是原文明示的基础数量，m 是官方最小量，s 是官方递增单位，capacity 是当前经审核持仓上限下的剩余容量。模拟数量仍须为正的 100 股整数倍。

| 路径 | 条件 | 数量与示例 |
| --- | --- | --- |
| `WEAK_MINIMUM` | WEAK、STRONG、S1、路径已许可；`0.5*Q0 < m <= Q0` | 唯一申请量恰为 m，只读。主板 Q0=100、m=100 可申请 100；科创板 Q0=300、m=200 可申请 200。Q0=400、m=200 属于普通 WEAK 买入，不是例外。不兼容的最小量不能向上替代。 |
| `BROKEN_STRONG` | BROKEN、STRONG、S2、路径已许可 | 人工明确填写 Qe，输入框初始为空。须满足 `0 < Qe <= Q0`、`Qe <= capacity`、`Qe >= m`、`(Qe-m) % s == 0`、`Qe % 100 == 0`。Q0=500、capacity=400 时可申请 300；空值／0／150／500 被拒绝。没有半量或全量默认值。 |

两条路径均要求证据已知、不受更高优先级风险阻断，并有容纳整笔数量的容量。批准冻结数量；后续容量不足阻断整笔，恢复后也不改量。普通路径仍向下取整。

## MLO1-03 — 审查、批准、撤销与模拟

1. 打开当前候选，检查路径、原确认交易日、已消费证据、官方单位、下一交易所交易日及到期时间，填写具体理由。`BROKEN_STRONG` 还须填写精确数量。
2. 请求服务器预览。只能批准该份精确预览及版本，或拒绝本次机会。证据／数量／版本过期后须重新预览；结果不确定的重试沿用命令身份。
3. 批准只改变授权。另行确认界面提供的完整模拟买入。服务器在消耗批准并记录库存／回执的同一事务内，重查当前权限、报价／可交易状态、库存、容量、风险和原执行窗口。
4. 如需撤销未消耗批准，须提供理由。拒绝、撤销、到期、失效和消耗均为终态。新日期、换路径、克隆、更正或重试不能重开原机会；只有既有、独立核验的重置／新事件策略才能产生另一机会。

执行窗口是确认日 D 之后的下一交易所交易日，到上海时间 15:00 截止。迟到证据或批准不能延长窗口。未知或修正日历会阻断旧窗口；接收时间由服务器确定。消费事实／复权口径、计划／审核、启用或所需规则身份变化使授权失效；无实质内容变化的接收记录或等价数字不影响它。必要来源暂缺时阻断执行，恢复后重新核验。被风险阻断的收盘不能重置待批准候选。

命令入口：`POST /api/v1/plan-exception-previews`、`POST /api/v1/plan-exception-decisions`、`POST /api/v1/plan-exception-revocations`。准确字段、摘要／版本绑定及错误类型以生成契约为准。请求不能直接携带可执行授权。

## MLO1-04 — 冻结研究

Schema 7 研究使用 `backtest-run-v8`。单次研究接收 `unified-research-input-v2`；已准备的单版／多版／工作台循环请求可接收 `exceptionProgram`，内部为 `exception-replay-program-v1`。每条 `frozen-exception-event-v1` 保留原候选、v2 证据、不可变事件、精确计划哈希、来源、顺序及封装哈希。工作进程只使用冻结输入和私有账户，绝不读取当前本地批准。

- `RECORDED_LOCAL` 标识提供的本地事件证据；`RESEARCH_SCENARIO` 标识明确的研究假设事件。结果保留区分，二者都不能导出为实时授权。
- 未提供事件就没有例外权限。仅批准不会产生例外成交，`FOLLOW_REMINDERS` 也不例外；必须有独立、明确的操作脚本。
- 研究开始前的来源事件被拒绝，应选择包含证据和授权时间线的开始时间。未来事件只在原接收时点应用，不改变较早决策。已消耗事件只验证先前的私有执行，不创建成交。
- 单次研究保留指定时点模拟语义。循环操作是在 `at` 提交的请求，须有当前有效例外提醒；按 `NEXT_ELIGIBLE_MINUTE_CLOSE` 及配置响应延迟执行。两条入口都保留原交易日窗口与整笔数量。
- 持久化结果把来源结果、操作请求绑定到冻结输入及审计。重复信号证据使用经过验证的同一决策内引用，不提高既有 32 KiB 单条上限。

界面不会虚构或自动导出事件脚本；高级冻结输入使用类型化 API。原有结构／哈希保持可读；未知版本拒绝处理，不降级。

## MLO1-05 — 本地运行与限制

增量迁移 `0026_market_exceptions` 增加候选／事件类型和唯一命令身份。在获准升级用户数据库前备份；实施验收只使用临时数据库。有例外记录时拒绝降级。旧读取器须保留新记录字节并阻断不支持的操作。

P1 仍是本地监测和隔离模拟，没有券商下单或自动人工批准。官方数量规则直接用于已记录日期／证券范围；不支持的历史范围会安全阻断。离线验收不认证实时数据商可用性。准确完成状态、测试数量及剩余限制以验收报告为准。
