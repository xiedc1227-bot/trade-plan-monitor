# 生成计划的真实AI验证

本流程独立于通用生成提示词，仅在用户明确要求真实供应商验证时执行。单纯生成文档不授权保存、审核、启用或执行计划。

1. 使用项目配置的接口、明确要求的模型及现有限额。跨标的样本检查选用`deepseek-flash`，限额为输入50,000字符、输出4096 tokens、超时30秒、最多重试2次。不打印凭证，不为规避失败提高预算。
2. 使用准确的README提示词及给定事实生成A／B，仅将A原文发送到真实提取函数，保留原始请求、响应、哈希和结果。不剥离前缀、补字段、删绑定或修补输出，保持Schema、来源审核及安全校验。
3. 核对提取状态、候选结构、全部来源条款及绑定、问题、假设和警告。按本次实际政策统计BUY／SELL、风险分支及提醒；JSON正确或`finish_reason=stop`不等于完整通过。另行审查B是否编造事实、过度确认或误述能力。
4. 必填上限缺失、不支持的必要依赖应阻断完整政策生成，不填假值、不削弱规则、不擅自替换为提醒。负样本A严格为`暂不提供可导入正文。`，不作为计划交给提取器。
5. 保留并报告失败和文字偏差。先诊断再修改验证，不重复请求未改提示词直至出现偏好结果，不用旧版本成功替代当前验证。
6. 将实际验证结果记录在模型生成的正文／附件之外；生成时不能声称未来提取已通过。需要时只读核对前后状态。验证成功不代表保存草稿、确认审核、启用计划、执行交易或修改实际／模拟库存。

跨标的合成测试只证明本次被测软件契约。中英文提示词一致性可单独检查，并应明确实际向供应商发送哪种语言。
