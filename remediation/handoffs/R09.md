## Delivered boundary

R09 provides an isolated, backend-authoritative BUY-only subset of the explicit-plan design. It preserves Schema 1/2 behavior and adds sibling Schema 3 contracts rather than changing legacy meanings. The evaluator consumes only completed declared facts, distinguishes unknown inventory from confirmed zero, enforces board-lot/max-quantity and revision fences, persists repeat state and the alert in one transaction, and emits a separately versioned `explicit-rule-alert-v1` payload with path-addressed evidence.

The installed execution chain is now explicit and tested: `MonitorWebComposition` starts `RuntimeLifecycleService`; `MarketSessionScheduler` supplies a `MarketDeadline`; `_ProductionRuntimeState.run_deadline` invokes `ProductionMonitorPipeline.run_deadline`; the shared `RuntimeDeadlineCoordinator` acquires and persists one normalized stock-minute batch through `SymbolService`, partitions legacy and Schema 3 plans, and invokes `ExplicitRuntimeEvaluationService.run_intraday_and_publish` only for completed five-minute contexts. The service commits the explicit result, repeat state, alert, and `ALERT_CREATED` monitor event before the publisher and dispatcher make the invalidation and reminder observable. Startup recovery reuses the same minute-history boundary and skips legacy official-close recovery for Schema 3.

Reference refresh always obtains the required exchange calendars, but daily limits and official daily history are requested only for legacy plans. Explicit-only evaluation does not prepare strategy market-index snapshots and never makes undeclared manual risk a prerequisite. Mixed-plan deadlines continue to share one symbol acquisition and preserve plan-order results.

The public surface now includes `GET /api/v1/plan-capabilities`, `GET /api/v1/position-inventory`, and `POST /api/v1/position-inventory-confirmations`. Persisted explicit BUY reminders are returned by the existing alerts API and have no legacy bucket, fill, or position-prefill semantics. The OpenAPI snapshot contains exactly 47 approved paths (32 live and 15 backtest), has SHA-256 `5338dbd1fbc93d10e9099d4a221ee725e504a530aa336834d2f2614b41629145`, and the generated TypeScript contract is synchronized.

Complete Schema 3 draft/import requests fail closed with `SERVICE_UNAVAILABLE`, malformed partial requests remain validation failures, and stored Schema 3 activation is blocked. `publicActivationAvailable` is therefore exactly `false`; isolated trusted review in tests is not a public activation grant.
