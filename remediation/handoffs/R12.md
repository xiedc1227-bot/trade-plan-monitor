# R12 handoff: public explicit activation and alert consumption (partial)

Date: 2026-09-13 (Asia/Shanghai). Canonical English; `R12.zh-CN.md` is the equivalent Chinese review copy.

## Implemented slices

- Public Schema-v3 activation now requires the current `reviewId`, `contentHash`, completed executable draft, draft status, and active-pointer `expectedRevision`; it atomically changes the active pointer through the existing repository transaction.
- The production active-plan source resolves a persisted complete `ExplicitPlanDraft` to the same `ExplicitTradePlan`; a partial active document fails closed.
- `GET /api/v1/plan-capabilities` reports public activation available with no pending ordinary-form gate. The frozen OpenAPI snapshot and generated TypeScript were regenerated.
- The Web plan client accepts the generated v3 detail fields, submits bound review confirmations, passes the review binding to activation, preserves v3 extraction identity on save, and renders source clauses plus individually selected server review issues without using the legacy JSON editor for v3.
- Alert transport and the alert table discriminate legacy and `explicit-rule-alert-v1` payloads. Explicit BUY, SELL and RISK_ALERT are all filterable; pure risk remains quantity-null and is not rendered as a legacy position reminder.
