Date: 2026-09-13 (Asia/Shanghai). Canonical English; `R12.zh-CN.md` is the equivalent Chinese review copy.

## Implemented slices

- Schema-v3 activation remains strict: it requires the current `reviewId`, `contentHash`, complete executable draft, draft status, and active-pointer `expectedRevision`; the active pointer changes atomically through the existing repository transaction.
- The public capability endpoint is deliberately closed: `publicActivationAvailable=false`, `isolatedTrustedReviewOnly=true`, and `pendingRequirements=["ORDINARY_PLAN_FORMS"]`. This is the externally truthful R12 gate; it must not be reported as open merely because isolated review tests can activate a version.
- The v3 plan workbench renders the server-returned source clauses and review issues without falling back to the legacy JSON editor. The ordinary-policy supplement form offers only unresolved policy fields, writes a new immutable version, labels every added or edited value as `USER_SUPPLEMENT`, and makes the user re-read server review issues. Editing a source-mapped price, quantity, boolean, or structural condition never re-labels it as source evidence.
- Independent inventory is separate from source-text assertions and alert acknowledgement. The symbol detail provides complete board-lot registration with a user confirmation, plus actual opening-balance closure with revision and idempotency binding. Neither operation is reachable through an alert acknowledgement.
- `GET /api/v1/explicit-plan-runtime/{symbol}` reads only the active v3 identity and its persisted rule evaluation; it returns `AWAITING_EVALUATION` when appropriate and never projects a legacy decision as v3. The plan workbench and dashboard render this read model separately from the legacy monitor projection.
- Alert transport and the alert table discriminate legacy and `explicit-rule-alert-v1` payloads. Explicit BUY, SELL, and RISK_ALERT are filterable; pure risk remains quantity-null and is not rendered as a legacy position reminder.
