# R07 交接：可持久化的人工事件风险确认

日期：2026-09-12（Asia/Shanghai）。本文为中文审阅副本；`R07.md` 是语义等价的英文正式交接。

## 完成情况

R07 在本地、离线边界内关闭 F05。它为每只股票增加一条可持久化的人工事件风险确认，范围限定为当前已启用不可变计划的内容哈希和包含边界的到期交易日。不可变源检查清单和原始验收产物均未编辑；完成情况记录在本双语交接对中。

## 已实现契约

- 存储的确认只有两个明确结果：`CLEAR` 和 `RISK_PRESENT`。记录缺失、计划内容变更后的哈希不匹配、到期，或晚于判断 cutoff 的确认，均成为第三种生产状态：未知（`None`）。未知绝不被强制转换为 `False`，因此仍会通过 `MANUAL_EVENT_RISK_CLEAR` 失败关闭。
- SQLite 迁移 `0012_manual_event_risk` 持久化股票、计划哈希、状态、到期日、确认时间和乐观 revision。每次被接受的写入都会追加一条 `MANUAL_EVENT_RISK_CONFIRMED` 审计记录。降级会拒绝丢弃已存在的确认凭据。
- 正常生产 context 在构造 `EvaluationContext` 前，使用与当前计划和风险事实相同的工作单元读取确认记录。这替换了此前硬编码的 `manual_event_risk=None`，但不改变官方收盘风险确认行为。
- 本地 API 暴露 `GET /api/v1/manual-event-risk` 和 `POST /api/v1/manual-event-risk-confirmations`。读取模型明确表达缺少启用计划、缺少确认、计划内容变更和到期。写入受计划哈希范围约束、校验 revision、写入审计，并支持幂等重放。
- `/stocks/:symbol` 组合独立的 `ManualEventRiskPanel`。它展示权威状态、计划版本、到期日、确认时间和明确的未知原因。普通用户选择结论和到期日，复核原生确认对话框后提交带幂等键的命令；浏览器代码绝不从未知状态推导出无风险结论。
