# R15 离线 AI 提取诊断交接

英文原版为 `R15.md`，本文是等价中文审阅副本。2026-09-14（上海时间）从 `cc4aa679b833cf78c642eb943e22b6acea31662a` 实施；实现提交为 `2252841`（`feat: 补齐AI提取有界脱敏诊断`）。本文位于随后单独的文档提交。没有真实 AI、行情、Webhook、券商、下单、成交或生产数据库调用；没有启动 R14 `--execute`，没有创建新自动任务。

## 1. 结果与诊断路径

真实 Web 提取入口现在会在每次提取完成后记录不含内容的回执。`create_production_app` 和专用 R14 有界启动器均根据各自配置的 SQLite 路径选择 JSONL 旁路文件：未来隔离库若为 `data/r14-acceptance/<new-run-id>/monitor.sqlite3`，回执则为 `data/r14-acceptance/<new-run-id>/monitor.ai-extraction-diagnostics.jsonl`。这**不会**追溯写入 2026-09-14 的 R14 数据库。文件仅在本地，沿用数据库目录访问控制，不通过 HTTP 提供。单条最多 2,048 字节；文件最多 512 条、1 MiB，达到上限时移除旧记录。没有自动按时间删除；诊断审阅后随隔离数据库删除。

每条记录包含版本、operation/request ID、原文 SHA-256、配置的 provider ID/model、prompt version、完成时间、提取状态、阶段/原因、安全路径、可选白名单 schema 错误类型与 provider 错误码、归一化 finish reason、供应商模型是否匹配配置模型、尝试次数，以及可用时的已验证 usage。供应商 envelope/usage 缺失时为 `unknown` 或 null。供应商返回的模型名称从不复制入记录；记录使用请求的配置模型。Schema 失败路径仅由代码自有的 schema 字段名导出，最多 12 段/160 字符，数组索引最大 255；陌生键变成 `unknown`。不保存 Pydantic input/context/message 或供应商原始错误正文。内部提取诊断被排除在普通 result 序列化之外。

公开的 `GET /api/v1/plan-extractions/{operation_id}` 在失败时仍不提供草稿、供应商内容、模型、原文 hash 或 usage。现在增加 `diagnosticStatus`：`RECORDED` 或 `WRITE_FAILED`。旁路文件不可写时普通 Web 启动/提取保持可用，后续写入失败也不改变 `INVALID_OUTPUT` 或 `SUCCEEDED`，不妨碍合法复核记录持久化。只有 R14 有界启动器在诊断文件不可写时、任何 AI 请求前拒绝启动付费会话。原有输出校验、激活复核、字节/token 限制以及 R14 3-AI/60-行情/日期/单会话门禁均不变。

## 2. 离线复现与安全证据

新测试的全部响应都经 `httpx.MockTransport` **SIMULATED**，没有一条是原始 DeepSeek 响应。测试使用真实 FastAPI lifespan 和生产 `OpenAICompatibleProvider`，模拟 HTTP 401、`length` 与未知 finish reason、非法 JSON、重复 JSON 键、含秘密标记的 schema 额外键、原文/映射不匹配、忠实合法 V4 输出、非有限 JSON，以及旧版 field-evidence 不匹配。回执能区分 provider 失败、finish reason、JSON 语法/重复/非有限/预算/编码、schema 错误类型与嵌套安全路径、映射/证据失败。合法 V4 输出仍仅供复核。R14 受控启动器测试确认三条 SIMULATED 回执使用其隔离数据库路径。

恶意标记分别置于假 API key、原文、供应商错误正文、供应商模型/finish reason、陌生 JSON 键、schema 输入值和证据摘录。测试检查 stdout、公开失败 JSON 和旁路文件均未出现该标记。生命周期重启后内存 operation 缓存消失，但旁路文件仍在。测试限额下旁路文件只保留最后三条。另以模拟的启动和追加 `OSError` 验证普通生产 Web 仍可用并报告 `WRITE_FAILED`，R14 启动器在 AI 调用前拒绝。已有审核且活动的计划在诊断 I/O 失败期间经历非法和合法模拟提取，激活版本/revision 不变；plan-version 仍为一条，持仓/库存行仍为零。失败未建立复核记录；合法提取仍只建立正常复核记录。

无法证实造成三次**真实** `INVALID_OUTPUT` 的独立提示词/解析器/供应商不匹配，因为当时的原始响应、finish reason 和校验路径均未留存。这些案例是故障模拟，不是历史精确重放；旧根因仍为 **UNKNOWN**。R14-A/C7 仍**未通过**。真实指数请求时序由协调任务另行分析，不属于本次 AI 变更。
