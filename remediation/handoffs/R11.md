## Delivered review chain

The v4 flow is `build_plan_extraction_prompt` -> provider boundary -> `parse_plan_extraction_response` -> server mapping and mandatory-issue validation -> immutable partial-draft save -> plan detail read -> exact review confirmation. The provider output remains untrusted: it cannot select its prompt version, omit a server source clause, invent an unrelated excerpt, suppress mandatory issues, or convert ambiguous/unsupported language into executable policy.

`plan-extract-v4` uses generated-schema digest `9461d3099a923e5f9fe172eeba010e0dbe44cbe9d8f93c9465be9626d08965a1`; the canonical golden prompt digest is `e91f6b32a69a60b1f35da3e5deee5acd17d326cecd0efcadd2aa99bdb36b4eb7`. An omitted extraction version now selects v4, while explicitly configured historical versions retain their old contracts. No real provider, model, credential, or provider configuration was changed or invoked.

Review identity separates the exact immutable plan hash from the semantic content hash. Confirmation also binds the source hash, review-evidence hash, plan-version ID, and optimistic review revision. Required issues are recomputed from persisted source, draft, and mapping on read and confirmation; persisted or returned snapshots that do not match are rejected. `USER_SUPPLEMENT` evidence remains distinct from `SOURCE` and cannot cite unrelated prose. Unsupported sequencing and unqualified close semantics require a supported rewrite, not a generic acknowledgement.
