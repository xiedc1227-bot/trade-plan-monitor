# R12 交接：明确规则复核、库存与当前状态分片（部分完成）

日期：2026-09-13（Asia/Shanghai）。英文 `R12.md` 为规范输入；本文件是等价中文审阅副本。

## 已实现分片

- Schema-v3 激活继续保持严格：它要求当前 `reviewId`、`contentHash`、完整可执行草稿、草稿状态以及活动指针 `expectedRevision`；活动指针通过既有仓储事务原子切换。
- 公开能力端点刻意保持关闭：`publicActivationAvailable=false`、`isolatedTrustedReviewOnly=true`，以及 `pendingRequirements=["ORDINARY_PLAN_FORMS"]`。这才是对外真实的 R12 gate；不能仅因隔离复核测试可以激活版本就报告为已开放。
- v3 计划工作台渲染服务端返回的原文片段和复核问题，不会回退到旧 JSON 编辑器。普通政策补充表单只提供尚未解决的政策字段，写入新的不可变版本，将每一个新增或修订值标记为 `USER_SUPPLEMENT`，并要求用户重新读取服务端复核问题。修订原文映射的价格、股数、布尔值或结构条件不会重新标记为原文证据。
- 独立库存与原文持仓断言、提醒确认相互隔离。个股详情提供完整整手库存登记及用户确认，以及带修订和幂等绑定的实际开仓余额减记。两项操作均不能由提醒确认触发。
- `GET /api/v1/explicit-plan-runtime/{symbol}` 只读取活动 v3 identity 及其已持久化的规则评估；合适时返回 `AWAITING_EVALUATION`，绝不将 legacy 判断投影为 v3。计划工作台和总览与旧监控投影分开展示该读模型。
- 提醒传输和提醒表格区分 legacy 与 `explicit-rule-alert-v1` payload。明确 BUY、SELL 和 RISK_ALERT 都可筛选；纯风险保持 quantity-null，不会被渲染为 legacy 持仓提醒。
