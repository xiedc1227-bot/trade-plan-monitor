## 已交付边界

R09 提供显式计划设计中隔离、以后端为权威来源且仅支持 BUY 的子集。它保留 Schema 1/2 行为，以平行 Schema 3 契约替代修改旧语义。求值器只消费已完成且已声明的事实，区分未知持仓与已确认零，执行整手/最大数量及 revision 保护，在一个事务内持久化重复状态和提醒，并发出独立版本 `explicit-rule-alert-v1` 载荷及按路径定位的证据。

已安装执行链路现已明确并受测试覆盖：`MonitorWebComposition` 启动 `RuntimeLifecycleService`；`MarketSessionScheduler` 提供 `MarketDeadline`；`_ProductionRuntimeState.run_deadline` 调用 `ProductionMonitorPipeline.run_deadline`；共用 `RuntimeDeadlineCoordinator` 通过 `SymbolService` 获取并持久化一次规范化个股分钟批次，随后分派旧计划与 Schema 3 计划，仅对已完成五分钟上下文调用 `ExplicitRuntimeEvaluationService.run_intraday_and_publish`。该服务先提交显式结果、重复状态、提醒和 `ALERT_CREATED` 监控事件，再由 publisher 与 dispatcher 使失效事件和提醒可观测。启动恢复复用相同分钟历史边界，并对 Schema 3 跳过旧官方收盘恢复。

参考数据刷新始终获取所需交易所日历，但只为旧计划请求每日涨跌停及官方日线历史。仅显式计划求值不会准备策略指数快照，也不会把未声明的人工风险变成前置条件。混合计划 deadline 继续共用一次个股获取并保持计划顺序结果。

公开接口现包含 `GET /api/v1/plan-capabilities`、`GET /api/v1/position-inventory` 和 `POST /api/v1/position-inventory-confirmations`。持久化显式 BUY 提醒通过既有提醒 API 返回，不带旧 bucket、fill 或 position-prefill 语义。OpenAPI 快照精确包含 47 条已批准路径（32 条实时、15 条回测），SHA-256 为 `5338dbd1fbc93d10e9099d4a221ee725e504a530aa336834d2f2614b41629145`，生成 TypeScript 契约已同步。

完整 Schema 3 草稿/导入请求以 `SERVICE_UNAVAILABLE` 关闭失败，格式错误的部分请求仍是校验失败，已存储 Schema 3 的启用被阻止。因此 `publicActivationAvailable` 精确为 `false`；测试中的隔离可信复核不是公开启用授权。
