## Implemented contract

- A successful configured-AI extraction now derives and persists one immutable server-owned review snapshot before the in-memory operation may become `SUCCEEDED`. The snapshot binds the extraction, provider, model, prompt version, exact source hash, canonical draft hash, required review-issue identities, and completion time.
- `POST /plan-drafts` accepts optional `extractionId`. The Vue extraction-review flow carries that identity through the generated contract. The server treats submitted `reviewIssues` only as confirmation attempts against its stored required identities; omitted, duplicate, unknown, or forged confirmation data cannot remove a required blocker.
- An explicit extraction identity must match both exact source and canonical draft hashes. An omitted identity does not reopen A1: exact source/draft matches recover the server-owned snapshot, while a known AI draft resubmitted under another source is saved as `AI_REIMPORT` with every required issue unresolved and cannot activate.
- `plan_extraction_review` and `plan_review_provenance` are additive SQLite tables introduced by `0010_plan_review_binding`. Every new version records `MANUAL`, `AI_EXTRACTION`, or `AI_REIMPORT` provenance. Existing rows are backfilled as `LEGACY_PENDING`; existing active pointers remain active, while legacy inactive versions cannot be newly activated.
- Repository reads validate source, plan, provenance, extraction, issue-set, confirmation-time, and hash consistency before returning a version. Retry persistence of the same extraction identity is idempotent while a conflicting binding fails closed. AI/provider or review-store failure never invokes plan activation and cannot replace the active plan.
- The generated OpenAPI snapshot also incorporates R03's already-committed default `plan-extract-v3`, which had not yet been regenerated, so the generated artifact and bilingual approval digest are current as one indivisible contract.
