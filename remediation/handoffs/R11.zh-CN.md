## 已交付复核链

v4 流程为 `build_plan_extraction_prompt` -> 提供商边界 -> `parse_plan_extraction_response` -> 服务端映射与必需问题校验 -> 不可变部分草稿保存 -> 计划详情读取 -> 精确复核确认。提供商输出始终不可信：它不能选择自身提示词版本、遗漏服务端原文条款、虚构无关引用、压制必需问题，也不能把歧义/不支持语句转成可执行政策。

`plan-extract-v4` 使用生成 Schema 摘要 `9461d3099a923e5f9fe172eeba010e0dbe44cbe9d8f93c9465be9626d08965a1`；规范黄金提示词摘要为 `e91f6b32a69a60b1f35da3e5deee5acd17d326cecd0efcadd2aa99bdb36b4eb7`。省略提取版本现选择 v4，显式配置的历史版本继续保留旧契约。没有修改或调用真实提供商、模型、凭据或提供商配置。

复核 identity 把精确不可变计划哈希与语义内容哈希分离。确认还绑定原文哈希、复核证据哈希、计划版本 ID 与乐观复核 revision。读取和确认时会根据持久化原文、草稿及映射重新计算必需问题；不匹配的持久化或返回快照会被拒绝。`USER_SUPPLEMENT` 证据与 `SOURCE` 保持区分，不能引用无关原文。对不支持的先后关系与未限定周期收盘语义，必须提供受支持改写，不能通用确认已读。

此前修正验证涵盖单位、可选的 `safety_conditions=null`、明确全局已完成 5 分钟上下文及有界数值定义。其中 `_ORIGINAL_SOURCE` 是派生简写，不是用户逐字原文；撤回此前“未改动完整原文”的表述。保留的回归因混合子句未解析及 symbol 未映射而正确地无法完成复核；它不证明验收闭环。

新的 `explicit-plan-literal-source-v3.json` 保留提供的中文原文与换行，仅作已记录的 `测试股票` → `003043.SZ` 替换。它经过真实离线 v4 提供商/解析器边界、普通保存/读取/编辑/复核 API 及临时 SQLite。独立的当前值/单位/结构/子句 oracle 在确认前核验提取和编辑后的内容。八条 `human_confirmed_test_supplement` 记录选择 TRADING_DAY、2026-09-14、成交量历史、三条重复政策及两条冲突政策。缺少选择仍阻断；遗漏两项处理确认仍阻断；完整当前复核返回有效 reviewId 和内容 canActivate=true。错误当前价格970、数量200、ALL→ANY 及错误子句归属的变异检查在发送确认前被拒绝。

依照 SPEC-source-treatment-review 及 ADR 0006，新保存仅把服务端映射/证据升级为 `plan-mapping-v2` / `source-processing-v1` / `plan-review-evidence-v2`。完整有限子句匹配生成类型化 `INVENTORY_ASSERTION` 和 `PRODUCT_GUARANTEE` 记录，含精确区段及受支持契约。每次保存/读取/复核都会重新推导；通用 ACK、孤立补录、缺失记录、伪造值/契约/区段及存储处理/解决记录篡改不能消除必审问题。历史 v1 映射哈希不变。这是有界来源处理加人工语义审核，不是通用中文语义证明器。
