# R16 发布滞后选择性补取计划

英文原版为 `R16-plan.md`，本文是等价中文审阅副本。R16 承接 R15 指数只读诊断。实际 R14 已用尽 `rt_idx_min_daily=25` 端点子额度；原始供应商响应和精确逐请求时间未保留。本计划不授权另一轮真实运行。

## 范围与边界

- 仅修复刚完成五分钟指数截止点在下一分钟的补取：只重新获取同一 cutoff 快照仅有 `MISSING_FIVE_MINUTE_BAR` 或 `STALE_DATA` 问题的指数。补取批次复用其他同 cutoff 快照，不对它们调用供应商。
- 保持普通 `prepare` 获取和协调器按 revision 识别的缓存行为不变，包括每个新 cutoff、新计划事实/历史需求、内容修订和新交易日。保留已完成 K 线及观察时间边界、计划自有条件评估、股票截止时间和指数失败隔离。
- 使用受控离线 SDK 与物理调用计数，验证生产调度、评估持久化及真实 Tushare 适配器。所有生成行情帧标记为 `SIMULATED`；不调用真实 AI、行情、Webhook、券商、订单或数据库服务。不执行 R14 `--execute`，不读取或暴露密钥，不提高其 60-行情或端点子额度，不改变 `_session_claimed`，不创建自动任务。
- 保留 `remediation/evidence/R14-preparation/protected-before.json` 记录的 16 个受保护文件。仅提交 R16 归属文件，保留用户先前改动。

## 验收清单

- [x] 同 cutoff 四个 `LIVE`、一个 `STALE` 的批次恰好只补取一个物理请求；该指数可变成 `LIVE`，其余四个保留原快照对象。全 `LIVE` 不补取，同 cutoff 不可二次申请。
- [x] 单纯供应商失败不补取。混合 `BLOCKED`/`STALE` 时仅补取符合条件的陈旧指数；补取失败仍明确不健康，不能满足指数条件。
- [x] 新 cutoff 或交易日正常获取所有指数。新计划事实/历史需求即使先前快照为 `LIVE` 仍走普通获取；普通供应商内容修订仍可见。
- [x] 离线生产调度→评估→持久化场景使用真实 Tushare 指数适配器和受控 SDK，在混合发布边界计数。报告准确物理调用量并检查不变的有界额度，包括全指数陈旧时仅选择性补取仍无法满足额度的情况。
- [x] 无指数条件的股票计划在可选展示指数失败时保留既有评估行为；不把任何不健康指数误报为 `LIVE`。
- [x] 使用唯一系统临时 pytest 基目录完成聚焦指数/runtime/R14 接线测试及适用 Ruff 检查。双语 R16 交接记录命令、计数、剩余预算限制以及 R14-A/C7 真实验收仍未通过。
